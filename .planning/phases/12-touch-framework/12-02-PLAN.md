<objective>
The system element, reachable - at the wire and in the fake, and nowhere above them yet.

**Why the library needs this seam at all.** `grid.get_element_events("system")` returns three events -
setup 0, utility 4, timer 6 - each with its own 908, and `grid-fw/common/src/lua/init.lua:46-50` runs
the system element's `post_init_cb` **first** on every page load. A function defined in system setup is
a global every touch configuration on that page can call by name. The library lives there. HANGAR has
only ever written element 0, and `12-RESEARCH.md` §1b names the five seams that assume it; this plan
takes the three below the device store, and 12-03 takes the two above.

**The one ordering fact that decides the writer.** `grid_decode.c:1283-1288` registers a written body
and runs it **immediately**, in write order. So at install time the init order is HANGAR's, not the
firmware's: write 255/0 before 0/0, or the touch Setup that calls `Q(` raises `attempt to call a nil
value` once, at install, on the desk, and installs no `touch_cb`. The Timer-before-Setup rule
`writeBoth` already carries (`sequence.ts:266-281`) stays. **System, Timer, Setup.**

**What is written, and what is never written.** Three writes per install, not five: 255/0, 0/6, 0/0.
Event 4's default `gpl(gpn())` is the module's physical utility button - page-load-next - and writing
or fetching it is a change to what the user's button does. Event 6's default `print("tick")` would run
once for nothing. Neither is snapshotted either; HANGAR should not snapshot what it never writes.

**Split from 12-03 so that nothing above the transport moves here.** `fetchBoth` / `writeBoth` become
adapters over `fetchAll` / `writeAll` that fetch and write the two touch events only, so
`install.spec.ts`, `session.e2e.ts` and `install.e2e.ts` stay at their pinned twos until 12-03 flips
the store and moves every count in one plan.

Purpose: element 255 addressable, faked, and ordered, with the device store untouched.
Output: three seams moved with four new tests, and the counts above them unmoved.
</objective>

## The wire, measured with the pinned package (12-RESEARCH §1b)

`CLASS_CONFIG_ELEMENTNUMBER` is a two-hex-digit field (`grid_protocol.h:1157-1158`; `dist/index.js:790-
791`). `encode_packet` with `ELEMENTNUMBER: 255` emits `...00 ff 00...` for page / element / event.
Firmware maps 255 to `element_list_length - 1` on receipt (`grid_decode.c:1254-1256`) and back to 255
on the REPORT (`:1338`), so a fetch filter naming 255 matches. Budget is the same
`scriptlength <= 909` for every element (`:1269`). **Nothing in `encode_packet` changes.**

`ElementType.SYSTEM` exists in the pin; `grid.get_element_events(ElementType.SYSTEM)` returns events
0 / 4 / 6 with defaults of length **24 / 19 / 22** - the setup default is `--[[@cb]]--[[page init]]`.

## The fixture shape - the lower-blast-radius choice, with its reason

The research says "key by `${element}/${event}`". Twelve `moduleState(n, { configs: ... })` fixtures
in `install.e2e.ts` and every `synthetic.spec.ts` state pass `configs` **keyed by event number for the
touch element**. Re-keying them is twelve edits in a file 12-03 also edits. **Instead:** keep
`configs[event]` as the touch element's RAM and add `system: Record<number, string>` beside it, defaulting
to `{ [EVENT_SETUP]: SYSTEM_DEFAULT_SETUP }` when absent (a factory module); `flashOf` / `powerCycle` /
`PAGESTORE` copy both maps. The responder routes on `ELEMENTNUMBER`: 255 reads and writes `system`,
anything else `configs`; the REPORT echoes the element it was asked about. A fetch of 255/4 or 255/6
answers the package default for that event (firmware would), but **nothing in HANGAR asks**.

`e2e/fake-zona.ts` shares `ZonaState` with the synthetic fixture; if it re-declares the type, add the
optional `system` map there too and say so.

## Anti-patterns (12-RESEARCH)

- Writing touch Setup before system Setup - raises once on the module.
- Writing or fetching 255/4 or 255/6.
- A literal `"--[[@cb]]--[[page init]]"` anywhere but a test that asserts the package's value.
