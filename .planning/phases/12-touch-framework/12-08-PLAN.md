<objective>
The four cell-toggling sequencers onto the library - three the probe was run for, and the fourth that
carries their guard byte for byte.

> `EUCLID: still not precise.` · `STEPS: same as the other sequencers` · `RADAR POINTS: nice but needs
> the touch detection framework.`

**SONAR is the fourth, and leaving it out was a planning defect.** The bench note names three; the
*guard* is on four. `sonar.ts:168` carries the same inlined guard as EUCLID, character for character,
and it **toggles** a cell (`s.v[n]=not s.v[n]`), so a finger on a boundary arms and disarms the same
cell rather than merely re-arming it - a strictly worse reading of Q2 than the three that were
reported. It is also already in the same smoke test as two of them
(`lua-smoke.spec.ts:1946`, *"arms one cell per cell a swipe crosses, on EUCLID, SONAR and STEPS"*), so
re-fitting three of the test's three subjects and not the fourth would leave one entry's guard
diverging from its neighbours' inside one assertion. The research's §3c table omitted it; this plan
does not.

**What "not precise" was, settled by Q2.** `71*9//128 = 4` and `72*9//128 = 5`: the boundary between
two cells is one unit wide, and a still finger wobbles one unit every sample. A finger anywhere near an
edge is read as alternating taps on two cells - the per-contact dedup 11-08 gave these three toggles
twice. Phase 11 read the same complaint as fast-tap loss and fixed code 9 everywhere; Q3 shows the
hardware never produces a 9 for a human tap, so those fixes were correct and harmless and not the
answer. **The answer is hysteresis, and the library carries it.**

**Each re-fit replaces an inlined guard with one call.** All four carry, verbatim,
`if e~=1 and e~=4 and e<9 then s.q[i]=nil return end local m=x*9//128+y*9//128*9 if s.q[i]==m then return end s.q[i]=e<9 and m`
(**125 characters**, with EUCLID's, RADAR POINTS' and SONAR's spelling identical and STEPS' differing
only in its index names) plus `self.q={}` (**9**) in Setup. The replacement is
`local m=Q(s,i,e,x,y)if not m then return end` - **44 characters, not the 43 the earlier draft said**
- and the table declaration goes. So the Setup saving is `125 + 9 - 44` = **90 before the entry's own
index arithmetic**, which is why no re-fit here can push an entry over budget. The research measured
92 / 87 / 92 with a four-argument call; the five-argument call costs two more each.
**Re-measure every one; do not copy a number from this paragraph or from the research.**

**Every one of the four ALSO takes `X`, and the reasoning that said otherwise was wrong.** The earlier
draft declined the Timer sweep on the grounds that "a stale `H[i]` is cleared by the next press on
that cell through `Q`'s own rule". **It is not.** `Q`'s onset rules reach a stale contact only when
some finger presses again - the same id re-pressing, or another contact landing on the held cell. A
contact whose lift was lost and which is then **never pressed again** (Q6.5 and Q7: four of five lifts
lost, a palm leaving phantoms) holds its cell in `H` for the rest of the session, and the hysteresis
reads every future press by that id against it. The only thing that reaches it is the Timer sweep.
All four already have a Timer - `gtt(0,@TEMPO)` or `gtt(0,@PERIOD)` - so the cost is **`X(s,20)`, 7
characters** appended to a Timer string that has its own 908 and hundreds free. Seven characters
against a failure the probe called its most important answer is not a trade worth arguing.

**What the four still do not take from the library, and why.** Not `F` - their armed cells toggle
under the finger, which is already the feedback, and after 12-07 `F` does not exist. Not `R` - they
hold no per-contact note, so an expiry has nothing to release; `E` calls `R` only if the entry
defined one, and none of these does. Say both in each header so the next reader does not add them.

**QUADRANT is named as a finding, not re-fitted, and the reason is that it is a different failure.**
`quadrant.ts` computes `x*9//128` too, but it acts on **onsets only** (`if e~=4 and e<9 then return end`)
- a MOVE returns before any cell is computed - so Q2's boundary wobble does not toggle it. What it
*does* have is Q6.5: it holds a note per contact in `s.k[i]` and releases it only on codes 3 and 5..8,
so a lost lift hangs a note with nothing to reach it. Closing that needs `R` **and** a Timer, and
QUADRANT has **no Timer at all** (`docs/HARDWARE-AUDITION.md:156` and `:161`: Setup only, cost
recorded 835 at defaults). Adding one is a new event, a `gtt` call and the sweep against a margin that
must be re-measured before it is quoted. **Write it into `deferred-items.md` through 12-12 with that
arithmetic**, and re-fit it only if the executor measures it and finds it fits cleanly - in which case
say so and do it. Do not guess the margin from the audition row; 11-16 found nine of twenty stale.

Purpose: three bench lines closed by the mechanism the probe found, a fourth entry that carried the
same defect closed with them, at a saving.
Output: four entries re-fitted, one test, one finding, no picture moved.
