repo; copy out of it, never edit it, never run git in it).** Its load-bearing properties, in order:
1. **Fail closed:** `if (!expectedPass) return unauthorized();` — with no secret configured, nothing is

**Why `vite preview` is NOT the static build (verified in `@sveltejs/kit@2.70.3`
`src/exports/vite/preview/index.js`):**
```js
const dir = join(svelte_config.kit.outDir, 'output/server');
if (!fs.existsSync(dir)) throw new Error(`Server files not found at ${dir}, did you run \`build\` first?`);
```
It boots the SvelteKit **Node server** from `.svelte-kit/output/server`. It never reads `build/`. sv's
generated `webServer: { command: 'npm run build && npm run preview', port: 4173 }` therefore tests an
artifact that is not the deployed one, and criterion 4's "preview it with no server running" is not met.

**Three Playwright facts, verified against current docs:**
- `webServer.url` readiness accepts **2xx, 3xx, 400, 401, 402 and 403**. The Basic Auth 401 is an
  acceptable "server is up" signal, so the gate needs no bypass.
- `port` is deprecated in favour of `url`; sv generates `port: 4173`, so this is a rewrite.
- `--ip 127.0.0.1` rather than the default `localhost` avoids the Node-17+ IPv6 resolution trap that
  `profile-cloud/vite.config.ts` already documents in a comment on this same machine.

**Pitfall 3 — `delete navigator.serial` does nothing.** `serial` is an accessor on `Navigator.prototype`,
not an own property of the `navigator` instance; `delete navigator.serial` returns `true` and removes
nothing. Delete it from the prototype AND assert the removal worked before asserting anything about the
UI. A degrade test that does not verify its own precondition is worse than no test.
