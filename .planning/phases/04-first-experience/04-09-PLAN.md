<interfaces>
**The routes** (D-12, UI-SPEC §Routes and deep links):

| Route | Prerendered | Splash | Behaviour |
|---|---|---|---|
| `/` | yes | yes | the row centred on the first row entry |
| `/c/{id}/` | yes, one real HTML file per row entry | **no** | lands with `{id}` centred and un-chosen |

With real routes the splash needs no suppression trick: `/c/[id]/` simply renders `FrontDoor` with
`splash={false}`. (04-RESEARCH §Architecture Pattern 5 proposed an inline `app.html` script to stop a
splash flash; that was for the hash design D-12 replaced, and it is not needed here. Do not add it.)

```ts
// src/routes/c/[id]/+page.ts
import { FRONT_DOOR, frontDoorIndex } from "$lib/catalog/front-door";
export const prerender = true;
export function entries() {
  return FRONT_DOOR.map((e) => ({ id: e.id }));
}
export function load({ params }: { params: { id: string } }) {
  return { id: params.id, index: frontDoorIndex(params.id) };
}
```

`front-door.ts` is the light module (plan 04-02) precisely so this can be imported into a route that
also ships to the client without dragging the compiler along.

**Shallow navigation and the lint rule.** `svelte/no-navigation-without-resolve` is `error` in the
recommended config this repository extends, and it accepts either an empty string or a `resolve()`
call from `$app/paths` as the first argument to `replaceState`/`pushState`. So

```ts
import { resolve } from "$app/paths";
import { replaceState } from "$app/navigation";
replaceState(resolve("/c/[id]", { id }), {});
```

needs **no** disable comment, and none may be added. Use `replaceState` for stepping and never
`pushState`: nine steps must not need nine Back presses (W-16). Choosing already uses
`pushState("", { chosen: true })` from plan 04-08 and stays exactly as it is.

If the resolved pathname turns out to need a trailing slash to match `trailingSlash: "always"`, prefer
letting Cloudflare's asset handler resolve `/c/aurora` to `/c/aurora/` over building a concatenated
string the lint rule cannot type-check. Record what was done and why in the SUMMARY.

`replaceState` throws if it is called before the router is initialised, so the first call happens after
`onMount` and never during prerender.

**An unknown id.** The static host serves `build/404.html` for an unmatched path
(`not_found_handling: "404-page"` in `wrangler.jsonc`, `fallback: "404.html"` from the adapter); the
client router then matches `/c/[id]` and `load` returns `index === -1`. Render the shelf centred on the
first entry with `Never heard of that one. Here is the shelf instead.` in place of the fidelity line
for 4 seconds, then cross back to the normal line. The 4 seconds is the one piece of timing in the UI
spec with no precedent in the brief, and the spec itself calls that out — keep it in one named
constant so it is easy to change.

**Head metadata.** `/c/{id}/` gets `<title>{name} — HANGAR</title>` and
`<meta name="description" content={description}>` from the row entry; `/` gets `<title>HANGAR</title>`
and a one-line description. One real HTML file per configuration with its own head is what makes Phase
5's link previews possible at all, and it is why D-12 chose routes over a fragment.

**Test ids in play:** `coverflow`, `nameplate-name`, `fidelity-line`, `splash`, `pad-canvas-{id}`.
