```ts
export const MAX_SLOT = 3;
/** X in multiples of the hero pad's CSS side length; index is |offset|. */
export const SLOT_X = [0, 0.78, 1.28, 1.66] as const;
export const SLOT_Z = [0, -160, -320, -480] as const;
export const SLOT_ROTATE = [0, 20, 26, 30] as const;
export const SLOT_SCALE = [1, 0.8, 0.62, 0.48] as const;
export const SLOT_OPACITY = [1, 0.8, 0.5, 0.24] as const;
export const SLOT_BRIGHTNESS = [1, 0.85, 0.7, 0.55] as const;

export type Slot = {
  offset: number;
  translateX: number;   // px
  translateZ: number;   // px
  rotateY: number;      // deg
  scale: number;
  opacity: number;
  brightness: number;
  zIndex: number;
  hero: boolean;
  mounted: boolean;
};

export function step(centre: number, delta: number, count: number): number;
export function slotOffset(index: number, centre: number, count: number): number;
export function radiusForWidth(px: number): 1 | 2 | 3;
export function visibleWindow(centre: number, radius: number, count: number): number[];
export function slotFor(offset: number, heroPx: number): Slot;
```

Implementation notes that are contract, not preference:

- `step` and `slotOffset` both use the double-modulo idiom so a negative delta wraps:
  `(((x % count) + count) % count)`. `slotOffset` then returns `raw > count / 2 ? raw - count : raw`,
  so on an even ring the antipode resolves to the **positive** value — deterministic, and the spec
  says so out loud.
- `slotFor` clamps `|offset|` at `MAX_SLOT` when indexing the ladder arrays but reports
  `mounted: Math.abs(offset) <= MAX_SLOT`, so an out-of-range slot still returns a well-formed object
  rather than `undefined`.
- `rotateY = -Math.sign(offset) * SLOT_ROTATE[k]` — the sign is inverted deliberately (UI spec: "Left
  slots rotate **positive** on Y, right slots **negative**, so both turn their inner edge toward the
  viewer"). Put that sentence in the comment.
- `translateX = Math.sign(offset) * heroPx * SLOT_X[k]`.
- `zIndex = 100 - Math.abs(offset)` per the UI spec. Add a comment recording the caveat from
