# Phase 4 — UI Design Contract

> Visual and interaction contract for the HANGAR front door: splash → coverflow → chosen → connect.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Binding upstream: `.planning/design/FIRST-EXPERIENCE.md` (the user's frame) and
> `.planning/phases/04-first-experience/04-CONTEXT.md` (D-01..D-19). Where this document adds detail
> it never contradicts those; where it decides something they left open it is listed at the bottom.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no shadcn, no component library, no icon font) |
| Preset | not applicable |
| Component library | none — hand-written Svelte 5 components in `src/lib/ui/` |
| Icon library | none — two hand-drawn inline SVG shapes only (name-plate triangles, 9×9 logo motif) |
| Styling | Tailwind CSS v4 utilities + an `@theme` token block in `src/app.css` (already exists, currently two placeholder tokens) |
| Font | `@fontsource/quicksand@5.3.0` (OFL-1.1), self-hosted, latin subset, weights 400 and 600 only + system monospace stack for numerals |
| Registry | not applicable (no registry is used) |

**Fonts, precisely.** `npm i @fontsource/quicksand@5.3.0`, imported once in `src/app.css` as
`@import "@fontsource/quicksand/latin-400.css";` and `@import "@fontsource/quicksand/latin-600.css";`.
No Google Fonts CDN request — self-hosted keeps the site working offline, avoids a `font-src` CSP
question, and costs nothing. Two woff2 files, roughly 36 KB total.

> **Build gate this touches.** `scripts/gen-licenses.mjs` `ALLOWED` does **not** currently contain
> `OFL-1.1`, so adding this production dependency fails `npm run build` until the allowlist is
> extended deliberately. The extension is correct and in the spirit of the gate's own comment: a font
> is aggregated data, not linked code, and the existing pipeline will then materialise the OFL text
> into `licenses/` and `THIRD-PARTY.md` automatically. See decision W-02.

**Font stacks:**

```css
--font-sans: "Quicksand", ui-rounded, "SF Pro Rounded", "Segoe UI Variable Display",
             system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
--font-mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas,
             "Liberation Mono", monospace;
```

`--font-mono` is used **only** for numerals that must not jitter as they change: the firmware
version, the page number, and (from Phase 5) the `chars / 908` meters. Nothing else.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Focus-ring offset, triangle-to-name gap inside the name plate |
| sm | 8px | Gap between a button and its inline reason line |
| md | 16px | Name plate horizontal padding, panel internal gaps, fidelity line to panel |
| lg | 24px | Panel padding, gap before the `KEEP ON DEVICE` separator, page gutter at phone widths |
| xl | 32px | Headline → coverflow, hero bottom edge → name plate, page gutter at desktop |
| 2xl | 48px | Top of viewport → headline (desktop) |
| 3xl | 64px | Coverflow band → footer (the existing `mt-16` in `+layout.svelte`, unchanged) |

**Exceptions (declared, not accidental):**

1. **44px** minimum interactive box for every control (`TRY ON DEVICE`, `KEEP ON DEVICE`, both
   name-plate arrows, the name-plate name button). The arrows' painted triangle is 10×12px; the 44px
   is the hit area.
2. **Coverflow geometry is viewport-relative, not token-relative.** Pad sizes, slot offsets and Z
   depths are expressed as multiples of `--pad-hero` and in px of perspective depth (see
   [Coverflow geometry](#coverflow-geometry)). A depth ladder cannot be built from an 8-point scale.
3. **Corner radii, and the optical insets derived from them, use their own 3-step scale** — 2px
   (meter and knob wells, Phase 5), 6px (name plate, buttons), 10px (pad frame, panel). The insets
   that follow from a radius are part of this exception and are deliberately off the 4-point scale:
   the pad canvas is inset **6px** inside its 10px-radius frame, which is the smallest inset that
   stops the 10px corner arc clipping a corner LED. Radii and radius-derived insets are not spacing.

## Typography

Five rows, but **exactly four sizes and exactly two weights**. Nothing outside this table ships,
with one exception stated below the table.

| Role | Size | Weight | Line Height | Tracking | Case | Used for |
|------|------|--------|-------------|----------|------|----------|
| Micro | 12px | 600 | 1.2 | 0.18em | UPPERCASE | Button labels, header wordmark, `DISCONNECT ZONA`, the `TUNING` region caption, the `ZONA IDENTIFIED` state caption |
| Micro (title) | 12px | 600 | 1.2 | 0.01em | Sentence | Failure and state titles that are written as sentences: `That module is not a ZONA`, `Nothing answered on that port`, and every `failureCopy().title` |
| Body | 16px | 400 | 1.5 | 0 | Mixed | The headline, the fidelity line, every sentence of state and reason copy |
| Heading | 20px | 600 | 1.2 | 0.01em | Mixed | The configuration name inside the name plate — the only heading on the front door |
| Display | 28px | 600 | 1.2 | 0.50em | UPPERCASE | The splash wordmark, and only that |

**Rules:**

- **Uppercase is reserved for the wordmark, button labels, and short structural captions of at most
  two words** (`TUNING`, `ZONA IDENTIFIED`, `DISCONNECT ZONA`). Anything that reads as a sentence —
  including every failure title — uses the sentence-case Micro variant. This is the line between a
  label and a statement, and it is what keeps the uppercase from turning into shouting.
- The wordmark's 0.50em tracking adds a trailing space; compensate with `margin-inline-end: -0.50em`
  so the mark stays optically centred.
- Micro at weight 400 in sentence case is permitted for **one** thing: the pre-existing footer links
  in `+layout.svelte`, which ship unchanged from Phase 1. It is an exception, not a sixth row.
- **Canvas-drawn texture is exempt from this table.** The splash glyph field is painted into a
  `<canvas>` at 10px in the browser's default sans; it is generated pixels, not interface type, no
  user reads it as words, and forcing it onto the type scale would flatten the mosaic it exists to
  make. No other exemption is granted — every string a user is meant to read uses a row above.
- "Quiet" is achieved with **colour**, never with a smaller size. The fidelity line is 16px at 55%
  lime, not 12px at 100%. This is what keeps the small print readable (5.6:1) while still receding.
- No italics anywhere. No third weight. No `font-stretch`.

## Color

The palette is two tokens and a ladder of alphas over black. There is no grey.

| Role | Token | Value | Contrast on `#000` | Usage |
|------|-------|-------|--------------------|-------|
| Dominant (~60%) | `--color-ground` | `#000000` | — | The entire page ground, the pad face behind unlit cells, the LED gutter grid, the wordmark's punch-out plate |
| Secondary (~30%) | `--color-ink` | `rgb(214 255 78 / 0.72)` | 9.3:1 | Default text: state sentences, reasons, steps, the name in the name plate |
| Secondary quiet | `--color-ink-quiet` | `rgb(214 255 78 / 0.55)` | 5.6:1 | The headline, the fidelity line, `DISCONNECT ZONA`, region captions |
| Secondary dim | `--color-ink-dim` | `rgb(214 255 78 / 0.50)` | 4.7:1 | Labels of **disabled** controls (still AA — a disabled control's reason must be readable) |
| Structure | `--color-line` | `rgb(214 255 78 / 0.40)` | 3.3:1 | Functional borders: name plate, both buttons, panel edge, hero pad frame |
| Structure soft | `--color-line-soft` | `rgb(214 255 78 / 0.20)` | 1.58:1 | Decorative only: unlit-cell dot field, side-pad frames, hairline separators, the dashed border of the reserved tuning region |
| Accent (~10%) | `--color-accent` | `#d6ff4e` | 18.3:1 | See the reserved list below |
| Glow | `--color-glow` | `rgb(214 255 78 / 0.18)` | — | One static `box-shadow` bloom on the hero pad frame and on `TRY ON DEVICE` hover |
| Destructive | none | — | — | **No third colour earns itself in Phase 4.** See below. |

`--color-ground` and `--color-accent` already exist in `src/app.css` as placeholders; this phase
replaces the comment above them and adds the six remaining tokens.

**Generated texture is outside the ladder, by design.** Three alphas in this document are not tokens
and must not be quantised onto the ladder: the splash glyph field randomises per-glyph lime alpha
between **0.14 and 0.28**, the halftone grain sits at **0.06**, and the favicon's dots at **0.35**.
All three are pixels inside a generated image — a canvas mosaic and a 32px SVG mark — rather than
interface surfaces, and snapping them to five fixed steps would destroy the noise that makes the
field read as texture at all. They are still `#d6ff4e` over `#000000`: the two-colour rule holds, the
token ladder does not apply.

**Accent (`#d6ff4e` at full strength) is reserved for, and only for:**

1. The splash wordmark and the lime rectangles punched through the glyph field.
2. The solid triangles in the name plate (`◀` and `▶`).
3. The `TRY ON DEVICE` button fill when it is enabled (label on it is `#000000`).
4. The focus ring (`outline: 2px solid #d6ff4e; outline-offset: 4px`).
5. The header wordmark that the splash mark flies into.
6. The one walking cell in the 9×9 loading motif.

It is never used for body text, never for a border, never for the disabled button, and never for the
side pads' frames.

**The pads are exempt.** `PadSim` emits real firmware RGB — blue, orange, white, whatever the config
produces. Those pixels are *content*, like a photograph, and are outside the palette by definition.
The chrome **around** the content stays two-colour. A checker looking at a screenshot will see
non-lime pixels inside pad faces; that is correct and required by PREV-02.

**No CSS may author a colour that the simulator did not.** There is no white bloom, no coloured
halo, no gradient tint over a pad face. The only light HANGAR adds around a pad is
`--color-glow`, which is lime. This is what keeps "the palette is two colours" a literal statement
rather than an aspiration.

**Why no destructive colour.** Phase 4 never writes to a module. `TRY ON DEVICE` connects and
identifies only; `KEEP ON DEVICE` — the genuinely destructive one — is disabled throughout. Failure
states (port busy, not a ZONA, nothing answered) are *informational*, not dangerous, so they render
in `--color-ink` with the copy doing the work. The first colour that will genuinely earn itself is a
warning on the flash-write confirmation in **Phase 7**; deciding it now would be inventing a token
with nothing to attach it to.

## Screen 1 — Splash

Full-viewport, above everything, `position: fixed; inset: 0; z-index: 50`.

**Composition, bottom to top:**

1. `#000000` ground.
2. **Glyph field**, one `<canvas>` sized to the viewport, drawn **once** on mount and never again —
   it does not animate. Content: 6–10 rectangular blocks of dense glyph mosaic (`x o + □ ◦`, 10px,
   14px cell pitch, per-glyph lime alpha randomised between 0.14 and 0.28 — generated texture,
   outside the token ladder as declared above), with black gaps between blocks, from a **seeded**
   PRNG (mulberry32, seed `0x48414E47`) so the field is identical on every load and can be
   pixel-asserted in a test.
3. **Punched rectangles**: exactly 4 solid `#d6ff4e` rects from the same generator, each between
   40×12 and 220×28 px, aligned to block boundaries.
4. **Halftone grain**, a CSS overlay:
   `background-image: radial-gradient(circle, rgb(214 255 78 / 0.06) 0 0.5px, transparent 0.6px); background-size: 3px 3px;`
5. **Wordmark** `HANGAR`, Display role, `#d6ff4e`, centred, sitting on a `#000000` plate with 32px
   padding so it stays legible over the noise.

The coverflow (Screen 2) is **mounted and already ticking** underneath from `t = 0`. When the splash
clears, the machines have been running for two seconds. This is the requirement in the brief
("You arrive and the machines are already running") and it is not a nicety — it is the reason the
splash exists at all.

**Timing (full motion):**

| Step | Duration | Easing | What moves |
|------|----------|--------|------------|
| Field in | 240ms | `cubic-bezier(0.4, 0, 0.2, 1)` | Splash layer opacity 0 → 1 |
| Hold | 900ms | — | Nothing |
| Dissolve | 700ms | `cubic-bezier(0.22, 0.61, 0.36, 1)` | Glyph field + grain opacity 1 → 0 with `scale(1.04)`; coverflow opacity 0 → 1 with slots `scale(0.96) → 1`; the **wordmark does not fade** — it translates and scales to the header slot (top-left, 32px gutter, Micro size) over the same 700ms |
| **Total** | **1840ms** | | Front door is interactive at 1840ms |

**Skip rules:**

- Any `pointerdown`, `keydown` or `wheel` during the field-in or hold cuts immediately to the
  dissolve. The user is never *required* to click (D-06 holds); impatience is simply respected.
- A deep link (`/c/{id}`) never renders the splash at all (D-12). `/` always does.
- No session suppression: reloading `/` plays it again. It is 1.84s.

**`prefers-reduced-motion: reduce`:** field in 0ms (present immediately), hold 400ms, crossfade
200ms, no scale on anything, the wordmark **crossfades** into the header slot rather than flying.
Total 600ms.

## Screen 2 — Coverflow (the front door)

Vertical stack, centred, section `min-block-size: 100svh`, page gutter 32px desktop / 24px phone.
The Phase 1 footer follows below the fold, unchanged.

```
  HANGAR                                          ← header wordmark, Micro, top-left, 32px gutter
                                                   (48px)
              You’ve got to start somewhere…      ← Body, ink-quiet, centred
                                                   (32px)
     ▢    ▢      ▣  ▣ ▣ ▣ ▣  ▣      ▢    ▢        ← the coverflow band
                                                   (32px from hero's bottom edge)
                ◀   Aurora   ▶                    ← name plate, lime-outlined
                                                   (16px)
     Every pad runs the firmware's own code…       ← fidelity line, Body, ink-quiet
```

### Coverflow geometry

- `--pad-hero: clamp(260px, 52vmin, 560px)` — the hero pad's CSS side length.
- Band wrapper: `width: min(100vw, 1280px)`, `overflow: clip`, `perspective: 1400px`,
  `perspective-origin: 50% 42%`, and an edge mask so the outer pads dissolve into the ground rather
  than being guillotined:
  `mask-image: linear-gradient(to right, transparent 0%, #000 14%, #000 86%, transparent 100%)`.
- Each slot is absolutely positioned with `left: calc(50% - var(--pad-hero) / 2)` (no percentage
  translate), then transformed as `translate3d(X, 0, Z) rotateY(R) scale(S)` — in that order.
- `z-index: calc(100 - abs(slot))`. Left slots rotate **positive** on Y, right slots **negative**, so
  both turn their inner edge toward the viewer.

| Slot | X (× `--pad-hero`) | Z | rotateY | scale | opacity | `filter: brightness()` | Apparent size | Paint |
|------|--------------------|------|---------|-------|---------|------------------------|---------------|-------|
| 0 (hero) | 0 | 0 | 0° | 1.00 | 1.00 | 1.00 | 1.00 | ≥30 fps |
| ±1 | ±0.78 | −160px | ∓20° | 0.80 | 0.80 | 0.85 | ≈0.72 | ≥20 fps |
| ±2 | ±1.28 | −320px | ∓26° | 0.62 | 0.50 | 0.70 | ≈0.50 | ≥20 fps |
| ±3 | ±1.66 | −480px | ∓30° | 0.48 | 0.24 | 0.55 | ≈0.36 | ≥20 fps |
| ±4 and beyond | — | — | — | — | — | — | **unmounted** (no DOM, no canvas, no engine) | — |

Perspective foreshortening compounds with `scale`, which is why the apparent sizes fall away faster
than the scale column and why the neighbours **overlap** the hero by roughly a fifth of its width —
the receding, overlapping row the brief asks for.

**Visible window by viewport width** (this is what keeps the canvas count bounded):

| Width | Slots per side | Total mounted canvases |
|-------|----------------|------------------------|
| ≥1024px | 3 | 7 |
| 640–1023px | 2 | 5 |
| <640px | 1 | 3 |

Entries outside the window are not in the DOM. With nine seeds and a window of seven the row wraps
(D-10); an entry leaving one edge is remounted at the other with a fresh engine at tick 0.

### The pad — the identity motif, drawn exactly this way

Four layers, bottom to top. **Two of the four never repaint.**

| Layer | What | How | Repaints |
|-------|------|-----|----------|
| 1 | Unlit-cell dot field | CSS `radial-gradient(circle at 50% 50%, var(--color-line-soft) 0 6%, transparent 6.5%)` at `background-size: 11.111% 11.111%` | never |
| 2 | The LEDs | `<canvas width="9" height="9">` with `image-rendering: pixelated`, CSS-sized to the face. One `putImageData` of a **reused** `ImageData(9,9)` per paint. Cells where `r === 0 && g === 0 && b === 0` get **alpha 0** so layer 1 shows through; every other cell gets alpha 255. | per paint |
| 3 | Gutter grid | Two CSS `repeating-linear-gradient`s in `#000000`, hard stops at `0 0.9%` / `0.9% 11.111%`, one per axis, `background-position: -0.45% -0.45%`. This is what turns a gapless nearest-neighbour upscale back into 81 discrete lights. | never |
| 4 | Frame | `border: 1px solid` — `--color-line` on the hero, `--color-line-soft` on side pads. `border-radius: 10px`, canvas inset 6px so no LED is clipped by the corner. Hero only: `box-shadow: 0 0 40px var(--color-glow)`. | never |

**Hard prohibitions** (the first three are documented performance failures in
`.planning/research/STACK.md`; the fourth is the palette):

- No `strokeRect` per cell per frame. Ever.
- No `ctx.shadowBlur`. Ever.
- No `drawImage`, no second canvas, no DPR-scaled backing store — the 9×9 store plus
  `image-rendering: pixelated` gives the compositor the upscale for free. **One draw call per pad per
  paint.**
- **No CSS filter that adds or tints colour on a pad canvas** — no `drop-shadow`, `blur`,
  `hue-rotate`, `sepia` or `invert`. A per-LED bloom would have to invent a colour the simulator
  did not emit, which breaks the two-colour rule for chrome and the "content is content" exemption
  at the same time. The hero's only added light is the lime `--color-glow` `box-shadow` on its
  frame.
  **The depth ladder's `filter: brightness()` (0.85 / 0.70 / 0.55, and the chosen-state recede
  × 0.8) is permitted and required.** It goes on the **slot wrapper**, never on the canvas itself,
  and it only scales channels the simulator already emitted toward black — it cannot introduce a
  hue that was not there. The slot wrapper is a leaf of the 3D tree, so the `transform-style: flat`
  that a filter forces has no 3D children to flatten and the perspective ladder is unaffected.
  The band wrapper that contains the row carries **no** filter of any kind, and clips with
  `overflow: clip` rather than `overflow: hidden`, so it never becomes a scroll container.
- No WebGL, no per-card contexts, no DOM cells.

> **Design finding for the planner.** The vendored `pad-sim-host.ts` `blit()` paints a `#0b0b0b`
> ground with white 7% `strokeRect` outlines at 12px cells. That is BOTOR's look, not HANGAR's, and
> it is also the exact draw pattern STACK §Decision 2 says to remove. HANGAR therefore owns its own
> painter. What the vendored file remains authoritative for — and what HANGAR must reproduce
> unchanged — is the **scheduling and touch semantics**, listed in the motion contract below. The
> vendored file is never edited.

### Name plate

One lime-outlined box directly beneath the hero, 32px below its bottom edge. `border: 1px solid
var(--color-line)`, `border-radius: 6px`, height 44px, `background: transparent`.

```
┌──────────────────────────────┐
│  ◀ │     Aurora     │ ▶      │
└──────────────────────────────┘
```

- Two arrow `<button>`s, 44×44 hit area, containing an inline `<svg width="10" height="12">` polygon
  filled `currentColor` = `--color-accent`, `aria-hidden="true"`.
  `◀` = `polygon(10,0 10,12 0,6)`; `▶` = `polygon(0,0 0,12 10,6)`.
- The name is itself a `<button>`: Heading role, `--color-ink`, `padding: 0 16px`, `min-width: 220px`,

- Hover on any of the three: the box border goes to `--color-accent`, 160ms.
- The whole plate is 260ms cross-faded when the centred entry changes (old name out 130ms, new name

### Fidelity line (PREV-03, D-17)

16px below the name plate, Body role, `--color-ink-quiet`, `max-inline-size: 62ch`, centred.
**Always present**, chosen or not. Exact copy in the copywriting contract.

### Empty and broken states

- **Catalog empty** (only reachable if `entries.ts` is emptied): the coverflow band renders one
  unlit 9×9 frame at hero size and the copy in the contract below. There is no name plate.
- **One entry fails to construct a `PadSim`**: its slot renders the frame and dot field with no
  canvas, and the name plate shows `{name} — unavailable`. One broken entry never blanks the row.

6. **`KEEP ON DEVICE`** — secondary and visibly so (SAFE-02): auto width, not full width, Micro label

## Screen 4 — Connect states (`TRY ON DEVICE`)

This phase connects and identifies. **It never writes.** The write path does not exist in this
screen's code.

**Handler discipline (from CLAUDE.md, non-negotiable):** the click handler calls
`navigator.serial.requestPort()` **first and synchronously**. Nothing is awaited before it — an
`await` there burns the transient user activation and the call rejects.

### State machine

| State | Entered when | Button | Region content |
|-------|--------------|--------|----------------|
| `unsupported` | `!("serial" in navigator)` | present, **disabled** | `failureCopy("no-web-serial", undefined, "TRY ON DEVICE")` — title Micro (title), detail Body, steps as an ordered list |
| `insecure` | `"serial" in navigator && !isSecureContext` | present, **disabled** | `failureCopy("insecure-context", undefined, "TRY ON DEVICE")` |
| `idle` | default on a capable browser | enabled, label `TRY ON DEVICE` | empty |
| `choosing` | after `requestPort()` is called | disabled, label `CONNECTING…`, 9×9 loading motif to its left | status line |
| `opening` | a port was picked | disabled, label `CONNECTING…` | status line |
| `identifying` | port open, listening for heartbeats | disabled, label `CONNECTING…` | status line |
| `identified` | `identify()` returned an `Identity` whose `zona.moduleType === "ZONA"` | back to `TRY ON DEVICE`, **disabled** with the "already identified" reason; a `DISCONNECT ZONA` text button appears | the identified block |
| `not-zona` | identified, but the module is not a ZONA | enabled again | the not-a-ZONA block |
| `silent` | identify window elapsed with no heartbeat | enabled again | the nothing-answered block |
| `failed` | `classifyOpenError()` returned `cancelled` \| `port-busy` \| `unplugged` \| `unknown` | enabled again | the matching `failureCopy(f, raw, "TRY ON DEVICE")` block |
| `unplugged-after` | `navigator.serial` `disconnect` fires while `identified` | enabled again | the unplugged-after block |

### Failure copy comes from Phase 2, with the control label interpolated

`failureCopy()` in `src/lib/transport/transport.ts` is good copy and is already covered by Phase 2's
tests. It is **not** re-authored here. But it names a **`Connect`** button at six sites, and Phase 4's
control is called `TRY ON DEVICE`; copy that tells a visitor to click a button that does not exist on
the screen is worse than no copy.

**Contract — a Phase 4 change to `src/lib/transport/transport.ts` (first-party HANGAR code, not
vendored, so editing it is allowed):**

```ts
export function failureCopy(
  f: OpenFailure,
  raw?: string,
  controlLabel = "Connect",
): FailureCopy
```

- **`controlLabel` is appended third, after `raw` — never in `raw`'s place.** Three live callers
  already pass `raw` positionally: `transport.spec.ts:72` (`failureCopy("unknown", "boom")`),
  `transport.spec.ts:83` (`failureCopy(failure, "raw text")`) and
  `src/routes/dev/skeleton/+page.svelte:122-125` (the caught error's message). Inserting the label
  second would silently retarget all three onto the new parameter and only fail at the moment a
  visitor reads the copy. An options object is not the answer either — it would rewrite the same
  three call sites this parameter exists to leave alone.
- `controlLabel` is interpolated at the **six** sites that currently hard-code `Connect`:
  `insecure-context` detail (~line 105) and its step (~108), `cancelled` step (~116), the last
  `port-busy` step (~131), the last `unplugged` step (~144), and the `unknown` step (~152).
- **The trailing position and the `"Connect"` default together keep Phase 2's `/dev/skeleton`
  page and every existing `transport.spec.ts` assertion passing unchanged.** No existing call
  site is touched.
- Phase 4 calls `failureCopy(f, undefined, "TRY ON DEVICE")`, or
  `failureCopy(f, raw, "TRY ON DEVICE")` in the one state that carries a raw error (`unknown`).
- Nothing else in the returned copy changes: titles, details and step ordering are Phase 2's,
  verbatim.

Rendering: `title` in **Micro (title)** / `--color-ink`, `detail` in Body / `--color-ink`, `steps` as
an `<ol>` in Body / `--color-ink-quiet` with `list-style: decimal` inside 24px.

Only the four states Phase 2 has no copy for are authored in the copy table below.

### Loading state = the identity motif (IDENT-01)

The 9×9 outline is the logo, the pad frame **and the loading state**. `PadSpinner`: a 32px 9×9 dot
field (layer 1 of the pad recipe, at 32px), with one cell lit `--color-accent` walking the perimeter
at 90ms per step. Reduced motion: static, three cells lit in the top-left corner, no walk.

### Favicon

`src/lib/assets/favicon.svg` is still the Svelte default logo. IDENT-01 requires the 9×9 outline as

## Motion Contract

### Simulation semantics — reproduce these exactly

These come from the vendored `pad-sim-host.ts` and are the difference between a firmware-faithful
preview and an animation. They are contract, not implementation preference.

| Property | Value | Why it is load-bearing |
|----------|-------|------------------------|
| Tick | 10ms, whole ticks from an accumulator | The firmware runs at 100 Hz |
| Catch-up clamp | 100ms max per frame | A backgrounded tab must not replay minutes of ticks on return |
| Paint cadence | hero ≤33ms (≥30 fps), sides ≤50ms (≥20 fps) | Ticking is cheap, painting is not |
| rAF loops | **exactly one** for the whole page | N loops is N× scheduler overhead and N desyncs |
| Idle behaviour | the loop cancels itself when no engine is running | A settled row must cost zero CPU |
| Visibility gating | `IntersectionObserver`, `{ threshold: 0, rootMargin: "200px" }` | The 200px margin wakes a pad *before* it enters view, so it never shows a frozen frame |
| Reduced motion | every engine `reset()` then `run(64)`, then frozen | Tick 64 puts a sine look near its peak, so the still frame shows colour and pattern |
| Touch delivery | at most **one** sample per contact per tick; MOVEs coalesce to newest, DOWN and UP always keep their place; max 5 contacts | This is the firmware's pop budget. Delivering pointer events directly makes the preview a lie |
| `setInterval` | **zero**, anywhere | |

Reduced motion animates the hero **only while a pointer is down on it** — the user causing the
motion is the carve-out; uninvited ambient motion is not.

### Interface motion

| Event | Duration | Easing | Detail |
|-------|----------|--------|--------|
| Splash field in | 240ms | `cubic-bezier(0.4, 0, 0.2, 1)` | opacity |
| Splash hold | 900ms | — | |
| Splash dissolve | 700ms | `cubic-bezier(0.22, 0.61, 0.36, 1)` | field out + scale 1.04, coverflow in + slots 0.96→1, wordmark flies to header |
| Coverflow step | 420ms | `cubic-bezier(0.22, 0.61, 0.36, 1)` | CSS transition on `transform, opacity, filter` so a rapid second step re-targets from the current computed value instead of restarting |
| Name plate swap | 260ms | `linear` | 130ms out, 130ms in |
| Side-pad hover | 160ms | `ease-out` | opacity +0.12, `translateZ(+20px)` |
| Name-plate hover | 160ms | `ease-out` | border → `--color-accent` |
| Choose / un-choose | 260ms / 200ms | `cubic-bezier(0.22, 0.61, 0.36, 1)` | panel slide + row recede |
| Button hover | 140ms | `ease-out` | brightness + glow |
| Focus ring | 0ms | — | Focus is never animated |
| Loading motif | 90ms/step | `steps(1)` | |

### `prefers-reduced-motion: reduce` — the complete override

| Thing | Full motion | Reduced |
|-------|-------------|---------|
| Pads | live simulation | still frame at tick 64; the hero still responds while a pointer is down |
| Splash | 1840ms with fly and scale | 600ms: present, hold 400, crossfade 200 |
| Coverflow step | 420ms slide | **instant**, 0ms |
| Name plate swap | 260ms crossfade | instant |
| Panel | slide + fade | opacity only, 120ms, no transform |
| Hover lifts | translateZ | colour change only |
| Loading motif | walking cell | three static cells |

Implemented as a media query on the CSS side **and** read by the host on the JS side
(`matchMedia("(prefers-reduced-motion: reduce)")` with a live `change` listener, so an OS toggle
mid-session takes effect without a remount — the vendored host already does this and it must
survive the port).

## Interaction Contract

### Stepping (D-10)

| Input | Behaviour |
|-------|-----------|
| Name-plate `◀` / `▶` | one step, wraps at both ends |
| `←` / `→` | one step, wraps |
| `Home` / `End` | jump to first / last entry |
| Horizontal wheel or trackpad swipe | accumulate `|deltaX|`; fire one step at ≥40, then a 260ms cooldown. Vertical `deltaY` is **ignored** so the page can still be scrolled to the footer |
| Click a side pad | steps to it — a click on slot ±2 steps two |
| Touch drag | horizontal swipe ≥ 48px steps one; a vertical drag scrolls the page |

The URL is updated with `replaceState` on every step — nine history entries for nine steps would trap
the Back button.

### Choosing (D-11)

The hero is playable **before** it is chosen, and a click both plays and chooses. The disambiguation
is explicit:

> A `pointerdown` on the hero always delivers a touch to the simulator. If the matching `pointerup`
> arrives within **250ms** and the pointer moved less than **6px**, it is also a choose. Anything
> longer or further is play only.

`Enter`, `Space`, or a click on the name-plate name also choose, with no touch delivered.
Choosing does a `pushState`, so **browser Back un-chooses** — the same action as `Esc`.

Cursor on the hero is `crosshair` (it is an instrument); on side pads, `pointer`.

### Routes and deep links (CAT-01, D-12)

| Route | Prerendered | Splash | Behaviour |
|-------|-------------|--------|-----------|
| `/` | yes | yes | Coverflow centred on the first featured entry |
| `/c/{id}` | yes, one real HTML file per catalog entry | **no** | Lands with `{id}` centred and un-chosen |

One prerendered file per entry is what gives each configuration its own `<title>` and
`<meta name="description">`, which is the link-preview story. An unknown `{id}` renders `/`'s
coverflow with the "never heard of it" copy in place of the fidelity line for 4 seconds, then fades
to the normal line.

## Accessibility Contract

| Concern | Contract |
|---------|----------|
| Coverflow semantics | The band is `role="listbox"` with `aria-label="ZONA configurations"`, `tabindex="0"`, and `aria-activedescendant` pointing at the centred slot's id. Each slot is `role="option"` with `aria-selected` true only on the centre |
| Name-plate arrows | The two arrow buttons carry `aria-label="Previous configuration"` and `aria-label="Next configuration"`. Their SVG triangles are `aria-hidden="true"`, so the label is the only accessible name and neither button is ever announced as "button" alone |
| Name-plate name | The name button's accessible name is `Choose {name}` via `aria-label`; its visible text stays the bare name |
| Canvas labelling | Every pad canvas is `role="img"` with `aria-label="{name}, live pad simulation"`. The slot's accessible name comes from the canvas label plus a visually-hidden `{description}` |
| Keyboard-only operation | Every action is reachable: step (`←` `→` `Home` `End` on the listbox, or Tab to the arrow buttons), choose (`Enter` / `Space` on the listbox, or Tab to the name button), un-choose (`Esc` anywhere, or Back), connect (Tab to `TRY ON DEVICE`). **The site is fully operable with no pointer.** Playing the instrument is the one pointer-only capability, and it is not required to reach any state |
| Focus visibility | `:focus-visible { outline: 2px solid #d6ff4e; outline-offset: 4px; border-radius: inherit; }`. Outlines are never removed. Lime on black is 18.3:1 |
| Tab order | header wordmark (not focusable) → coverflow listbox → `◀` → name → `▶` → `TRY ON DEVICE` → `KEEP ON DEVICE` → footer links |
| Text contrast | Every text token is ≥4.7:1 on black. The lowest is `--color-ink-dim` at 4.7:1, used only on disabled labels, which WCAG exempts anyway — held above AA on purpose so DEGR-02's reason is genuinely readable |
| Non-text contrast | Functional borders use `--color-line` at 3.3:1. `--color-line-soft` (1.58:1) is restricted to decoration whose meaning is carried elsewhere: the unlit dot field (the pad is identified by its lit content and its name plate), side-pad frames, and the dashed reserved-region border |
| State announcement | The connect state region is `aria-live="polite"`. The name plate is **not** live — stepping is user-initiated and `aria-activedescendant` already announces it |
| Motion | `prefers-reduced-motion` is honoured completely, per the table above |
| Touch targets | 44×44 minimum on every control |
| Language | `<html lang="en">` already set |

## Decisions taken without the user

Authored overnight under the delegation recorded in `04-CONTEXT.md`. Every one of these is a first
cut Botond can overturn in the morning; none contradicts D-01..D-19 or the design brief.

| # | Decision | Rationale (one line) |
|---|----------|----------------------|
| W-01 | **Quicksand** (OFL-1.1) is the one typeface, self-hosted via `@fontsource/quicksand@5.3.0`, weights 400 + 600 | It is the free face that actually is a *rounded geometric sans*, which is what the reference frame specifies; self-hosting costs nothing and avoids a CDN and a `font-src` question |
| W-02 | `OFL-1.1` is added to `ALLOWED` in `scripts/gen-licenses.mjs` | A font is aggregated data, not linked code; the allowlist's own comment invites deliberate extension, and this makes the OFL text ship automatically in `licenses/` and `THIRD-PARTY.md` |
| W-03 | System monospace for numerals only (firmware, page, future meters) | Tabular digits stop the readouts jittering as they change, and it costs zero bytes |
| W-04 | Four type sizes: 12 / 16 / 20 / 28, with the 12px Micro row in two case variants | "Quiet" is done with alpha, not with 11px text; the case split keeps `TUNING` legible as a caption without shouting a whole failure sentence |
| W-05 | **No third colour** in Phase 4, and no CSS-authored light on a pad face | Nothing here is dangerous — the phase never writes; and any bloom would invent a colour the simulator did not emit. The first colour that will earn itself is a Phase 7 flash-write warning |
| W-06 | The alpha ladder is 0.72 / 0.55 / 0.50 / 0.40 / 0.20, chosen by measured contrast; generated texture (glyph field, grain, favicon) sits outside it deliberately | 9.3 / 5.6 / 4.7 / 3.3 / decorative — every text token clears AA and every functional border clears 3:1, while the mosaic keeps the randomness that makes it read as texture |
| W-07 | Canvas backing store is **9×9** with `image-rendering: pixelated`; gutters and dots are static CSS layers; unlit cells are alpha 0. **This supersedes 04-CONTEXT D-15's wording** ("`ImageData` upscaled … `putImageData` into a persistent 9×9 offscreen canvas, then one `drawImage`") | The compositor does the upscale, so there is no offscreen canvas and no `drawImage`: one draw call per pad per paint instead of 163, and the dot field shows through unlit cells for free. The planner implements this path only, not both |
| W-08 | HANGAR owns its painter; the vendored `blit()` is not used | Its `#0b0b0b` + white `strokeRect` look is BOTOR's, and it is the exact pattern STACK says to delete |
| W-09 | Splash: 240 / 900 / 700ms = 1840ms total; the wordmark **flies** to the header rather than fading | Under two seconds keeps a shared link fast, and the flight makes the mark persist rather than vanish |
| W-10 | The coverflow mounts and starts ticking **behind** the splash at t=0 | The brief's "you arrive and the machines are already running" is only true if they have been running |
| W-11 | Any click, key or wheel during the splash cuts to the dissolve | Respects impatience without making a click *required*, so D-06 still holds |
| W-12 | Coverflow slot ladder: X 0.78 / 1.28 / 1.66, Z −160 / −320 / −480, rotateY 20 / 26 / 30°, scale 0.80 / 0.62 / 0.48 | Produces overlap near the centre and a fast fall-off at the edges — the classic coverflow read, tuned so neighbours overlap the hero by about a fifth |
| W-13 | A gradient **edge mask**, not a hard clip, ends the row | "Falling off the edge of the viewport" holds at every width including ultra-wide, in one CSS property |
| W-14 | Slots beyond ±3 (±2 tablet, ±1 phone) are **unmounted**, not hidden | Bounds canvas count at 7 and keeps compositor memory flat regardless of catalog size |
| W-15 | Tap-versus-play on the hero: ≤250ms and <6px chooses; anything else is play only | D-11 makes the hero both playable and choosable; without a rule the two collide on the first click |
| W-16 | Routes are `/c/{id}`, prerendered one file per entry; stepping uses `replaceState`, choosing uses `pushState` | Real files give each config its own `<head>` for link previews; `replaceState` keeps nine steps from trapping the Back button, while `pushState` on choose makes Back and `Esc` the same gesture |
| W-17 | The coverflow is a `listbox` with `aria-activedescendant`; arrows and name are additionally real buttons with explicit `aria-label`s | A standard, screen-reader-comprehensible pattern that makes the row fully keyboard-operable and never announces a bare "button" |
| W-18 | Failure copy is rendered from Phase 2's `failureCopy()` verbatim **except the control label**: the function gains a third, trailing parameter `controlLabel = "Connect"` — appended after `raw`, never in its place, because three callers already pass `raw` positionally — interpolated at its six `Connect` sites, with Phase 4 calling `failureCopy(f, raw, "TRY ON DEVICE")` | Two copies of the port-busy instructions would drift, but copy that tells a visitor to click a "Connect" button that is not on the screen is worse than none. The trailing position plus the default keeps Phase 2's page and tests green, and `transport.ts` is HANGAR code, not vendored, so it may be edited |
| W-19 | The reserved tuning region shows a caption and one sentence, **not** inert `— / 908` meters | A dead meter reads as broken; the region still reserves 152px so Phase 5 docks without a reflow |
| W-20 | Once identified, `TRY ON DEVICE` becomes disabled and a small `DISCONNECT ZONA` appears; stepping does not reset the connect state | The port belongs to the session, not the configuration; and a site that opens a port should offer to close it, naming what it closes |
| W-21 | `forget()` / "revoke this site's access" is **not** in Phase 4 | It belongs with the full connection lifecycle in Phase 6, and adding a permission-revoking control to the front door before install exists is noise |
| W-22 | The favicon is replaced with the 9×9 motif | It is still Svelte's default logo, and IDENT-01 names the 9×9 outline as the mark |
| W-23 | Loading state is the 9×9 motif with one walking lime cell | IDENT-01 requires the motif to serve as the loading state; this is the only place in the phase that waits |
