```ts
export interface HostEngine {
  tick(): void;
  run(n: number): void;
  reset(): void;

  readonly animating: boolean;       // true while any layer still counts down
  readonly coordMax: 127 | 1023;
  readonly pendingTouches: number;
```

**What the vendored host does that HANGAR keeps verbatim in behaviour** (`pad-sim-host.ts:415-470`),
each one a bug someone already paid for:

- The self-cancelling loop: `if (any) rAF(...) else lastNow = undefined`, with every waking event
  calling `wake()`.
- Paint on the render cadence **and** on the frame where `animating` goes false, "so the freeze frame
  shown is the true final state and not a 33 ms stale one".
- The reduced-motion carve-out: the preview animates only while a pointer is actually down.
- One `destroy()` that cancels the frame, disconnects the observer, drops the media listener and
  releases held contacts.

**What HANGAR changes** (D-15, 04-RESEARCH §Architecture Pattern 2): per-slot paint intervals instead
of one global; `{ threshold: 0, rootMargin: "200px" }` instead of a bare `{ threshold: 0 }`;
`running = intersecting && inWindow` instead of `running = intersecting`; one engine per entry for the
whole session instead of a separate preview engine, so stepping never restarts a pad at tick 0; and
`paintPad` instead of `blit`.

```ts
export interface HostDeps {
  now(): number;
  raf(cb: (now: number) => void): number;
  caf(handle: number): void;
  /** Observe visibility. Returns an unobserve function. */
  observe(el: unknown, cb: (intersecting: boolean) => void): () => void;
  /** Live reduced-motion source. Returns the current value and an unsubscribe. */
  reducedMotion(cb: (reduced: boolean) => void): { matches: boolean; stop: () => void };
  lowPower: boolean;
}

export class SimHost {
  constructor(deps?: Partial<HostDeps>);
  register(id: string, canvas: HTMLCanvasElement, engine: HostEngine): void;
  unregister(id: string): void;
  /** The centred entry, or undefined. Only the hero receives pointer samples. */
  setHero(id: string | undefined): void;
  /** |slotOffset| <= radius. The half an IntersectionObserver cannot see. */
  setInWindow(id: string, inWindow: boolean): void;
  touchDown(pointerId: number, x: number, y: number): boolean;
  touchMove(pointerId: number, x: number, y: number): void;
  touchEnd(pointerId: number): void;
  destroy(): void;
}
```

Every dependency has a real default (`performance.now`, `requestAnimationFrame`,
`cancelAnimationFrame`, an `IntersectionObserver` with `{ threshold: 0, rootMargin: "200px" }`, a
`matchMedia("(prefers-reduced-motion: reduce)")` subscription, and
`isLowPower(navigator.hardwareConcurrency)`), each guarded so the module can be imported in a node
test without any of them existing. Injecting them is not a testing nicety: it is the only way this
loop is testable at all, because there is no browser Vitest project (04-RESEARCH §Pitfall 6).

Per-entry state, in a plain `Map` — never a rune:
`{ canvas, ctx, scratch, engine, hero, inWindow, intersecting, wasRunning, lastPaint, unobserve }`.

`register` sets `canvas.width = 9` and `canvas.height = 9` (the host owns the backing-store size so a
component cannot forget it — 04-UI-SPEC W-07), takes a 2D context, creates the scratch `ImageData`,
paints the first frame immediately so a still pad shows its picture before the loop ever runs, starts
observing, and calls `wake()`.

The frame callback, in order: compute `dt` from the previous `now` (0 on the first frame after a
wake), `ticksFor` it, then for each entry decide

```
const touchActive = entry.hero && (sampler.size > 0 || engine.pendingTouches > 0);
const running = entry.inWindow && entry.intersecting && (touchActive || (!reduced && engine.animating));
```

and if running: deliver at most one pending touch sample per tick for the hero, tick, then paint when
`shouldPaint(now, entry.lastPaint, intervalFor(entry.hero, lowPower))` **or** when `animating` has
just gone false. If not running but it was running last frame, paint once and clear the flag. Set
`any` when anything ran; at the end, `if (any) raf(...) else lastNow = undefined`.

  <action>
Extend `src/lib/sim/host.ts` with the parts that were deliberately left out of task 1.

**Reduced motion.** Subscribe once in the constructor through `deps.reducedMotion` and keep the
returned `stop`. On any change: if it became `true`, for every entry `engine.reset(); engine.run(64);`
and paint; if it became `false`, `wake()`. Do **not** re-register anything. Carry the vendored
reason: an operating-system toggle mid-session must take effect without a remount (IDENT-02), and tick
64 puts a sine look near its peak so the still frame shows colour and pattern rather than a dark one.

**The finger.** The host owns one `TouchSampler`. `touchDown/touchMove/touchEnd` route into it and
call `wake()`; `setHero` calls `sampler.clear()` when the hero changes, so contacts never leak onto a
pad the visitor has stepped away from. The loop drains the sampler for the hero entry, once per tick,
before `tick()`.

The coordinate mapping stays in the component: it owns the canvas rect, and `mapAxis` is already
exported from `./touch`. The host's `touchDown` takes LED coordinates, not client coordinates. Say why
in a comment: the host is testable in node precisely because no DOM geometry crosses into it.

**Teardown.** `destroy()` sets a destroyed flag first (so a frame callback already queued does
nothing), cancels the frame handle, calls every entry's `unobserve`, calls the media subscription's
`stop`, clears the sampler, and sets `canvas.width = 0` on every canvas before dropping the map. The
last one is not tidiness: nine mounted pads at a large backing store are megabytes of compositor
memory, and PITFALLS C14 names releasing them explicitly. `unregister(id)` does the same for one entry.
