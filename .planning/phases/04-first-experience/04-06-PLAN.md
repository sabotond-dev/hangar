<standing_rules>
- **No `.svelte.spec.ts` files.** `vite.config.ts`'s `server` project excludes that pattern and no
  other project picks it up, so such a file is collected by nothing and never runs — the
  green-and-vacuous trap `docs/TESTING.md` names. Component behaviour is proven in Playwright against
  the real build; everything decidable lives in the pure modules plans 04-02, 04-03 and 04-05 already
  tested.
- **Nothing that holds a `PadSim`, a canvas or a frame buffer goes into a rune.** `$state` deep-proxies
  objects and arrays, and a proxy trap inside a 100 Hz loop is a silent performance cliff
  (04-RESEARCH §Pitfall 3). Only scalars cross into Svelte: `centre` (number), `radius` (number),
  `ready` (boolean). If a non-scalar must be reactive, use `$state.raw`.
- **CSS grouping properties flatten a 3D scene.** `overflow` at any value other than `visible` or
  `clip`, `opacity` below 1, any `filter`, `mask-image`, `mix-blend-mode` and `contain: paint` all
  force `transform-style: flat` on descendants. The clip and the mask go on an **outer** wrapper that
  carries no `preserve-3d`; `filter: brightness()` goes on the **slot wrapper**, which is a leaf of
  the 3D tree. Never on the stage. (04-RESEARCH §Pitfall 5, 04-CONTEXT D-16.)
- **No CSS may author a colour the simulator did not emit** on a pad: no `drop-shadow`, `blur`,
  `hue-rotate`, `sepia` or `invert` anywhere near a pad canvas. `filter: brightness()` is permitted
  and required because it only scales emitted channels toward black.
- **Never edit anything under `src/vendor/`.**
- `npm run format` is scoped to the files the task created.
- No Claude or Anthropic attribution anywhere. No emojis. Real apostrophes (U+2019) and a real
  ellipsis (U+2026) in every visitor-facing string.
- Every new file carries the house header comment ending
  `Copyright (C) 2026 Botond Sandor. Licensed under the GNU GPL v3 or later.`
- **Before any Playwright run:** `netstat -ano | grep -w LISTENING | grep ":4173"`. If occupied, walk
  the process tree to the `npx-cli.js` root and `taskkill /PID <root> /T /F` from PowerShell — killing
  `workerd.exe` alone leaves a zombie that accepts connections it never answers. Capture output into
  `.tmp-e2e/`, never under `test-results/`. **No Playwright test title may contain the word `failed`.**
- **Counting convention (shared tree).** Phase 8 plan 08-01 lands `scripts/check-counts.mjs`, which
  reads a Vitest or Playwright summary on stdin and compares it against an expected file/test count,
  **reporting the todo count without asserting it**. Whole-suite gates in this phase use it with
  **baseline plus delta**: take the observed totals recorded in the previous plan's SUMMARY (for this
  phase's first plan, capture them once before touching anything and write them down), add this task's
  own delta, and pipe `npm run test:quick 2>&1 | node scripts/check-counts.mjs $EXPECTED_FILES $EXPECTED_TESTS`.
  Never hard-code an absolute total in a criterion and never assert a todo count — the tree is shared
  with Phase 8. If `scripts/check-counts.mjs` is absent, fall back to the pair
  `npm run test:quick 2>&1 | grep -E "Tests +[0-9]+ passed"` matching **and**
  `npm run test:quick 2>&1 | grep -qE "Tests +[0-9]+ failed"` exiting non-zero, and say so in the SUMMARY.
  Every SUMMARY records the observed `test:quick` file and test totals so the next plan has a baseline.
- **Every structural scan strips comments first, with one uniform expression.** Six of these checks
  look for a token the same task deliberately *names* in a comment (the painter's header lists the
  forbidden calls; the host cites the vendored file; the spinner explains that it is the loading
  state). A scan over raw source would then fail on correct code. Use this form everywhere, and note
  that it is deliberately **backslash-free** — inside `node -e "…"` both bash and PowerShell eat a
  backslash, which silently turns a pattern into one that matches nothing:

  ```js
  const strip = (t) => t
    .replace(/^[ ]*[/][/].*$/gm, "")      // line comments
    .replace(/[/][*][^]*?[*][/]/g, "")    // block comments
    .replace(/<!--[^]*?-->/g, "");        // markup comments
  ```

  If inline quoting gets fragile, write the check into a scratch `.mjs` under the system temp
  directory and run it with `node` — never into the repository.

**The engines**, constructed once per row entry, inside `onMount`, from a dynamic import. Plan 04-02's
spec guarantees every id in `FRONT_DOOR` today is a `preview: "padsim"` catalog entry, but the catalog
grows underneath this phase, so the construction is written defensively rather than on that guarantee:

```ts
const [{ PadSim }, { presetById }] = await Promise.all([
  import("../../vendor/botor/pad-sim"),
  import("../../vendor/botor/_pad"),
]);
const engine = new PadSim(presetById(id)!.state);
```

`new PadSim(state)` costs 0.044 ms measured, so all eight are built eagerly — there is no reason to
lazy-construct (04-RESEARCH §Measured Facts). The import must be dynamic: `_pad.ts` imports
`@intechstudio/grid-protocol` at module scope, and that chunk is 131,101 bytes, which a splash should
not wait on and a static import would put on `/`'s critical path (§Pitfall 9). Phase 8 plan 08-03 will
add `createEngine(entry)` over the same shape; when it lands, this call site becomes a one-line change
and nothing else moves.

**The pad, exactly** (04-UI-SPEC §The pad). Four layers, and **two of the four never repaint**:

| Layer | What | How |
|---|---|---|
| 1 | unlit-cell dot field | CSS `radial-gradient(circle at 50% 50%, var(--color-line-soft) 0 6%, transparent 6.5%)` at `background-size: 11.111% 11.111%` |
| 2 | the LEDs | `<canvas width="9" height="9">`, `image-rendering: pixelated`, CSS-sized to the face; one `putImageData` per paint; unlit cells at alpha 0 so layer 1 shows through |
| 3 | gutter grid | two CSS `repeating-linear-gradient`s in `#000000`, hard stops at `0 0.9%` / `0.9% 11.111%`, one per axis, `background-position: -0.45% -0.45%` |
| 4 | frame | `border: 1px solid` — `--color-line` on the hero, `--color-line-soft` on side pads; `border-radius: 10px`; canvas inset **6px** so the corner arc cannot clip a corner LED; hero only: `box-shadow: 0 0 40px var(--color-glow)` |

**The band** (04-UI-SPEC §Coverflow geometry):

```css
--pad-hero: clamp(260px, 52vmin, 560px);
/* outer wrapper: no preserve-3d here */
.band { width: min(100vw, 1280px); overflow: clip;
        mask-image: linear-gradient(to right, transparent 0%, #000 14%, #000 86%, transparent 100%); }
/* inner stage: the 3D context */
.stage { position: relative; height: var(--pad-hero);
         perspective: 1400px; perspective-origin: 50% 42%; transform-style: preserve-3d; }
/* each slot */
.slot { position: absolute; top: 0; left: calc(50% - var(--pad-hero) / 2);
        width: var(--pad-hero); height: var(--pad-hero);
        transform: translate3d(Xpx, 0, Zpx) rotateY(Rdeg) scale(S);
        transition: transform 420ms cubic-bezier(0.22, 0.61, 0.36, 1),
                    opacity 420ms cubic-bezier(0.22, 0.61, 0.36, 1),
                    filter 420ms cubic-bezier(0.22, 0.61, 0.36, 1); }
```

The transition is on the CSS property rather than driven from JavaScript so a rapid second step
re-targets from the current computed value instead of restarting.

**Stepping inputs** (04-UI-SPEC §Stepping, D-10): `←`/`→` one step, wrapping; `Home`/`End` to first
and last; horizontal wheel accumulating `|deltaX|` with a 40 px threshold and a 260 ms cooldown, with
vertical `deltaY` **ignored** so the page still scrolls to the footer; a click on a side pad steps to
it (a click on slot ±2 steps two); a horizontal touch drag of 48 px or more steps one, while a
vertical drag scrolls. `onwheel` in Svelte 5 attaches directly to the element (`wheel` is not in
Svelte's delegated-event list) and element-level wheel listeners are non-passive by default, so
`event.preventDefault()` works with no plumbing.

**Accessibility** (04-UI-SPEC §Accessibility Contract): the band is `role="listbox"` with
`aria-label="ZONA configurations"`, `tabindex="0"` and `aria-activedescendant` pointing at the centred
slot's id; each slot is `role="option"` with `aria-selected` true only on the centre; each canvas is
`role="img"` with `aria-label="{name}, live pad simulation"` and the slot's accessible name is
completed by a visually-hidden `{description}`. Cursor: `crosshair` on the hero (it is an instrument),
`pointer` on side pads.

**`src/lib/ui/Coverflow.svelte`** — props `{ initialId?: string }`. One component owns the row.

**State.** `let centre = $state(...)` (a number), `let radius = $state(3)`, `let ready = $state(false)`.
Nothing else is reactive. The `SimHost` and the engines live in plain `let` bindings — a `Map<string,
HostEngine>` and the host instance — never in a rune. Canvas elements are collected into a plain
`Map<string, HTMLCanvasElement>` by `PadCanvas`'s `onready` callback.

**Markup.** All eight entries are rendered in a keyed `{#each FRONT_DOOR as entry (entry.id)}` in
**stable catalog order, never reordered**. Stepping changes `centre` only; every slot's transform is
derived from `slotFor(slotOffset(index, centre, FRONT_DOOR.length), heroPx)`. A keyed each that
reordered would move DOM nodes and fight the layout engine instead of the compositor.

Slots with `mounted === false` render nothing at all — no element, no canvas, no engine registration
(04-UI-SPEC W-14: bounding the canvas count at 7 is what keeps compositor memory flat as the catalog
grows). Keep the engine itself alive in the map: an entry leaving the window and returning must not
restart at tick 0.

The band, the stage and the slot use exactly the CSS in `<interfaces>`. `translateX` is in pixels and
comes from `slotFor`, which takes the hero's measured pixel side length — read it once per resize from
the stage element's own computed height (the CSS `clamp()` owns the value; JavaScript reads it and
never sets it).

**Mount.** In `onMount`:

1. construct the `SimHost`;
2. `await` the two dynamic imports and build one engine per row entry. Build an engine **only** for an
   entry the vendored shelf knows: `presetById(id)` returning `undefined` means the catalog has grown
   past what a `PadSim` can run (Phase 8 appends Lua-sourced entries, and their engine arrives with
   plan 08-03), so skip that entry, `console.warn` once naming the id, and render its slot as the frame
   and dot field with **no canvas** — the broken-entry state 04-UI-SPEC §Empty and broken states
   already specifies. One entry without an engine must never blank the row. Keep the skipped ids in a
   plain `Set<string>` and expose it, so the name plate can render the contract's
   `{name} — unavailable` for such an entry when plan 04-07 builds it;
3. register every mounted canvas with the host, `setHero(FRONT_DOOR[centre].id)`, and
   `setInWindow(id, true)` for the window;
4. set `ready = true`.

Nothing before step 4 blocks the markup: the row's frames, dots and gutters are in the prerendered
HTML and visible immediately; the canvases fill in when the simulator arrives. That is what gives the
splash (plan 04-07) a real job rather than a decorative one.

**Stepping.** One `stepBy(delta)` function calling `step(centre, delta, count)`, then updating the
host: `setHero(newId)`, and `setInWindow` true/false across the changed window. Inputs, all of them:

- `onkeydown` on the band: `ArrowLeft`/`ArrowRight` (one step, `preventDefault`), `Home`/`End`;
- `onwheel` on the band: accumulate `Math.abs(e.deltaX)`, fire one step at 40 and start a 260 ms
  cooldown, `preventDefault()` only when a horizontal step is taken; ignore `deltaY` entirely;
- `onclick` on a side slot: step by that slot's offset;
- `onpointerdown`/`onpointerup` on the band for the touch drag: a horizontal movement of 48 px or more
  steps one; a vertical drag is left alone so the page scrolls.

**Resize.** A `resize` listener, debounced 200 ms, recomputing `radius = radiusForWidth(innerWidth)`
and the hero pixel size, and skipping all work when neither changed — reallocating backing stores per
resize event is its own jank source (§Pitfall 10). Remove the listener in `onDestroy`.

**The hero's finger (PREV-04).** `onpointerdown`, `onpointermove`, `onpointerup`, `onpointercancel`
and `onlostpointercapture` on the hero slot only. On down: `setPointerCapture` inside a `try`/`catch`
(the canvas can detach between the event and the capture), then map the client coordinates through the
canvas's `getBoundingClientRect()` and `mapAxis(offset, extent, engine.coordMax)` and call
`host.touchDown(...)`. Move and end likewise. The host does the tick-locked delivery; this component
does the geometry and nothing more.

D-11's "hover already shows mouse-as-finger before choosing" falls out for free, because the listeners
follow whichever entry is centred. **The tap-versus-choose rule (250 ms, 6 px) belongs to plan 04-08**,
which owns choosing; do not add a half of it here.

**Teardown.** `onDestroy`: `host.destroy()`, remove the resize listener, drop the engine map.
