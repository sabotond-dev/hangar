## What the user asked for, and what shipped

> *"Edit color should not be pop up window in the left upper corne but instead open down seamlessly
> to edit color."* (BENCH-2026-09-12.txt line 7, first half; 13.1-CONTEXT D-08)

**Where the block mounts.** Inside each swatch `.row` (a flex column, `gap: 8px`, held), after the
`.value` line that carries the 34 x 34 square, the hex and the toggle:

```svelte
{#if openFor === knob.id}
  <div class="editor" id="{uid}-{knob.id}-editor" role="group"
       aria-labelledby="{uid}-{knob.id}-label" data-testid="colour-editor" data-knob={knob.id}
       onkeydown={(event) => onEditorKeydown(event, knob.id)}>
    {#key knob.id}<ColourPicker … selectedId={knob.id} />{/key}
  </div>
{/if}
```

One block per panel (`openFor` is one id); a click on another row's toggle moves it there. `.editor`
is `padding-block: 12px`, `background: var(--color-panel)`, `border-block-start: 1px solid
var(--color-boundary)` - no `position`, no shadow, no `z-index`, and **no `border-radius` declared in
the file at all** (the `.popover { border-radius: 0 }` went with the dialog; layer A's declaration
count 33 -> 32, the exempt zeros). The rows below move down.

**The toggle's two labels.** `{openFor === knob.id ? POPOVER_CLOSE : EDIT_COLOR}` - `Edit color`
(PDF page 5) closed, `Close` (F.8, 13-18 "keep") open - with `aria-expanded={openFor === knob.id}`
and `aria-controls="{uid}-{knob.id}-editor"`; `aria-describedby` to the row's label kept. The open
state takes the file's one accent declaration: `.edit[aria-expanded="true"] { color:
var(--color-action) }` (`Swatch.svelte:296`).

**Escape.** `onEditorKeydown` on the group: `Escape` -> `preventDefault`, `stopPropagation` (so
`KeepConfirm`'s window listener, if a confirmation is open, does not also fire), read the row's
toggle from `toggles[id]` (`bind:this` by knob id), `openFor = undefined`, `await tick()`,
`toggle?.focus()`. The file's only `.focus()`. No `showModal`, no `inert`, no `aria-modal`, no
`focusTrap`, no `onDestroy`, no `trigger`.

**The a11y warning.** A `role="group"` with a keydown is
`a11y_no_noninteractive_element_interactions`; it is delegated (the rails, the selector and the
buttons inside take focus and receive the key), so it is ignored with BrowseGrid's one-line
`svelte-ignore` and BrowseGrid's separate explanation. `KeepConfirm` handles the same key at the
window instead; either shape is in the tree, this one is scoped by construction. Check 656 / 0 / 0.

**The Sandbox.** `RegionInspector.svelte` is untouched and still mounts `<Swatch>` with the region's
colour as its one knob; its Appearance row opens the same inline block, and `radius.e2e.ts` measures
the picker's three circles there too (`/sandbox/?new`, chromium and webkit-phone).

### 1. [Rule 3 - Blocking] The block's hairline is `--color-boundary`, not `--color-divider`

- **Found during:** the first whole quick run.
- **Issue:** the plan's action writes "a 1px `--color-divider` rule above". `identity.spec.ts` test 5
  ("the boundary rule: no rule in app.css or any component puts --color-divider on a property that

  block is a `role="group"`: red on `Swatch.svelte:305 .editor { border-block-start: 1px solid
  var(--color-divider) }`.
- **Fix:** `--color-boundary` - the swatch square's own hairline, and the popover's border before it.
  The rule's comment says why. The standing rule wins over the plan's word.
- **Files:** `src/lib/ui/Swatch.svelte`; commit `a2b11af` (a third commit, between the plan's two,
  so the build the chunks ran against stamps a HEAD that contains it - `artifacts.e2e.ts` reads HEAD).
