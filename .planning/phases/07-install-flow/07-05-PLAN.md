<objective>
The strings channel from the tuner, and the pin that says the bytes are the numbers.

Wave 5. `buildTuner` computes both strings at the same instant it computes both meter numbers, and
today it publishes only the numbers, the ladder, the over-budget view and the stamp. Nothing carries
the compiled Setup and Timer out. One emit inside `land()` closes the gap and makes D-10's pin
structural rather than an assertion about two separate compiles (07-CONTEXT D-17).

The emit has a second job. The 120 ms compile debounce marks the feed `stale` in `moveTo` and
recompiles on a trailing timer; a visitor who drags a knob and clicks `TRY ON DEVICE` inside that
window would otherwise write the previous strings under the current meters (Pitfall 5).
`onconfig(undefined)` fires at exactly the same instant the feed goes stale, the install store treats
`undefined` as "not ready to write", and the primary control is disabled for those 120 ms with the
same *measuring* language the meters already use. That is a structural property, not a race.

The pin is exact and was measured (07-RESEARCH): with `reserved = {setup: 0, timer: 0}`,
`cost(result).setup.used === result.setupLua.length` for all nine shelf presets, both events, zero
mismatches - because `budgetOf` is `Math.max(measure(lua), lua.length) + reserved` and the
uncompressed figure is the larger by exactly one character per action. **Therefore the strings go on
the wire verbatim, never compressed at install time**; `wire-pin.spec.ts` holds that across every
catalog entry.

Purpose: SAFE-07's "installed means these exact bytes", SAFE-02's primary control writing what it
showed.
Output: one emit, one prop threaded through two components, six tests.
</objective>

```ts
/** The exact bytes a write would put on the wire, beside the numbers that measured them (D-17). */
export type ConfigStrings = { readonly setup: string; readonly timer: string };

export type TunerOptions = {
  // ... existing ...
  /**
   * The compiled pair, emitted with every settled measurement, and UNDEFINED
   * the instant the feed goes stale - which is what makes "the debounce cannot
   * land a new compile between the click and the write" a structural property
   * rather than a race (07-RESEARCH Pitfall 5). Optional, so every existing
   * caller and every existing test is unchanged.
   */
  onconfig?(config: ConfigStrings | undefined): void;
};

// land() gains the pair as its third argument, so a landing cannot publish
// numbers without the strings they were measured from:
function land(setup: number, timer: number, config: ConfigStrings): void {
  numbers = { setup, timer };
  feed = "settled";
  emit();
  options.onconfig?.(config);
}

// measurePadsim: the compile is already in hand.
const result = await compileState(state);
const measured = await costOf(result, options.reserved);
if (stale(mine)) return;
land(measured.setup.used, measured.timer.used, { setup: result.setupLua, timer: result.timerLua });

// measureLuaRoute: renderLua already produced exactly the wire text.
land(setup, timer, { setup: lua.setup, timer: lua.timer });

// moveTo, and overView's apply(): wherever `feed = "stale"` is assigned, the
// next statement is options.onconfig?.(undefined).
```
