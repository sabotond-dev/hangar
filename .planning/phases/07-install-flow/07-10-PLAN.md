<objective>
The panel writes.

Wave 10. Two shipped literals in `TryOnDevice.svelte` promise that HANGAR never writes (the header
note's third, `SAFE_PROMISE`, is 07-04's) - `HONESTY`
(*"Writing arrives in the next release - this never writes."*) and `identifiedBody`'s *"nothing will be
until install ships in the next release"*. Both are Phase 4's and both are load-bearing for a layout
invariant; both become false the moment this wave lands, and both are retired here by name
(07-CONTEXT D-18, the second of two; Pitfall 10; Z-06, Z-07). The honesty slot's string set goes from
three to **five** - a pre-connect form, a ready form, a snapshotting form, a capability form and
Phase 5's budget reason - and the 72px reservation and the twin mechanism are untouched, because the
longest new string is under the 129 cap plan 07-03 asserts.

`KEEP ON DEVICE` moves from the Secondary tier to the **Quiet** tier (Z-02): in Phases 4 to 6 it was
a bordered control that could not be clicked; now it can, and it writes flash, so it becomes the
quietest control on the panel and spends its weight inside the confirmation. Its line cell reserves
**48px** across its enabled line and all six reasons. The install row becomes a single column at a
16px rhythm - `PUT BACK`, `KEEP ON DEVICE`, `COPY LINK` - because two 16px sentences side by side in
a 372px column are about twenty characters a line (Z-03).

The primary control's click is the one Phase 6 built plus one branch: when the session is not
`connected`, `session.connect()` is the first statement; when it is, `install.tryOnDevice(config,
entry.name)`. From `snapshot-failed` the same click retries the snapshot and writes only if that
lands.

Purpose: SAFE-01's sentence made true in the present tense, SAFE-02's hierarchy as three tiers,
SAFE-08's settled state with an instant label and nothing animating, DEGR-02's reasons on all three
controls.
Output: four components amended, one structural test.
