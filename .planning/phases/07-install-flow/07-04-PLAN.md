<objective>
The session's seams, and nothing else about the session.

Wave 4. `GridTransport` carries exactly **one** `onData` callback (`transport.ts:12`,
`web-serial.ts`, `fake.ts`); whoever registers last owns the byte stream. After identification Phase
6's session owns it, and that fold is what keeps the header's page number and the rig tail true. An
install store that registered its own `onData` to feed its `RequestQueue` would silently unhook the
fold: the page number on screen would freeze at its connect-time value and a page change would then
make every write NACK with no explanation on screen (Pitfall 1). So the session grows a class sink -
`onClass()` - and the install store subscribes through it. **A second raw registration is refused**,
not merely discouraged: the transport the session hands out is a view whose `onData` throws naming
`onClass`, and a spec asserts the throw (07-CONTEXT D-16).

Four more members ride with it, each a few lines, none reaching a forbidden needle: a connection
event seam so the store can snapshot at connect and abort at teardown without a Svelte effect;
`announce()` so the twelve install utterances go through the one session live region (Y-16, Z-17);
and `writeLock` with `unpluggedWhileWriting`, which is how the header locks its two controls under a
write (Z-15) and how the session knows to keep quiet when the install store has the truer sentence -
Phase 6's `The ZONA was unplugged. Nothing was written.` is false when a write was in flight (Z-11).

`session-copy.ts` gains the header's four strings for this phase - the write-lock reason, the
snapshot line in its durable and session-only forms, the unplugged-while-writing form - and the
amended `FORGET THIS ZONA` explanation (Z-13). `session-copy.spec.ts` test 5 asserts the old
explanation character for character and is **rewritten, not deleted**.

**`session.svelte.ts` keeps exactly four static `from` specifiers.** Everything added here is
scalars, `$state.raw` snapshots, a `Set` of callbacks and bound methods.

Purpose: SAFE-01's "zero writes without a click" as a property the session keeps enforceable, and
SAFE-09's lost-mid-write state with the one true utterance.
Output: six members on the session, five strings, five tests grown or rewritten.

```ts
type DecodedClass = import("$lib/protocol").DecodedClass;   // erased; not a specifier

/**
 * The open transport, as a WRITE VIEW, or undefined. Phase 7's install store
 * borrows it to build its RequestQueue. Its onData THROWS: GridTransport
 * carries exactly one data callback and this session owns it after
 * identification - a second registration would silently unhook the fold that
 * keeps the page number and the rig tail true (07-RESEARCH Pitfall 1). The
 * install store subscribes through onClass() instead. This is the one place
 * this file names `write`, and it still never calls it.
 */
get transport(): GridTransport | undefined {
  const t = this.#transport;
  if (!t) return undefined;
  return {
    get isOpen() { return t.isOpen; },
    write: t.write.bind(t),
    onData() {
      throw new Error("The session owns the byte stream; subscribe with session.onClass() instead");
    },
    onClose: t.onClose.bind(t),
    close: t.close.bind(t),
  };
}

/** Every decoded class from the session's ONE frame pump. Returns the unsubscribe. */
onClass(cb: (cls: DecodedClass) => void): () => void;

/**
 * "connected" once identification has resolved and the fold is registered;
 * "closed" on every teardown - unplug, disconnect(), forget(), a read error,
 * the missed-disconnect watchdog. Returns the unsubscribe. Fired synchronously
 * at the transition, after `phase` has been assigned.
 */
onConnection(cb: (ev: "connected" | "closed") => void): () => void;

/** Speak through the one session live region. A public wrapper over #say and nothing more. */
announce(line: string): void;

/**
 * True while an install leg is in flight. Set and cleared by the install
 * store, read by DeviceDetails (the header lock, Z-15) and by every path into
 * `unplugged-while-connected` (Z-11): when true, the session says nothing on
 * the unplug - the install store owns the truer sentence - and records
 * unpluggedWhileWriting so the disclosure renders the writing form.
 */
writeLock = $state(false);
unpluggedWhileWriting = $state(false);
```

The fold pump (06-04) already decodes every frame; after `absorbFrame` it now also does
`for (const sink of this.#classSinks) sink(cls)` for every class in the frame, inside a try that
swallows a sink's throw so one bad subscriber cannot stop the fold. `#classSinks` is a `Set` on the
instance, cleared on teardown.

`unpluggedWhileWriting` is set from `writeLock` at the moment of every transition into
`unplugged-while-connected` (the `disconnect` handler, `#onTransportClosed`, the watchdog) and
cleared by `#clearFailure()`. `failureFor` renders
`unpluggedWhileConnectedBlock(this.unpluggedWhileWriting)`. The `#say(LIVE_UNPLUGGED)` at those
transitions becomes `if (!this.writeLock) this.#say(LIVE_UNPLUGGED)`.
