<objective>
The install store, finished: flash, the failure taxonomy, and the bounds.

Wave 7, same file as wave 6. Everything a visitor can be told about a write that did not go to plan,
and the one write that survives a power cycle.

**The store is proved, not believed.** After `KEEP ON DEVICE` the module reloads the page from flash
and restarts its Lua VM (`grid_decode.c:955-961`), and `CONFIG/FETCH` has no bulk guard - so a
re-fetch straight after the ACK can race the module's own reload (Pitfall 6). The settled state
therefore waits for the first heartbeat after the `PAGESTORE` acknowledgement and then re-fetches for
at most **three** rounds with `retryBackoffMs` between them, succeeding on the first byte-identical
pair (07-CONTEXT D-19). On exhaustion the state is `kept-mismatch`, honest rather than green: the
ACK already means stored; the re-fetch is a proof, not the definition.

**The taxonomy is decided by error type, never by message text.** The queue already exposes
`NackError` and `AbortedError` and already refuses to retry either; the store must not wrap it in a
retry of its own (Pitfall 7). A dropped second acknowledgement is `partial` and names Setup; a
refusal or an exhausted timeout on the first leg is `nothing-landed`; a dead link is `lost`; a store
that never acknowledges is `unconfirmed` on the keep and `restored-unconfirmed` on the put-back.

**Two bounds ship as mitigations for what hardware has not answered** (D-19): the three re-fetch
rounds above, and pacing - 0 ms pre-send has never met two back-to-back 957-byte writes against a
2,048-byte ring that discards silently (SKELETON-RESULTS (b)). On a `write-*` timeout with zero NACKs
in the action, `preSendDelayMs` escalates to `DESKTOP_PRE_SEND_DELAY_MS` and the queue is rebuilt, so
the RETRY the visitor is already offered runs the experiment.

**Flash only what you have heard** (Z-05, Z-21): `KEEP ON DEVICE` is live exactly when the module's
memory holds the pair on screen. The confirmation closes on a knob move and on a session drop. And
`PUT BACK` after a keep stores too (Z-04) - a kept-then-put-back would otherwise leave the owner's RAM
right and their flash still holding HANGAR's work.

Purpose: SAFE-05 and SAFE-06's confirmed store, SAFE-07's detected half-write, SAFE-08's settled
state with no theatre, SAFE-09's bounded retries and named lost state.
Output: the store complete, its spec at eighteen.
</objective>

**`keepReason(capable)`**, the closed decision in one place:

| Condition, first match wins | Reason |
|---|---|
| `!capable` (the session is `unsupported` or `insecure`) | `incapable` |
| `phase === "partial"` | `after-partial` |
| `phase === "kept"` | `already-kept` |
| `phase === "kept-mismatch"` | `after-mismatch` |
| `(phase === "settled" \|\| phase === "unconfirmed") && armed` | **undefined - live** |
| `(phase === "settled" \|\| phase === "unconfirmed") && !armed` | `knobs-moved` |
| anything else (`idle`, `snapshotting`, `ready`, `writing`, `restored`, `lost`, `snapshot-failed`, `restored-unconfirmed`, `nothing-landed`) | `never-tried` |

**`putBackState()`**, decided on `snapshot` first: `"enabled"` **only** when the session is
`connected` **and** `snapshot !== undefined` - including over budget (I9 cause 5: it writes the
snapshot, never the tuned pair) and every failure state with a snapshot; `"needs-zona"` when a
snapshot or a remembered module exists and the session is not `connected` (I0 with a surviving
record, I8 `lost`); `"absent"` otherwise - no snapshot and no remembered module (I1, I9 causes
1/3/4), **and** the session `connected` with no snapshot in hand, which is `snapshotting` before the
fetch answers and `snapshot-failed` even on a remembered module (the record is consulted only after a
fetch passes `canWriteBack`, 07-06's deferred note). `enabled` never returns with `snapshot ===
undefined`: the component's click writes `snapshot`, and a remembered module is not a snapshot.
`writing` disables it in the component, not here.

**The store leg**, shared by the keep and by a put-back after a keep:

```ts
async #storeLeg(action: "keep" | "put-back", sent: ConfigStrings): Promise<"kept" | "mismatch" | "unconfirmed" | false> {
  const gen = this.#generation;
  const T = await heavy();
  this.leg = "store"; this.phase = "writing";
  this.#session.writeLock = true;
  this.#armSlow();
  try {
    await this.#queue!.request(T.storePage(), "store");        // pagestoreMs 3000, ACK-only; on a rig N ACKs resolve once
    if (gen !== this.#generation) return false;
    // D-12 / D-19: the ACK is sent by the success callback that STARTS the page reload
    // (grid_decode.c:947-961). Wait for the module's next heartbeat, then prove the bytes.
    await this.#nextHeartbeat();                                   // resolved by the onClass sink
    for (let round = 0; round < 3; round++) {
      const after = await T.fetchBoth(this.#queue!, this.#identity(), "refetch");
      if (gen !== this.#generation) return false;
      if (after.setup.actionString === sent.setup && after.timer.actionString === sent.timer) return "kept";
      this.refetchRounds = round + 1;                              // recorded for the runbook, rendered nowhere
      await this.#sleep(T.retryBackoffMs(round));
    }
    return "mismatch";
  } catch (err) {
    if (gen !== this.#generation) return false;
    if (err instanceof T.AbortedError) { this.cause = "aborted"; this.phase = "lost"; return false; }
    return "unconfirmed";                                          // the 3000 ms timeout: dropped under a bulk op, no NACK ever
  } finally {
    this.#disarmSlow();
    this.#session.writeLock = false;
  }
}
```

`keepOnDevice()`: `confirmOpen = false`; run `#storeLeg("keep", lastWritten)`; `"kept"` ->
`phase = "kept"`, `keptThisSession = true`, `announce(liveKept(name))`; `"mismatch"` ->
`kept-mismatch`, `cause = "mismatch"`, `announce(announceTitle(keptMismatchBlock().title))`;
`"unconfirmed"` -> `unconfirmed`, `cause = "timeout"`, its title announced; `armed` recomputed after
each (live again only in `unconfirmed`).

`putBack()`: the RAM leg from 07-06 lands the caption and first line (`phase` stays `writing`; the
component reads `action === "put-back" && leg === "store"` to render `RESTORED`'s caption and first
line - I5's interval is the store leg, after the two RAM acknowledgements; during the RAM leg,
before any ACK, `leg` is `ram` and the previous block holds under `aria-busy`, since nothing is
restored yet); if `keptThisSession`, `#storeLeg("put-back", snapshot)` follows: `"kept"` -> `restored`
with `keptThisSession = false`; `"mismatch"` or `"unconfirmed"` -> `restored-unconfirmed`. Without a
keep this session, `restored` directly. `LIVE_RESTORED` is announced once, on entry to `restored`.

**`#classify(err, T)`**, widened:

| Signal | Phase | `cause` | `landed` / `failed` |
|---|---|---|---|
| `AbortedError` | `lost` | `aborted` | - |
| `NackError` and `write-timer` already `ok` in `lastSteps` | `partial` | `nack` | `Timer` / `Setup` |
| `NackError` otherwise | `nothing-landed` | `nack` | - |
| anything else (the queue's timeout) and `write-timer` `ok` | `partial` | `timeout` | `Timer` / `Setup` |
| anything else otherwise | `nothing-landed` | `timeout` | - |

After any `timeout` cause where **no** step in `lastSteps` has `outcome: "nack"`, set
`#preSendDelayMs = DESKTOP_PRE_SEND_DELAY_MS` and rebuild the queue on the same transport (abort the
old one first, re-subscribe the sink). Record the escalation on the store as
`pacingEscalated = $state(false)` so the probe can show it and the runbook can ask about it.

**`#armSlow()`**: `setTimeout(2000)` that sets `slow = true` and announces `LIVE_STILL_WRITING`
once; `#disarmSlow()` clears the timer and sets `slow = false`. The comment beside it gives Z-09's
arithmetic: roughly 90x the slowest `CONFIG/EXECUTE` ever observed on a RAM leg, roughly 50x the
slowest `PAGESTORE/ACKNOWLEDGE` on a store leg, and below the 3000 ms `pagestoreMs` on purpose - the
line says busy; only the timeout says failed.

**`observeConfig`** now also: when `confirmOpen` and the new pair differs from `lastWritten`, close
the confirmation (`confirmOpen = false`). **`onConnection("closed")`** also closes it. A page change
while `ready` (the session's `identity.activePage` differs from `snapshotPage`, seen from the
`onClass` sink) drops back to `snapshotting` for the new page - Pitfall 4's third layer.
