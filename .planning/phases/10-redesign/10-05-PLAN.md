<objective>
No card rests dark — and the machinery that makes that true without touching a single configuration.

Wave 5. Blocked on 10-04.

**The evidence first, because it decides the ruling.** `src/lib/catalog/frames.json` records
`nonZeroBytes` at ticks 0, 37, 101, 500 and 1009 for every entry. For **Trackpad, GHOST, MORPH and
ETCH** the value is **0 at every one of the five ticks**. There is no representative motion frame to
show: with nothing touching them these four paint nothing at any tick. So D-09's choice is not
"rest state versus motion frame". It is: change what four pads do on somebody's hardware, or supply a
finger.

> **Every card paints. A configuration that paints nothing until it is touched is given a finger, not
> a light.** HANGAR supplies the gesture; the firmware supplies every lit pixel. **Motion is never
> faked**, and this is the sentence that keeps that true: a demo card shows what a real finger would
> make it do, drawn by the same code as a real finger.

**The half of D-09 the spec corrected itself on.** "It goes through the existing queue" is only half
true. The *rate* contract survives intact — `touch.ts`'s sampler already enforces at most one sample
per contact per 10 ms tick with MOVEs coalescing to newest, and nothing here changes that. The
*plumbing* does not exist, and three named things block it:

| Today | Why it blocks a demo card |
|---|---|
| `host.ts:415` delivers a sample only `if (entry.hero)` | a browse card is never hero, so a demo path would be queued and never delivered |
| `host.ts:447`'s `active()` counts a touch as activity only for the hero | a demo card whose configuration is otherwise still would be judged frozen and its rAF would stop mid-gesture |
| `host.ts:188` holds **one** `TouchSampler` for the whole host, and `touch.ts:25` sets `MAX_CONTACTS = 5` globally | four demo cards plus a live finger contend for five slots. Trackpad's path uses two contacts, so **two demo cards alone can starve the visitor's finger** |

**A fact the spec did not have, and it makes the phase's other promise easy to keep.** All four dark
entries are browse-only: `tpad` is out of the front-door row by PREV-01, and `ghost`, `morph` and
`etch` are Lua, which `front-door.spec.ts:110-112` excludes by requiring `preview === "padsim"`.
**So no demo card ever mounts inside `Coverflow.svelte`, and §16's "nothing at all" survives D-09 as
well as it survives the CRT.** Verify it and state it; it is what keeps this plan's blast radius to
the browse grid.

**V-04, stated here because this is the plan it changes.** §16 gives `PadFrame.svelte` a "`demo`
mode". `PadFrame` holds no engine, issues no draw call, and declares `entry: { id: string }`
precisely so `svelte/no-unused-props` stays green — a `demo` prop on it is an unused prop and a lint
failure. **The flag is a fourth argument to `SimHost.register`**, passed from `CatalogCard.svelte`.
`PadFrame.svelte` keeps Layer S from 10-04 and gains nothing here.

Purpose: PREV-01 extended to four cards that had no picture; IDENT-02 extended to a motion that has
to stop.
Output: one new module, four authored paths, three host changes plus a second `stillFrame` branch,
one retirement, four regenerated OG images.

<interfaces>
**The four paths, one per dark entry** (§9.3). Each is a short array of
`{ tick, pointer, event, x, y }` samples, looped over a fixed period:

| Entry | The gesture |
|---|---|
| Trackpad | one finger crossing the pad and lifting, then two fingers scrolling |
| GHOST | one drag that leaves a ghost, then a lift — the ghost then retraces on its own, which is the entry's whole point |
| MORPH | a slide between two corners and back |
| ETCH | a short stroke drawn, then a fast sweep that wipes it |

**The rate contract, reproduced exactly and not restated in `demo.ts`:** 10 ms tick, 100 ms catch-up
clamp, one rAF, `IntersectionObserver { threshold: 0, rootMargin: "200px" }`, **at most one touch
sample per contact per tick**, MOVEs coalescing to newest, DOWN and UP always keeping their place,
zero `setInterval`. `demo.ts` **queues into the sampler**; the sampler decides the rate. If `demo.ts`
ever calls `engine.touch` directly, the guarantee is gone.

**The three host changes, each with a test in `host.spec.ts`'s existing idiom:**

| Line | Today | Becomes |
|---|---|---|
| `:415` | `if (entry.hero) this.sampler.deliver(entry.engine);` | delivery gated on `entry.hero \|\| entry.demo`, and a demo entry delivers from **its own** sampler |
| `:447` | `entry.hero && (this.sampler.size > 0 \|\| entry.engine.pendingTouches > 0)` | the `touchActive` term widens to demo entries, on the same `size > 0 \|\| pendingTouches > 0` test |
| `:188` | one `private readonly sampler = new TouchSampler()` for the whole host | **one sampler per demo entry**, held on the entry. **The hero keeps the host's sampler untouched**, so the interactive preview's guarantee is byte-for-byte what Phase 4 signed off |

**`stillFrame()`'s second branch** (`host.ts:467`). The shipped machinery is `engine.reset()` then
`engine.run(REDUCED_MOTION_TICKS)`, with `REDUCED_MOTION_TICKS = 64` at `schedule.ts:53`, pinned
against the vendored constant by `schedule.spec.ts:101-102`. **There is no `stillFrameOf(entry)`
anywhere in the tree** and the spec should not have named one. Under reduced motion a normal entry
runs to tick 64 and freezes, as today; a **demo entry resets and then replays its path to the end,
once, and freezes**. One private method, two branches, called from the three sites that already call
it (`:244`, `:274`, `:480`).

**The register signature** becomes
`register(id, canvas, engine, options?: { demo?: DemoPath })`. Three-argument callers are unchanged,
which is every caller except `CatalogCard.svelte`.

**Two consequences that are named amendments:**

- **`restsBlack` is retired as a rendering input and kept as a recorded fact.** It selects a demo
  path, and its two-directional assertion against `frames.json` is the site's proof that a card is not
  accidentally black. **Deleting it would delete the proof.**
- **`RESTS_DARK_NOTE` is retired** (R-10), because after this phase no card rests dark and the
  sentence is false. `listing.spec.ts:245-255` and `copy.spec.ts:173-174` are rewritten by name, not
  deleted: they become "no entry carries a resting-dark note" plus "every `restsBlack` entry declares
  a demo path", which is a stronger pair than the one they replace.

**`e2e/browse.e2e.ts`'s reduced-motion test gets stronger, not looser.** Its `dark` exemption at
`:514-520` — *"three of the sixteen configurations are declared `restsBlack` and their still frames
are legitimately black, so the two samples would be identical even if reduced motion did nothing"* —
is **retired**, and the replacement is an assertion the old test could not make: **under reduced
motion every card, including those four, shows a still frame with `nonZeroBytes > 0`.** The suite
loses an exemption and gains a universal. **No e2e title is added**; the count is unchanged.

**`static/og/`.** Four images regenerate from the end of their demo path rather than from a black rest

gates, and neither's count moves.
