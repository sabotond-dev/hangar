<objective>
Fifty-five tags become sixteen, in two facets, exactly three per entry — in one plan, because it is
one edit spread over twenty-eight files and splitting it would leave the tree red in the middle.

Wave 6. Blocked on 10-05, which last touched `listing.ts`.

**The problem, counted.** Thirty-six entries carry **55 distinct tags**, **27 of them on exactly one
entry**, with **28 chips** standing in the toolbar and three or four tags per entry. Three quarters of
the vocabulary matches a single card. *That is a list, not a filter.*

**The rule that replaces the derivation:**

> A term earns a chip when it is a member of a declared facet. **Every facet member is always a
> chip.** The vocabulary is closed and lives in `facets.ts`; it is not derived from counts, so it does
> not drift as the catalog grows, and no disclosure is needed. An entry that cannot be described with
> these sixteen terms is evidence that the vocabulary is wrong, not that the entry needs a new word.

**And there is nothing called `MORE TAGS` to retire, because it was never built.**
`BrowseToolbar.svelte:44-52` says so in as many words: 05.1-CONTEXT D-15 beat 05.1-UI-SPEC W-19.
What actually retires is the **count-derived chip row** and, with it, the **outsider chip** — the
vocabulary is closed, so no active facet member can fall outside the standing rows. `disabledTags()`
stays, unchanged, and becomes rare: a chip is disabled only when it would return zero given the
*other* facet's active set.

**This plan is data and gates only.** The toolbar's two rows, the URL parameters, the sort removal and
the card's three chips are 10-07's. Nothing in this plan renders anything.

**Scope watch, and no split.** Task 10-06-02 edits **twenty-nine** files in one task — twenty-eight
entry sources plus `listing.ts` — which is the top of this repository's norms. It stays one task
because it is a **table-driven** edit: every file gets exactly one `tags:` array, read row by row off
the assignment table in `<interfaces>`, and it is **gated in both directions** — `listing.spec.ts`
asserts `tags` deep-equal to the catalog entry both ways, so re-cutting `listing.ts` alone or an
entry alone goes red on arrival rather than passing quietly. Splitting it would only create a wave in
which the tree is knowingly red. **The clean resumption boundary is the assignment table itself:**
work the entries in the table's order, and if an executor's context runs short, stop after a whole
entry, record **which rows of the table are landed and which are not** — by entry id, from the table,
not from memory — and note that `listing.spec.ts` is expected red until `listing.ts` and all
twenty-eight sources agree. `listing.ts` is edited **last**, so the red is one-directional and
readable.

Purpose: CAT-03 and CAT-04 amended; CONT-03's "four feel tags" amended to exactly three.
Output: one new import-free module, four gate files re-cut, twenty-eight entry files edited, one
approved document amended by name.

**Semantics, and this is a named amendment to 05.1-UI-SPEC's "Combining is AND":**

> **Within a facet, chips are OR. Across facets, they are AND.**

Required rather than conventional: `FOR` gives every entry exactly one term, so under a pure AND any
second `FOR` chip would return zero and immediately disable itself. **A facet where the second click
is always dead is not a facet.**

**Where the tags actually live.** Twenty-eight source files, verified by the planner on 2026-09-08:
twenty-seven `src/lib/catalog/entries/<id>.ts` files with one `tags:` each, and
`src/lib/catalog/entries/ported.ts` with ten `tags:` occurrences covering the nine presets (confirm
the tenth — it may be a type or a comment). Plus `listing.ts`'s thirty-six restatements.
**`listing.spec.ts` asserts `tags` deep-equal in both directions, so a re-cut that edits only
`listing.ts` goes red on arrival.**

**`facets.ts` imports nothing at runtime**, the same discipline `front-door.ts:20-23` and `listing.ts`
carry, for the same measured reason: the ten `FOR` terms must be in the prerendered HTML at first
paint and must not drag the 131,101-byte compiler chunk onto the critical path. `facets.spec.ts` scans
its source and fails on any specifier that is not `import type`.

**The legacy map.** `?tag=` is accepted for one release. Twenty-seven singletons and the twenty-eight
old chips map through a declared table to a facet member where one is honest, and to nothing where it
is not. **An unmapped value is NOT dropped** — its destination is 10-07's, and this plan only declares
the table and asserts that every key is one of today's 55 and every value is one of the sixteen or
`undefined`.
