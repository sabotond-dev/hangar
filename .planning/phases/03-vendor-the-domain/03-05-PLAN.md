The vendored code is already careful: `measure()` asserts before measuring, so `cost`, `fits`,
`ledger`, `ghostCost` and `fit` throw rather than return a wrong number, and `validate()`
short-circuits to a single `not-ready` diagnostic rather than letting `checkSyntax`'s silent `false`
become "your Lua is broken". This plan puts one memoised gate in front of all of it so that a HANGAR
caller never sees either failure mode, and proves the simulator stays outside the gate.

One apparent conflict, resolved here so a verifier does not re-litigate it: CONTEXT says the app
root awaits the gate before first render of anything that compiles, while CLAUDE.md's stack notes
say never call `initLuaFormatter()` at boot. Both hold, because the gate is attached to the COMPILE
surface rather than to the root layout - nothing calls `padReady()` until something asks for a cost,
and what the page shows while that resolves is Phase 4's concern.

The readiness mechanism inside the vendored compiler, read from source at `_pad.ts:47-72`
(upstream line numbers - add the header offset recorded in VENDOR.md):

```ts
let formatterReady = false;
let readyPromise: Promise<void> | undefined;

export function padCompilerReady(): Promise<void> {
  if (typeof readyPromise === "undefined") {
    readyPromise = initLuaFormatter().then(() => { formatterReady = true; });
  }
  return readyPromise;
}

export function isPadCompilerReady(): boolean {
  if (formatterReady) return true;
  formatterReady = GridScript.checkSyntax("local a=1");   // logs to console.error pre-init
  return formatterReady;
}

export function assertPadCompilerReady(): void {
  if (!isPadCompilerReady()) {
    throw new Error(
      "The Lua formatter is not initialised. Await padCompilerReady() first.",
    );
  }
}
```

Two consequences the spec depends on:

- `padCompilerReady()` is already memoised, so `padReady()` composes with it rather than racing it.
- `isPadCompilerReady()` falls back to `GridScript.checkSyntax("local a=1")`, which before
  initialisation returns `false` AND makes the protocol package emit
  `"ERROR: Lua formatter not initialized! Call 'await initLuaFor..."` on `console.error`
  (`grid-protocol/dist/index.js:4193-4240`, swallowed at `:4459-4479`). So any call that reaches
  `assertPadCompilerReady()` before the gate resolves emits that log. HANGAR's surface must never
  produce it; the deliberate pre-init probe in the spec must.

Other vendored exports used here: `compile`, `cost`, `fits`, `measure`, `validate`, `presetById`,
`PRESETS`, `PadSim`, and the types `CompileResult`, `PadCost`, `PadState`, `PadUserCode`,
`PadDiagnostic`, `PadReserved`.

`validate(result, reserved?)` returns `PadDiagnostic[]`; each diagnostic has `severity`, `code` and
`message`, and the pre-init short circuit is a single entry with `code: "not-ready"`.

**1. `src/lib/pad/ready.ts`** - one memoised promise, and nothing else:

```ts
// The FOUND-05 gate.
//
// GridScript.compressScript throws when the WASM Lua formatter has not
// initialised, and GridScript.checkSyntax merely returns false - so a caller
// that measured before initialisation would either crash or, worse, report a
// correct config as syntactically broken. Every HANGAR entry point that
// compiles, costs, fits, measures or validates awaits this promise first.
//
// PadSim is deliberately NOT behind this gate: it takes a PadState, never Lua,
// and works with the formatter uninitialised. Gating it would make the catalog
// wait on a 628 KB WASM download for a picture that does not need it.
//
// Copyright (C) 2026 Botond Sandor. Licensed under the GNU GPL v3 or later.
import { initLuaFormatter } from "@intechstudio/grid-protocol";
import { padCompilerReady } from "../../vendor/botor/_pad";

let gate: Promise<void> | undefined;

/** Resolves once the Lua formatter WASM is initialised. Memoised: every caller awaits one load. */
export function padReady(): Promise<void> {
  gate ??= (async () => {
    await initLuaFormatter();
    // The vendored compiler keeps its own memoised flag; awaiting it here is
    // what makes assertPadCompilerReady() take the fast path afterwards
    // instead of falling back to checkSyntax and logging.
    await padCompilerReady();
  })();
  return gate;
}

/** Test-only. Drops the memo so a spec can observe the pre-init branch. Never call this from app code. */
export function resetPadReadyForTests(): void {
  gate = undefined;
}
```

export async function compilePreset(
  id: string,
  user?: PadUserCode,

  await padReady();
  const preset = presetById(id);
  if (!preset) throw new Error(`unknown preset: ${id}`);
  return vendorCompile(preset.state, user);

export async function compileState(
  state: PadState,
  user?: PadUserCode,
): Promise<CompileResult> {
  await padReady();
  return vendorCompile(state, user);

export async function costOf(
  result: CompileResult,
  reserved?: PadReserved,

  await padReady();
  return vendorMeasure(lua);
