**Three things decided here, each with its reason.**

1. **`N`, not `Q`, at both sites.** The Timer has no event code and no contact - it lights a stored or a
   replayed point - so `Q`'s contract (`s,i,e,x,y`, hysteresis, expiry) does not apply there, and the key
   test is a press-time lookup exactly like ARC's stop tap (12.1-03: "a press-time lookup wants no
   hysteresis"). `N` is the nearest calibrated cell with no state. Both sites read the same `U`, so the
   key and the comet agree on where the LEDs are.
2. **The finger colour is `@RECC`, not white (D-13).** GHOST has its own colour knob for exactly the thing
   the finger is - the recording comet that follows your hand - so the gradient takes it, as RADAR
   POINTS took `@SWEEPC` and LUMEN `@CURSORC`. At the picker corner `@RECC` renders `255,255,255`, so the
   cost is the white literal's. The ghost's replay stays on layer 2 in `@GHOSTC`; the live finger is on
   layer 0; telling your hand from its ghost is still the two layers' job.
3. **No `Q`, no `X`, no `R` - GHOST keeps its own contact model, and the alternative is on record.** The
   library's expiry (`Q` registering the contact, `X(s,n)` in the Timer, `E` clearing the block, `R`
   as the release convention) would let a lost lift end the recording and darken the gradient - but it
   would also end the recording of a **still** finger after `n` Timer ticks, because a motionless
   contact sends nothing, and GHOST's header says in so many words that "a motionless finger still
   records, which is correct". That is a behaviour change to the card's one promise, not a re-fit.
   Measured for the record: `R=function(s,i)s.h=nil end` + `Q(s,i,e,x,y)` before `G` + `X(s,150)` in the
   Timer (3 s of stillness before expiry, against the 5 s recording cap) is **Setup 530 / Timer 417**,
   both inside 908. It is not taken; row 27 asks the user whether a paused drag should keep recording,
   and if the answer is no the shape above is a one-commit change. Until then a lost lift leaves GHOST
   exactly where it leaves it today (the comet held at the last point, the recording running to
   `@LEN`), plus one lit 2x2 block on layer 0 that the next onset's `G` clears (`local o=B[i]if o then
   V(o)end`) - stated, not hidden.

## The library functions GHOST now calls (from `src/lib/catalog/library.ts`, as shipped at 781 + 705)

```lua
-- 255/6
function N(x,y)return(U(x,KX)+32)//64+(U(y,KY)+32)//64*9 end
function G(s,i,e,x,y,l,r,g,b)L=l local o=B[i]if o then V(o)end if e~=1 and e~=4 then B[i]=nil return end
  local u,w=U(x,KX),U(y,KY)local c,q=glim(u//64,0,7),glim(w//64,0,7)local f,h=u-c*64,w-q*64 local n=c+q*9
  for d=0,3 do local p,t=d%2,d//2 local a=glag(0,n+p+t*9)glc(a,l,r,g,b,1)glp(a,l,255*(p>0 and f or 64-f)*(t>0 and h or 64-h)//4096)end B[i]=n end
```

`N` returns the nearest calibrated cell, stateless. `G` clears the contact's previous 2x2 block, returns
on an end code (3, 5..8) **and on 9**, and lights the 2x2 around the calibrated position with the colour
re-asserted (D-11). Both read `U` and the two tables in 255/0. The TS twin for test expectations is
`calibratedAxis(v, axis)` in `calibration.ts` (12.1-01): cell `c = floor((calibratedAxis(x,"x")+32)/64)`,
weights `(64-f)(64-h)`, `f(64-h)`, `(64-f)h`, `fh` with `f = u - c*64` clamped as `G` clamps.
