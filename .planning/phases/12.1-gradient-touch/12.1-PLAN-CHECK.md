## 4. The two slots' join, and the one unproved link

Source supports the claim as far as source can: `init.lua:25-46` registers every stored body of every
element (`gas(i, eve[j], path)`) **before** `ele[#ele]:post_init_cb()` runs, so `tim` is a method on the
system element when the system `ini` calls `self:tim()`; `grid_ui_system.c:26` binds event index 2 to
`GRID_LUA_FNC_A_TIMER_short` = "tim" (`grid_protocol.h:876`); `grid_decode.c:1286-1287` registers then
runs a written body at once, which is why 255/6 goes first. What no probe has tapped is the system `ini`
calling the system `tim` on a page load. No plan's automated verification depends on it: plan 02's host
models the working case and a no-op `tim` for the default; the wire plans write 255/6 first regardless;
if `G` is nil, `B` stays empty so `E` never reaches `V` - the failure is contained to "`G` nil on the
first finger", as R-6 says. Row I (plan 08) is written, declinable, with the failure signature.

**The written fallback carries the same doubt.** D-04 and plan 09's deferred-items D name "255/6's
functions in 255/4 (same mechanism, same doubt)". The mechanism that IS proved on this ZONA is a
**touch** script calling a **system** method (`ele[#ele]`, cell 80, probe 2) and an element calling its
own `tim` (probe 1). So the fallback with no new doubt is: drop `self:tim()` from 255/0 (-10) and open
every re-fitted Setup with `ele[#ele]:tim()` (+15 each; CONSOLE at 69 free becomes 54). Write it beside
the 255/4 one so the gate has a fallback that does not need a second proof.
