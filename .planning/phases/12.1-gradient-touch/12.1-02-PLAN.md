<objective>
The library on two slots, and the host that runs both.

**Why two slots** (`12.1-CONTEXT.md` D-03, the user's "yes"): the gradient does not fit beside Q6.5's
expiry machinery in one - every variant is over 908, the smallest by 135 - and the system element's
Timer (255/6) is a slot nobody has claimed. Split as the research measured and plan 01 re-ran: **255/0
at 782 (126 free)** holds the marker, `H T C P B L`, `KX`, `KY`, `U`, `W`, `E`, `Q`, `X` and `self:tim()`;
**255/6 at 714 (194 free)** holds the marker, `V`, `G`, `N`, `A`, `D`. The rule that decides which side a
thing lives on: 255/0 holds state and the map, 255/6 the painters and the senders, so a change to the
gradient's look never touches the string that holds the knots.

**Why `G` carries the colour** (D-11, decided at the plan-check with the firmware in front of it). Layer
0 is the alert layer, and `grid_alert_all_set` (`grid_led.c:260-271`) rewrites layer 0's **colour** on
every LED - on a CONFIG write (`grid_decode.c:1282`, before the Setup runs, so the Setup wins), but also
on page-discard completion (`:887`, WHITE_DIM), on a refused page change (`grid_lua_api.c:1695`, PURPLE),
on a TX overflow (`grid_transport.c:253`, BLUE) and at boot. A finger coloured once in an init loop turns
grey, purple or blue after any of those until the Setup re-runs. So `G(s,i,e,x,y,l,r,g,b)` takes the
colour and re-asserts it with `glc(a,l,r,g,b,1)` on each of its four cells on every call: the finger
heals on the next sample, the 81-cell init colouring goes from every entry, and the peak is fixed at 255
(every caller passed 255). Measured: **255/6 714** against 683 for the pre-coloured shape, and every
re-fit **cheaper** (plans 03 and 04). And the trailing `1` in `glc(...,1)` forces the layer's min to 0
(`l_grid_led_layer_color`, nargs 6) - so there is no byte-6 floor and the research's floor paragraph was
wrong; a cell `V` clears is dark, not dim.

**Why the hysteresis stays** (research finding 3): the gradient removes the cell for the *light*, not for
the *toggle*. A bare argmax would toggle both neighbours alternately at 100 Hz for a finger resting on a
seam - the exact Q2 failure. `W` holds the previous LED while the calibrated coordinate is within 45/64 of
its centre.

**What 12-07's file says that is superseded, and must be rewritten rather than left.** Section 2 rule 5
of `library.ts` - *"The finger lights its cell. NOT HERE, AND NO FUNCTION SHIPS FOR IT … If a later entry
wants it, it comes back WITH ITS CALLER NAMED"* - is exactly what happens here: `G` ships with eight
callers named (EUCLID, STEPS, RADAR POINTS, SONAR, CHORUS, MORPH, CONSOLE, LUMEN), `N` with one (ARC) and
one future (13-15), and `F` stays dropped because `G` is not `F`. Section 1's single-capital rule gains
its two exceptions, `KX` and `KY`; the planner and the plan-check both grepped `../grid-fw/common/src/lua/
*.lua` for `KX`, `KY`, `function U`, `function G`, `function V`, `function N` - zero matches. Repeat it
and cite it.

**The 12-07 lesson applies verbatim:** run it, then measure it, then pin it. Every semantic below is

before either string is pinned; the research's stub-VM run is not the gate (research Pitfall 8).

## The host

```ts
export type LuaHostOptions = {
  sim: PadSim; setup: string; timer?: string;
  system?: string;        // 255/0, as today
  systemTimer?: string;   // NEW: 255/6. Run AFTER the pristine snapshot and BEFORE `system`,
                          // as a method the 255/0 body reaches through self:tim().
};
```

Install order becomes `registerGlobals -> SELF_PRELUDE -> timer wrapper -> PRISTINE_SNAPSHOT ->
[255/6 as self.tim, then 255/0] -> setup -> TOUCH_DISPATCH`; restart `RESTART_WIPE -> [the same pair]
-> SELF_PRELUDE -> setup -> TOUCH_DISPATCH`. The pair is one `doString`: save `self`, set `self` to a
table whose `tim` is a function wrapping the 255/6 body (the `--[[@cb]]` marker comments itself out
inside a function, as the Timer wrapper already relies on), run the 255/0 body (its `function G(` forms
define plain globals, which is what the module does too), restore `self`. **When `systemTimer` is
absent and `system` is present, `tim` is a no-op** - standing for a module whose 255/6 still holds the
firmware default, which prints "tick" and defines nothing - so the install does not raise and `G` is
simply undefined (`12.1-VALIDATION.md` R-6). Both sources are kept for `restart()`.

`lua-pad-sim.ts:220` passes `systemTimer: TOUCH_LIBRARY_TIMER` beside `system: TOUCH_LIBRARY`. Every
hand-built host in `lua-smoke.spec.ts` that passes `system` passes `systemTimer` too (five sites plus the
helper at `:5229`); `presetParity` deliberately passes neither and says so.
