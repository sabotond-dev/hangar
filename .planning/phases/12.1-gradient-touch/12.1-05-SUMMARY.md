## Task 1: the forward map behind both doors, the axis defaulted

### `mapAxis`, as landed

```ts
import { sensorAt } from "../catalog/calibration";
export function mapAxis(offset: number, extent: number, max: number, axis: "x" | "y" = "x"): number {
  if (extent <= 0) return 0;
  const u = (offset / extent) * 9 - 0.5; // LED n at u = n
  return sensorAt(u, axis, max); // clamped into 0..max inside
}
```

The plan's interface, character for character apart from prettier's line breaks. `u` is the LED
coordinate - the centre of the n-th ninth of the canvas is `u = n` - and `sensorAt` (12.1-01) is the
piecewise-linear forward map over the measured knots, saturating at `k[0]` below LED 0 and `k[8]`
above LED 8 as the sensor does, floored, clamped into 0..127, and scaled by `(max + 1) / 128` so a
hi-res state (`coordMax` 1023) reads the knot x8 - the firmware's own `txma(1023)` identity. The
header's "every ninth of the canvas lands on one LED column" paragraph is rewritten, not left: it now
says what the old map was, why it became a lie under the calibrated library (LED 7: 106 where the
sensor reports 120), what the map is now, why the axis defaults, and what the y error is until plan
08 (at most the KX/KY difference, 4 raw units).

**How the default keeps the canvases untouched (D-21).** `HeroSurface.svelte:136-137` and
`src/routes/playground/[id]/+page.svelte:435-436` each call
`mapAxis(event.clientX - rect.left, rect.width, engine.coordMax)` and the same on y with three
arguments; with `axis = "x"` defaulted both compile and both are correct on x. `git diff --quiet --
src/lib/ui/intro/HeroSurface.svelte` holds; the route's working-tree diff (58 / 16) is 13-11's
