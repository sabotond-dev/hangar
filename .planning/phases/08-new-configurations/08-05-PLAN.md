### CHORUS - "nine chords, and every one of them blooms"

Setup, canonical, 729 characters:

```
--[[@cb]]for n=0,80 do local a=glag(0,n)if(n%9//3+n//9//3)%2==0 then glc(a,1,0,60,120,1)else glc(a,1,80,40,140,1)end glp(a,1,255)glc(a,2,255,200,80,1)glp(a,2,0)end local t={0,2,4,5,7,9,11}self.h={}for z=0,8 do local c={}for j=0,2 do local d=z+j*2 c[j+1]=48+t[d%7+1]+d//7*12 end self.h[z]=c end self.z={}self.t={}self.touch_cb=function(s,i,e,x,y)s.t[i]=0 local z=x*3//128+y*3//128*3 if e==3 or e>=5 then z=nil end local o=s.z[i]if o==z then return end if o then for j=1,3 do s:gms(0,128,s.h[o][j],0,0)end end if z then for j=1,3 do s:gms(0,144,s.h[z][j],100,0)end local u,v=z%3*3+1,z//3*3+1 for n=0,80 do local p,q=n%9-u,n//9-v local a=glag(0,n)glpfs(a,2,255-math.sqrt(p*p+q*q)*22//1,4,0)glt(a,2,64)end end s.z[i]=z end gtt(0,100)
```

Timer, canonical, 173 characters (a per-contact chord watchdog):

```
--[[@cb]]gtt(0,100)local s=self for i,z in pairs(s.z)do local t=(s.t[i]or 0)+1 s.t[i]=t if t>20 then for j=1,3 do s:gms(0,128,s.h[z][j],0,0)end s.z[i]=nil s.t[i]=nil end end
```

Verified substitutions:

| Needle | Replacement |
|---|---|
| `c[j+1]=48+t[d%7+1]` | `c[j+1]=@KEY+t[d%7+1]` |
| `local t={0,2,4,5,7,9,11}` | `local t={@SCALE}` |
| `glc(a,2,255,200,80,1)` | `glc(a,2,@BLOOMC,1)` |
| `*22//1,4,0)` | `*22//1,@BLOOMRATE,0)` |
| `s:gms(0,144,s.h[z][j],100,0)` | `s:gms(@CH,144,s.h[z][j],@VEL,0)` |
| `s:gms(0,128,s.h[o][j],0,0)` | `s:gms(@CH,128,s.h[o][j],0,0)` |
| `s:gms(0,128,s.h[z][j],0,0)` | `s:gms(@CH,128,s.h[z][j],0,0)` |

The last two look alike and are not: `s.h[o]` is in the Setup (releasing the previous chord),
`s.h[z]` is in the Timer (the watchdog). Apply both.

Six knobs: `key`/`note`/`@KEY`, `scale`/`scale`/`@SCALE`, `bloomColour`/`colour`/`@BLOOMC`,
`bloomSpeed`/`speed`/`@BLOOMRATE`, `velocity`/`amount`/`@VEL`, `channel`/`amount`/`@CH`.
Defaults reproducing the canonical text: `48`, `0,2,4,5,7,9,11`, `255,200,80`, `4`, `100`, `0`.
Give `@SCALE` at least a natural minor (`0,2,3,5,7,8,10`) alongside major, and `@BLOOMRATE` a range
from a slow `2` to a fast `12`; every value must keep both events canonical, which the gate checks.

Metadata: name `CHORUS`, tags along the lines of `["chords", "harmonic", "blooming", "playable"]`,
`featured: true`, `addedAt: "2026-09-04"`. Description in one line, feel-based - the measured
behaviour is C, Dm, Em, F, G, Am, Bdim, C(8va), Dm(8va) in C major, generated in 130 characters, and
the honest limit worth carrying in the copy is that a new press **replaces** the bloom rather than
stacking it.

### ARC - "a modulation LFO you draw with your finger"

Setup, canonical, 379 characters:

```
--[[@cb]]for n=0,80 do local a=glag(0,n)glc(a,2,0,110,255,1)glpfs(a,2,math.atan(n//9-4,n%9-4)*41//1%256,4,3)glt(a,2,65535)glc(a,1,255,255,120,1)glp(a,1,0)end self.r=4 self.d=127 self.h=0 self.touch_cb=function(s,i,e,x,y)if i>0 or e==3 or e>=5 then return end s.d=127-y local r=1+x*31//127 if r~=s.r then s.r=r local f=glim(r//2,1,120)for a=0,80 do glf(a,2,f)end end end gtt(0,20)
```

Timer, canonical, 251 characters:

```
--[[@cb]]gtt(0,20)local s=self local p=(s.h+s.r)%256 s.h=p if p<s.r then for a=0,80 do glt(a,2,65535)end end local v=p<128 and p*2 or 510-p*2 s:gms(0,176,16,glim(64+(v-128)*s.d//255,0,127),0)for j=-1,1 do for k=-1,1 do glp(glag(0,40+j*9+k),1,v)end end
```

Verified substitutions:

| Needle | Replacement |
|---|---|
| `glc(a,2,0,110,255,1)` | `glc(a,2,@SWIRLC,1)` |
| `*41//1%256` | `*@ARMS//1%256` |
| `glc(a,1,255,255,120,1)` | `glc(a,1,@HEARTC,1)` |
| `s:gms(0,176,16,glim(` | `s:gms(@CH,176,@CC,glim(` |

Five knobs: `swirlColour`/`colour`/`@SWIRLC`, `arms`/`count`/`@ARMS` (41 = one arm, 82 = two,
123 = three - the phase multiplier the compiler itself uses), `heartColour`/`colour`/`@HEARTC`,
`cc`/`amount`/`@CC`, `channel`/`amount`/`@CH`. Defaults `0,110,255`, `41`, `255,255,120`, `16`, `0`.

**ARC's two `glt(a,2,65535)` calls are correct and must not be removed.** They sit on the swirl
background whose rate is `4` at rest and at most `glim(r//2,1,120)` under a finger, so they are the
legitimate keeper form. The wave-4 smoke gate's pitfall-1 guard fires only on `timeout === 65535`
together with `fre >= 200`, which is the keeper-on-a-decaying-trail signature. Say this in the
entry's comment so a later reader does not "fix" it. Note also that the Timer's keeper is folded
into the oscillator - `if p<s.r` is true exactly on the phase wrap - which re-arms layer 2 once per
LFO revolution for 40 characters instead of a separate keeper.

Metadata: name `ARC`, tags along the lines of `["modulation", "hands-free", "hypnotic", "gestural"]`,
`featured: true`, `addedAt: "2026-09-04"`. The honest limit for the copy: the 20 ms Timer is the LFO
clock, so the fastest cycle is about 165 ms and anything faster gets steppy.

### GHOST - "draw an automation curve once, and it loops forever"

Setup, canonical, 305 characters:

```
--[[@cb]]for a=0,80 do glc(a,1,0,255,180,1)glp(a,1,0)glc(a,2,255,80,255,1)glp(a,2,0)end self.g={}self.n=0 self.j=0 self.touch_cb=function(s,i,e,x,y)if i>0 then if e==4 then s.g={}s.n=0 s.j=0 for a=0,80 do glp(a,1,0)end end return end if e==3 or e>=5 then s.h=nil return end s.h=1 s.x=x s.y=y end gtt(0,20)
```

Timer, canonical as printed in the research, 331 characters:

```
--[[@cb]]gtt(0,20)local s=self local x,y if s.h then x=s.x y=s.y if s.n<250 then s.n=s.n+1 s.g[s.n]=x*128+y end s.j=0 elseif s.n>0 then s.j=s.j%s.n+1 local v=s.g[s.j]x=v//128 y=v%128 end if x then s:gms(0,176,16,x,0)s:gms(0,176,17,127-y,0)local a=glag(0,x*9//128+y*9//128*9)local l=s.h and 1 or 2 glpfs(a,l,255,250,0)glt(a,l,42)end
```

Verified substitutions:

| Needle | Replacement |
|---|---|
| `glc(a,1,0,255,180,1)` | `glc(a,1,@RECC,1)` |
| `glc(a,2,255,80,255,1)` | `glc(a,2,@GHOSTC,1)` |
| `if s.n<250 then` | `if s.n<@LEN then` |
| `s:gms(0,176,16,x,0)` | `s:gms(@CH,176,@CCX,x,0)` |
| `s:gms(0,176,17,127-y,0)` | `s:gms(@CH,176,@CCX+1,127-y,0)` |

The last row is why GHOST's Timer renders 333 rather than 331 at the defaults: `@CCX+1` costs two
characters more than the literal `17` and buys one knob that moves both CC numbers together.

Five knobs: `recordColour`/`colour`/`@RECC`, `ghostColour`/`colour`/`@GHOSTC`,
`loopLength`/`size`/`@LEN`, `cc`/`amount`/`@CCX`, `channel`/`amount`/`@CH`. Defaults `0,255,180`,
`255,80,255`, `250`, `16`, `0`. `@LEN` is samples at 20 ms, so `250` is five seconds; give it a
handful of values and keep every one under 250 so the recorded table cannot outgrow what the loop
replays.

Metadata: name `GHOST`, tags along the lines of `["looper", "automation", "gestural", "generative"]`,
`featured: false`, `addedAt: "2026-09-04"`. The design note worth writing into the comment: recording
is done by the **Timer**, not by the touch callback, because touch enqueue is change-gated - so
record and replay both run at exactly 20 ms per point and the loop plays back at the speed you drew
it. A callback-driven recorder would replay a slow drag faster than it was made.
