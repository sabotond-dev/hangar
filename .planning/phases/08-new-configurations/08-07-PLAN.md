<objective>
Prove the lazy seam against the deployed bytes, and write down what the phase costs.

Wave 7. `08-CONTEXT.md` D-14 requires "a production-build e2e assertion that a cold catalog load
fetches neither the Lua WASM nor the formatter WASM". That is not a nicety: the whole argument for
adding a 271 KB Lua VM to a public playground is that a browse-only visitor never downloads it, and
an argument nobody tested is a hope.

Phase 3 learned the harder half of this twice, and both lessons apply:

- **A WASM asset that resolves in dev can fail in `build/`.** So this e2e runs against `build/`
  served by `worker/index.js` under `wrangler dev`, never against `vite dev` and never against
  `vite preview` - Kit's preview boots the Node server from `.svelte-kit/output/server` and never
  reads `build/` at all.
- **A wrong MIME does not break anything visibly.** `@wasm-fmt/lua_fmt` falls back from
  `instantiateStreaming` to `WebAssembly.instantiate` with only a console warning and then runs the
  slow path forever. `e2e/fidelity.e2e.ts` asserts the content type for exactly that reason; do the
  same for the VM's asset.

Purpose: D-14's bundle assertion, and the developer-facing record `docs/TESTING.md` exists to keep.
Output: one unlinked probe page, 2 e2e tests, 3 unit tests, two updated docs.
</objective>
