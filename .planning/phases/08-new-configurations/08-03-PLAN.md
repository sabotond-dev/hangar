<objective>
Prove the Lua route before anything is authored against it, and give Phase 4 one engine interface.

Wave 3. This is the **Wave 0 gate** `08-CONTEXT.md` D-07 names: "the Lua host must reproduce all nine
presets' layer records and golden-frame hashes before any new config is authored". Waves 4 to 6 are
blocked on it.

The gate is strong for a specific reason. The nine presets are the one corpus where two independent
producers exist: BOTOR's compiler emits Lua, and `PadSim` re-implements in TypeScript what that Lua
would do. Running the emitted Lua through a real Lua 5.4 VM and getting the same 243 layer records
and the same frame hashes is a three-way agreement - compiler, transcription, and real Lua - and it
is what makes PREV-02 literally true rather than true by coincidence.

`08-RESEARCH.md` reports this cross-check already built and green in a scratchpad. **Do not import
the scratchpad.** Re-derive it inside `src/lib/`, from the vendored sources and the committed
fixtures, so the gate runs on a fresh clone with nothing outside the repository - the Phase 3 rule
that `format-parity.spec.ts` is the one deliberate exception to.

If the parity spec cannot be made green: stop, do not author a configuration, and record the failure.
The documented fallback is route 1a (new `PadState` combinations, which the 4,860-state invariant
sweep already maps), and the phase summary must say so out loud rather than shipping a hand-drawn
preview - which PREV-02 forbids outright.

**One amendment to 08-CONTEXT.md D-08, made here and recorded so nobody re-litigates it.** D-08 lists
the surface the Lua host must implement as `tick`, `frame`, `animating`, `touchDown/Move/Up`,
**`setState`**, `coordMax`, `pendingTouches`. `SimEngine` takes all of those **except `setState`**.
The reason is that the two engines take incompatible state: `setState` means "here is a new
`PadState`", which is meaningless for a hand-authored Lua entry whose state change is a knob index
moving and whose rebuild is a re-render plus a fresh VM. Rather than widening `setState` to a union
that neither engine can implement honestly, both engines are rebuilt through `createEngine`, and
`PadSim`'s own comment prices that at "microseconds". D-08's intent - that Phase 4's card component
picks an engine by `entry.preview` and changes nothing else - is preserved exactly; only the
mechanism for a state change moves from a method to a constructor. Write this into `engine.ts`'s
module comment as well, and flag it in the SUMMARY so `08-CONTEXT.md` can be amended in place.

```
expected = new PadSim(preset.state)
actual   = a LuaPadSim over a blank fully "user"-owned PadSim, having run compile(preset.state).setupLua

  compare { min, mid, max, pha, fre, sha, timeout }      -> 81 * 3 = 243 records
```

**1. `src/lib/sim/engine.ts`.**

```ts
export interface SimEngine {
  tick(): void;
  run(n: number): void;
  reset(): void;
  readonly frame: Uint8Array;
  readonly animating: boolean;
  readonly coordMax: 127 | 1023;
  readonly pendingTouches: number;
  touchDown(id: number, x: number, y: number): void;
  touchMove(id: number, x: number, y: number): void;
  touchUp(id: number, x: number, y: number): void;
  touchTap(id: number, x: number, y: number): void;
}

/** Structural proof that the vendored simulator already satisfies the interface. */
const _padSimIsASimEngine: (s: PadSim) => SimEngine = (s) => s;
void _padSimIsASimEngine;

export async function createEngine(
  entry: CatalogEntry,
  knobs?: Readonly<Record<string, number>>,
): Promise<SimEngine>;
```

`createEngine`:

- `entry.preview === "padsim"` -> build a `PadSim` **synchronously inside the async function** from
  `presetById(entry.source.presetId).state` (for `kind: "preset"`) or `entry.source.state` (for
  `kind: "state"`). Throw a named error if a preset id does not resolve.
- `entry.preview === "lua"` -> `const { createLuaPadSim } = await import("./lua-pad-sim");` and
  delegate. **Dynamic, never static.** A static import would put wasmoon in the chunk of every
  consumer of `engine.ts`, and plan 08-07's e2e asserts a cold catalog load fetches no WASM.
- `knobs` defaults to `entry.defaults`. For a `padsim` entry it is ignored (Phase 5 owns compiler
  knobs); say so in a comment rather than silently dropping it.

The `_padSimIsASimEngine` line is a compile-time assertion, not decoration: if a future vendored
re-sync renames `pendingTouches`, `npm run check` names this line instead of Phase 4 discovering it
in a browser.

**2. `src/lib/sim/lua-pad-sim.ts`.**

```ts
export class LuaPadSim implements SimEngine { ... }
export function createLuaPadSim(
  entry: CatalogEntry,
  knobs?: Readonly<Record<string, number>>,
): Promise<LuaPadSim>;
export function renderLua(
  entry: CatalogEntry,
  knobs?: Readonly<Record<string, number>>,
): { setup: string; timer: string };
```

`renderLua` is the token substitution (D-12): for each knob, replace every occurrence of
`knob.token` with `knob.values[index]` in both event strings, where `index` comes from `knobs`
falling back to `entry.defaults` falling back to `knob.default`. It is a pure function with no VM and
no await, exported from here because plan 08-04's budget gate calls it thousands of times and must
not spin up a VM to do so. Use `String.prototype.replaceAll` with a plain string needle - never a
regex, because a token is user data and a regex would make `@` a metacharacter question.

`createLuaPadSim` builds the blank fully-detached `PadSim`:

```ts
const blank: PadState = { ...DEFAULT_PAD_STATE, owned: { /* every slot: "user" */ } };
```

Enumerate the slots from `_pad.ts`'s `PadSlot` / `PadOwnership` rather than from memory, then
`createLuaHost({ sim: new PadSim(blank), setup, timer })`.

`LuaPadSim`'s members map straight onto the host:

- `tick` / `run` -> the host's, which owns the pop-timer-ledTick order.
- `frame` / `coordMax` / `pendingTouches` -> the host's.
- `animating` -> `sim.animating || host.timerArmed`. An entry with a stored Timer never settles,
  which is correct - `SimHost` uses `animating` to decide whether to keep the rAF loop running.
  MORPH has no Timer at all, so its trails expire and it settles, which is also correct. Comment
  both halves; this is the field a reviewer will most want explained.
- `reset()` -> rebuild the VM and re-run Setup. Because `LuaHost.create` is async and `reset` is
  sync in `SimEngine`, implement `reset()` as "reset the wrapped `PadSim` and re-run Setup in the
  existing VM" (the VM is already loaded by construction, so no await is needed). If that turns out
  not to restore a clean VM global table, say so in the SUMMARY and make `reset()` throw a named
  error rather than silently half-resetting.
- `touchDown/Move/Up/Tap` -> the host's FIFO, not the wrapped sim's.
- `close()` -> expose it beyond `SimEngine` so a test can release the VM; Phase 4 will need it when a
  card leaves the DOM.
