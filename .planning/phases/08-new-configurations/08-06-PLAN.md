### LATTICE - "the whole pad is one instrument, tuned in fourths"

Setup, canonical, 615 characters:

```
--[[@cb]]self.m={0,2,4,5,7,9,11}self.n={}self.p={}self.t={}for i=0,80 do local a=glag(0,i)local n=36+i%9+(8-i//9)*5 self.n[i]=n local p=(n-36)%12 local q=0 for j=1,7 do if self.m[j]==p then q=1 end end if p==0 then glc(a,2,255,180,60,1)elseif q>0 then glc(a,2,0,90,160,1)else glc(a,2,0,25,50,1)end glp(a,2,255)glc(a,1,255,255,255,1)glp(a,1,0)end self.touch_cb=function(s,i,e,x,y)s.t[i]=0 local c=x*9//128+y*9//128*9 if e==3 or e>=5 then c=nil end local o=s.p[i]if o~=c then if o then s:gms(0,128,s.n[o],0,0)glp(glag(0,o),1,0)end if c then s:gms(0,144,s.n[c],100,0)glp(glag(0,c),1,255)end s.p[i]=c end end gtt(0,100)
```

Timer, canonical, 171 characters (a per-contact watchdog):

```
--[[@cb]]gtt(0,100)local s=self for i,c in pairs(s.p)do local t=(s.t[i]or 0)+1 s.t[i]=t if t>20 then s:gms(0,128,s.n[c],0,0)glp(glag(0,c),1,0)s.p[i]=nil s.t[i]=nil end end
```

Verified substitutions:

| Needle | Replacement |
|---|---|
| `self.m={0,2,4,5,7,9,11}` | `self.m={@SCALE}` |
| `local n=36+i%9+(8-i//9)*5` | `local n=@BASE+i%9+(8-i//9)*@ROW` |
| `local p=(n-36)%12` | `local p=(n-@BASE)%12` |
| `glc(a,2,255,180,60,1)` | `glc(a,2,@ROOTC,1)` |
| `s:gms(0,128,s.n[o],0,0)` | `s:gms(@CH,128,s.n[o],0,0)` |
| `s:gms(0,144,s.n[c],100,0)` | `s:gms(@CH,144,s.n[c],@VEL,0)` |
| `s:gms(0,128,s.n[c],0,0)` | `s:gms(@CH,128,s.n[c],0,0)` |

`@BASE` occurs **twice** in the Setup and both must be substituted - the note table and the
scale-degree test have to agree or the highlight map lights the wrong cells. The last two rows again
look alike and are not: `s.n[o]` is the Setup's note-off for the previous cell, `s.n[c]` is the
Timer's watchdog note-off.

Six knobs: `scale`/`scale`/`@SCALE`, `base`/`note`/`@BASE`, `rowInterval`/`size`/`@ROW`,
`rootColour`/`colour`/`@ROOTC`, `velocity`/`amount`/`@VEL`, `channel`/`amount`/`@CH`. Defaults
`0,2,4,5,7,9,11`, `36`, `5`, `255,180,60`, `100`, `0`. `@ROW` is the row interval that makes the
layout what it is: `5` is fourths (the LinnStrument / Push / guitar tuning), `3` minor thirds, `4`
major thirds, `2` whole-tone. Offer those four.

Metadata: `restsBlack: false` - all 81 cells are lit on layer 2 at phase 255 from Setup, including
the deliberately dim out-of-scale cells. Name `LATTICE`, tags along the lines of `["isomorphic", "playable", "still", "instrument"]`,
`featured: true`, `addedAt: "2026-09-04"`. Measured behaviour: the bottom-left cell, one column
right, and one row up produce `36, 37, 42` - one semitone across, a perfect fourth up. The honest
limit for the copy: two fingers in the same cell clear the light when the first leaves, though the
note stays correct - the same known limitation as the shipped Nine pads card, because the repaint
keys on the cell rather than on a per-cell contact count.

### MORPH - "four macros in the corners, one finger between them"

Setup, canonical, 507 characters:

```
--[[@cb]]for a=0,80 do glc(a,2,180,255,255,1)glp(a,2,0)end self.k={0,7,63,70}for j=0,3 do for d=0,3 do local a=glag(0,self.k[j+1]+d%2+d//2*9)glc(a,1,255-j*60,j*60,128,1)glp(a,1,0)end end self.touch_cb=function(s,i,e,x,y)if i>0 or e==3 or e>=5 then return end local u=127-x local v=127-y local w={u*v//127,x*v//127,u*y//127,x*y//127}for j=1,4 do s:gms(0,176,15+j,w[j],0)local b=s.k[j]for d=0,3 do glp(glag(0,b+d%2+d//2*9),1,w[j]*2)end end local a=glag(0,x*9//128+y*9//128*9)glpfs(a,2,255,250,0)glt(a,2,42)end
```

Timer: **none.** Store `timer: ""`.

Verified substitutions:

| Needle | Replacement |
|---|---|
| `glc(a,2,180,255,255,1)` | `glc(a,2,@TRAILC,1)` |
| `glc(a,1,255-j*60,j*60,128,1)` | `glc(a,1,255-j*@SPREAD,j*@SPREAD,128,1)` |
| `s:gms(0,176,15+j,w[j],0)` | `s:gms(@CH,176,@CCB+j,w[j],0)` |
| `glt(a,2,42)` | `glt(a,2,@TRAIL)` |

`@SPREAD` occurs **twice** in the corner-colour expression and both must be substituted, or the four
corners stop being four distinct hues. It is the arithmetic hue derivation - `255-j*60, j*60, 128` -
which is why four coloured corners cost nothing.

Five knobs: `trailColour`/`colour`/`@TRAILC`, `hueSpread`/**`amount`**/`@SPREAD`,
`ccBase`/`amount`/`@CCB`, `trail`/`size`/`@TRAIL`, `channel`/`amount`/`@CH`.

Two knob-kind choices worth writing into the entry's comment rather than leaving to be re-argued:

- `hueSpread` is **`amount`, not `colour`.** Its value is a single scalar (the `60` in
  `255-j*60, j*60, 128`) that widens the arithmetic spread between the four corner hues. A `colour`
  widget renders a colour picker and would be handed a bare number it cannot show; `amount` is the
  kind for "a scalar with a range", which is exactly what this is. `@TRAILC` is a real RGB triple
  and stays `colour`.
- **MIDI channel and CC number are `amount` deliberately.** The vendored `KnobKind` union has no
  MIDI-destination kind - its `note` is a pitch and its `mode`, `bend` and `spring` are named
  switches - and D-12 forbids inventing a Lua-specific kind. `amount` is the closest honest fit: a
  bounded integer chosen from a list. If Phase 5 finds it wants a distinct widget for a MIDI
  destination, that is a `KnobKind` addition in BOTOR and a re-sync, not a HANGAR-local union.
  Every `@CH` and `@CC` knob in this phase uses `amount` for that reason; say it once, here. Defaults
`180,255,255`, `60`, `15`, `42`, `0`. `@CCB` is the base of four consecutive CCs (`@CCB+j` for
`j` in 1..4), so keep every value at or below 110 - four consecutive numbers must stay under 127.
Assert nothing about that in a spec; choose the values so it is true, and say so in a comment.

Metadata: **`restsBlack: true`** - the four corner blocks are coloured at Setup but left at phase 0,
and MORPH has no Timer, so with no finger on the pad it is black forever. That is the design: its
only animation is a per-touch decay. Name `MORPH`, tags along the lines of `["macros", "blend", "readable", "expressive"]`,
`featured: true`, `addedAt: "2026-09-04"`. Measured behaviour: dead centre produces weights
`31,31,31,32` (sum 125, two units of floor loss, invisible), the top-left corner produces
`127,0,0,0`. The honest limit for the copy: single-contact by design, because four fingers fighting
over one blend is noise.

**Write the no-Timer reasoning into the entry comment**, in these terms: MORPH's only animation is a
per-touch decay, which is self-limiting, so its Timer is genuinely empty and that is the right
answer. Adding the standard keeper `for a=0,80 do glt(a,L,65535) end` to a layer whose cells are
handed `glpfs(a,L,255,250,0)` + `glt(a,L,42)` replaces the 42-tick countdown with 65535, the rate 250
keeps decrementing past zero and wraps, and every touched cell strobes forever. The smoke gate's
pitfall-1 guard would catch it; the comment is so nobody writes it in the first place.

### SONAR - "a radial 16-step sequencer, five voices deep"

Setup, canonical, 432 characters:

```
--[[@cb]]self.a={}self.o={}self.v={}local t={0,3,5,7,10}for n=0,80 do local c=glag(0,n)glc(c,1,255,60,120,1)glp(c,1,0)glc(c,2,120,255,255,1)glp(c,2,0)self.a[n]=(math.atan(n//9-4,n%9-4)*41//1%256)//16 local d=math.max(math.abs(n%9-4),math.abs(n//9-4))self.o[n]=36+t[d+1]end self.touch_cb=function(s,i,e,x,y)if e~=4 and e~=9 then return end local n=x*9//128+y*9//128*9 s.v[n]=not s.v[n]glp(glag(0,n),1,s.v[n]and 255 or 0)end gtt(0,70)
```

Timer, **canonical, 279 characters** - note `if s.v[n]then` with no space, which is what the
minifier produces and what the research document prints incorrectly as `if s.v[n] then`:

```
--[[@cb]]gtt(0,70)local s=self local k=(s.k or 0)%16 s.k=k+1 if s.z then for j=1,#s.z do s:gms(0,128,s.z[j],0,0)end end s.z={}for n=0,80 do if s.a[n]==k then local a=glag(0,n)glpfs(a,2,255,250,0)glt(a,2,42)if s.v[n]then local m=s.o[n]s:gms(0,144,m,100,0)s.z[#s.z+1]=m end end end
```

Verified substitutions:

| Needle | Replacement |
|---|---|
| `local t={0,3,5,7,10}` | `local t={@RINGS}` |
| `self.o[n]=36+t[d+1]` | `self.o[n]=@ROOT+t[d+1]` |
| `glc(c,2,120,255,255,1)` | `glc(c,2,@SWEEPC,1)` |
| `gtt(0,70)` | `gtt(0,@SWEEP)` |
| `s:gms(0,128,s.z[j],0,0)` | `s:gms(@CH,128,s.z[j],0,0)` |
| `s:gms(0,144,m,100,0)` | `s:gms(@CH,144,m,100,0)` |

`gtt(0,70)` occurs once in each event and both must be substituted, or the Setup arms one period and
the Timer re-arms another.

Five knobs: `rings`/`scale`/`@RINGS`, `root`/`note`/`@ROOT`, `sweepColour`/`colour`/`@SWEEPC`,
`sweep`/`speed`/`@SWEEP`, `channel`/`amount`/`@CH`. Defaults `0,3,5,7,10`, `36`, `120,255,255`,
`70`, `0`. `@RINGS` is a five-entry table because there are exactly five Chebyshev rings on a 9x9
grid - the default is minor pentatonic. Every value must have five entries.

Metadata: `restsBlack: false` - the pad is dark at tick 0 and the sweep lights a column of cells on
its first fire at 70 ms, well inside the sampled ticks, so only tick 0 is black and the entry does
not rest black. Name `SONAR`, tags along the lines of `["radial", "sequencer", "polar", "hypnotic"]`,
`featured: false`, `addedAt: "2026-09-04"`. Measured behaviour: arming the top-left corner (ring 4)
and running two revolutions fires exactly two note-ons, both `note 46` = the pentatonic top; pending
note-offs are tracked and cleared on the following tick, so nothing hangs. The honest limit for the
copy: cells on the same ring share a pitch, which is the point - ring is voice, angle is time.

**SONAR is the entry whose smoke-test gesture matters most.** Its Timer sends MIDI only for armed
cells, so the wave-4 smoke test's "every entry produced at least one MIDI message" assertion is only
satisfied if the scripted tap lands on a cell and the sweep then crosses it within the 200 ticks. At
70 ms per step and 16 steps, one revolution is 1.12 s = 112 ticks, so 200 ticks is comfortably more
than one revolution. If it still produces none, the tap did not land - **fix the gesture in
`lua-smoke.spec.ts`, and say in the SUMMARY that you did**, because that is the one spec edit this
plan may legitimately need and it must not happen silently.
