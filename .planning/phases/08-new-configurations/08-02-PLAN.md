Two facts about `pokeLayer` that shape the stubs:

- It runs `wrapU8` on `pha`/`fre`/`sha` and `wrapU16` on `timeout`, and **`wrapU8` throws on a
  non-integer**: `non-integer value ${v} reached a uint8 narrowing`. So the F2Ieq rule must be
  applied in the stub, before the call. If you forget, you get a throw where firmware would silently
  store 0 - a loud failure, but the wrong behaviour.
- It does not touch `min`/`mid`/`max` unless the patch names them, so `glp`, `glf`, `gls`, `glt` and
  `glpfs` are pure partial writes and `glf` is genuinely rate-only (no phase reset). That is what
  makes ARC's accelerating swirl work.

**The blank, fully detached PadSim** the host wraps (plan 08-03 constructs it; the host takes one as
a constructor argument so this plan can unit-test the stubs directly). Build it from
`DEFAULT_PAD_STATE` with every slot detached:

```ts
{ ...DEFAULT_PAD_STATE,
  owned: { touchHandler: "user", timer: "user", layer1: "user", layer2: "user" } }
```

With every slot `"user"`, `rebuild` arms nothing, `timerPeriod` stays `null` and `runTimerBody`
never fires - so `tick()` degenerates to exactly "pop a touch sample, then `grid_led_tick`", which is
what the host wants. Read `PadSlot` / `PadOwnership` from `_pad.ts` for the real slot names rather
than trusting the four above; assert in the spec that the constructed sim's `animating` is `false`
before the host writes anything.

**The Grid API surface the ten candidates actually call** (this is the complete list; anything else
must fail as a Lua "attempt to call a nil value", never as a silent no-op):

| Lua | Firmware meaning | Host implementation |
|---|---|---|
| `glag(0, n)` | `led_address_get` - logical n to HARDWARE index | `screenToHw(n % 9, Math.floor(n / 9))` |
| `glc(a, L, r, g, b, k)` | `led_color` | `pokeLayer(a, L, glcStops(u8(r), u8(g), u8(b), k !== 0))` |
| `glp(a, L, pha)` | `led_value` | `pokeLayer(a, L, { pha: f2i(pha) })` |
| `glf(a, L, fre)` | `led_animation_rate`, rate only | `pokeLayer(a, L, { fre: f2i(fre) })` |
| `gls(a, L, sha)` | `led_animation_type` | `pokeLayer(a, L, { sha: f2i(sha) })` |
| `glt(a, L, t)` | `led_timeout` | `pokeLayer(a, L, { timeout: f2i(t) })` |
| `glpfs(a, L, p, f, s)` | `led_animation_phase_rate_type` | one `pokeLayer` with all three |
| `glim(v, lo, hi)` | `limit` | clamp, integers |
| `gtt(slot, ms)` | `timer_start` | arm the host deadline for the stored Timer event |
| `self:gms(ch, cmd, p1, p2, mode)` | `midi_send` | record `{ch, cmd, p1, p2, mode}` in order |
| `self:grxm(slot, mode)` | `rx_mode` | record the mode; no behaviour in the host |
| `self:txma(v)` / `self:tyma(v)` | `touch_x_max` / `touch_y_max` | set the host's `coordMax` |

`gms`'s signature is confirmed from the recipe book (`zona-docs/docs/ZONA_RECIPES.md:1058`):
`self:gms(ch, cmd, p1, p2, mode)` - **the first argument is the channel**, zero-based. Do not
re-derive it.

`f2i(v)` is the F2Ieq rule: `Number.isInteger(v) ? v : 0`. `u8(v)` is the colour rule:
`((Math.trunc(v) % 256) + 256) % 256` - firmware truncates a colour channel to uint8 rather than
clamping it, so 260 becomes 4 and a bright cell turns almost black with no warning.

**1. `src/lib/sim/ready.ts`** - the second gate.

```ts
import type { LuaEngine, LuaFactory } from "wasmoon";

// A TYPE-ONLY re-export. It is erased at build time and creates no runtime edge,
// so lua-host.ts can be typed without naming the package and the lazy-chunk
// guard in plan 08-07 stays a one-module rule rather than a two-module one.
export type { LuaEngine, LuaFactory };

let gate: Promise<LuaFactory> | undefined;

/** Resolves the Lua VM factory. Memoised: every caller awaits one WASM load. */
export function luaReady(): Promise<LuaFactory> {
  gate ??= (async () => {
    const { LuaFactory: Factory } = await import("wasmoon");
    return new Factory();
```

08-07's "only `ready.ts` names it" guard true without an exemption.

The `import("wasmoon")` is **dynamic**. That is the whole lazy story: a static import would put
wasmoon in whatever chunk imports this module, and plan 08-07's e2e asserts a cold catalog load

```ts
import type { LuaEngine } from "./ready";   // TYPE-ONLY, via ready.ts - see there for why

export type HostMidi = { ch: number; cmd: number; p1: number; p2: number; mode: number };

  get coordMax(): 127 | 1023;
  get pendingTouches(): number;

  close(): void;                  // engine.global.close()
```

Implementation notes, each of which exists because the research found the failure:

- **Globals.** Register `glag`, `glc`, `glp`, `glf`, `gls`, `glt`, `glpfs`, `glim`, `gtt` as Lua
  globals, and build `self` as a Lua table carrying `gms`, `grxm`, `txma`, `tyma` as methods (called
  with `:`, so their first parameter is the table itself). Do **not** register anything the table
  above does not list: an unlisted call must surface as a Lua "attempt to call a nil value" error,
  never as a silent no-op. Say that in a comment.
- **`glag` is not the identity.** `screenToHw(n % 9, Math.floor(n / 9))`. The identity mirrors 40 of
  81 cells and produces a result that looks plausible and is wrong. This is the single biggest trap
  in the phase; give it its own comment citing `pad-sim.ts`'s serpentine note.
- **F2Ieq.** Every numeric argument that reaches a `pokeLayer` field goes through
  `f2i(v) = Number.isInteger(v) ? v : 0` first. `PadSim.pokeLayer` throws on a non-integer, so
  skipping this converts a firmware behaviour into a crash. Colour channels go through
  `u8(v) = ((Math.trunc(v) % 256) + 256) % 256` instead - firmware truncates colours, it does not
  clamp them.
- **The touch FIFO.** The host keeps its own, mirroring `PadSim`'s: a per-contact change gate on
  `(x, y, event)`, a 10-deep cap, and **at most one sample popped per tick**. Do not delegate to
  `PadSim`'s FIFO: the sim's FIFO feeds its own compiled handlers, which are all detached here.
  Firmware event codes, as `pad-sim.ts` documents them: `1` MOVE, `4` DOWN, `5` UP, `9` DOWNUP (the
  fast tap, one message with no separate DOWN or UP). The compiled guards read "contact ended" as
  `e == 3 or e >= 5`, so a config that filters on `e ~= 4 and e ~= 9` is tap-only and one that
  filters on `e == 3 or e >= 5` is lift-only; both appear in the candidates.
- **The Timer body is compiled ONCE, at `LuaHost.create`, and invoked as a cached Lua function.**
  Do not `doString` the Timer text per tick. A configuration's Timer runs at 100 Hz and the smoke
  gate runs 200 ticks per entry across seven entries; re-parsing several hundred characters of Lua
  on every one of those would put the Lua parser, not the simulation, at the top of the profile, and
