<objective>
Make the coverflow able to hold one entry, and stop the tuner closing an engine somebody else is
painting.

Wave 4. Two changes to signed-off components, both small, both deliberate, both recorded.

**The row prop.** `slots.ts` was read at `count = 1` and is well defined there:
`visibleWindow(c, r, 1)` is `[0]`, `step(0, ±1, 1)` is `0`, `slotOffset(0, 0, 1)` is `0`. So a
one-entry ring renders as a hero at slot 0 and stepping is a no-op — which is exactly what an off-row
configuration's page should be (W-09). Every downstream component (`NamePlate`, `FidelityLine`,
`ChosenPanel`, `TuningRegion`, `CopyLink`, `TryOnDevice`) already takes a `FrontDoorEntry` and needs
no change at all, because `ListingEntry` is a `FrontDoorEntry` with more fields.

**What must not happen:** `/c/aurora/` must not change. D-04 keeps the row's curation untouched, so
the default stays `FRONT_DOOR` and the eight-pad ring on the front door and on every row entry's page
is byte-for-byte the behaviour Phase 4 signed off.

**The ownership bug (D-18), which is a visible failure and not a tidiness point.** `buildTuner`'s
`destroy()` ends in `closeEngine(engine)` — and `engine` is always the one it handed to the consumer
through `onpreview`. `swapEngine` already says the right thing in its own comment ("after the
handover, never before") and closes the *previous* engine only. `destroy()` contradicts it. Today
that is harmless because no Lua entry sits in `FRONT_DOOR`, so the closed engine is a `PadSim` whose
`close` does not exist. From plan 05.1-05 onward `/c/euclid/` exists, its row is EUCLID alone, and
un-choosing would **close the Lua VM behind the only pad on the page and blank it**. The rule this
plan lands: *ownership of an engine transfers at `onpreview`; `destroy()` closes only an engine the
consumer has never been given.*

Purpose: CAT-03's detail view for the eight configurations that have never had one.
Output: two widened component props, one ownership fix, one new test.
</objective>

**The ownership fix in `src/lib/tune/model.ts`:**

```typescript
/**
 * The engine most recently handed to the consumer. Ownership transfers at
 * onpreview: from that moment the row holds it in its session engines map and
 * SimHost is painting it, so destroy() closing it would blank a live pad. On a
 * Lua detail page whose row is one entry, that pad is the only one there
 * (05.1-CONTEXT D-18).
 *
 * swapEngine already closes the PREVIOUS engine after the handover, so nothing
 * leaks: at most one live engine per tuner, and it is the one the row is using.
 */
let published: SimEngine | undefined;

function swapEngine(next: SimEngine): void {
  const previous = engine;
  engine = next;
  options.onpreview(next);
  published = next;
  if (previous !== next) closeEngine(previous);
}

// … in destroy():
destroyed = true;
if (typeof pending !== "undefined") clearTimeout(pending);
pending = undefined;
// Only an engine the consumer has never seen. See `published`.
if (engine !== published) closeEngine(engine);
engine = undefined;
```

`TuningRegion.svelte`'s `if (!mounted) { built.destroy(); return; }` branch is covered by the same
rule and needs no edit.
