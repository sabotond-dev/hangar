**1. [Rule 1 - Bug] `config-shape.spec.ts` test 14 could not see the mutation it exists to catch**

- **Found during:** Task 3, running the plan's own test-14 negative check
- **Issue:** The plan predicted that a static `import { CATALOG } from "$lib/catalog"` in
  `src/routes/c/[id]/+page.svelte` would make test 14 name `build/c/euclid/index.html` as referencing
  the protocol chunk. **It did not. The test stayed green (14 passed) with the mutation built into the
  artefact** — `x-catalog-count` was verifiably in `build/c/euclid/index.html`. The chunk really was
  in the page's static graph: `_app/immutable/nodes/3.*.js` → `chunks/C4ys7kig.js` →
  `chunks/BFIKf6sX.js` → `chunks/C1rLf53t.js` (the chunk containing
  `GRID_PARAMETER_ELEMENT_POTMETER`), every edge a real `import ... from` statement. Test 14 asked
  only whether the page's HTML **named** a carrying chunk, and Kit's `<head>` preloads eleven modules
  — none of the three new ones was among them. Test 13 was blind to it as well: `COMPILER_MARKERS` is
  `["vendor", "intechstudio", "lib/pad"]` matched against specifier **text**, and `$lib/catalog`
  contains none of the three. So the exact class of regression this plan could introduce had **no**
  gate anywhere.
- **Fix:** test 14 now walks each page's **transitive static import graph** — the modules named in the
  HTML, then every relative `.js` specifier reachable from them through `import`/`export ... from`.
  Dynamic imports stay invisible by construction: Vite emits them as `__mapDeps` string tables, never
  as import statements, which is why `Coverflow.svelte`'s `await import()` of the simulator does not
  trip it. A per-page `edges` counter is asserted `> 0`, so a matcher that silently stopped matching
  goes red rather than reporting a clean graph for a page that pulls the world. Test count still 14;
  nothing else in the file moved.
