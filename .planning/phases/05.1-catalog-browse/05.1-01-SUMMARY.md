## Task 2 - `listing.ts`

326 lines. **The records were generated, not retyped.** The scratch script (kept out of the
repository, run from the scratchpad) is:

```javascript
// dump-catalog.mjs - the fields, straight out of CATALOG, plus the frames evidence.
const server = await createServer({ configFile: join(ROOT, "vite.config.ts"), root: ROOT,
  server: { middlewareMode: true }, appType: "custom", logLevel: "warn" });
const { CATALOG } = await server.ssrLoadModule("/src/lib/catalog/index.ts");
const { FRONT_DOOR, EXCLUDED_FROM_ROW } = await server.ssrLoadModule("/src/lib/catalog/front-door.ts");
const frames = JSON.parse(readFileSync(join(ROOT, "src/lib/catalog/frames.json"), "utf8"));
const rows = CATALOG.map((e) => {
  const records = frames.entries[e.id] ?? [];
  const anyAnimating = records.some((r) => r.animating);
  const anyLit = records.some((r) => r.nonZeroBytes > 0);
  const motion = e.restsBlack ? "dark" : anyAnimating ? "animated" : anyLit ? "static" : "dark";
  const front = FRONT_DOOR.find((f) => f.id === e.id);
  return { id: e.id, name: e.name, description: e.description, tags: e.tags, featured: e.featured,
    addedAt: e.addedAt, restsBlack: e.restsBlack, preview: e.preview, motion,
    naiveMotion: anyAnimating ? "animated" : anyLit ? "static" : "dark",
    inRow: front !== undefined, frontQuiet: front ? front.quiet : undefined };
});
```

A second script (`gen-records.mjs`) turned that JSON into the `LISTING` array body with
`JSON.stringify` per field, so every description reached the file as bytes rather than as typing;
Prettier then formatted it. Precedent for loading a TypeScript module from a plain `.mjs`:
`scripts/gen-og.mjs`.

## Decisions Made

1. **`ListingEntry` carries `preview`.** The plan's interfaces block lists seven fields; D-12 names
   eight, and `preview` is the one that decides whether a card mounts the Lua VM. It is gated in test
   1 with every other field, so it cannot drift either.
2. **`PreviewMotion` is re-exported bare** (`export type { PreviewMotion };`), not as
   `export type { PreviewMotion } from "./front-door";`. The second form would put a second specifier
   in the file, and test 5's rule is "every specifier sits on an `import type` line" - an
   `export ... from` is erased too, but admitting it would weaken a rule that is currently absolute.
3. **Test 3 compares `quiet` for every front-door id**, not only the non-animated ones. That is what
   the plan's wording asks for, and it has a real consequence: Dial is animated and still carries the
   shelf's usage hint, so the listing must carry it too or the two files drift.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The scratch dump script could not resolve `vite` from the scratchpad**

- **Found during:** Task 2 (generating the records)
- **Issue:** The plan requires the scratch script to live outside the repository. A file under the
  scratchpad has no `node_modules` above it, so `import { createServer } from "vite"` failed with
  `ERR_MODULE_NOT_FOUND` and the dump was empty.
- **Fix:** Imported Vite by absolute file URL from the repository's own `node_modules`
  (`file:///…/hangar/node_modules/vite/dist/node/index.js`). No install, no repo file.
- **Verification:** The script printed all sixteen records; `LISTING.length = 16` with sixteen unique
  ids.
- **Committed in:** nothing - the script is scratch and stays out of the tree.

**2. [Rule 1 - Bug] The dump's stdout carried one line of foreign output**

- **Found during:** Task 2
- **Issue:** Loading the catalog through Vite prints `HEARTBEAT_INTERVAL 250000 250` from a module
  the graph pulls in, so the redirected JSON did not parse.
- **Fix:** Dropped the first line before parsing (`tail -n +2`). The alternative - writing the JSON
  with `writeFileSync` instead of to stdout - would have been equally fine; this was one command.
- **Verification:** `catalog.clean.json` parses; `count 16`.
- **Committed in:** nothing - scratch only.

**3. [Rule 3 - Blocking] `PreviewMotion` was imported but unused**

- **Found during:** Task 2
- **Issue:** The plan's interfaces block imports `FrontDoorEntry` **and** `PreviewMotion`, but the
  records only need the first. `svelte-check` tolerated it; ESLint would not, and an import that
  exists for a document rather than for the code is a smell.
- **Fix:** Re-exported it (`export type { PreviewMotion };`) so the name is used and a browse
  component can read the motion union from the module it already imports.
- **Verification:** `npx eslint src/lib/catalog/listing.ts` exits 0; `npm run check` 0 errors; test 5
  still collects exactly one specifier.
- **Committed in:** `1eff748`
