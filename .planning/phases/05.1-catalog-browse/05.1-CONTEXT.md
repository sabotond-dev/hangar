# Phase 5.1: Catalog Browse — Context

**Gathered:** 2026-09-04, unattended (the user said "proceed" on the roadmap order). Sources: the
user's design brief (the coverflow is ONLY the front door; "after that the catalog will be much more
sophisticated"), the kickoff decisions (sort by Featured / Newest / Name, no popularity metrics; feel
tags; a focus view per configuration), the project feature research (D2 search, D3 tag chips, D4
sort, D5 focus view), and what Phases 4, 5 and 8 shipped. [user] decisions are the user's;
[orchestrator] ones were taken without the user and are open to veto.

## Phase boundary

Phase 5.1 adds the browse screen behind the front door: every configuration, sortable, searchable
and filterable by tag, opening into the existing chosen-pad state and returning without losing
position. It does not change the coverflow's curation, does not install (Phase 7), and adds no
accounts or backend.

## Decisions

### What the visitor sees
- **D-01 [user]** The whole collection: name, one-line description, feel-based tags, Featured flag.
  The coverflow's data file (`src/lib/catalog/`, CATALOG) is the only source.
- **D-02 [user]** Sort by Featured, Newest and Name. No popularity metric is shown or faked.
- **D-03 [user]** Any configuration opens into its focus/detail view — the chosen-pad state from
  Phase 4 with the knobs and meters Phase 5 docked and the install controls Phase 7 will dock — and
  the visitor returns to browse without losing position.
- **D-04 [orchestrator]** Route `/browse/`, prerendered, reached from the front door by one quiet
  control (`BROWSE ALL`, uppercase button vocabulary) beneath the name plate or in the header, and
  from every `/c/<id>/` page. The coverflow stays the front door; the row's curation is untouched.
- **D-05 [orchestrator]** Free-text search over name, description and tags (feature research D2;
  no `$` power syntax) and tag chips that filter on click and are individually removable (D3).
  Sort, query and active tags live in `/browse/`'s query string (`?sort=&q=&tag=`) so a browse
  state is linkable — the query-string ban applies to the tuning stamp only, which stays in the
  hash on `/c/<id>/`.
- **D-06 [orchestrator]** Cards are the pad motif again — the pad is the card — each a live 9×9
  canvas hosted by the Phase 4 `SimHost` (paint at the side-pad rate, IntersectionObserver gating,
  `prefers-reduced-motion` stills at tick 64), with the name plate beneath and the description and
  tags in quiet text. Sixteen cards on one page is the STACK research's design case (offscreen
  cards cost nothing). Lua-sourced cards mount the Lua engine lazily on first intersection; the
  front-door laziness guard (a cold `/` fetches no WebAssembly) is unaffected and `/browse/` gets
  its own guard: a cold `/browse/` with no Lua card in view fetches no WebAssembly.
- **D-07 [orchestrator]** The SEVEN Lua-sourced entries (EXCLUDED_FROM_ROW is tpad plus seven; sixteen entries in all) become reachable here for the first time.
  They get real `/c/<id>/` pages: Phase 4's `entries()` widens from the front-door row to the whole
  CATALOG, and the Open Graph generator covers all sixteen. `EXCLUDED_FROM_ROW` keeps the
  coverflow curated; the row is unchanged.
- **D-08 [orchestrator]** Returning from a detail view restores the browse scroll position, sort,
  query and tags: the `/c/<id>/` page reached from browse carries a back control (`BACK TO BROWSE`)
  that navigates to the recorded browse URL, and the browse page restores scroll from history state.
- **D-09 [orchestrator]** Identity: true black, lime and its ladder, `--color-over` only where
  Phase 5 scoped it; Quicksand at Phase 4's four sizes; the 9×9 outline as frame; no third colour;
  no emojis or exclamation marks; keyboard-operable grid (arrow keys move focus between cards,
  Enter opens), visible focus, cards labelled by name.
- **D-10 [orchestrator]** Newest is by `addedAt` (already on every entry); Featured sorts featured
  first then Newest; Name is locale-aware A→Z. The default sort is Featured.
- **D-11 [orchestrator]** Quiet and resting-black entries show their real static picture with the
  Phase 4 fidelity wording; motion is never faked; tpad is browsable here (it has an entry) but
  keeps no `/c/` page? — NO: D-07 gives every entry a page, tpad included; its page renders the
  all-black pad honestly with the quiet note.

### Added after research (2026-09-04) **[orchestrator]**
- **D-10 amended:** sorts follow the shipped comparators in `src/lib/catalog/index.ts` — Featured is
  featured-first then Name (`byFeatured`), Name uses the codebase's deterministic comparator (its
  own comment forbids `localeCompare`), Newest is `addedAt` descending with Name as the explicit
  tiebreak (only two distinct `addedAt` values exist). No sort may be unstable.
- **D-12:** The browse page never imports `$lib/catalog` statically — `entries/ported.ts` is the one
  runtime edge to the vendored compiler. A new import-free `src/lib/catalog/listing.ts` carries the
  sixteen entries' browse data (id, name, description, tags, featured, addedAt, restsBlack, preview)
  gated against CATALOG and `frames.json` — the fourth use of the `front-door.ts` pattern — and it is
  what `entries()`, `scripts/gen-og.mjs` and `og/build.spec.ts` read.
- **D-13:** D-07 knowingly changes four shipped gates, each edited deliberately in the plan that
  widens the routes: `e2e/first-experience.e2e.ts` (asserts `/c/euclid/` is 404 — becomes a page),
  `og/build.spec.ts` (loops FRONT_DOOR — loops the listing), `config-shape.spec.ts` test 13 (its
  markers do not match `$lib/catalog` — add one) and test 14 (scans `/` and `/c/aurora/` — add
  `/browse/`). Every edit is named in a SUMMARY; none is silent.
- **D-14:** A card's motion classification keys on `restsBlack` FIRST (GHOST derives `animated`
  under the shipped rule while lighting nothing at every sampled tick); resting-black cards carry
  the quiet note, never an unexplained black square.
- **D-15:** Tag chips: the nine tags carried by two or more entries are chips; the 32 single-entry
  tags stay searchable text on the card. Active chips INTERSECT. Search folds case and diacritics.
- **D-16:** Browse state is a local rune seeded once from `page.url.searchParams` inside `onMount`
  (SvelteKit's `disable_search()` throws on `searchParams` during prerender; shallow routing never
  updates `page.url`); the URL is a write-only projection via `replaceState(resolve("/browse/?…"), …)`,
  lint-clean. The detail view is `Coverflow` with a one-entry `row` prop (a one-entry ring is already
  well-defined in `slots.ts`).
- **D-17:** Measured, not claimed: all sixteen OG images generate in ~2.2 s end to end, so widening
  `gen-og` costs nothing; sixteen canvases at 20 fps and a still pad surviving a sort on WebKit are
  measurement tasks in the plan, not assertions.
