<objective>
The wall: sixteen live pads in a grid of links, one clock, one tab stop.

Wave 6. Almost nothing here is new machinery, and that is the point — `SimHost`, `PadFrame`,
`PadCanvas`, `createEngine` and `frames.json` already do everything a live card wall needs, and
`src/routes/dev/catalog/+page.svelte` is the working precedent for mounting a Lua card behind a
dynamic import. **Anything that starts to look like new simulator or new canvas machinery is a signal
that the wrong path is being taken.**

Four decisions this plan implements rather than re-opens:

1. **A plain `<ul>` of `<li>` with one real `<a>` each, and a roving tabindex** — not
   `role="listbox"`, not `role="grid"` (W-07). A card is a link to a real prerendered URL, and both
   roles **replace** the link role, which destroys the screen-reader links list, middle-click and
   open-in-new-tab. Roving tabindex buys back the single tab stop a listbox would have given.
2. **A browse card is a picture, not an instrument** (W-15). No touch is delivered to any card's
   engine, at any width, under any pointer. `host.setHero(undefined)`; the cursor is `pointer`, never
   `crosshair`. The instrument is the detail view, where the hero already plays.
3. **All sixteen mount and none is unmounted offscreen** (W-16), with a documented ceiling at roughly
   40 entries. Observer-paused cards cost nothing, and unmounting would restart an engine a visitor is
   about to scroll back to.
4. **Engines are built lazily, per card, on first intersection.** That single line is what keeps a
   visitor who never brings a Lua card into view from downloading the 271 KB VM — and plan 05.1-10's
   e2e is what proves it against the deployed bytes.

**One honest note about what is watching this wave.** Both components land here, but the spec that
scans them — `src/lib/ui/browse-ui.spec.ts` — is written in plan 05.1-08, and the widening of
`config-shape.spec.ts` test 13 that can see `$lib/sim/engine` lands in the same plan. So for two
waves the structural claims in this plan are held by the hand-run comment-stripped scans in its
acceptance criteria and by nothing else; wave 8 is where they become gates, and wave 10 is where the
browser confirms them. That gap is deliberate — writing the spec before the components exist would
mean writing it against imagined markup — and it is the reason every scan here is quoted into the
SUMMARY rather than merely run.

Purpose: CAT-03's "every configuration, running" and CAT-02's rendered order.
Output: two components, no new unit test, and a wall that a keyboard can walk.
</objective>

Five rules that are easy to get wrong:

- **The `FEATURED` band is reserved on every card**, holding the word on the **eight** featured ones
  and nothing on the other **eight**. (Counted from `src/lib/catalog/entries/` on 2026-09-04: ARC,
  CHORUS, EUCLID, LATTICE, MORPH, Aurora, Pinwheel and Nine Pads. `05.1-UI-SPEC.md` § The `FEATURED`
  mark says eight; a plan that said seven and nine would send an executor looking for a ninth
  unfeatured card that does not exist.) That reservation is what keeps sixteen pads aligned across a
  row. It is
  `--color-ink`, **not accent**: accent means "this is the live value" on this site and a curation
  flag is not a value (W-05).
- **Exactly one link per card.** The plate's `<a href={resolve("/c/[id]", { id })}>` carries
  `::after { position: absolute; inset: 0; content: "" }` over a `position: relative` card. The
  accessibility tree contains one link; the tab order gains one stop. `aria-label` is the entry's
  name, verbatim, and `aria-describedby` points at the description element.
- **The pad wrapper is `aria-hidden="true"`** (W-17). `PadCanvas`'s `role="img"` label is right on the
  front door where the pad is the thing; inside a named link it would announce the name a second time
  on every one of sixteen cards.
- **The description is never clamped and never truncated with an ellipsis.** The longest shipped is
  110 characters. A `…` on this site means "this is still happening".
- **The description renders through `typographic()`** from `$lib/browse/typographic` (plan 05.1-02):
  `{typographic(entry.description)}`. This is the second and last render site of the transform — the
  first is `Coverflow.svelte`'s `sr-only` span, wired in plan 05.1-04. It exists for Radar, whose
  sentence is vendored copy that may never be corrected at source (`05.1-UI-SPEC.md` § Data
  corrections; `src/lib/fidelity/vendored-diff.spec.ts`). It is **not** applied to the entry's
  `name`, and it is **not** applied to `quiet` or to `RESTS_DARK_NOTE`, which are HANGAR's own copy
  and are already authored with U+2019.
- **The resting-dark note is `entry.quiet`**, which plan 05.1-01 set to `RESTS_DARK_NOTE` for exactly
  the three dark entries. Do not type the sentence into this component: one string, one source.
- **A card whose engine could not be built** renders the frame and dot field with no canvas and a
  plate reading `{name} — unavailable` in `--color-ink-dim` (real em dash). **The link stays a link**
  — the detail page can still explain, and one broken entry never blanks the grid.

**`BrowseGrid.svelte`** — props and responsibilities.

```svelte
let { entries, onreorder }: {
  /** Already sorted and filtered by the page. This component never sorts. */
  entries: readonly ListingEntry[];
  /** Optional hook so the page can flush its address after a reorder. */
  onreorder?: () => void;
} = $props();
```

- **One `SimHost` for the page**, created in `onMount`, `setHero(undefined)`, destroyed in
  `onDestroy`. Never a second host and never a second rAF loop.
- **Per-card engine building.** `SimHost` exposes no visibility callback, and it is not gaining one:
  the grid keeps its own tiny `IntersectionObserver` for the **build** decision while `SimHost` keeps
  owning the **tick** decision. The two observers answer two different questions. On a card's first
  intersection: `const [{ createEngine }, { byId }] = await Promise.all([import("$lib/sim/engine"),
  import("$lib/catalog")])`, build, and `host.register(id, canvas, engine)` — `register` is right
  here (the canvas has never been registered), `replaceEngine` is not. Skip on throw, exactly as
  `Coverflow` does, and record the id so the card can render the unavailable state.
- **`host.repaintAll()` after any reorder**, in a post-update tick, because a still pad does not tick
  and nothing else would repaint it after its `<li>` moved (Pitfall 10).
- **The keyed `{#each}` is keyed by `entry.id`**, so Svelte moves nodes instead of recreating them and
  a card that is still on screen keeps its engine and its canvas.
- **The roving tabindex.** One state: `rovingIndex`. `tabbable={index === rovingIndex}` per card. A
  `keydown` on the `<ul>` calls `nextIndex(event.key, rovingIndex, entries.length, columns)`; when it
  returns a number, set the index, `preventDefault`, and `.focus()` the new card's anchor; when it
  returns `undefined`, do nothing at all. Skip the handler entirely when any modifier is held, so
  `Alt+Left` still means Back.
- **The column count is read from the layout**, not from a media query:
  `getComputedStyle(list).gridTemplateColumns.split(" ").length`, refreshed on resize (debounced) and
  after a reorder. `columnsForWidth` from `$lib/browse/grid` is the fallback before first layout.
- **When a filter removes the roving card, the index resets to 0 and focus is NOT moved.** Stealing
  focus out of the search field on a keystroke would make the field unusable.
- **Two empty states**, both from the copy contract, both left-aligned in the content column:
  - no result matches — title `Nothing here matches`, the by-condition sentence supplied by the page,
    and `CLEAR FILTERS brings back all {total} configurations.`
  - the catalog itself is empty — Phase 4's two strings **verbatim**: `Nothing on the shelf` and
    `The catalog file has no configurations in it. That is a build problem, not something you did.`
    Reusing them is what keeps a build failure distinguishable from a filter miss.
- **The grid never animates its own layout**: no FLIP, no stagger, no fade-in, 0 ms on a filter change
  (W-11). Animating sixteen live canvases through a reflow fights the shared rAF loop for exactly the
  frames the pads need.

`data-testid`s, from the spec: `browse-grid`, `browse-empty`, `card-{id}`, `card-name-{id}`.
