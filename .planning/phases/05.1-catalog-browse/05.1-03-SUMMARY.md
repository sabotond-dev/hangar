### The address, in both directions

|---|---|

Every one of them round-trips, and the round trip is asserted as a **fixed point** —
`serialise(parse(search)) === search` — as well as `parse(serialise(x)) === x`, because a serialiser
that consumed its input would satisfy the second alone.

Four spellings of the default all parse to `DEFAULT_QUERY`: `""`, `"?"`, `"sort=featured"` and
`"?sort=featured&q="`. That is what makes a plain `/browse/` the canonical entry rather than one
address among several.

### The three rules in the module header, and where they came from

Written into `query.ts` because the page in wave 8 depends on them and a reader must not have to
re-derive them from the framework's source a second time:

1. **This module is never given `page.url` on the server.** `respond.js:433-434` calls
   `disable_search(url)` when prerendering, and `utils/url.js:174-188` then defines `search` and
   `searchParams` as properties that **throw**. `/browse/` is prerendered, so the page reads the
   address only behind a `browser` guard at component-init scope; this module only ever sees a
   `URLSearchParams` somebody already had — which is also why it takes one rather than a URL or a
   string.
2. **The address is written, never read again.** `client.js:2551-2581` (`replaceState`) sets
   `page.state` and never `page.url`; `client.js:2871-2905` (the popstate shallow branch) *does* call
   `update_url`. `page.url` is stale on write and fresh on back — a `$derived` over it would be a
   latent bug pointing in two directions at once.
3. **`replaceState`, never `pushState`.** Sixteen chip presses must not cost sixteen Back presses.

### The fallbacks, and why dropping is not cosmetic

- `?sort=popular` → `featured`. So does `?sort=` and `?sort=NEWEST` (the values are lower case).
- `?tag=nonesuch` → dropped, and it is dropped **in place**: `tag=gestural&tag=nonesuch&tag=hypnotic`
  parses as `["gestural", "hypnotic"]`, and an unknown tag in first position does not shift the rest.
- `?q=  ghost  ` → `ghost`; an inner space survives (`nine drums`); a whitespace-only query is `""`.
- `?sort=name&utm_source=discord&page=3` → `{ sort: "name", q: "", tags: [] }`. Somebody else's
  parameters are ignored rather than rejected.

`filter.ts` deliberately does **not** drop an unknown tag — 05.1-02 recorded that as a decision — so
an unknown tag that survived parsing would **intersect the grid to nothing** and open the page on an
empty catalog. The drop is the difference between a stale link working and a stale link looking
broken.

### The four rules in the module header

- **It is a session store**, so a middle-click into a new tab correctly gets no back control: in a
  new tab there is nothing to go back to and offering it would be a lie.
- **The record is written from the page's own state, not from the address bar.** The browse address
  is projected on a 500 ms trailing timer, so a card clicked 200 ms after a chip toggle would record
  a view one toggle stale. Composing the href from live state at the moment of leaving removes the
  race instead of racing it — which is why `href` is an argument here and this module never reads an
  address of its own.
- **Returning is a `goto`, never a `history.back()`.** `Coverflow.choose()` pushes a history entry,
  so a visitor who arrived from browse and then tapped the pad is two entries deep and a back-by-one
  lands on the un-chosen detail page.
- **The record is consumed on arrival at `/browse/`.** Kit's own back-button restoration already
  targets the offset the record holds, so the two cannot disagree; the record exists for the
  *forward* hop, which gets no restoration at all.

### One apparent conflict between the plan and the UI spec, reconciled rather than hidden

The plan writes the return as `goto(href, { noScroll: true })`; `05.1-UI-SPEC.md` § What "recorded"
means writes it as *"`replaceState` with `noScroll`, so browse → detail → back reads as one round
trip rather than growing the history"*. These are the same call with one more option —
`goto(href, { noScroll: true, replaceState: true })` — not two designs. The module header says so
explicitly and names both, because the one thing they agree on is the thing that matters here:
**neither of them is `history.back()`**. The choice itself belongs to the page in wave 9.

### What "malformed" covers

Thirteen recorded values, each asserted to read as `undefined` **and** asserted not to throw:

`not json` · `{"href":"/browse/",` · `null` · `"/browse/"` · `1847` · `["/browse/",1847]` ·
`{"href":"/browse/"}` · `{"scrollY":1847}` · `{"href":7,"scrollY":1847}` · `{"href":"","scrollY":1847}` ·
`{"href":"/browse/","scrollY":"1847"}` · `{"href":"/browse/","scrollY":null}` ·
`{"href":"/browse/","scrollY":1e999}`

Plus three cases that are not "malformed data" at all and take the same path:

- **An absent key.** The ordinary case; the same answer.
- **A `NaN` written through the typed API.** `JSON.stringify` writes it as `null`, and the shape check
  refuses it on the way back out — so a bad number can never reach a scroll even though the type says
  it cannot happen.
- **A store whose three methods all throw** (`SecurityError`, `QuotaExceededError`): Safari in a
  private window, and a storage over quota. None of the three functions propagates it. This is beyond
  the plan's four behaviours and is recorded as deviation 1 below.

A `scrollY` of **0** is a real record — the visitor was at the top of the catalog — and an **empty**
`href` is refused, because it would render a control that navigates nowhere.

## Decisions Made

1. **`q` is trimmed on parse and not on serialise.** One side owns the normalisation, and it is the
   reading side, because that is the side that feeds the search. The consequence — a state carrying
   untrimmed text writes it verbatim and reads back trimmed — is written into the module header. The
   round trip is a fixed point over *parsed* states, which is the property the page needs.
2. **A repeated `?tag=` is one tag.** The address projects a SET of active chips whose order happens
   to be meaningful; the same chip twice is still one chip, and reproducing it would render a
   duplicate control.
3. **`readBrowseReturn` refuses an empty `href`** as well as a missing one. It is falsy, it would
   render a control that navigates nowhere, and no correct writer produces one.
4. **`DEFAULT_QUERY` is frozen, `tags` included.** It is handed straight back as the seed during
   prerender and on any address with nothing in it, so a caller that mutated it would move the
   default for every later reader.
5. **`repaintAll` was placed after `replaceEngine` in `host.ts`**, because its comment is a
   continuation of that method's — the two exist for the same reason and a reader who finds one
   should find the other.
