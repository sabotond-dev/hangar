<objective>
One control, two labels, one place on the screen.

Wave 9. D-19 is the whole design: *the header's single right-hand slot reads `BROWSE ALL` on the front
door and detail pages, or `BACK TO BROWSE` when a browse return is recorded.* It never moves when a
visitor chooses, it does not compete with the row's own navigation, and it cannot be confused with an
install control.

`BACK TO BROWSE` is a `goto(record.href, { noScroll: true })`, **never** a `history.back()`.
`Coverflow.choose()` does `pushState("", { chosen: true })`, so a visitor who arrived from browse and
then tapped the pad would land on the *un-chosen detail page* with a Back — one entry short, and
short by a different amount depending on what they did. A recorded address is deterministic regardless
of how many entries the detail page collected (Pitfall 8).

Two details that look small and are not:

- **The splash.** The control carries the wordmark's exact `.covered` treatment — `opacity: 0;
  transition: none` while the splash covers the row, then up to 1 across the dissolve on the same
  curve. It must be **absent from the very first painted frame** rather than fading out of one, which
  is the same reason the wordmark's rule exists.
- **The tab order.** `BROWSE ALL` is the **first** tab stop on both routes, before the coverflow
  listbox, because it is site navigation and it is first in the DOM. Nothing else in Phase 4's order
  is reordered.

Purpose: CAT-03's "return to browse without losing position", and D-04's route into the catalog from
everywhere.
Output: one new component and two wiring edits.
</objective>

<interfaces>
**`BrowseLink.svelte`** — one component, two labels, decided at render time.

```svelte
let { covered = false }: {
  /** True while the splash covers the row. The wordmark's own treatment. */
  covered?: boolean;
} = $props();
```

| Condition | Element | Label | Action |
|---|---|---|---|
| On `/browse/` | — | — | not rendered; the page it would lead to is the page you are on |
| A browse return is recorded | `<button>` | `BACK TO BROWSE` | `goto(record.href, { noScroll: true })` |
| Otherwise | `<a href={resolve("/browse/")}>` | `BROWSE ALL` | a plain navigation |

Treatment, following the shipped `DISCONNECT ZONA` precedent exactly: Micro (12px / 600 / 0.18em /
uppercase), `--color-ink-quiet` at rest, `--color-ink` on hover over 160 ms `ease-out`,
`min-block-size: 44px; min-inline-size: 44px; display: grid; place-items: center; padding-inline: 0`,
no border, Phase 4's focus ring. `data-testid="browse-link"`.

**The record is read in the browser only**, after mount — `sessionStorage` does not exist during
prerender, and a prerendered `BACK TO BROWSE` would be a lie in every other visitor's tab. The
prerendered HTML therefore carries `BROWSE ALL`, and the label switches on hydration when a record is
present. Say that in the component's header: it is the reason the control must not be rendered from a
`$derived` over something the server can see.

**Clearing.** The record survives a reload of the detail page — the way back is still there, which is
a virtue — and is cleared when the visitor navigates from the detail route to anything that is not
`/browse/` and not another `/c/` route. Stepping the row with the arrows uses `replaceState` and never
leaves the route, so the record survives stepping, which is correct: the visitor still came from
browse.

**`FrontDoor.svelte`'s header row.** Today the wordmark and the headline are siblings with
`padding-inline: 32px`. The wordmark and the new slot become one flex row carrying that same gutter:

```css
.header {
  display: flex;
  justify-content: space-between;
  align-items: center;
  min-block-size: 44px;
  padding-inline: 32px;   /* 24px below 640px, matching the existing rule */
}
```

The `<h1 class="wordmark">` keeps its `.covered` class and its transition; `BrowseLink` receives the
same `covered` value. The headline's `margin: 48px 0 0` is now measured from the row and does not
change.

**`/c/[id]/+page.svelte`** gains only the record-clearing `afterNavigate` described above. It does not
render the control itself — `FrontDoor` does, on both routes, which is what keeps the two from
drifting apart.
