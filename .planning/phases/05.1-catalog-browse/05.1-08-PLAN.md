<objective>
The route, and the two guards that would otherwise be blind to it.

Wave 8. The page itself is composition: the toolbar from wave 7 over the grid from wave 6, both fed by
the pure modules from waves 2 and 3. What makes this plan load-bearing is everything around it.

**There is no `+page.ts`, deliberately.** `src/routes/+layout.ts` already sets `prerender = true` and
`trailingSlash = "always"` for the whole site, and `vite.config.ts`'s `prerender.entries: ["*"]` picks
up every route with no required dynamic parameter. A `+page.ts` here would buy nothing and could cost
the build: `respond.js:433-434` and `load_data.js:71` call `disable_search(url)` whenever
`state.prerendering`, and `utils/url.js:174-188` makes `url.search` and `url.searchParams` **throw**.
The `05.1-UI-SPEC.md` component inventory names a `+page.ts`; it is not built, and the SUMMARY says so.

**The state is a rune seeded once, and the address is a projection of it.** Read from Kit 2.70.3's own
source in both directions: `client.js:2551-2581` (`replaceState`) sets `page.state` and never
`page.url`, while `client.js:2871-2905` (the popstate shallow branch) *does* call `update_url`. So
`page.url` is stale on write and fresh on back — a `$derived` over it is a bug pointing two ways at
once.

**And the seed happens at component init, not in `onMount`.** `05.1-CONTEXT.md` D-16 says "inside
`onMount`"; the reason D-16 gives is prerender safety and the staleness of shallow routing, and both
are satisfied by an init-scope read behind a `browser` guard. Seeding in `onMount` is not: the first
client render would show all sixteen while the address said `?tag=drums`, so the grid would be tall
at the moment Kit restores scroll and short a frame later, and the visitor lands in the wrong place
(Pitfall 7). The deviation is deliberate, it is one word of mechanism rather than of intent, and it is
recorded here and in the SUMMARY.

**Two guards must widen with the page, and both are load-bearing rather than hygiene.**
`config-shape.spec.ts` test 13's `COMPILER_MARKERS` are `["vendor", "intechstudio", "lib/pad"]` — and
**`$lib/catalog` matches none of them**, so today's source scan would not catch a browse component
importing the whole catalog and shipping 131 KB of protocol on the page. Test 14's artefact scan
covers `build/index.html`, `build/c/aurora/index.html` and (from plan 05.1-05)
`build/c/euclid/index.html`, and cannot see `build/browse/index.html` at all.

Purpose: CAT-02 and CAT-03's screen, and the guards that keep it light.
Output: one route, one lifted constant, two widened guards and six new structural tests.

**The page's state, exactly.**

```svelte
<script lang="ts">
  import { browser } from "$app/environment";
  import { beforeNavigate, replaceState } from "$app/navigation";
  import { resolve } from "$app/paths";
  import { page } from "$app/state";
  import { onMount, untrack } from "svelte";
  import { LISTING } from "$lib/catalog/listing";
  import { allTags, chipTags, disabledTags, filterListing } from "$lib/browse/filter";
  import { DEFAULT_QUERY, parseBrowseQuery, serialiseBrowseQuery } from "$lib/browse/query";
  import { readBrowseReturn, writeBrowseReturn, clearBrowseReturn } from "$lib/browse/return";
  import { sortListing, type BrowseSort } from "$lib/browse/sort";

  const TAGS = allTags(LISTING);
  const CHIPS = chipTags(LISTING);

  // ONCE, at component init, and only in the browser. untrack is the same idiom
  // Coverflow.svelte uses for initialId: capturing only the initial value is
  // exactly what is wanted. Never a $derived over page.url - replaceState does
  // not update it, and reading searchParams during prerender THROWS.
  const seed = () => (browser ? parseBrowseQuery(page.url.searchParams, TAGS) : DEFAULT_QUERY);
  const initial = untrack(seed);

  let sort: BrowseSort = $state(initial.sort);
  let q = $state(initial.q);
  let tags: string[] = $state([...initial.tags]);

  const shown = $derived(sortListing(filterListing(LISTING, q, tags), sort));
</script>
```

**The address, written and never read again.**

```ts
function currentHref(): string {
  const search = serialiseBrowseQuery({ sort, q, tags });
  return search === "" ? "/browse/" : `/browse/?${search}`;
}

function syncAddress(): void {
  if (!mounted) return;                       // replaceState throws before the router is ready
  const search = serialiseBrowseQuery({ sort, q, tags });
  // resolve() accepts a pathname WITH a search string, so this is lint-clean
  // with no suppression and no cast.
  replaceState(search === "" ? resolve("/browse/") : resolve(`/browse/?${search}`), page.state);
}
```

Written on a **500 ms trailing timer shared with the live region's announcement**, and **flushed
synchronously** before any navigation away.

**The return record.**

```ts
beforeNavigate((nav) => {
  const to = nav.to?.url.pathname ?? "";
  if (to.startsWith("/c/")) {
    flushAddress();                 // so a card clicked 200ms after a chip toggle is not stale
    writeBrowseReturn(store(), { href: currentHref(), scrollY: window.scrollY });
  }
});
```

`currentHref()` is composed **from the state**, not read from the address bar, which removes the race
rather than racing it. `store()` returns `sessionStorage` in the browser and `undefined` otherwise.

**The scroll restore.** In `onMount`: read the record; if it exists and its `href` equals the current
href, `window.scrollTo(0, record.scrollY)`; clear it either way. Kit's own back-button restoration
targets the same offset the record holds, so the two cannot disagree — the record exists for the
*forward* hop from a detail page, which gets no restoration at all.

**The composition**, from `05.1-UI-SPEC.md` § Screen 2: one content column,
`max-inline-size: 1280px; margin-inline: auto; padding-inline: 32px` (24px below 640px),
`padding-block: 32px` (24px below 640px), **everything left-aligned**. The `<h1>` is the wordmark and
on this route it is a **real link to `/`**; the header has no right-hand slot here, because the page
that control would lead to is the page you are on. The fidelity line sits **beneath** the grid, 48px
below the last row, unconditionally (W-13).

**Head copy**, verbatim: title `Browse — HANGAR`, og:title the same, description and `og:description`
`Every ZONA configuration in HANGAR, running live in the firmware's own simulator.` (with a real
U+2019 apostrophe). `og:url` is `${SITE_ORIGIN}/browse/`; the image is the opening centre's, exactly
as `/` does it, since there is no shelf-level image and inventing one would be a second composition to
keep true to the site.

**The empty-result sentence** is chosen by the page and passed to the grid, from the copy contract:
query only → `No configuration matches "{query}".` · tags only → `No configuration carries all of
those tags.` · both → `No configuration matches "{query}" with those tags.` The quotation marks are
real typographic doubles (U+201C, U+201D).
