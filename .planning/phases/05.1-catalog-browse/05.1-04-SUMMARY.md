The other seven stayed green throughout, which is also what proves the `close` spy disturbs nothing.

### Why it matters, in one sentence

On `/c/euclid/` the row is EUCLID alone, so before this change un-choosing closed the Lua VM behind
the only pad on the page and blanked it. Plan 05.1-11's e2e is what proves it in a browser; this is
what proves it in node.

### The change

```typescript
let published: SimEngine | undefined;

function swapEngine(next: SimEngine): void {
  const previous = engine;
  engine = next;
  options.onpreview(next);
  published = next;
  if (previous !== next) closeEngine(previous);
}

// … in destroy():
// Only an engine the consumer has never seen. See `published`.
if (engine !== published) closeEngine(engine);
engine = undefined;
```

Nothing leaks. `swapEngine` still closes the **previous** engine after the handover, so there is at
most one live engine per tuner and it is the one the row is using. The engine `destroy()` may still
close is the other kind — one built for a measurement that went stale before it was ever published
(`run()`'s `if (stale(mine)) { closeEngine(next); return; }`, untouched).

`TuningRegion.svelte`'s `if (!mounted) { built.destroy(); return; }` branch is covered by the same
rule and needed no edit, as the plan said.

### The observation, not a fixture

`watchClose()` shadows the engine's own `close()` with an own property, installed from **inside
`onpreview`** — the one moment guaranteed to precede any close of that engine, because `swapEngine`
calls `onpreview` before `closeEngine`. `closeEngine` calls `maybe.close()` on the very object handed
over, so the spy is what it reaches, and the real method still runs. The engine is EUCLID's real
`LuaPadSim`, so this observes the real `close()` at `src/lib/sim/lua-pad-sim.ts:192` rather than a
stand-in.

Test 8 asserts in both directions: the **replaced** engine was closed exactly once, at the swap; the
**last published** engine is not closed by the swap and is still not closed after `tuner.destroy()`.
The "no timer outlives destroy" half is deliberately left to test 7, which is unchanged and green —
this test runs on real timers for test 6's reason (two real Lua 5.4 VMs; the debounce is not what is
under measurement).

## Decisions Made

1. **`PadFrame` takes `{ id }` and the other two take `{ id; name }`.** A structural prop should
   declare what the component reads and nothing more; the lint rule that caught it is right.
2. **The front door's non-regression is a diff of two builds, not an inspection.** It costs sixteen
   seconds and it produces a claim nobody has to trust: the whole rendered row of `/` and
   `/c/aurora/` differs in one character. Any future change to this component should be checked the
   same way.
3. **The two-entry negative check runs in a browser, deliberately.** SSR cannot discriminate a wired
   `count` from a stale one — both render identical slot offsets. Only stepping does, because that is
   where `step()` and `goTo()` index the array.
4. **`count` is a lowercase `$derived`, not an uppercase constant.** The casing carries the fact that
   it is no longer a compile-time constant; leaving it `COUNT` would have read as one.
5. **Ownership of a preview engine transfers at `onpreview`.** The tuner may close only an engine the
   consumer has never been given. `swapEngine` already obeyed this for the previous engine; `destroy()`
   now obeys it too, and the two halves are documented against each other rather than separately.
