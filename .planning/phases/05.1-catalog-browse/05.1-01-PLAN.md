<objective>
The phase's keystone: one import-free module that carries all sixteen entries' browse data, gated
against the catalog it restates.

Wave 1. Nothing else in this phase can start cleanly before it. `/browse/` needs sixteen names,
descriptions, tags, dates and Featured flags **in its prerendered HTML**, and `src/lib/catalog/`
reaches `@intechstudio/grid-protocol` through exactly one runtime edge —
`src/lib/catalog/entries/ported.ts:13`'s `import { presetById } from "../../../vendor/botor/_pad"` —
so a page that statically imports `$lib/catalog` puts a 131,101-byte compiler chunk on its first
paint. This is the situation `src/lib/catalog/front-door.ts` was invented for, and this is the same
answer used a fourth time (`protocol-pin.ts`, `front-door.ts`, `share/url.ts`, now `listing.ts`).

Three things make it more than a copy:

1. **The motion derivation is not `front-door.spec.ts`'s.** That one is
   `any animating → "animated"; else any lit → "static"; else "dark"`. Applied to `frames.json`,
   **GHOST derives `"animated"` while lighting zero bytes at every sampled tick** — its layers really
   are counting down, they just resolve to black until a finger arrives. `FidelityLine.svelte` only
   shows the quiet line when `motion !== "animated"`, so a GHOST card built on that derivation is a
   silent black square with no explanation, which is exactly what D-11 forbids. **`restsBlack` is
   read first** (D-14).
2. **Three sentences have to be authored**, because tpad, ghost and morph have never had one.
3. **`ROUTED` is exported from here**, so the widened `entries()`, `scripts/gen-og.mjs`,
   `src/lib/og/build.spec.ts` and `e2e/artifacts.e2e.ts` all read one name instead of four
   declarations of the same set.

This plan also re-measures the four suite baselines, because every later plan in the phase asserts
its own totals as the previous SUMMARY's numbers plus a stated delta (D-17).

Purpose: D-01 and D-12 in executable form, and the data every later wave reads.
Output: one new module, one new spec with five tests, and four recorded baselines.
</objective>

```typescript
// src/lib/catalog/listing.ts
//
// This module imports NOTHING at runtime, and listing.spec.ts asserts it. The
// one permitted import is `import type`, which is erased at build time.
import type { FrontDoorEntry, PreviewMotion } from "./front-door";

export type ListingEntry = FrontDoorEntry & {
  readonly tags: readonly string[];
  readonly featured: boolean;
  /** "YYYY-MM-DD". */
  readonly addedAt: string;
  readonly restsBlack: boolean;
};

/** The one sentence a resting-black card carries. One string, three entries. */
export const RESTS_DARK_NOTE =
  "This pad rests dark. That is the configuration, not a broken picture.";

/** All sixteen, in CATALOG order. */
export const LISTING: readonly ListingEntry[] = [ /* 16 records */ ];

/**
 * The entries that have an address. Today that is every listed entry, and the
 * point of the name is that four files read ONE declaration of it instead of
 * four: src/routes/c/[id]/+page.ts, scripts/gen-og.mjs, src/lib/og/build.spec.ts
 * and e2e/artifacts.e2e.ts.
 */
export const ROUTED: readonly ListingEntry[] = LISTING;

export function listingIndex(id: string): number;   // -1 for unknown
export function listingById(id: string): ListingEntry | undefined;
```

**The sixteen, as counted from `src/lib/catalog/` and `frames.json` on 2026-09-04.** Nine ported at
`addedAt` `2026-09-02`, seven Lua at `2026-09-04`. `EXCLUDED_FROM_ROW` is **tpad plus the seven Lua
entries** — there are seven Lua configurations, not eight. Any copy that says eight produces an
off-by-one gate.

| id | in row | restsBlack | frames.json | listing `motion` |
|---|---|---|---|---|
| aurora, pinwheel, starfield, radar, dial | yes | – | animated | `animated` |
| ninepads, faders, joystick | yes | – | static | `static` (quiet from FRONT_DOOR) |
| tpad | no | **yes** | dark | `dark` |
| euclid, chorus, arc, lattice, sonar | no | – | animated | `animated` |
| ghost | no | **yes** | **animating at every tick, 0 lit bytes at every tick** | **`dark`** |
| morph | no | **yes** | dark | `dark` |

**The derivation, in this order and no other:**

```
restsBlack            -> "dark"
else some(animating)  -> "animated"
else some(lit > 0)    -> "static"
else                  -> "dark"
```

**The `quiet` rule.** Every entry whose `motion` is not `"animated"` carries a non-empty, single-line
`quiet`. For the eight row entries it is **byte-equal to `FRONT_DOOR`'s** so the two files cannot
drift. For tpad, ghost and morph it is `RESTS_DARK_NOTE` verbatim — one sentence, because it says
only what is true of all three (with nothing touching it, the pad is black), and what each of them
*does* is already in its own description. `05.1-UI-SPEC.md` § The resting-black note is the source of
that sentence; do not rewrite it, and do not author three variants.
