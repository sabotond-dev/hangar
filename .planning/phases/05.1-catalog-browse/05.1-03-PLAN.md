<objective>
The three pieces of state that have to survive a round trip: the address, the way back, and the
picture on a card that has just moved in the DOM.

Wave 3. All three are small, all three are pure or injectable, and all three are the kind of thing
that is invisible in review and obvious to a visitor when it is wrong.

1. **`query.ts`** is the parse/serialise half of D-16. The rune that holds browse state is seeded
   from it once and the address is a **write-only projection** of the state afterwards — verified
   from Kit 2.70.3's own source in both directions: `client.js:2551-2581` (`replaceState`) sets
   `page.state` and **never** `page.url`, while `client.js:2871-2905` (the popstate shallow branch)
   *does* call `update_url`. So `page.url` is stale on write and fresh on back, and a `$derived` over
   it would be a latent bug pointing in two directions at once. The page comes in wave 8; the pure
   half comes now, where it can be tested.
2. **`return.ts`** is W-20's one `sessionStorage` record. `sessionStorage`, so a middle-click into a
   new tab correctly gets no back control — in a new tab there is nothing to go back to and offering
   it would be a lie.
3. **`SimHost.repaintAll()`** makes a genuinely unresolved question moot. The HTML specification
   resets a canvas bitmap only on a `width`/`height` set, and Svelte's keyed `{#each}` *moves* nodes
   rather than recreating them — so a sort should preserve every picture. Cross-browser behaviour
   under a re-parenting move is not verified here, and the failure mode is silent and **only affects
   still pads** (an animating pad repaints on the next frame and self-heals). Five lines and two
   tests remove the question instead of researching it.

Purpose: D-16's testable half, D-08's record, and the one new `SimHost` method the wall needs.
Output: two new modules with nine tests, and `host.spec.ts` from 13 to 15.
</objective>

**`src/lib/browse/query.ts`**

```typescript
import { BROWSE_SORTS, DEFAULT_SORT, type BrowseSort } from "./sort";

export type BrowseQuery = {
  readonly sort: BrowseSort;
  readonly q: string;
  /** In activation order. Repeated once per tag in the address. */
  readonly tags: readonly string[];
};

export const DEFAULT_QUERY: BrowseQuery = { sort: DEFAULT_SORT, q: "", tags: [] };

/**
 * `known` is the catalog's tag vocabulary, passed in so this module never
 * imports the catalog. An unknown tag is DROPPED SILENTLY and renders no chip
 * (W-12): unlike a tuning stamp the visitor did not author it, there is nothing
 * for them to do about it, and the count line already tells the truth.
 */
export function parseBrowseQuery(
  params: URLSearchParams,
  known: readonly string[],
): BrowseQuery;

/** "" for the default query, so a plain /browse/ is the canonical address. */
export function serialiseBrowseQuery(query: BrowseQuery): string;
```

The address is `/browse/?sort=newest&q=ghost&tag=gestural&tag=generative`. `sort` is omitted when it
is `featured`; `q` is omitted when empty and is URL-encoded by `URLSearchParams`; `tag` repeats once
per active tag, in activation order. `q` is trimmed on parse.

**`src/lib/browse/return.ts`**

```typescript
export type BrowseReturn = {
  /** The full browse URL including its query string. */
  readonly href: string;
  readonly scrollY: number;
};

/** Anything with the three methods. In the browser this is sessionStorage. */
export type ReturnStore = Pick<Storage, "getItem" | "setItem" | "removeItem">;

export const BROWSE_RETURN_KEY = "hangar:browse-return";

/** Never throws: a malformed or absent record is undefined, not an exception. */
export function readBrowseReturn(store: ReturnStore | undefined): BrowseReturn | undefined;
export function writeBrowseReturn(store: ReturnStore | undefined, record: BrowseReturn): void;
export function clearBrowseReturn(store: ReturnStore | undefined): void;
```

`store` is optional and every function is a no-op on `undefined`, because the page renders on the
server during prerender where there is no storage at all. A `JSON.parse` that throws, a record with a
missing field, or a `scrollY` that is not a finite number all read as `undefined` — a broken record
must degrade to "no way back offered", never to a crash on a page whose job is to paint.

**`SimHost.repaintAll()`**

```typescript
/**
 * Repaint every registered pad from its engine's current frame, without
 * touching the engines, the observers or the backing stores.
 *
 * NOT register(). register() calls unregister(), which sets canvas.width = 0
 * and re-enters with intersecting: false - the exact bug replaceEngine was
 * added to avoid in Phase 5. This exists for one caller: the browse grid, after
 * a sort or a filter has moved cards in the DOM. A still pad does not tick, so
 * nothing else would repaint it, and whether a canvas bitmap survives a
 * re-parenting move is not a question this repository wants to depend on.
 */
repaintAll(): void {
  if (this.destroyed) return;
  const now = this.deps.now();
  for (const entry of this.entries.values()) this.paint(entry, now);
}
```

It does **not** call `wake()`: repainting is not a reason to start the loop, and a wall of settled
still pads must stay at zero CPU.
