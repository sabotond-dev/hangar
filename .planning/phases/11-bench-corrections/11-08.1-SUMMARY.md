## Task 1 — the harness stops swallowing the engine's own error

Commit **`e418aad`**.

### The eleven poll sites, with a per-site verdict

`expect.poll` retries a **failing matcher** and not a **throwing callback**. Read
out of the shipped implementation rather than the documentation —
`node_modules/playwright/lib/matchers/expect.js`, `invokePollMatcher`:

```js
const value = await actual();            // OUTSIDE the try
try {
  await callMatcherAsStep(...);          // inside it
  return { continuePolling: false, ... };
} catch (error) {
  return { continuePolling: true, result: error };
}
```

The same reading yields the fact the positive guard depends on: **every** error
from the matcher is caught, including jest's usage error *"received value must
be a number or bigint"*. A string handed to `.toBeGreaterThan(0)` therefore
**continues** the poll rather than aborting it — confirmed in the run output
below.

## Task 2 — two assertions taken before the thing they measure, and two hazards

Commit **`780a530`**.

### `onlyReads` now waits on signals that imply completion, in that order

`session.svelte.ts` sets `phase = "connected"` and only **then** fires the
connection event; `install.svelte.ts` calls `void this.#attach(...)`,
fire-and-forget by design; `#snapshot` issues one `SERIALNUMBER/FETCH` and then
`fetchBoth`, which `sequence.ts` runs as two awaits **in series**. So
`connected` in the DOM means three CDP round trips are **about to start**.

`/dev/session/` now publishes `install-phase` beside `session-phase`, and the
page header's specifier sentence is corrected **two → three**.

**A finding the plan did not anticipate, and it decided the shape of the fix.**
Three of the seven `onlyReads` call sites load `/` and `/c/{id}/`, where the
shipped chrome renders no `install-phase` row — and
`expect(getByTestId(...)).not.toHaveText(...)` **passes immediately against an
element that does not exist**. A single causal wait would have been vacuous on
exactly the sites nobody was watching. Both forms ship, in order:

1. the fetch counters are polled to their totals at **every** call site — the
   timer fetch is the last chunk `#snapshot` issues, so `CONFIG/FETCH` reaching
   `2 * connects` **is** completion;
2. **where** the row is published, the store is then required to have **left**
   `snapshotting`. Step 1 is what makes step 2 sound rather than racy: by then
   both awaits inside `#snapshot` have returned, so the phase is a settled one
   and not a pre-snapshot `idle` that would satisfy the negation for free.

Wait first, read the safety counters second, so a late write is still caught.

**Negative check — `this.phase = "ready"` commented out of `#snapshot`:**
**RED**, and it failed **naming the phase**:

```
Error: the install store is not still inside #snapshot, so nothing is in flight behind these counters
Expected: not "snapshotting"
Received: "snapshotting"
  59 × locator resolved to <dd data-testid="install-phase">snapshotting</dd>
```

The counter polls above it **passed**, which is the proof the second wait is on
a signal and not on a number that happens to arrive.

### The assertion that measured nothing, retired as an equality

`expect(shown).toBeGreaterThanOrEqual(0)` is vacuous over a count, and
`<= await writes(page)` asserted `0 <= shown <= 3`. It was *structurally*
guaranteed to measure nothing: the probe re-read the shim only on
`session.phase` or `session.identity`, and every write it is about happens after
the last such change. Adding `void install.phase;` to that `$effect` makes it
re-read on `ready`.

**The constant-zero plant, published both ways:**

| Form | Exit | Outcome |
|---|---|---|
| the old pair, `0 <= shown <= 3` | **0** | **GREEN in 1.9 s** with the readout wired to `writes = 0` |
| the new equality | **1** | **RED** — `the readout is the shim's own count: Expected: 3 Received: 0` |

`built >= 4` of 27 let the sampling run against a grid **15% built**.

```

of 13 (the 2 cards this test scrolled to, unioned with what is on screen)
```

**The first attempt timed out on a perfectly healthy page**, and the wrong

`name-lattice`, `name-lumen`, `name-morph` and `name-ninepads` — four ids no

### `artifacts.e2e.ts` reads the build, not `git` at module load

It ran `git rev-parse HEAD` at **module load in every worker** and asserted
`build/source-<that sha>.tar.gz` existed, so **committing while the suite ran
turned it red** and reported it as *"file missing"* — the one diagnosis that
sends a reader looking in the wrong place. It now globs `build/`, asserts
exactly one archive (`postbuild.mjs` writes one and deletes every other), and
holds **its** sha against HEAD with a message naming the two real causes:
*"the build is stale, or HEAD moved during the run"*. The assertion still bites
in both directions; only its diagnosis improves.

### The `reuseExistingServer` hazard, and the run procedure that was followed

`playwright.config.ts` carries `reuseExistingServer: !process.env.CI` and is not
editable in this phase, so this half is a **recorded hazard plus a run

every run in this plan:** `tasklist | grep -icE "workerd|wrangler"` was checked
(**0** each time) and `npm run build` was run by hand before every suite
invocation. No commit was made while a suite was running.

## Task 3 — HANGAR notices when a canvas dies, and comes back

Commit **`88f896c`**.

### Before and after

```
BEFORE:  grep -rn "contextlost\|contextrestored\|isContextLost" src/   ->  EMPTY
AFTER:   src/lib/sim/host.ts       16 matches
         src/lib/sim/host.spec.ts  16 matches
```

### Where the regression came from, which is the sentence worth writing down

`src/vendor/botor/pad-sim-host.ts` takes its context **inside `blit()`, on every
paint**, so the reference design never holds a reference across a loss.
`host.ts` caches the context **and** a persistent `ImageData` scratch because
`putImageData` into a 9x9 backing store is the whole point of the faster painter
(04-CONTEXT D-15). **The performance win traded away an accidental resilience,
and nobody noticed the trade.**

**No vendored byte moves and no `intendedDivergence` row is declared**, and the
grep was run rather than the paragraph trusted: `pad-sim-host` appears **18**
times outside `src/vendor/` and **0** of them is an import statement. The bug is
HANGAR's own file, so the fix is too.

### The two-halves table, as shipped and as measured

It is written into `host.ts`'s header so neither half can later be deleted as
duplication.

| Half | Catches | Cannot catch | Measured |
|---|---|---|---|
| `contextlost` / `contextrestored` listeners | a **still** card, which never paints again and which nothing else would ever repaint | an engine that drops a store **without emitting** | removing it → the **still** branch RED in both engines, `Expected: 81 Received: 0` |
| the `paint()` re-acquire guard | any **animating** card, on its very next paint, **with no event at all** | a **still** card — it settles to zero CPU by design | removing it → the **animating** branch RED in both engines, `arc Expected: > 0 Received: 0` |

Both halves are load-bearing in a browser. Neither check came back green.

### `preventDefault()` polarity, with its source

**Canvas 2D is the opposite of WebGL, and this code does not call it.** HTML
Living Standard, *"Canvas context lost and restored"*: `shouldRestore` is the
result of firing a **cancelable** `contextlost`, and *if `shouldRestore` is
false, abort these steps* — firing returns false exactly when the event was
canceled. MDN states it in one sentence: canceling `contextlost` prevents the
browser from attempting to restore the context. For `webglcontextlost` the
polarity is reversed and `preventDefault()` is what **enables** restoration.

Copying the WebGL idiom from memory would have shipped a listener that runs and
achieves nothing. The browser test asserts `defaultPrevented === false` after
HANGAR's listener has run, and it passed in both projects.

### Which `isContextLost` shape the toolchain needed

**Neither a cast nor a local structural type.** TypeScript 6.0.3's
`lib.dom.d.ts` declares `isContextLost(): boolean` on the `CanvasState` mixin of
`CanvasRenderingContext2D` (line 10467). It is still **feature-detected at the
call site** — `typeof ctx.isContextLost === "function"` — because it ships in
Chrome 130+ and Firefox 151+ and is not in the Chrome 89 baseline HANGAR's
support matrix names. The hot path costs one `typeof` plus one call, never a
`getContext` per paint per card.

### The scratch clear: defensive, not load-bearing — a green check recorded as a finding

**Negative check:** carry `entry.scratch` across the loss and rebuild only
`entry.ctx`. **Result: GREEN, 21 of 21.** An `ImageData` is a plain object and
`putImageData` accepts one minted by a context that has since died. The clear is
**kept with that label** in `host.ts`'s header — the cost is one allocation on a
path that runs once per loss — rather than claimed as a check that bites. This
is 11-08's lesson applied in the other direction.

### The e2e proof, and the vacuity trap it does not walk into

**A synthetic `contextlost` loses nothing.** Dispatch-then-assert-pixels-unchanged
**passes against the unfixed code**, because the pixels were never disturbed. The
shipped test dispatches the event, **clears the 9x9 store from the test**,
asserts the clear really landed at **0 of 81**, and only then dispatches
`contextrestored`.

One `@webkit` title, both branches, following 11-08's precedent of extending
rather than adding. Observed, identical in both projects:

```
context loss recovery: ninepads (still) 81 lit before, 0 while dropped,
81 after contextrestored at index 7; arc (animating) 74 lit after a drop with
NO event; engine-fired (isTrusted) contextlost 0, contextrestored 0
```

Both cards are **derived** — `motion === "static" && !restsBlack` and
`motion === "animated" && !restsBlack` — never typed as ids. The card's **DOM
index and its box on screen are asserted unmoved** across the whole thing: no
sort, no scroll, no reload, no re-`register()`. `BrowseGrid.svelte` is
byte-untouched (`git diff --quiet 7faa93c HEAD -- src/lib/ui/BrowseGrid.svelte`
exits 0) and its `started` set was never an obstacle.

**What each branch is red against is stated in the test itself**, because a
negative check that cannot redden is this phase's recurring lesson:

- the **still** branch is RED against the code as it shipped;
- the **animating** branch is **GREEN against that same unfixed code** — clearing
  pixels does not lose a context, so an unfixed host's loop simply repaints —
  and RED against a build with the listener half and no paint guard. Said out
  loud in the source rather than hidden.

The file header's tag arithmetic is corrected: **four tests, eight runs**.

### Whether WebKit emits `contextlost` for a 2D canvas: a NAMED UNKNOWN for 11-16

**Measured as far as a test can measure it, and claimed in neither direction.** A
capturing listener on `document` counts events with `isTrusted === true` —
capture reaches a non-bubbling event, bubble does not — and printed **0 and 0**
in both chromium and webkit-phone across the full run.

That is **"not observed in this run"**, not *"WebKit does not emit these"*.
Emission cannot be forced from a test: the run never put the engine under the
memory pressure that would drop a store. It is a named unknown for 11-16 and a
bench-adjacent row.

**This is exactly why the paint-time guard is not optional.** A fix that depended
on an event the engine may never send would run green in CI and blank the pads on
the device the bug was found on.
