All four `sends` states pass `planLayers` with `sends: true` alongside `look` and `touch`, so the

**`fingers = "each"` is cheaper still** on AURORA (313) and PINWHEEL (368) if per-finger streams are

`"first"` is the conservative reading — one stream, one position, the thing a host expects from an XY
pad — and if `"each"` is chosen instead, that is a decision to state with its reason, not a saving to
take quietly.

## NINE PADS: reachable is not selectable

`sends.grid` already accepts `"4x4"`, so a 4x4 NINE PADS is one field. **The user said
"selectable"**, which means a knob, not a different default.

- The knob's kind must be one the shared vocabulary already has. `knobs.preset.ts`'s carve-out at
  `:100-110` is the thing to read first: `brightness` is a HANGAR-added universal knob borrowing the
  `amount` kind, excluded from the kind comparison **by id and never by kind**, because filtering by
  kind would also drop ninepads' real channel knob. A new grid knob must not collide with that.
- `knobs.preset.spec.ts:108` compares **deduped kind sets**, so adding a knob whose kind is already
  present changes nothing there; adding one with a new kind requires `presets.ts`'s `knobs` array to
  declare it. **11-05 repointed that spec at HANGAR's nine precisely so this change goes green for the
  right reason.**
- **The knob is APPENDED**, so every NINE PADS link ever shared still decodes to the same knob values.
  The stamp encodes one base-32 character per knob **by index**; a knob inserted anywhere but the end
  re-points every existing link. `stamp.spec.ts` compares indices and would stay green, so no test will
  tell you.
- `knobs.preset.ts:730` derives every knob default from the shipped `state` and **throws at import
  time** if a default is not in its own option list. The 3x3 default must be present in the option
  list, in the position the state names.

**Cost both positions**, not just the default: `3x3` at 580 and `4x4` at 550, both inside 908 with
their Timers, and the sweep will check every knob cross-product anyway.

**One thing to check and report rather than assume:** whether `sends.showGrid`'s painted zones and the
`sends.fingers = "each"` held-lit behaviour still read correctly at 4x4, where sixteen zones of four
cells do not tile a nine-by-nine pad the way nine zones of nine cells do. Look at the compiled output
and at the simulator frame, and **if the 4x4 picture is worse than the 3x3, say so** — the user asked
for selectable, and a selectable option that looks wrong is a finding.

## JOYSTICK: the rest position, and a trail that no longer costs anything

`sends.springTo = "centre"` with `invertY = false` moves `springRestCell` to **cell 40** — the dot
rests in the middle and is **lit from power-on**, which is the whole of *"should start from the
middle by default"*. The compiled rest is an exact literal (`8192` for a bend axis, `64` for a CC
axis), not a scaled position, so the joystick lands bit-perfect wherever the finger left.

**Read the shipped mutator's comment before overwriting it.** It says: *"The classic pitch/mod stick:
the bend axis centres by definition, and the CC axis falls to zero like a mod amount. Up is more, like
the fader cards, so the stick rests at the bottom-centre cell."* That is a deliberate design decision
being reversed by the user's note, and **reversing it must be recorded as a reversal** — including
what is lost: the Y axis no longer falls to zero on lift, so a held mod amount now rests at 64 rather
than 0. If that is wrong for a mod axis, the honest configuration is `springTo: "centre"` on the bend
axis and `"zero"` on the CC axis if the descriptor permits it; **check whether it does, and report
either way.**

**The trail.** `touch.kind = "comet"` costs `535 → 468` — it is *cheaper*, because the glow path
carries the spring re-park's own `glp` and the comet path does not. The research required this plan to
state that `comet` leaves **one permanent unit of residue per crossed cell** while `glow` leaves zero.
**11-04 removed that residue at its source**, measured at zero cells against the research's seven.
State both numbers. This is the one place in the phase where an earlier wave turned a trade-off into a
free win, and saying so is how the ordering justifies itself.

**Also check the front door.** `front-door.ts` carries joystick's `quiet` line byte-equal to the
preset's (`front-door.spec.ts:303`), and its `motion` is declared `"static"`. **A trail is motion.**
`front-door.ts` says motion must never be "guessed or aspirational" and `frames.json` proves it in
both directions — so if the comet trail makes joystick animate, its `motion` moves and both the row
and the listing move with it. **Check `frames.json`'s `animating` flag rather than reasoning about
it.**
