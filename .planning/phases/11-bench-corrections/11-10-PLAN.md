## The host surface as it stands

`lua-host.ts:144-171` declares **fifteen** globals and **nine** `self:` methods, and the array **is**
the list rather than a description of it: `registerGlobals()` iterates it, so a name added here without
a binding **fails to construct**, and a binding added without a name here is **unreachable**.
`host-surface.spec.ts` refuses any call outside the list **and cross-checks the array against a booted
VM's own `_G`** rather than trusting it.

```
glag glc glp glf gls glt glpfs glim gtt grxm txma tyma gmms gmbs gks
```

`gmms`, `gmbs` and `gks` are the compiler's HID out-calls, recorded by `recordHid` at `:458`:

```
gmms: (...args) => this.recordHid("gmms", args),
gmbs: (...args) => this.recordHid("gmbs", args),
gks:  (...args) => this.recordHid("gks",  args),
```

**That is the template.** `gmss` is a fourth out-call of the same character: fire-and-forget, no return
value, its payload worth recording so a test can assert what was sent.

**One thing to decide rather than copy.** `HostHid`'s `call` union is `"gmms" | "gmbs" | "gks"` — three
HID calls. **Sysex is not HID.** Widening `HostHid` would put a MIDI message in a type named for human
interface devices, and the union is the thing that makes the recorded list readable. **Prefer a
sibling recorder** — `recordSysex`, its own recorded list, its own union — and if you widen `HostHid`
instead, say why. Either way `gms` already has a recorded-MIDI path; look at it before inventing a
third shape, because a sysex message may belong beside the MIDI it is a kind of, not beside the mouse
clicks it is not.

**Every literal `15` in the tree must be found rather than remembered.**
`grep -rn "fifteen\|15 globals\|HOST_GLOBALS" src/ docs/` and read every hit: `lua-host.ts`'s header,
`host-surface.spec.ts`, `lua-host.spec.ts`, `docs/TESTING.md`, and the prose in any entry header that
cites the surface. **Publish the list.** A count that lives in five places and moves in four is the
shape of Phase 10's seven miscounts.

## LUMEN's sysex

`gmss`'s contract: **every argument is one payload byte, and the entry supplies `0xF0` and `0xF7`
itself.** So a colour as hex is a call whose first byte is 240, whose last is 247, and whose middle is
whatever encoding the entry chooses.

**The encoding is a design decision the user's note does not settle**, and it must be stated rather
than assumed. *"Should send HEX in sysex"* most naturally means the colour's hex digits as ASCII —
a desk or a bridge reading `#FF3B30` — but a raw three-byte RGB payload is also "the colour in sysex"
and is shorter. **Cost both** against LUMEN's 302 free Setup characters and its **completely free
Timer**, state which was chosen and why, and note that sysex data bytes are **seven-bit**: a raw RGB
byte above 127 is not transmissible without an encoding, which is a real argument for the ASCII form
and is exactly the kind of fact that should decide this rather than taste.

**LUMEN's other latent defect, reported and not necessarily fixed.** `x*127//128` maps 0..127 onto
0..**126** and can never emit 127 — on **both** axes. It is the same family as CONSOLE's 111 but it is
**not one of the user's complaints**. Report it with its measurement; fix it only if it is free and
does not disturb the sysex work, and say which you did.

## The depth half, per 11-09's answer

- **If `lumen-ramp`:** `d = 36 - row*@DEPTH` runs 36..4 and never reaches black. Re-cut `@DEPTH` so the
  low settings read as a real change and, if the answer asked for it, so the bottom row can reach
  black. **Changing a knob's values keeps every shared link decodable and silently changes what it
  renders** — same rule as 11-02's two re-cuts, same sentence owed to the SUMMARY, old value beside
  new.
- **If `lumen-emitted`:** a third stream carrying the opacity as a value rather than as a picture.
  Cost it beside the sysex work and say whether the sysex change made it redundant, which is what
  11-09's option text warned it might.
- **If neither:** ship the sysex half only and record the depth half as unanswered.
