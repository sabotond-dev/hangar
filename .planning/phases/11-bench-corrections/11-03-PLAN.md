<interfaces>

**What the manifest holds today.** `upstream-manifest.json` has `upstream` (repository, branch, commit
`a0fb69d5d0e78ce0f6423fc1d1a9783937c5380c`), `headerSentinel`, `note` and `files`. Each file entry has
`vendored`, `upstream`, `bytes`, `sha256` and `deltas`, where a **delta** is a permitted *import
rewrite* recorded as a `{vendored, upstream}` pair, applied in reverse to reconstruct pristine bytes.
Six files, with 1, 0, 0, 1, 2 and 1 deltas respectively.

**`vendored-diff.spec.ts` today is 14 tests**: two `it.each` over the six files (byte-identity after
inverting deltas; the provenance header naming repository, path, commit and sync date) plus two
singles (the manifest pins the D-01 commit; `VENDOR.md` names the same upstream and lists every
vendored file). Its byte-identity test asserts each delta occurs **exactly once**, because a
replace-all would hide a rewrite nobody recorded.

**The shape of the change.** `intendedDivergence` sits **beside** `deltas`, never inside it, because
the two mean different things and conflating them would lose the distinction that makes the record
useful:

- a **delta** is a mechanical rewrite forced by vendoring (an import path that cannot resolve here);
- an **intendedDivergence** is a deliberate behaviour change HANGAR chose, with a reason and the plan
  that chose it.

```
"intendedDivergence": [
  {
    "vendored": "<the bytes as they are here>",
    "upstream": "<the bytes as they are upstream>",
    "reason": "<one sentence saying what behaviour changed and why>",
    "plan": "11-04",
    "dated": "2026-09-09"
  }
]
```

Reconstruction inverts **both** lists, so **upstream's sha256 still rules** and a change outside both
still moves the hash and still names the file. That is the property worth protecting: the gate does
not get weaker, it gets **more specific**.

**Two rules the table must enforce, or it becomes a rubber stamp:**

1. **Exactly once, like `deltas`.** A divergence whose `vendored` text matches twice means the edit
   hit a site nobody recorded.
2. **Every field present and non-empty.** A row without a `reason` or without a `plan` fails. The
   whole value of the record is that a future reader learns *why*, and a row that only says *what* is
   a diff they could have got from git.

**The re-sync procedure `VENDOR.md` must now describe** — and this is the sentence D-02 was asking
for: a re-sync is a **merge**, not a copy. Pull the new upstream file; re-apply each `delta`; re-apply
each `intendedDivergence`, **checking each one is still needed** (an upstream fix that lands the same
behaviour retires the row); re-run `scripts/record-upstream-manifest.mjs`; re-run
`scripts/capture-preset-baseline.mjs` **in BOTOR's tree** to re-take the baseline at the new commit;
and re-run the suite. An `intendedDivergence` that no longer applies cleanly is the whole reason the
row carries a sentence.

**The two fidelity fixtures, and why they are not the same kind of thing.**

| Fixture | What it is | Regeneration |
|---|---|---|
| `preset-baseline.json` | **BOTOR's behaviour**, captured by running BOTOR's own compiler in BOTOR's own tree at the pinned commit. Its spec's header: *"the fixture is the original's behaviour, and the copy is what is on trial."* | **Never.** No sanctioned path exists and none is added. Divergence is declared **in the spec**, per preset, per field, with a reason |
| `golden-frames.json` | **A regression tripwire, not an oracle** — the hashes come from the simulator itself, so they prove only that something changed a named preset's appearance. Its own header says so | `UPDATE_GOLDEN=1 npx vitest run ...`, which rewrites, runs prettier and then **fails by design**. 11-04 uses it and lists every moved row |

`preset-baseline.spec.ts` therefore gains an `INTENDED_DIVERGENCE` table of the same shape as the
manifest's — **empty in this plan** — and its per-preset comparison consults it. **A preset with no
entry keeps D-08's STOP-and-report rule exactly as written.** That is the point: the rule is not
weakened for the nine, it is suspended for the named few, and everything else still stops.

**`firmware-oracle.spec.ts` is not edited by this plan or by any plan in this phase**, and that is
deliberate. It compares the simulator against constants re-derived from `grid-fw` by an author who
never read the simulator. It is the mechanical proof of D-02's load-bearing half — that
`pad-sim.ts:883-891`'s `pha += fre` wrap was not "fixed" — and 11-04 states its green run as evidence.

**And the proof is sharper than "a standing gate stayed green", for a reason worth writing down
because neither this plan nor 11-04 previously stated it.** The oracle's **seventh** test, *"agrees on
the tick order at layer expiry"* (`firmware-oracle.spec.ts:213`), builds `defaultState()`, sets
`enabled.look = false` and `enabled.sends = false`, leaves `enabled.touch = true` and drives one
`touchDown`. `DEFAULT_PAD_STATE.touch.kind` is **`"comet"`** (`_pad.ts:637`), and disabling Look
removes the keeper that would otherwise re-arm forever — **so the only layer ticking in that test is
the comet layer painted at `pad-sim.ts:986-988`, which is exactly the site 11-04 edits.** The test is
not adjacent to the change; it runs through it.

**And its assertions are relative to an observed expiry, not to an absolute tick.** It scans for the
`animating` true-to-false transition, calls that `expiry`, and then asserts `hashes[expiry + 1]`
equals `hashes[expiry - 1 + offset]` where `offset` is the oracle's
`TICK_ORDER.phaseAdvanceOffsetAtExpiry`. **Moving the start constant moves `expiry` and every index
moves with it, so the test stays green. Clamping the phase walk changes which frame is frozen relative
to `expiry`, so the test goes red.** That asymmetry is what makes the boundary check mechanical rather
than incidental, and it is why the negative check in 11-04-01 plants its change on `& 255` and nowhere
else.

**The two requirements this phase will falsify, named here so 11-16 amends rather than discovers:**

- **CONT-01**: *"each compiling to the same Lua as BOTOR at the pinned protocol version"*. After 11-04
  five of the nine will not. The amendment is not "delete the clause" — it is *"the same Lua as BOTOR
  except at the enumerated divergences in `upstream-manifest.json`, each named with its reason."*
- **FOUND-02**: *"with their existing test suites passing unchanged"*. `tests/pad.test.js` carries the
  literal `glpfs(a,1,255,250,0)` and will need one hunk of its own. The amendment says the vendored
  suites pass with the enumerated divergences applied, and names the count.

**This plan writes neither amendment.** It records both, with the exact wording and the exact reason,
in its SUMMARY, so 11-16 amends them by name and dated rather than rewording a claim it just noticed.
