## The vendored reference host, and why no manifest row is declared

`src/vendor/botor/pad-sim-host.ts` takes a context too - **but it takes it INSIDE `blit()`, on every
paint**:

```ts
function blit(canvas: HTMLCanvasElement, frame: Uint8Array | undefined, cell: number): void {
  const g = canvas.getContext("2d");
  if (g === null) return;
```

So the reference design **never holds a reference across a loss**. That is not a fix - a lost 2D
context is returned again by `getContext`, and a still card in that host does not blit either - but it
is strictly better than caching, and it is where HANGAR's regression came from: `host.ts` caches the
context **and** a persistent `ImageData` scratch because `putImageData` into a 9x9 backing store is the
whole point of the faster painter (04-CONTEXT D-15). **The performance win traded away an accidental
resilience, and nobody noticed the trade.** Say that in the SUMMARY.

`pad-sim-host.ts` is **read and never imported** - `grep -rn "pad-sim-host" src/` outside `src/vendor/`
returns fourteen comment references and zero import statements. **So `src/lib/sim/host.ts` is HANGAR's
own file, the bug is HANGAR's own, and no `src/vendor/` byte moves and no `intendedDivergence` row is
declared.** Verify that grep rather than trusting this paragraph.

## The fix, in two halves, and NEITHER IS REDUNDANT

This is the load-bearing design statement of the plan and it must survive into `host.ts`'s header.

| Half | What it catches | What it CANNOT catch |
|---|---|---|
| **A `contextlost` / `contextrestored` listener pair** on each registered canvas | a **still** card, which never paints and which nothing else would ever repaint | an engine that drops a backing store **without emitting the events** |
| **A `paint()` guard** that re-acquires when `entry.ctx` is missing or reports `isContextLost()` | any **animating** card, on its very next paint, with no event at all | a **still** card - it settles to zero CPU by design and `paint()` is never called again |

**A wall of settled still pads at zero CPU is the host's own proudest property** (`host.ts`'s header:
*"the last frame with nothing running does not ask for another"*), and it is exactly what makes the
paint guard insufficient on its own. **Ship both, and write the table above into the header** so the
next author cannot delete either half as duplication.

### The `preventDefault()` trap, which is OPPOSITE between WebGL and canvas 2D

For `webglcontextlost`, `preventDefault()` is what makes the UA attempt restoration. For the canvas 2D
`contextlost` event the polarity is **not** the same. **Look it up, then prove it with the dispatched
event before shipping either behaviour**, and write the answer into the header with its source. Do not
copy the WebGL idiom from memory: it is the single most likely way to ship a listener that runs and
achieves nothing.

### `isContextLost()` may not be in this toolchain's DOM lib

TypeScript 6.0.3's `lib.dom` may not declare `CanvasRenderingContext2D.isContextLost`. If it does not,
**declare a minimal structural type locally in `host.ts` and feature-detect at the call site** -
`typeof ctx.isContextLost === "function"` - rather than casting to `any`, which `npm run lint` refuses.
State which of the two the toolchain turned out to need.

### The scratch

`entry.scratch` is `createScratch(ctx)`, i.e. `ctx.createImageData(9, 9)`. Clear it with the context
and rebuild it from the NEW one. **Whether that is load-bearing is a question, not an assumption** -
an `ImageData` is a plain object and `putImageData` may well accept one minted by a dead context. It
has a negative check below, and **if that check comes back green the finding is that the clear is
defensive rather than load-bearing, and it is recorded as such** - 11-08's lesson, in the other
direction.

### `BrowseGrid`'s `started` set must never be consulted

`BrowseGrid.svelte:242` builds a card's engine exactly once, forever. **The recovery happens entirely
inside `SimHost` without a re-`register()`**, so `started` is not an obstacle and is not edited. The
e2e proof below is written to make that true rather than assumed: the card **does not move, is not
re-sorted, is not scrolled away from and is not reloaded**.

`host.ts:342`'s `repaintAll()` goes through `paint()`, so it inherits the guard for free - which means
a sort or a filter also heals a still card. That is a bonus, **not** the mechanism, and the e2e test
must not lean on it.

## `expect.poll` retries a FAILING MATCHER and not a THROWING CALLBACK

Playwright evaluates the poll callback **outside** its try block. One transient exception anywhere in a
30-second budget kills the test outright, so the 30 seconds are illusory against the failure mode most
likely to occur. **There are eleven `expect.poll` sites in `e2e/` and every one has the hole:**

| File | Line | Matcher | Note |
|---|---|---|---|
| `browse-webkit.e2e.ts` | 181 | `.toBe(1)` | over `page.evaluate` |
| `browse-webkit.e2e.ts` | 257 | `.toBeGreaterThan(0)` | **the site that flaked** |
| `browse-webkit.e2e.ts` | 278 | `.toEqual(byName)` | over `page.evaluate` |
| `browse.e2e.ts` | 980 | `.toBeGreaterThan(0)` | reads a node-side array - **check whether it can throw at all** |
| `browse.e2e.ts` | 1306 | (scroll restore) | inline `page.evaluate` |
| `aesthetic.e2e.ts` | 319 | `.toBe(expected)` | |
| `aesthetic.e2e.ts` | 324 | (`--crt`) | |
| `aesthetic.e2e.ts` | 339 | (screen attribute) | |
| `tuning.e2e.ts` | 821 | **`.not.toBe(was)`** | **the trap - see below** |
| `tuning-webkit.e2e.ts` | 269 | (backing store sample) | |
| `tuning-webkit.e2e.ts` | 316 | (row layout) | |

**THIS PLAN FIXES ALL ELEVEN, and the reason is the diagnosis's own: a half-fix that leaves ten is
worse than a recorded finding.** The change is mechanical, it cannot redden a green run (it only
changes behaviour on a throw), and leaving ten would mean the next flake is unattributable again in a
file this plan already opened.

**The eleven are not homogeneous, and `tuning.e2e.ts:821` is the trap.** A guard that returns a
descriptive string on a throw makes every `.toBe` / `.toEqual` / `.toBeGreaterThan` site keep polling -
a string is never equal to a number or an array. But `remeasured()` asserts `.not.toBe(was)`, and a
string is **also** not equal to `was`, so a caught throw would **satisfy the negation and turn the
test green on a broken page.** That site needs the inverted shape: on a throw return `was` itself, so
the poll keeps going, and record the last error so a trailing assertion can name it.

**A site that provably cannot throw is recorded as such rather than silently skipped**, with the reason
in one sentence. `browse.e2e.ts:980` is the candidate; read it before deciding.

## The harness ordering bug, and the form that also retires the vacuous pair

The failing call site is `onlyReads(page, zona, 2)` - the `connects: 2` sites, which is where *expected
4, received 3* comes from - reached from the test at `session.e2e.ts:769`. `onlyReads` is at
`session.e2e.ts:262-272` and **seven call sites** share it.

**The cheap form**, which the diagnosis states:

```ts
await expect.poll(() => zona.seen("CONFIG", "FETCH")).toBe(2 * connects);
await expect.poll(() => zona.seen("SERIALNUMBER", "FETCH")).toBe(connects);
// only now are the must-be-zero counts meaningful
expect(zona.seen("CONFIG", "EXECUTE"), "config writes").toBe(0);
```

**The better form, and the one this plan takes unless it turns out to be blocked:** expose
`install.phase` on `/dev/session/` the way `/dev/install/+page.svelte` already does, and wait on the
store LEAVING `snapshotting`. That makes the assertion **causal rather than timing-based** - the timer
fetch is the last thing `#snapshot` issues, and `install.svelte.ts:659` sets `phase = "ready"` after
it - and it retires the vacuous pair as a side effect.

**Three things checked rather than assumed, all three already verified during planning:**

1. **The install store is already live on `/dev/session/`.** `src/routes/+layout.svelte:29` calls
   `install.start()` for the whole site, and the session probe uses the root layout. It is not rendered
   there, which is the only reason its phase is invisible.
2. **`$lib/device/install.svelte` is already on the chunk guard's `PERMITTED_SPECIFIERS`**
   (`src/lib/config-shape.spec.ts:86-105`, widened by 07-08). And the guard's walk covers
   `FRONT_DOOR_PAGES`, `BROWSE_PAGE`, `src/lib/ui/` and `src/lib/browse/` - **not** the probe routes -
   so a third static specifier on the session probe is permitted twice over. **Re-run the guard anyway
   and say so**; the page's own header states its specifier count and must be updated with it.
3. **The route's own path string is not duplicated**, so `config-shape.spec.ts`'s probe-route scan is
   unaffected.

**Order matters and it is the whole point: wait first, read the counters second.** Reading first and
waiting after would let a late write slip through unseen, which is the opposite of what `onlyReads`
exists for.

## The assertion that measures nothing

`session.e2e.ts:684-686`:

```ts
const shown = Number(await page.getByTestId("session-writes").innerText());
expect(shown).toBeGreaterThanOrEqual(0);
expect(shown).toBeLessThanOrEqual(await writes(page));
```

The first line is **vacuous over a count**. The second asserts `0 <= shown <= 3`. **It would pass with
the readout wired to a constant zero**, and it is *structurally* guaranteed to measure nothing: the
probe's `$effect` re-reads the shim only on `session.phase` or `session.identity`, and every write it
is about happens after the last such change.

**Somebody hit the race that fails at line 769, understood it, and weakened the assertion instead of
waiting for the event.** Line 769 is the same defect where the value could not be weakened.

Adding `void install.phase;` to that `$effect` makes the readout re-read on every install transition -
including `ready`, i.e. after all three round trips - which turns the pair into a single **equality**:

```ts
expect(shown, "the readout is the shim's own count").toBe(await writes(page));
```

**Retire it properly. Do not delete it and do not leave a range where an equality is now true.**

## Two hazards to fold in

**`artifacts.e2e.ts:19` runs `git rev-parse HEAD` at MODULE LOAD, in each worker**, and every test
asserts `build/source-<sha>.tar.gz` exists. **Committing while the suite runs turns it red for a reason
that has nothing to do with the code.** Moving the read later makes it *worse*, not better - the
archive is named for the sha the BUILD saw. The honest fix reads the build instead of git:
`scripts/postbuild.mjs:75-78` writes exactly one `source-<SHA>.tar.gz` into `build/` and deletes any

`git rev-parse HEAD` with a message that names the real cause** - *"the build is stale, or HEAD moved
during the run"* - instead of an unrelated "file missing". The assertion still bites; only its
diagnosis improves.

Combined with `reuseExistingServer: !process.env.CI`, a stale server from an earlier run is reused and

Phase 10 EPERM trap by another route. `playwright.config.ts` is not edited in this phase, so this half
is a **recorded hazard plus a run-procedure rule**: stop wrangler parents-first including both
`workerd` children, then run `npm run build` yourself before the suite, and state in the SUMMARY that
you did.

**`browse.e2e.ts:669`'s `settled()` returns true at `built >= 4` of 27**, so an assertion may run

## The e2e proof, and the vacuity trap that would ruin it

**A synthetic `contextlost` does not actually lose anything.** A test that dispatches the event and
then asserts the pixels are unchanged would **pass against the unfixed code** - the pixels were never
disturbed. That is the trap, it is the obvious way to write this test, and the plan names it so it
cannot be walked into.

The shape that is not vacuous, in the test's own terms:

1. arrive cold at `/browse/`, scroll a **still, lit** card into view and poll `litCells` above zero -
   deriving the card from `motion === "static" && !restsBlack` exactly as the sort test does, never
   from a typed id;
2. record `before`;
3. dispatch `contextlost` at that canvas **and clear its 9x9 backing store from the test**, which is

4. dispatch `contextrestored`;
5. assert `litCells` returns to `before` **with the card sitting exactly where it was** - no sort, no
   scroll, no reload, no re-register.

**Unfixed, a still card stays black there and the test is red.** That is the assertion.

Then the second branch, in the **same title** rather than a twelfth: an **animating** card, cleared the
same way, with **no `contextrestored` dispatched at all**, must come back on its own next paint -
which is the half the event listener cannot claim. Print both observed counts.

**One title, both branches**, following 11-08's precedent of extending a test rather than adding
another. **Tag it `@webkit`** and update the file header's *"three tests... contribute six"* arithmetic
