## THE FINDING THE USER HAS TO BE TOLD, AND IT IS NOT A FOOTNOTE

**Appending two intervals to POMODORO broke every previously shared POMODORO link.**

The user asked for it in their own words — *"make a 1 minute and a 5 minute one"* — the least ambiguous
note on the whole bench sheet, and one 11-09 correctly shipped ahead of its own checkpoint. The append
was done the safe way: `"1"` and `"5"` went on the END, so indices 0..3 still name 15, 20, 25 and 50,
proved by four payload literals captured before the change.

**And it still cost something, because appending is a RESIZE.** `stamp.ts:324`'s `shapeOf` sums a
rack's option counts:

```ts
const values = knobs.reduce((n, knob) => n + knob.options.length, 0);
return STAMP_ALPHABET[(knobs.length * 7 + values) % STAMP_ALPHABET.length];
```

Four values became six, so **POMODORO's shape character moved `n` → `p`**, and a stamp minted under the
old shape can no longer be called `restored`. The captured literal `xn33333` in `wild-stamps.json` —
a fixture whose own note reads *"Every payload here must keep decoding to `restored` … forever"* and
*"Nothing in this file is ever regenerated"* — now lands `older`. **It is the first payload in the tree
to spend that tripwire, and `stamp.spec.ts` test 3 had pinned the semantics in the abstract since
Phase 10 without anything ever reaching it.**

**Report it plainly, in the user-facing half of the gate, with all four of these sentences:**

1. **What happened** — a POMODORO link shared before this phase now opens on the card with the tuning
   panel at its defaults and an "older link" notice, instead of restoring the knobs it was minted with.
2. **Why it is honest rather than wrong** — `older` is an apology, not a wrong interval. The failure
   mode the design refuses is a link silently rendering a *different* configuration under the same
   name, and that did not happen and cannot happen: the indices were appended, never inserted.
3. **Why the cost is zero in practice** — **the site has never been public.** There is no real POMODORO
   link in anybody's hands. Say it, because it is the difference between a recorded price and an
   incident.
4. **What it costs NEXT time** — the tripwire is now spent once and it is spent per entry, not per
   phase. Every future knob resize on any entry demotes that entry's existing links the same way.
   **11-09.1 and 11-09.2 were both written under an explicit no-new-knob rule for exactly this
   reason**, and both prove it with a before-and-after comparison of every knob's value count.

**Do not let a reader find this in a spec comment.** The code side is already right — the expectation
moved into `stamp.spec.ts` where the reason could be written down, and `wild-stamps.json` was
correctly neither regenerated nor edited. What is missing is that anybody outside the repository knows,
and that is this plan's job.

**And name the second entry rule it implies:** a second entry appearing in that branch of
`stamp.spec.ts` is a signal that somebody is resizing knobs casually. Put it in `docs/TESTING.md`.
