<objective>
Make a tuned configuration travel, and prove the phase's load-bearing claim.

Wave 5. Two jobs that share a wave because they share the same cross-product.

**Sharing.** `STAMP_PREFIX = "z."` and `STAMP_ALPHABET` is base **32**, not 36 — D-12's "base36" is
loose wording and the codec packs five bits per character. BOTOR's five formats (`a`, `b`, `c`, `d`,
`p`) already round-trip a `PadState` as a measured identity, and `decodeStamp` already fails closed
on an unknown format, an out-of-domain field, a set reserved bit, a truncated payload and a non-zero
tail. What it does **not** do is check the stamp belongs to *this* entry: `/c/aurora/#z.pdial`
decodes cleanly and would render Dial under Aurora's name plate — precisely the "subtly wrong one"
SHARE-03 forbids. The entry-consistency check is the whole guard and it is one line.

Lua entries get a HANGAR-owned format letter. BOTOR's payload alphabet is `a`–`v` and its format
letters so far are `a`, `b`, `c`, `d`, `p`; **HANGAR claims `w`, `x`, `y`, `z`** — outside the base-32
alphabet, so BOTOR's own `BitWriter` can never emit them as payload, and BOTOR would need eighteen
more format bumps to collide. **`x`** carries knob indices in catalog order.

**The proof.** The whole shape of TUNE-04 and TUNE-05 rests on one measured claim: no state a visitor
can produce is over 908. A claim that load-bearing belongs in the suite, in the project whose whole
purpose is anti-drift — `pad-invariants.test.js` is the precedent. It runs per wave, never per task,
and never partially. And it is a property of **the pinned compiler**, not a law: `docs/PIN-POLICY.md`
learns that in plan 05-12.

Purpose: SHARE-01 and SHARE-03's mechanism, and the evidence under D-10 as amended.
Output: two modules, two specs, two sweep specs, one config change.
</objective>

**Emit no stamp at the defaults.** A URL with no fragment *is* the base configuration, which is both

**`src/lib/share/stamp.ts`** imports the vendored codec and the wave-3 knob modules, so it is on the
model side and is reached only through the same dynamic import as `model.ts`.

```ts
export const HANGAR_FORMAT_LUA = "x";   // HANGAR claims w, x, y, z

export type Landing =
  | { kind: "none" }
  | { kind: "restored"; indices: Record<string, number> }
  | { kind: "older" }
  | { kind: "unreadable" };

/** "#z.at7ghh1pv8j00" -> "at7ghh1pv8j00". Anything else -> undefined. */
export function parseHash(hash: string): string | undefined;
/** Undefined when every index is at its default. */
export function encodeFor(entry: CatalogEntry, indices: Record<string, number>): string | undefined;
export function decodeFor(entry: CatalogEntry, payload: string | undefined): Landing;
```

**Format `x`'s payload**, one base-32 character each:

```
x <shape> <i0> <i1> … <i(n-1)>
shape = STAMP_ALPHABET[(knobs.length * 7 + sum(values.length)) % 32]   // a tripwire, not a hash
i(k)  = STAMP_ALPHABET[index into knobs[k].options]
```

The shape character is what turns an added, removed or resized knob into a graceful failure instead
of a silently wrong restore.

**The classification, exactly.** This is the one place the two SHARE-03 strings are chosen between,
and the rule must be written down rather than inferred:

| Condition | Landing |
|---|---|
| no hash, or a hash without the `z.` prefix | `none` |
| format `x`, right length, every index in range, **shape character disagrees** | **`older`** |
| format `x`, right length, every index in range, shape agrees | `restored` |
| format `x` with a wrong length, an out-of-alphabet character or an out-of-range index | `unreadable` |
| **format `p` whose preset id equals this entry's `source.presetId`** | **`restored`, at every knob's default index** |
| a BOTOR format that `decodeStamp` refuses | `unreadable` |
| a BOTOR format that decodes but fails the entry-consistency check | `unreadable` |
| format `x` on a compiler entry, or a BOTOR format on a Lua entry | `unreadable` |
| a format letter in neither set | `unreadable` |

**`older` is reachable only through format `x`'s shape character**, because `decodeStamp` fails
closed and cannot tell an old encoding from a corrupt one. That is a real limitation, it is not a
defect, and the SUMMARY must state it so nobody later "fixes" the classifier by guessing.

**The `p` row is not an exception bolted on; it is the one link the consistency check would otherwise
refuse.** `p<presetId>` is what `encodeStamp` emits for an untuned card, so it is exactly the stamp a
BOTOR user's base-card link carries — a legitimate, common inbound URL. Run it through the four steps
below and it fails: step 3 rebuilds by *applying* knobs, every `apply` goes through `withChange`, and
`withChange` deletes `state.preset`, so `encodeStamp(rebuilt)` is a field dump and can never equal
`paurora`. Classifying that `unreadable` would put SHARE-03's apology on a link that is perfectly
correct. So format `p` is decided **before** the consistency check, by one string comparison against
`entry.source.presetId`, and it lands `restored` at every default index — which is the same state the
URL would have shown with no fragment at all. `p<any other preset>` is untouched by this and stays
`unreadable`, which is what test 5 pins.

**The entry-consistency check**, from 05-RESEARCH § The entry-consistency check:

```
1. decode -> PadState, else unreadable.
2. read each of the entry's knob descriptors OUT of the decoded state -> an index vector.
3. rebuild: start from the entry's base state, apply every knob at its read index.
4. require encodeStamp(rebuilt) === the payload. Otherwise unreadable.
```

Step 4 is a one-line assertion that the stamp is reachable from *this entry's* knobs and nothing
else. It also covers a future vendored re-sync widening a field HANGAR does not expose.

**The Vitest projects.** `vite.config.ts` today gives `sweep` a single-file include and excludes that
file from `server` **by file name, never by directory** — the Phase 3 green-and-vacuous lesson. This
plan widens both by the same rule: `sweep` includes `src/**/*.sweep.spec.ts`, `server` excludes it.
`src/lib/config-shape.spec.ts`'s test that counts `pad-invariants.test.js` twice must stay green,
untouched.

**The measured cross-products** (05-RESEARCH): 16,645 HANGAR knob states across the nine presets
(aurora 1,920 · pinwheel 960 · starfield 80 · radar 3,840 · joystick 1,440 · ninepads 7,680 ·
faders 40 · dial 640 · tpad 45), and 1,080 look × touch × sends kind combinations. Worst observed:
906 characters, `none/none/trackpad`. Over budget: zero.
