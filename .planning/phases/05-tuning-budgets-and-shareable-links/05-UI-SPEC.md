> state, `SURPRISE ME` / `RESET ALL`, `COPY LINK` and the stamp restore — docked into the chosen
> panel Phase 4 shipped.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This document EXTENDS `04-UI-SPEC.md`. It restates none of it, and it amends it in exactly one
> place.** Tokens, type scale, spacing, motion, copy rules and the accessibility contract are
> Phase 4's and are binding here unchanged. Where this phase adds something — one colour token, two
> accent uses, one new usage of an existing type role, four new copy states — it is called out
> explicitly and justified. Where it corrects a Phase 4 number that does not survive contact with six
> controls (the 152 px reservation), the correction is stated with its arithmetic.

> shipped test. `src/lib/ui/identity.spec.ts` asserts that `src/app.css`'s `@theme` block declares

> listed in the Component Inventory as a modified file, and it is on the morning list as an open

## Spacing Scale

Phase 4's tokens, unchanged. The values this phase actually consumes:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between knob rows; gap between the meter caption row and its bar; gap between the two meters; gap between wrapped word-row options |
| sm | 8px | Meter bar height; dot-rail dot diameter; minimum gap between dots; gap between `SURPRISE ME` and `RESET ALL` when they wrap |
| md | 16px | Tuning-region padding (Phase 4's, unchanged), and **every vertical gap inside the region**: caption → contents, rack → actions row, actions row → meters, meters → message slot B |
| lg | 24px | Phase 4's panel padding and the hairline gaps, unchanged |
| xl | 32px | Not used inside the region |
| 2xl / 3xl | 48 / 64px | Not used inside the region |

**Declared non-token values, and why each is not spacing:**

1. **44px** — the interactive box floor, Phase 4 exception 1. Every knob row, every word-row option, every swatch, `SURPRISE ME`, `RESET ALL`, `TURN IT DOWN`, `COPY LINK` and the copy-fallback field are at least 44×44.
2. **2px / 6px / 10px radii** — Phase 4 exception 3. This phase uses 2px on meter bars, knob tracks and the copy-fallback field (the "well" radius Phase 4 already assigned to meters and knobs by name), 6px on every button, 10px on the region.
3. **12px label gutter, 88px label column, 120px minimum control width.** These are not spacing — they are the *internal metric of one control*, in the same class as Phase 4's viewport-relative coverflow geometry. All three are on the 4-point scale anyway. **The 12px is horizontal and only ever horizontal**: it is the column gap between a knob's label and its control, and the gap between a meter's three cells. No vertical gap in this phase is 12px.
4. **A 14px fixed line box on every 12px line inside the tuning region.** Every 12px text line in the region sets `line-height: 14px` in place of Phase 4's `1.2` ratio (which computes to 14.4px). The list is closed and complete: the `TUNING` caption, the `SETUP` caption, the `TIMER` caption, both numeric columns of a meter, and the label line of a stacked knob row. **The declaration is `line-height` and nothing else** — family, size, weight, tracking and case are exactly what the type role already says, so the captions and labels stay Quicksand 600 and only the numeric columns are `--font-mono`. **It overrides the shipped `.caption { line-height: 1.2 }` inside the tuning region and nowhere else**: `ZONA IDENTIFIED` in `TryOnDevice.svelte`, and every other Phase 4 caption, keep the ratio. It is a line box, not spacing, and it exists because the region's vertical arithmetic is exact — `(14 + 4 + 8) × 2 + 4 = 56` for the meters block and `14 + 4 + 44 = 62` for a stacked row — and 14.4 divides into neither. A ratio is a readability rule for prose; a fixed box on a one-word caption or a numeric readout is a layout guarantee, and this region is contracted on the guarantee.

`overflow-x: auto` and `overflow-x: scroll` appear **nowhere** inside the tuning region. This is a grep-checkable prohibition and it is D-11's "horizontal scroll never".

| Role | Size | Weight | Line Height | Tracking | Case | Used for in this phase |
|------|------|--------|-------------|----------|------|------------------------|
| Micro | 12px | 600 | 1.2 | 0.18em | UPPERCASE | `TUNING` (Phase 4's caption, unchanged), `SETUP`, `TIMER`, and every button label: `SURPRISE ME`, `RESET ALL`, `TURN IT DOWN`, `COPY LINK`, `LINK COPIED` |
| Micro (title) | 12px | 600 | 1.2 | 0.01em | Sentence | **New usage:** every knob label (`Tempo`, `Ring colour`, `MIDI channel`), and every word-row option (`Major`, `C4`, `Relative`) |

| Heading (20) / Display (28) | — | — | — | — | — | **Not used in this phase** |

**Every 12px line inside the tuning region sets a fixed 14px line box** — spacing exception 4 above.
The declaration is `line-height: 14px` and *nothing else*: it changes no family, no size, no weight,
no tracking and no case. The `TUNING`, `SETUP` and `TIMER` captions and the stacked-row labels are
therefore Quicksand 600 exactly as the Micro rows above specify, sitting in a 14px box instead of a
14.4px one. **Only a meter's two numeric columns are monospaced**, and they add
`font-family: var(--font-mono); font-weight: 400; font-variant-numeric: tabular-nums` on top of that
same box. The fixed box replaces the `1.2` ratio because the region's arithmetic is exact —
`(14 + 4 + 8) × 2 + 4 = 56` for the meters block, `14 + 4 + 44 = 62` for a stacked knob row — and 14.4
divides into neither. The ratio rule governs type roles carrying sentences; every line this touches is
a one-word caption, a knob label, or a number.

**Tabular numerals are mandatory on every changing number**: `702 / 908`, `77%`, and the rail's
integer readout. A budget that jitters horizontally as it counts is the exact failure `--font-mono`
was introduced for in Phase 4 W-03. Nothing else in this phase is monospaced — the fit-ladder line,
the over-budget sentence and every label are Quicksand.

## Color

Phase 4's eight tokens, unchanged, plus **one** new token. The justification is below and it is an
accessibility argument, not a taste argument.

| Role | Token | Value | Contrast on `#000` | Usage in this phase |
|------|-------|-------|--------------------|---------------------|
| Dominant (~60%) | `--color-ground` | `#000000` | — | The region's ground, every bar track's interior, the gutters between swatches |
| Secondary (~30%) | `--color-ink` | `rgb(214 255 78 / 0.72)` | **9.26:1** | Knob labels; settled meter numerals and percentages; the over-budget sentence; the back-off explanation; the stamp notice; the `COPY LINK` quiet line; the copy-fallback URL |
| Secondary quiet | `--color-ink-quiet` | `rgb(214 255 78 / 0.55)` | **5.57:1** | The `TUNING`, `SETUP` and `TIMER` captions; unselected word-row options; the fit-ladder line; **stale** meter numerals during a debounce; the `measuring…` word |
| Secondary dim | `--color-ink-dim` | `rgb(214 255 78 / 0.50)` | **4.72:1** | The label of `RESET ALL` when it is disabled, and of `KEEP ON DEVICE` (Phase 4's, unchanged) |
| Structure | `--color-line` | `rgb(214 255 78 / 0.40)` | **3.31:1** | Unselected dot-rail dots; every secondary button's border; the swatch's 1px hairline; the copy-fallback field's border; the 2px left rule on the fit-ladder and stamp messages |
| Structure soft | `--color-line-soft` | `rgb(214 255 78 / 0.20)` | 1.58:1 | Bar and track backgrounds; the default-position marker under every knob; the region's dashed border (Phase 4's, unchanged) |
| Accent (~10%) | `--color-accent` | `#d6ff4e` | **18.27:1** | See the reserved list below |
| Glow | `--color-glow` | `rgb(214 255 78 / 0.18)` | — | Unchanged; the primary button's hover bloom only. **No glow is added to any meter or knob** |
| **Over budget** | **`--color-over`** | **`#ff3b30`** | **5.92:1** | **New. Exactly three uses, listed below** |

### Accent — the reserved list, restated in full with two additions

Phase 4 reserved accent for six things. This phase adds two and takes nothing away. The canonical
list is now:

1. The splash wordmark and the lime rectangles punched through the glyph field.
2. The solid triangles in the name plate.
3. The `TRY ON DEVICE` button fill when it is enabled.
4. The focus ring.
5. The header wordmark.
6. The one walking cell in the 9×9 loading motif.
7. **New — the fill of the two budget meters, while in budget.**
8. **New — the selected value of a knob**: the filled dot on a dot rail, the fill and thumb on a
   detent track, the text of the selected word-row option, and the 2px selection ring around the
   selected swatch.

Both additions say the same thing accent has always said on this site: *this is the live value*.
Neither is a border, neither is body text, neither is on a disabled control.

**Why the meter fill must be full-strength accent and not `--color-ink`.** The over-budget meter
turns `--color-over`. For a viewer who cannot distinguish red from yellow-green by hue, the two fills
must still be told apart by luminance, which WCAG puts at 3:1 for a non-text graphical object:

- `--color-accent` `#d6ff4e` → relative luminance **0.8637**
- `--color-over` `#ff3b30` → relative luminance **0.2460**
- ratio = `(0.8637 + 0.05) / (0.2460 + 0.05)` = **3.09:1** ✓ clears 3:1

If the fill were `--color-ink` (lime at 0.72 over black, composited `#9ab838`, luminance 0.4129) the
same ratio would be **1.56:1** — indistinguishable. The bright fill is therefore required, not chosen.

### `--color-over` — the third colour, and the case for it

Phase 4 ruled that no third colour earned itself, and predicted the first one would be a Phase 7
flash-write warning. This phase introduces one earlier. The case, in order:

1. **It is a stated user requirement, three times.** ROADMAP Phase 5 success criterion 3, REQUIREMENTS
   TUNE-05, and `05-CONTEXT.md` D-09 (marked `[user]`) all say the offending meter *turns red*.
2. **Lime cannot carry the failure, because lime already means "go" 24 px away.** Full-strength accent
   is the fill of an *enabled* `TRY ON DEVICE`. Over budget, that button becomes disabled — it loses
   its lime and goes transparent with a dim label. So the moment the panel most needs to shout is the
   moment it would get *quieter and less lime*. Signalling the failure with more lime would put "go"
   and "stop" in the same hue, in the same 372 px column, in the same instant. That is a semantic
   collision, not a preference.
3. **The value is picked for contrast, not for mood.** `#ff3b30` clears **5.92:1** on black (AA for
   12px text, which the numerals are) *and* **3.09:1** against `--color-accent` (the non-text
   threshold, so the two fills are distinguishable by luminance alone). A darker red would fail the
   first; a brighter red would fail the second. The arithmetic is in the table above.

**Exact scope. `--color-over` is used for these three things and nothing else:**

1. The offending meter's bar fill, and a `2px` outline at `2px` offset around that meter's track.
2. The offending meter's numerals (`941 / 908`) and its percentage (`104%`).
3. A `2px` left rule on the over-budget message block.

It is **never** a button fill, never a button border, never a knob, never body text, never a border
anywhere else, and never applied to `TRY ON DEVICE` (which keeps Phase 4's disabled treatment — a
red CTA would say "dangerous" when the truth is "not yet"). The over-budget *sentence itself* stays
`--color-ink`; red is a marker beside it, not the text of it.

**Colour is never the only channel.** Over budget is carried by six independent signals: the red, the
outlined-and-completely-full bar, numerals that exceed 908, a percentage above 100, a disabled
primary control with a written reason, and a sentence naming the knob. WCAG 1.4.1 is satisfied with
the red removed entirely, which is the test that makes introducing it safe.

### Swatches, and the boundary of the pad exemption

A colour knob paints its options as real firmware RGB — a cyan square, an orange square. This is the
same exemption Phase 4 granted the pad faces ("those pixels are content, like a photograph"),
narrowed to its minimum: **the exemption extends to colour swatches and to nothing else in this
phase.** A swatch is a 1:1 preview of the light the LEDs will emit; rendering it in lime would be a
lie about the value, and rendering it as a word would be a worse one. Everything *around* a swatch —
its 1px hairline, its selection ring, its label — stays on the two-colour ladder. A checker looking
at a screenshot will see non-lime squares inside the knob rack; that is correct and required by
TUNE-01.

No CSS in this phase authors a colour the simulator did not: no gradients on a swatch, no tint, no
glow, no `filter` of any kind on a swatch or a pad.

### Vertical arithmetic

| Band | Height |
|------|--------|
| Region padding, top | 16 |
| `TUNING` caption | 14 (the region's fixed line box, spacing exception 4) |
| gap | 16 |
| Message slot A (stamp notice), when present | **auto** + 16 gap |
| Knob rack, `r` row-layout knobs and `w` word rows | `48r + 66w − 4` |
| gap | 16 |
| Actions row (`SURPRISE ME` / `RESET ALL`) | 44 |
| gap | 16 |
| Meters block | **56** (`(14 + 4 + 8) × 2 + 4`) |
| Message slot B, when present | 16 gap + auto |
| Region padding, bottom | 16 |

**Every vertical gap in the region is 16px** — Phase 4's `md`, so this phase still adds no new spacing
value. The 12px that appears elsewhere in this document is the *horizontal* column gap between a
knob's label and its control, and it is never used vertically. No gap in the region is spent twice at
two different values.

**Both message slots are billed `auto`.** Slot A's longest string — the older-version sentence, ~123
characters — wraps to three lines of Body 16px/1.5 (72px) inside the message block's ~324px content
box, while the shortest wraps to two (48px). Reserving one number for it would be a guess, and it
costs nothing not to: **slot A's height is settled at landing, before the panel is ever visible**, so
whatever it resolves to, every band beneath it in this table is laid out once and never moves again.
When it is removed — on the first knob change or on `RESET ALL` — the region shortens by exactly that
amount, which is an explicit, visitor-initiated change and one of the two message-slot exceptions the
size invariant already declares. Slot B is `auto` for the reason already given: it moves only inert
content beneath it.

**The height formula.** A row-layout knob is 44px plus a 4px gap = 48. A word row always stacks, so it
is 62px plus a 4px gap = 66. The rack drops its trailing gap. With no messages:

> **`194 + 48r + 66w − 4`** — where `r` is the number of row-layout knobs and `w` the number of word
> rows.

The pure-row case is the **lower bound** of that formula, and the figure to quote when knob kinds are
not yet known: **`194 + (48n − 4)`** → **334px** at n=3, **478px** at n=6. Any entry with a `scale` or
a `note` knob is taller: three knobs of which one is a word row is `194 + 96 + 66 − 4` = **352px**; six
knobs of which two are word rows is `194 + 192 + 132 − 4` = **514px**.

### The size invariant — what D-11 actually protects, and the correction

D-11 says "the panel must not resize when the region fills", and Phase 4 sized the reservation at
152px = 96px rack + 56px meters. **The meters half is exactly right and is honoured to the pixel: the
meters block is 56px.** The 96px half does not survive contact with six controls, and the arithmetic
says why: Phase 4's own accessibility contract puts a 44×44 floor under every control, so six knobs
plus an actions row cannot occupy less than `44 × 7 + 4 × 6 = 332px` however they are arranged. No
layout closes that gap; two columns only trades height for a control area too narrow to hit.

So the reservation is a floor, not a ceiling — which is what `min-block-size` already says in the
shipped CSS — and the invariant this phase contracts is the one Phase 4's own comment was written to
protect:

> **The primary control never moves.** `TRY ON DEVICE`, its honesty line and the connect-state region
> sit *above* the tuning region and their position is byte-identical to Phase 4's. The region grows
> downward. **The honesty line's slot carries a reserved height across both of the strings it can
> hold** — Phase 4's idle sentence and this phase's over-budget reason — so that swapping one for the
> other cannot change its line count and shove the rack and the meters down at the exact instant a
> knob crosses 908. The reservation and its mechanism are specified under "3. `TRY ON DEVICE` is
> disabled, with its reason".
>
> **The region's height is fixed the moment an entry is chosen.** It is a pure function of that
> entry's knob count and knob kinds, settled before the panel animates in, and it does not change
> while a visitor turns knobs — not when a meter changes, not when a bar crosses 908, not when the
> numerals go stale.
>
> **The two message slots are the only exception, and they move only inert content.** Slot A sits
> above the rack and is decided at landing, before the panel is visible. Slot B sits below the
> meters; when it appears, everything the visitor is looking at — the pad, the primary control, the
> knobs, the meters — stays exactly where it is, and the only thing that moves is the hairline and
> the disabled `KEEP ON DEVICE` beneath it.
>
> **Stepping while chosen** re-fills the region with another entry, which may have a different knob
> count. The height change is masked inside Phase 4's existing 260ms name-plate crossfade: the
> region's contents fade out over 130ms, the height changes at the midpoint, the new contents fade in
> over 130ms. Reduced motion: instant swap, per Phase 4.

### Knob row layout, and the phone-width rule (D-11: wrap, never scroll)

**Row layout (default).** `display: grid; grid-template-columns: minmax(88px, 34%) 1fr; column-gap: 12px; block-size: 44px; align-items: center;`
Label in the left column, control in the right.

**Stacked layout.** Label on its own 14px line box (spacing exception 4), a 4px gap, then the control
full width beneath it inside a 44px box: row height `14 + 4 + 44` = **62px**. Used in exactly two
cases:

1. `@container (width < 220px)` — every row stacks. At a 320px viewport the region's content box is
   192px, which leaves 92px for a control; the floor is 120px, so it stacks. At 375px the content box
   is 247px, leaving 147px, and rows stay side-by-side.
2. **Every word row always stacks**, at every width, so its options get the full content width to
   wrap into. A six-option scale knob at 340px lays out three per line over two lines.

**Word rows wrap** (`flex-wrap: wrap; gap: 4px`) and their row height is `auto` with a 44px floor.
Nothing in the rack ever scrolls horizontally, at any width, in any state.

## The knob vocabulary (TUNE-01, D-01, D-02)

D-02: one widget per kind family, chosen by `kind`, never per configuration; the panel cannot tell a
compiler-driven entry from a Lua one. That holds because **every knob in HANGAR is the same thing:
an ordered list of 2 to 16 discrete values and an index into it.** Compiler entries index a curated
value set per `PadState` field; Lua entries index `LuaKnob.values`. The widget is chosen by two facts
only — the `kind`, and `n = values.length`.

### Three widgets, twelve kinds

| Widget | Kinds | Condition | What it renders |
|--------|-------|-----------|-----------------|
| **Swatch row** | `colour` | every value parses as three integers in 0..255 | `n` swatches, each 28×28 painted in that RGB, inside a 44×44 hit box, 4px gaps, 1px `--color-line` hairline, 2px `--color-accent` ring at 2px offset on the selected one |
| **Word row** | `direction`, `mode`, `bend`, `spring`, `scale`, `note` | every value resolves to a word through the kind's table below, **and** `n ≤ 8` | `n` words, Micro (title), selected in `--color-accent`, unselected in `--color-ink-quiet`, each in a 44px-tall box with 12px inline padding, wrapping |
| **Rail** | `speed`, `size`, `count`, `feel`, `amount`, and anything above that falls through | always available | `n ≤ 8`: **dot rail** — `n` 8px dots, gap `max(4px, (W − 8n) / (n − 1))`, selected `--color-accent`, others `--color-line`. `n ≥ 9`: **detent track** — a 4px `--color-line-soft` track filled to the index in `--color-accent`, with a 12px `--color-accent` thumb dot |

The fall-through is deliberate and total: a `colour` whose values are not RGB, a `scale` whose
semitone set is not in the table, a `note` with more than 8 options, and every kind not named above
all render as a rail. **No knob can ever fail to render.**

`arms`, `pulses`, `trail`, `tempo`, `velocity`, `hue spread` and every other ordinal are rails.
Across everything shipped today the only `n ≥ 9` knob is `MIDI channel` at 16.

### The default marker

Every widget shows where "home" is: a **2px `--color-line-soft` dot, centred 4px below** the option
at the knob's default index — beneath the dot, beneath the word, beneath the swatch, or on the track
at the default position. It is decorative (1.58:1) because its meaning is carried by `RESET ALL`,
which is a labelled control on the same screen. It is what makes double-click-to-reset discoverable
without a tooltip, and it is what lets a visitor see at a glance which knobs a shared link moved.

### Readouts — the pad is the readout, with three exceptions

A knob's raw value is a **Lua literal** (`"0,200,255"`, `"3,5,7"`, `"0,2,4,5,7,9,11"`). Those strings
are not display copy and must never be shown to a visitor. The design position is the one the whole
site rests on: **the pad sits directly above the panel at Phase 4's
`--pad-hero: clamp(260px, 52vmin, 560px)` — 260px on the narrowest phone, 560px on a large desktop —
and it updates on the same tick as the knob (D-05/D-06). It is the readout.** The rack shows position,
not value.

The three exceptions, where the number or the word *is* the information:

| Kind | Readout | Example |
|------|---------|---------|
| `colour` | none — the swatch is the value. Accessible name only (see Accessibility) | — |
| `note` | the scientific pitch name, C4 = 60, sharps never flats: `NAMES[n % 12] + (⌊n / 12⌋ − 1)` | `24 → C1`, `36 → C2`, `60 → C4`, `30 → F#1` |
| `scale` | the mode name from the table below | `0,2,4,5,7,9,11 → Major` |
| **any rail** whose every value is a single integer | that integer, right-aligned in the row, `--font-mono` 12px, `--color-ink` | `110`, `42`, `3` |
| any rail whose values are not all single integers | none | `3,5,7` shows nothing |

The integer readout is the **raw literal, never reinterpreted**. A MIDI channel whose Lua literal is
`0` displays `0`, because the firmware is zero-based and showing `1` would be HANGAR silently
renumbering a value it is about to write to someone's hardware. This is recorded as an open question,
not papered over — see the morning list.

### Word tables

**`scale`** — semitone-offset set → name. Covers every set shipped by Phase 8 and the compiler's own
four `ScaleKind` members:

| Value | Word | | Value | Word |
|-------|------|-|-------|------|
| `0,2,4,5,7,9,11` | Major | | `0,3,5,7,10` | Minor pentatonic |
| `0,2,3,5,7,8,10` | Minor | | `0,2,4,7,9` | Major pentatonic |
| `0,2,3,5,7,9,10` | Dorian | | `0,2,4,6,8` | Whole tone |
| `0,2,4,5,7,9,10` | Mixolydian | | `0,2,3,7,9` | Kumoi |
| `0,2,4,6,7,9,11` | Lydian | | `0,1,5,7,10` | Insen |
| `0,1,3,5,7,8,10` | Phrygian | | `chromatic` / `major` / `minor` / `pentatonic` | Chromatic / Major / Minor / Pentatonic |

**`direction`** (compiler `Axis`): `x → Across`, `y → Down`, `diagonal → Rising`, `antidiagonal → Falling`.
**`mode`** (`DialMode`): `relative → Relative`, `absolute → Absolute`.
**`bend`** (`BendAxis`): `none → No bend`, `x → Left-right`, `y → Up-down`.
**`spring`** (`spring` + `springTo`): `off → Stays put`, `centre → Springs to centre`, `zero → Springs to zero`.

## Knob interaction contract

Every knob is a **real form control with a real label**, operable by keyboard alone, with a visible
focus ring. There is no `div` pretending to be a slider anywhere in this phase.

| Widget | Markup | Keyboard, for free from the platform |
|--------|--------|--------------------------------------|
| Rail (both skins) | one `<input type="range" min="0" max="n−1" step="1">`, `opacity: 0`, absolutely positioned over the painted dots or track, filling the 44px box. A real `<label for>` carries the visible label | `←` `→` step one, `↑` `↓` step one, `Home` / `End` jump to the ends, `PageUp` / `PageDown` step |
| Word row | `role="radiogroup"` with `aria-labelledby` on the visible label, containing real `<input type="radio">` inside `<label>`s | Tab enters at the selected option only; `←` `→` `↑` `↓` move *and* select; the group is one tab stop |
| Swatch row | identical to the word row; the `<label>`'s text is a visually-hidden colour name and the visible content is the painted square | as above |

**The range input's focus ring is drawn on its wrapper** with `:has(:focus-visible)`, using Phase 4's
exact ring (`2px solid #d6ff4e`, `outline-offset: 4px`, `border-radius: inherit`), because the input
itself is invisible. A knob is never focusable without a visible ring.

### States

| State | Rail | Word row | Swatch row |
|-------|------|----------|------------|
| Rest | selected dot / fill / thumb `--color-accent`; others `--color-line`; track `--color-line-soft` | selected `--color-accent`, others `--color-ink-quiet` | selected has a 2px accent ring at 2px offset |
| Hover (row) | unselected dots `--color-line` → `--color-accent` at 40% opacity; 140ms `ease-out` | hovered option `--color-ink-quiet` → `--color-ink`; 140ms | hovered swatch's hairline `--color-line` → `--color-accent`; 140ms |
| Focus | ring on the wrapper | ring on the focused option | ring on the focused swatch |
| Drag / active | the selected dot or thumb scales to 1.25× while the pointer is down | option background `rgb(214 255 78 / 0.08)` while pressed | ring thickens to 3px while pressed |
| Disabled | **does not exist.** No knob is ever disabled in this phase | | |

Reduced motion: no scale on drag, no transition on hover — colour change only, per Phase 4's
"Hover lifts → colour change only".

### Reset one knob (TUNE-06)

| Input | Behaviour |
|-------|-----------|
| **Double-click** anywhere on the knob's control area | the knob returns to its default index |
| **`Delete` or `Backspace`** while the control is focused | the same |
| **Long press ≥ 500ms** on a coarse pointer (`@media (pointer: coarse)`) | the same |

`Escape` is deliberately **not** a reset: Phase 4 binds `Escape` to un-choosing the panel and the two
must not collide. The discoverable path to reset is `RESET ALL`; the per-knob gestures are the
shortcut the roadmap asked for, and the default marker under every knob is what makes them guessable.

Confirmation is the movement itself: the selection lands on the marked default position. There is no
pulse, no flash, no toast.

### Touch, and iOS in particular (DEGR-01, D-16, D-17)

- `touch-action: pan-y` on every knob row. A horizontal drag adjusts the knob; a vertical drag scrolls
  the page. This matches Phase 4's coverflow touch rule and, as a side effect, removes double-tap zoom
  from the row so the double-click reset is safe on iOS.
- `-webkit-touch-callout: none; user-select: none` on every knob control, so the 500ms long-press
  reset does not raise iOS Safari's selection callout instead.
- The range input's native thumb is hidden but the input still receives the tap position on iOS, so a
  tap anywhere on the rail jumps to that detent and a drag tracks it — the same behaviour as on
  desktop.
- **Every `<input>` that shows text is 16px or larger.** The only one in this phase is the copy
  fallback field, and it is 16px specifically because iOS Safari zooms the viewport when a field
  smaller than 16px takes focus. The range inputs carry no text and are `opacity: 0`.
- Hit boxes are 44×44 minimum everywhere, including each swatch and each word-row option.

## `SURPRISE ME` and `RESET ALL` (TUNE-03, TUNE-06, TUNE-07, D-03, D-04, D-11)

D-11 places them at the rack's end as secondary controls. They share one 44px row:
`display: flex; flex-wrap: wrap; gap: 8px; justify-content: space-between`, each `flex: 1 1 auto`.
They sit side by side when they fit and stack into two 44px rows when they do not — never truncated,
never scrolled. Both are Phase 4's secondary button treatment: `background: transparent`,
`border: 1px solid var(--color-line)`, `border-radius: 6px`, `min-block-size: 44px`,
`padding-inline: 16px`, label Micro uppercase in `--color-ink`. Hover: border → `--color-accent`,
140ms. Neither ever takes an accent fill; the only filled button on this panel is `TRY ON DEVICE`.

**`SURPRISE ME`** — always enabled. On click it draws a fresh index for every knob and re-rolls until
the state fits (D-04); for Lua entries every draw fits by construction, so the roll is a single pass.
While the roll is running the button is a real `disabled` button with `aria-busy="true"` and **its
label does not change** — a label that flickers for 80ms is worse than a brief disable. The knobs do
not move until the roll settles. If the bounded roll has not landed within **400ms**, the ladder-
resolved state is applied instead, which by construction fits. The result therefore never lands over
budget, and `SURPRISE ME` has no failure state.

**`RESET ALL`** — returns every knob to its default index. It is a real `disabled` button when every
knob is already at its default, with Phase 4's disabled treatment (label `--color-ink-dim`,
`cursor: not-allowed`). It carries **no adjacent reason line**: Phase 4's DEGR-02 rule exists for the
install controls, where the cause of a disabled state is invisible (a browser capability, a port). Here
the cause is the rack directly above the button, with every marker showing every knob already at home.
A sentence explaining that would be noise.

There is **no confirmation dialog** on `RESET ALL`. It is not destructive: nothing is written, nothing
is lost that a second knob turn cannot recreate, and the roadmap asks for it as a one-click.

Both controls are absent entirely when the entry has no knobs.

## The two meters (TUNE-03, D-07, D-08)

Two meters, `SETUP` and `TIMER`, in that order. One meter is 26px:

```
SETUP                                       702 / 908    77%     ← 14px line box: caption and numerals alike
████████████████████████████████░░░░░░░░░░░░░░░░░░░░░░░░░       ← 4px gap, then 8px bar
```

- **Row**: `display: grid; grid-template-columns: auto 1fr 40px; column-gap: 12px; align-items: baseline`.
  Caption left — Micro, uppercase, `--color-ink-quiet`, **Quicksand 600, not monospaced**. Numerals
  right-aligned in the middle column, percentage right-aligned in the 40px column; **only these two
  numeric columns** are `--font-mono` 12px with `font-variant-numeric: tabular-nums`. **All three
  cells carry the region's fixed `line-height: 14px`** (spacing exception 4) — the caption included,
  which is exactly what makes the row 14px and the block 56px rather than 14.4 and 56.8.
- **Bar**: full content width, `block-size: 8px`, `border-radius: 2px`, track `--color-line-soft`,
  fill `--color-accent`, fill width `min(100%, used / 908)`. The fill's width transitions over 120ms
  `ease-out` so it glides when a measurement lands; instant under reduced motion.
- The two meters are separated by 4px. The block is exactly 56px.

### Percentage

`⌊used / 908 × 100⌋` while `used ≤ 908`, and `⌈used / 908 × 100⌉` while `used > 908`. So `100%` means
exactly at the limit and never means "nearly there": 907 reads `99%`, 908 reads `100%`, 909 reads
`101%`, 941 reads `104%`.

### The four meter states

| State | When | Numerals | Bar | ARIA |
|-------|------|----------|-----|------|
| **Measuring** | no measurement has ever been shown — the formatter WASM is still resolving (D-08) | the word `measuring…` in `--font-mono` `--color-ink-quiet`, in the numerals column; the percentage column is empty | track only, no fill | `aria-busy="true"` on the meters block |
| **Settled** | a measurement is current | `702 / 908` and `77%` in `--color-ink` | lime fill | — |
| **Stale** | a knob moved and the debounced recompile (≈120ms, D-06) has not landed | the *same last-known numbers*, dropped from `--color-ink` to `--color-ink-quiet` over 100ms linear | fill unchanged | `aria-busy="true"` |
| **Over budget** | `cost().fits === false` for this event | `941 / 908` and `104%` in `--color-over` | fill 100% in `--color-over`, plus `outline: 2px solid var(--color-over); outline-offset: 2px` on the track | see the live region below |

**Why staleness is an alpha change and not the `measuring…` word.** During a drag the debounce fires
several times a second; swapping numerals for a word and back would strobe. An alpha change moves no
layout, cannot reflow, and reads as "these numbers are catching up" rather than "these numbers are
gone". The word `measuring…` is reserved for the very first measurement, when there is genuinely
nothing to show. **Staleness never applies while over budget** — the numerals stay at full
`--color-over`, because dimming a warning is wrong.

**The word `measuring…` is not "loading".** Phase 4 forbids "loading" and requires every wait to name
what it is waiting for. This wait is a character count being taken with the pinned minifier, and
`measuring…` says exactly that.

### The formatter never loads at all

If the WASM formatter fails to resolve (blocked, 404, offline), the meters block is replaced by one
Body line in `--color-ink-quiet` — copy in the contract. `TRY ON DEVICE` is **not** disabled by this
in Phase 5, which connects and identifies and needs no compiler. Everything else in the region keeps
working: knobs turn, the preview animates, `COPY LINK` copies.

### Timer of length zero

MORPH ships an empty Timer. Its meter reads `0 / 908` and `0%` with an empty bar. That is a true
measurement, not a dead meter, and it tells the visitor something real: this configuration has no
timer. The visually-hidden expansion says so in words.

## The over-budget state (TUNE-05, D-09, D-10)

Reachable only for compiler-driven entries (D-10). Three things happen at once, and they are three
different jobs — none of them repeats another's wording.

### 1. The offending meter turns

`--color-over` fill, `--color-over` numerals and percentage, 2px `--color-over` outline on the track.
If both events are over, both meters turn.

### 2. The message block, next to the knobs

**Message slot B**, below the meters, with a 2px `--color-over` left rule. This is the "surfaced next
to the knobs and never travels to the wire" half of success criterion 3.

- **One line naming the knob**, Body, `--color-ink`. The named knob is the most recently moved knob
  whose change crossed the boundary.
- **The back-off control**, `TURN IT DOWN`, Phase 4's secondary button treatment, 44px, at the block's
  end. One click, no confirmation.
- **One quiet line beneath it**, Body, `--color-ink-quiet`, saying exactly what the click will do and
  what the meter will read afterwards. The resulting number is real: for the knob case it is the
  measurement before the knob moved; for the ladder case it is `fit()`'s own `saves` for that step.

If the state arrived over budget without a knob having moved — a landed stamp, or the known
pre-existing 941/908 preset debt recorded in STATE.md — there is no knob to name. The block says so
in its own words and `TURN IT DOWN` applies the fit ladder's first step instead. The label is the same
in both cases, because "turn it down" is literally what both do.

The label is `TURN IT DOWN` and deliberately **not** `PUT IT BACK`: Phase 7 owns `PUT BACK` for
restoring a module's own configuration, and two controls a phase apart with near-identical names on
the same panel would be a genuine hazard on hardware people paid for.

### 3. `TRY ON DEVICE` is disabled, with its reason

Phase 4's exact disabled treatment: a real `disabled` button (never `aria-disabled` alone), fill
transparent, `1px solid var(--color-line)`, label `--color-ink-dim`, label text unchanged, with the
reason rendered adjacent in the honesty line's position. The reason names the budget; it does not
repeat the knob sentence.

**The honesty line's height is reserved across both strings, so nothing below it moves.** That slot
holds either Phase 4's idle sentence (`Connects to your ZONA and identifies it. Writing arrives in the
next release — this never writes.` — 97 characters) or this phase's over-budget reason (89 characters
in its longest, `Setup and Timer`, form). Both are Body 16px/1.5, and at the panel's full 372px column
the longer wraps to three lines while the shorter wraps to two. Without a reservation the swap changes
the slot's line count and shifts the whole tuning region — the rack, the meters, the thing the visitor
is staring at — by roughly 24px, at the exact instant a knob crosses 908. That is the worst possible
moment for the page to jump.

The reservation is two declarations:

1. **`min-block-size: 72px`** on the slot — three Body lines at 16px/1.5.
2. **The slot is a one-cell grid** holding *both* strings at `grid-area: 1 / 1`, with the inactive one
   `visibility: hidden`. Its height is therefore the taller of the two at whatever width the panel
   currently is, not only at 372px, and it is identical before and after the swap. This is a sizing
   twin, not a duplicate for an AT: `visibility: hidden` already removes the hidden copy from the
   accessibility tree, and it additionally carries `aria-hidden="true"`.

The result is the contract: when a knob crosses 908, the only things that change above the region are
which sentence is visible and the button's fill. Nothing moves.

**Precedence when there are two reasons.** On a browser that cannot install at all (`unsupported`,
`insecure`), the capability reason wins and the budget reason is not shown — the permanent obstacle
is the honest one to state. The message block near the knobs still appears in full, because an
over-budget configuration still matters to someone who is about to share it.

## The stamp, and the three landings (SHARE-01, SHARE-03, D-12, D-13)

Envelope `/c/<id>#z.<format><payload>`, in the hash and never the query string.

**A URL that carries a stamp lands CHOSEN.** A bare `/c/<id>` still lands un-chosen exactly as Phase 4
ships it. The reason: the whole content of a tuned link is what somebody moved, and the knobs are the
only evidence of it — landing a tuned link on a closed panel would show the tuning and hide the
tuner. Phase 4's route logic is otherwise untouched, and the stamp is applied after the coverflow has
centred the entry (D-13).

| Landing | Knobs | Message slot A |
|---------|-------|----------------|
| **No stamp** | defaults | none |
| **Stamp decoded** | restored exactly to the decoded indices; the default markers make the moved knobs visible at a glance | one Body line in `--color-ink` with a 2px `--color-line` left rule, naming `RESET ALL` |
| **Stamp unreadable** | defaults, never a partial restore (D-13) | one Body line in `--color-ink` with a 2px `--color-line` left rule |

The unreadable case splits into two strings, one condition apart, because asserting "older version"
about a corrupted stamp would be a small lie and this site does not tell those:

- the format letter is known but its version is behind the current one → the older-version sentence
- the stamp is undecodable, or its payload does not match the entry's current knob count → the
  neutral sentence

Both land on the base configuration and both name the configuration, so the visitor knows what they
are looking at.

Message slot A carries `role="status"` so it is announced after hydration without a container that
was already live at first render. It **disappears on the first knob change or on `RESET ALL`** — it
describes how the panel arrived, and once the visitor has taken over it is no longer true.

## Interaction Contract

### Tab order inside the panel

Phase 4's order with this phase's controls inserted, and nothing reordered:

> coverflow listbox → `◀` → name → `▶` → **`TRY ON DEVICE`** → knob 1 → … → knob n →
> `SURPRISE ME` → `RESET ALL` → `TURN IT DOWN` (only when over budget) → **`KEEP ON DEVICE`** →

Each word row and each swatch row is **one** tab stop (native radio-group roving focus), so a

### Keyboard, complete

| Action | Key |
|--------|-----|
| Move between knobs | `Tab` / `Shift+Tab` |
| Change a rail | `←` `→` `↑` `↓` `PageUp` `PageDown` `Home` `End` |
| Change a word row or swatch row | `←` `→` `↑` `↓` |
| Reset one knob | `Delete` or `Backspace` on the focused control |

## Accessibility Contract

| Concern | Contract |
|---------|----------|
| Knob labelling | Every knob is a real labelled form control. Rails use `<label for>` on a real `<input type="range">`; word and swatch rows use `role="radiogroup"` + `aria-labelledby` over real radios. No knob has a placeholder label, a title-only name, or an implicit one |
| Rail value announcement | `aria-valuetext` carries the readout: the integer (`110`), the note name (`C4`), the mode name (`Major`), or `Position {i} of {n}` when the value has no display form. Never the raw Lua literal |
| Swatch names | Each swatch's accessible name is a hue word plus its position: `Cyan, 1 of 5`. The word comes from a 12-hue table in 30° buckets (Red, Orange, Amber, Lime, Green, Spring green, Cyan, Azure, Blue, Violet, Magenta, Rose) with three neutrals below 10% saturation (White above 80% lightness, Grey above 20%, otherwise Black). Verified against the shipped sets: `0,200,255 → Cyan`, `255,90,0 → Orange`, `0,255,120 → Spring green`, `255,255,255 → White`, `120,0,255 → Violet` |
| Default marker | Announced through `aria-describedby` on the group once, as `Default is {word or position}.` — not repeated per option |
| **Meters** | **No ARIA role at all.** The caption, the numerals and the percentage are real text in the DOM and every screen reader reads real text. The bar is `aria-hidden="true"` decoration. The visible `702 / 908` is `aria-hidden` and paired with a visually-hidden expansion: `Setup uses 702 of 908 characters, 77 per cent.` (and `Timer uses 0 of 908 characters. This configuration has no timer.` when the event is empty) |
| Why not `role="meter"` | DEGR-01 requires iOS Safari, where VoiceOver's support for `role="meter"` is partial and inconsistent. Real text plus a hidden expansion is understood by every AT on every platform, and it cannot regress |
| Meters and the tab order | Not focusable, no `tabindex`. A readout with no action must not become a dead tab stop; a screen-reader user reaches the text with the virtual cursor, and a sighted keyboard user can already see it |
| **Live region politeness** | Exactly **one** visually-hidden `aria-live="polite" aria-atomic="true"` region for the whole tuning region. It **never fires on a value change**. It fires only on a *category transition* — in budget → over budget, over budget → in budget — and on the two explicit commands (`SURPRISE ME`, `RESET ALL`) and on a successful copy. Transitions are coalesced with a 500ms trailing delay, so a knob dragged across 908 and back says nothing at all. By construction it cannot chatter at the 100Hz tick, at the 30fps paint, or at the 120ms debounce |
| `aria-busy` | Set on the meters block while measuring or stale, so an AT does not read numbers that are about to change |
| Focus visibility | Phase 4's ring, unchanged, on every control including the invisible range input (drawn on its wrapper via `:has(:focus-visible)`) |
| Text contrast | `--color-ink` **9.26:1**, `--color-ink-quiet` **5.57:1**, `--color-ink-dim` **4.72:1**, `--color-over` **5.92:1**. Every text token clears AA (4.5:1) at 12px |
| Non-text contrast | `--color-line` **3.31:1** for functional borders and unselected dots; `--color-accent` **18.27:1**; accent-versus-over **3.09:1**, which is what makes the two bar states distinguishable without hue. `--color-line-soft` (1.58:1) is decoration only — bar tracks whose value is stated in adjacent text, and default markers whose meaning is carried by `RESET ALL` |
| Colour is never the only channel | Over budget carries six signals: colour, an outlined and completely full bar, numerals above 908, a percentage above 100, a disabled control with a written reason, and a sentence naming the knob. Remove the red entirely and the state is still fully legible — that is the test that makes introducing the red safe |
| Touch targets | 44×44 minimum on every knob option, every swatch, every button, and the copy-fallback field |
| Motion | `prefers-reduced-motion` honoured completely, per the table above |

**Copy rules specific to this phase:**

- The fit-ladder label and the back-off label are the compiler's own sentences, lower-cased at the
  first character where they sit inside another sentence, and never rewritten. Two copies of the same
  explanation would drift.
- `TURN IT DOWN` is never `PUT IT BACK` — Phase 7 owns `PUT BACK` for restoring a module's own
  configuration, and near-identical labels on the same panel would be a hazard on real hardware.
- A raw Lua literal is never rendered as visible copy. `0,200,255` is a swatch, `0,2,4,5,7,9,11` is
  the word `Major`, `3,5,7` is a position on a rail.
- Percentages read `77%`, never `77.4%`. Character counts read `702`, never `702 chars`; the caption
  and the `/ 908` already say what they are.
- **A command and a category transition are one utterance, never two.** The live region is
  `aria-atomic="true"` and emits at most one string per event. The case that forces the rule is real:
  `RESET ALL` can land on a configuration whose *defaults* are already over budget — tpad ships at
  941/908 today — so the command and the crossing happen on the same tick. That case uses the two
  combined reset strings above, **not** the reset string followed by a transition string, and the
  "{Knob label} pushed it over" clause is dropped because no knob moved. The bare no-knob transition
  string is declared for the same reason the back-off carries two explanations: the next command that
  can cross the boundary must reuse this wording rather than invent its own. `SURPRISE ME` cannot
  reach any of it — by construction its result always fits.

## Decisions taken without the user

Authored overnight under the delegation recorded in `05-CONTEXT.md`. Every one is a first cut Botond
can overturn; none contradicts D-01..D-17 or Phase 4's approved contract.

| # | Decision | Rationale (one line) |
|---|----------|----------------------|
| X-01 | **`--color-over: #ff3b30` ships as the third colour**, scoped to exactly three uses | The user asked for a red meter three times (ROADMAP SC-3, TUNE-05, D-09 `[user]`), and lime cannot carry it because full-strength lime is the *enabled* CTA's fill 24px away — "go" and "stop" in one hue in one column |
| X-02 | The value is `#ff3b30` and not any other red | It is the only band that clears **5.92:1** on black (AA for the 12px numerals) *and* **3.09:1** against `--color-accent` (so the two bar states are distinguishable by luminance, not hue); darker fails the first, brighter fails the second |
| X-03 | The meter fill is **full-strength accent**, not `--color-ink` | Required by X-02's arithmetic: at `--color-ink` the accent-vs-over ratio collapses to 1.56:1 and a red-green-colourblind viewer cannot tell the two states apart |
| X-04 | The accent reserved list gains exactly two entries: the meter fill and the selected knob value | Both say what accent has always said here — "this is the live value" — and neither is a border, body text, or a disabled control |
| X-05 | **Twelve `KnobKind`s collapse to three widgets** — swatch row, word row, rail — chosen by kind and by `n`, with the rail as a total fall-through | D-02 demands one widget per kind family and that the panel cannot tell a preset entry from a Lua one; a total fall-through means no knob can ever fail to render |
| X-06 | The rail has two skins: a **dot rail** at `n ≤ 8` and a **detent track** at `n ≥ 9` | 16 dots do not fit a 120px control area at a hittable size; the only `n ≥ 9` knob shipped anywhere today is `MIDI channel` at 16 |
| X-07 | **Knob readouts are positional; the pad is the readout** — with colour as a swatch, `note` as a pitch name and `scale` as a mode name, plus the raw integer when every value is a single integer | The values are Lua literals with no display contract (`0,200,255`, `3,5,7`); the live pad directly above the panel — Phase 4's `--pad-hero: clamp(260px, 52vmin, 560px)` — is the honest readout, and the only numbers that need to be numbers are the two meters |
| X-08 | A MIDI channel whose literal is `0` **displays `0`** | HANGAR does not silently renumber a value it is about to write to someone's hardware; a one-based display is a catalog data change, not a UI trick — flagged for the morning |

## Open questions for the morning

1. **The third colour.** `--color-over: #ff3b30` is the first hue on this site that is not lime, and
   Phase 4 predicted the first one would arrive in Phase 7. The arithmetic is in X-01..X-03 and the
   scope is three uses. If the answer is still no, the fallback is a fully-filled outlined bar in
   accent plus the copy — the state stays legible, it just stops shouting.
2. **The identity guard is amended, not bypassed** (X-27). `src/lib/ui/identity.spec.ts` is a Phase 4
   gate: it asserts eight colour tokens and two permitted hexes, and the third colour breaks both.
   Widening it is small, it is written down, and it keeps the guard a guard — but it is a deliberate
   change to a signed-off phase's test, in the same class as Phase 4's own W-02 change to a Phase 1
   licence gate, and it is Botond's gate. If question 1 lands on "no red", this question disappears
   with it and `identity.spec.ts` is left exactly as it ships.
3. **MIDI channel is displayed zero-based** (X-08), matching the Lua literal and the firmware. If it
   should read one-based, that is a `LuaKnob` display field in the catalog data, not a UI hack, and it
   touches seven entry files and their specs.
4. **The 152px reservation** (X-11). The meters half is exact; the rack half is not achievable under
   Phase 4's own 44px rule. With every vertical gap in the region at 16px, the panel is roughly
   **182px taller at three knobs and 326px taller at six** (334px and 478px of region against a 152px
   reservation), and more again for entries with word rows, which always stack. The primary control
   does not move, but the panel is now long on a phone.
5. **`SURPRISE ME` as a label** — kept from the kickoff decision and still `05-CONTEXT.md`'s open
   question 3. It reads warm and it is unambiguous; nothing here needs it changed.
6. **`COPY LINK` sits beside `KEEP ON DEVICE`** because D-11 says "beside the install controls". It is
   not an install control and the two are distinguished by state and by their reason lines, but if a
   visitor ever reads it as one, moving it into the tuning region beneath the meters is a one-line
   change and arguably where a share control belongs.
7. **Lua entries still are not in the front-door row** (`05-CONTEXT.md` open question 2). Everything
   here works for them the moment they join; nothing in this contract depends on the answer.
