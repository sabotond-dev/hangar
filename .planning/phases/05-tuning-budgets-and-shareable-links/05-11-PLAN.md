<objective>
Wire the region into the row, land a shared link, and prove all of it in a real browser against the
deployed bytes.

Wave 11. Everything exists; this plan connects it and then watches it work.

Four connections, each with a rule behind it:

1. **The engine swap goes through `replaceEngine`, never `register`.** `register()` calls
   `unregister()`, which sets `canvas.width = 0`, and re-enters with `intersecting: false` — so a
   knob turn would blank the hero for a frame and then stall it until the `IntersectionObserver`
   fires again. Wave 1 added `replaceEngine` for exactly this moment.
2. **The knob indices live in the row, not in the region.** The region unmounts on un-choose; if it
   owned the indices, re-choosing would show defaults while the pad still played the tuned state.
   Indices are scalars, so they may be runes; the engines and canvases stay in the plain `Map`s they
   are in today.
3. **The stamp is applied after the coverflow has centred the entry** (D-13). Phase 4's route logic is
   untouched: nothing here edits `syncAddress`, `choose`, `unchoose` or the slot arithmetic.
4. **Phase 5 never writes the hash.** `COPY LINK` composes a string and puts it on the clipboard.
   Nothing navigates. The consequence — stepping to another entry drops the stamp, because
   `syncAddress()` replaces the URL with `resolve("/c/[id]", …)`, which has no fragment — is correct
   and must be written into the SUMMARY so nobody files it as a bug later.

Purpose: TUNE-02's live preview and SHARE-01 to SHARE-03's whole journey, observed in a browser.
Output: one edited component and 7 e2e tests.
</objective>

<interfaces>
**What `Coverflow.svelte` gains, and nothing more:**

```ts
// Knob indices per entry id. Scalars only, so a rune is correct here - and it is
// what makes re-choosing restore the panel to what the visitor left, because the
// region unmounts on un-choose and the row does not.
let knobIndices: Record<string, Record<string, number>> = $state({});
let overBudgetReason: string | undefined = $state(undefined);
let shareStamp: string | undefined = $state(undefined);
let landing: Landing = $state({ kind: "none" });
```

and, in the markup:

```svelte
<ChosenPanel entry={centred} {tuning} {share}>
  <TryOnDevice entry={centred} budgetReason={overBudgetReason} bind:this={tryOn} />
</ChosenPanel>
```

with the two snippets rendering `TuningRegion` and `CopyLink`.

**The preview swap.** `TuningRegion`'s `onpreview(engine)` handler does exactly two things:

```ts
engines.set(heroId(), engine);      // the session map, so stepping away and back keeps the tuning
host?.replaceEngine(heroId(), engine);
```

Never `register`. Never `unregister`. Never a rune around `engine`.

**The stamp landing.** In the same `onMount` async block that builds the engines, **after**
`adopt()`/`syncHost()` have run and the entry is centred:

1. `const payload = parseHash(page.url.hash)` — from a dynamically imported `$lib/share/stamp`.
2. `const result = decodeFor(entry, payload)`.
3. `restored` sets `knobIndices[id]`; `older` and `unreadable` leave the defaults.
4. Anything other than `none` **auto-chooses**: `replaceState("", { chosen: true })`. A bare
   `/c/<id>` still lands un-chosen exactly as Phase 4 ships it. The reason is in the UI spec (X-18):
   the whole content of a tuned link is what somebody moved, and the knobs are the only evidence of
   it — landing a tuned link on a closed panel would show the tuning and hide the tuner.
   Phase 4's `unchoose()` already handles the `pushedChosen === false` case by replacing rather than
   going back, so nothing new is needed there.
5. `landing` is passed to `TuningRegion`, which renders `StampNotice`.

`replaceState("", …)` with an **empty string** first argument is what
`svelte/no-navigation-without-resolve` permits for shallow navigation — the same form `choose()`
already uses. No suppression is needed here and none may be added.

**The share URL** is `shareUrl(heroId(), shareStamp)` from `$lib/share/url`, which imports nothing and
may be named statically. It is recomputed whenever `onstamp` fires, so `CopyLink` always holds a
current precomputed string and its handler never awaits.

**The e2e harness** is `build/` served by `worker/index.js` under `wrangler dev` — the deployed bytes,
never a dev server and never `vite preview`. `trailingSlash: "always"`, so navigate to `/c/aurora/`
**with** the slash. `e2e/first-experience.e2e.ts`'s `sample()`, `waitForPicture()` and
`waitForFrontDoor()` helpers are the proven shapes for canvas comparison; import or re-derive them
rather than inventing a third way to read a canvas.

**Clipboard in Playwright**: `context.grantPermissions(["clipboard-read", "clipboard-write"])` is
**Chromium-only**. So the copied-text round trip is asserted in the chromium project, and the WebKit
project (wave 12) asserts only the confirm state — which is what SHARE-02 actually requires.
