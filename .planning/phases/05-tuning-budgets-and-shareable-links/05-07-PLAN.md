<objective>
Put the picture on disk before the build looks for it, and put the tags in the head.

Wave 7. One ordering fact decides this plan's whole shape, and it was read out of the installed
SvelteKit rather than guessed: **the prerender crawler follows `og:image`.**
`node_modules/@sveltejs/kit/src/core/postbuild/crawl.js` carries `og:image` in its meta-property
allow-list and calls `push_href(content)` for it. `vite.config.ts`'s `handleHttpError` rethrows every
404 except three known postbuild paths. So an `og:image` pointing at a file that does not exist yet
**fails the build**, naming `/og/aurora.png`.

Therefore the PNGs are generated into `static/og/` **before** `vite build`, as the first step of the
`build` script. Do not widen `handleHttpError` — that guard is how a genuinely broken footer link
still fails the build, and it has already earned its keep once.

Two smaller facts shape the script:

- **Plain Node cannot import `pad-sim.ts`** — its extensionless `from "./_pad"` is not resolvable by
  Node's ESM loader, as `scripts/capture-preset-baseline.mjs` already records. The measured answer is
  Vite's own Node API: `createServer(...)` in middleware mode, then `ssrLoadModule`. 135 ms to spin up
  and load two modules, resolving `$lib`, extensionless TS and the pinned protocol package correctly.
  No new dependency — Vite is already a devDependency.
- **`static/og/` is a build artefact** and belongs in `.gitignore`. A clean checkout regenerates it,
  and the deploy script's clean-tree gate stays satisfied because an ignored path is not a dirty one.

Purpose: SHARE-04, everything about it that can be proven without a crawler that can reach the site.
Output: one script, one build-script change, two heads, 5 unit tests, 1 e2e test.
</objective>

have no page to unfurl: `src/routes/c/[id]/+page.ts` generates `entries()` from `FRONT_DOOR`, so
`/c/euclid/` does not exist. Generate from **the same source the route's `entries()` uses** — so

header and in the SUMMARY: eight entries deliberately have no image because they have no address.

**The engine per entry.** `createEngine(entry)` from `$lib/sim/engine`, `engine.run(OG_TICK)` with
`OG_TICK = 64`, then `engine.frame`. That covers both routes — a Lua entry gets a real VM in Node,
which already works (`lua-smoke.spec.ts`). Every `FRONT_DOOR` entry declares `restsBlack: false`, so
no generated image may be a black square.

**The head tags**, from `05-UI-SPEC.md` § The OG image:

```
og:type          website
og:site_name     HANGAR
og:title         {name} — HANGAR
og:description   {entry.description}
og:url           {SITE_ORIGIN}/c/{id}/
og:image         {SITE_ORIGIN}/og/{id}.png
og:image:type    image/png
og:image:width   1200
og:image:height  630
og:image:alt     The {name} configuration running on a ZONA’s 9 by 9 pad.
twitter:card     summary_large_image
```

`twitter:card = summary_large_image` is what makes Discord render the large embed rather than an
80x80 thumbnail. Ship it even though nothing here is about Twitter. The alt string already exists as
`ogAlt(name)` in `src/lib/tune/copy.ts` — use it; do not author a second copy.

The existing `<title>` and `<meta name="description">` stay exactly as they are, and `og:title`
carries the same em-dash form the page title already uses.

**`/` gets the same treatment**, with the shelf's own title and description and an `og:image`
pointing at `FRONT_DOOR[0]`'s image — the opening centre. One line, no new asset, and a bare
`hangar.sabotond.workers.dev` link then unfurls too. It is the one thing here the UI spec does not
fix, so the SUMMARY calls it out as a decision the designer may overturn in favour of a shelf-level
picture.

**Both route files are scanned by `config-shape.spec.ts` test 13.** `$lib/share/url` imports nothing
and its specifier contains none of the three markers, so importing `SITE_ORIGIN` there is safe — and

`$lib/catalog` (which would drag the vendored shelf into the page's chunk); the route already has
`FRONT_DOOR`.

**The honest limitation, recorded rather than glossed.** `worker/index.js` gates the whole site behind
Basic Auth, fail-closed, so Discord's crawler cannot fetch anything until the embargo lifts on launch

size, the tags, the absolute URLs, and the image reachable over HTTP through `wrangler dev` with
credentials — and nothing more. The SUMMARY says exactly that and does not claim SHARE-04 was

   the number of lit cells. A build artefact that reports what it made is how a changed picture
   becomes a diffable decision instead of a mystery.

```
"build": "node scripts/gen-og.mjs && vite build && node scripts/postbuild.mjs"
```

run for a bare `npx vite build`, and the failure would then be a prerender 404 with no clue attached.

`.gitignore` gains `static/og/` beside the other build output, with a one-line reason.

Run the script standalone, check the output count and sizes, and confirm `git status --porcelain`
