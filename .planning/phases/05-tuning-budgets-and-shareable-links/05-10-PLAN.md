<objective>
Fill the region Phase 4 reserved, without moving anything Phase 4 promised would not move.

Wave 10. `ChosenPanel.svelte`'s comment has been waiting for this since Phase 4:

> THE RESERVED REGION'S HEIGHT IS LOAD-BEARING, NOT DECORATIVE. Reserving it now is what lets Phase 5
> dock those in without the panel growing under a visitor who is already reading it.

The arithmetic did not survive contact with six controls, and the UI spec says so with its working:
Phase 4's own 44px accessibility floor makes six knobs plus an actions row at least
`44 x 7 + 4 x 6 = 332px` however they are arranged. So the 152px reservation is a **floor, not a
ceiling** — which is what `min-block-size` already said in the shipped CSS — and the invariant this
phase actually contracts is the one that comment was written to protect:

> **The primary control never moves.** The region grows downward. **The region's height is fixed the
> moment an entry is chosen** — a pure function of that entry's knob count and kinds, settled before
> the panel animates in, unchanged while a visitor turns knobs, unchanged when a meter changes,
> unchanged when a bar crosses 908.

Two mechanisms make that true and both are in this plan: the region's height formula, and the honesty
line's **reserved 72px one-cell sizing grid**, which holds Phase 4's idle sentence and this phase's
over-budget reason at the same `grid-area` with the inactive one `visibility: hidden`. Without it the
slot's line count changes when a knob crosses 908 and the whole region jumps roughly 24px at the exact
instant the visitor is staring at it.

Purpose: the region, the panel seam, and the structural gate over both.
Output: one new component, two edited components, one spec with 5 tests.
</objective>

<interfaces>
**`TuningRegion.svelte`'s props.** It takes an **entry id**, not an entry object, so `/dev/tune/` can
mount it for `tpad` — a catalog entry with no front-door page — without inventing a fake row entry:

```ts
let {
  entryId,
  knobs = {},                 // knob id -> index; the region reports changes upward
  reserved,                   // { setup, timer } - Phase 7's install marker, and /dev/tune/'s way in
  landing = { kind: "none" }, // the stamp landing, decided by the route before the panel opens
  onknobs,                    // (indices) => void - the owner keeps them so re-choosing restores them
  onpreview,                  // (engine) => void - the owner hands it to SimHost.replaceEngine
  onstamp,                    // (stamp: string | undefined) => void
  onbudget,                   // (reason: string | undefined) => void - the TRY ON DEVICE reason
}: { ... } = $props();
```

**The compiler arrives dynamically.** `const { buildTuner } = await import("$lib/tune/model")` inside
`onMount`. Never a static import, never an `import type` from anything under `src/vendor` or
`$lib/pad`. `Coverflow.svelte` already does exactly this with `$lib/sim/engine`; copy the shape.

**The formatter prefetch (D-08).** `onIdle` from `$lib/tune/idle` — `requestIdleCallback` with a
`setTimeout(fn, 200)` fallback, because Safari has no `requestIdleCallback` — kicks `padReady()` once
the panel opens. Until it resolves the meters show `measuring…` and **the simulation never waits on
it**: the preview is already running. Nothing here may await the formatter before the first paint.

**Contents, top to bottom** (`05-UI-SPEC.md` § The tuning region):

```
TUNING caption                     14px line box, ink-quiet, Phase 4's, unchanged
message slot A (StampNotice)       auto, only when a stamp landed
knob rack (KnobRack)               48r + 66w - 4
actions row                        44px: SURPRISE ME, RESET ALL
meters block (BudgetMeter x2)      exactly 56px
message slot B (BudgetMessage)     auto, only when it applies
```

**Every vertical gap in the region is 16px** — Phase 4's `md`, so this phase adds no new spacing
value. The 12px in the UI spec is horizontal only: the column gap between a knob's label and its
control, and between a meter's three cells.

**The height is fixed once an entry is chosen.** Compute it from the entry's knob count and kinds —
`194 + 48r + 66w - 4` — and hold it, so a meter change, a bar crossing 908 or a stale readout cannot
resize the region. The two message slots are the declared exceptions and they move only inert content.
**Stepping while chosen** re-fills the region with another entry inside Phase 4's existing 260 ms
name-plate crossfade: contents out over 130 ms, height changes at the midpoint, contents in over
130 ms; instant under reduced motion.

**`SURPRISE ME`** is always enabled; while the roll runs it is a real `disabled` button with
`aria-busy="true"` and **its label does not change** — a label that flickers for 80 ms is worse than a
brief disable. The knobs do not move until the roll settles, and the result never lands over budget.
**`RESET ALL`** is a real `disabled` button when every knob is already at its default, with Phase 4's
disabled treatment and **no adjacent reason line**: Phase 4's DEGR-02 reason rule exists for install
controls whose cause is invisible, and here the cause is the rack directly above the button with every
marker at home. Neither takes an accent fill; the only filled button on this panel is `TRY ON DEVICE`.
Both are absent entirely when the entry has no knobs.

**Exactly one live region** for the whole tuning region: visually hidden,
`aria-live="polite" aria-atomic="true"`. It **never fires on a value change**. It fires only on a
category transition (in budget to over budget and back), on the two explicit commands, and on a
successful copy. Transitions are coalesced with a 500 ms trailing delay, so a knob dragged across 908
and back says nothing at all. **A command and a category transition are one utterance, never two** —
`RESET ALL` can land on defaults that are already over budget, and that case uses the combined reset
strings from `copy.ts` rather than two announcements.

**When the formatter never loads at all** (blocked, 404, offline) the meters block is replaced by one
Body line and **nothing else is disabled**: this phase connects and identifies and needs no compiler.
Knobs still turn, the preview still animates, `COPY LINK` still copies.

**`ChosenPanel.svelte`'s two changes.** Region 4 renders a `tuning` snippet instead of the placeholder
caption and sentence; the row below the hairline gains a `share` slot beside `KeepOnDevice`, laid out
`display: flex; flex-wrap: wrap; gap: 8px; justify-content: space-between` with `KEEP ON DEVICE` left
and `COPY LINK` right, each with its own quiet line. Its scoped `.caption { line-height: 1.2 }` is
overridden to `14px` **inside the tuning region only** — `ZONA IDENTIFIED` in `TryOnDevice.svelte` and
every other Phase 4 caption keep the ratio.

**`TryOnDevice.svelte`'s two changes**, and nothing else in that component moves:

1. The honesty line's slot gains `min-block-size: 72px` (three Body lines at 16px/1.5) **and** becomes
   a one-cell grid holding *both* strings at `grid-area: 1 / 1` with the inactive one
   `visibility: hidden` and `aria-hidden="true"`. Its height is then the taller of the two at whatever
   width the panel currently is, identical before and after the swap. This is a sizing twin, not a
   duplicate for an AT: `visibility: hidden` already removes the hidden copy from the accessibility
   tree.
2. A new optional prop carries this phase's over-budget reason. When present the control is a real
   `disabled` button with Phase 4's exact disabled treatment and the reason in the honesty slot.
   **Precedence**: on a browser that cannot install at all (`unsupported`, `insecure`) the capability
   reason wins and the budget reason is not shown — the permanent obstacle is the honest one to state.
   The message block near the knobs still appears in full, because an over-budget configuration still
   matters to someone about to share it.

`--color-over` is **never** applied to `TRY ON DEVICE`: a red CTA would say "dangerous" when the truth
is "not yet".
