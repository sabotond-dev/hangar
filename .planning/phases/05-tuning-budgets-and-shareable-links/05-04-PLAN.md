<objective>
Make a knob turn mean something: a new picture immediately, a new character count shortly, and an
honest answer when the count does not fit.

Wave 4. This is the compiler side of D-18 — the one module a component reaches only through
`await import("$lib/tune/model")`. Everything it touches is already built: the descriptors and their
`PadState` bindings from wave 3, the view types and the sentences from wave 2, `fitState` and
`replaceEngine` from wave 1.

Three measured facts shape it:

- **`compile() + cost()` is 1.1–4.0 ms in node**, and `cost()` crosses the WASM boundary twice. A
  120 ms debounce collapses a slider drag into one compile and is generous. `PadSim` takes a
  `PadState` and rebuilds in microseconds, so the **preview is not debounced** (D-05, D-06).
- **`fit()` compiles once per ladder step**, N+1 minifier calls. It is called only when
  `cost().fits === false` — which, per the phase's headline finding, is never in practice and
  therefore free.
- **Over budget is unreachable for anything a visitor can produce.** So TUNE-04 and TUNE-05 are built
  as guards and proven against a *real* over-budget measurement produced by passing a real
  `reserved` to `cost()` and `fit()`. `cost(result, { setup: 400, timer: 0 })` puts `tpad` over
  instantly and exercises `validate()`'s own worded sentence. That is the honest way to reach the
  branch; a hand-made `PadCost` literal would prove only that the renderer can render a literal.

Purpose: the whole tuning behaviour, in node, before a pixel of it exists.
Output: two modules, three specs, 16 tests.
</objective>

```ts
import type { TuneView } from "./view";
import type { SimEngine } from "$lib/sim/engine";

export const COMPILE_DEBOUNCE_MS = 120;

export type LadderView = { label: string; line: string; saves: { setup: number; timer: number } };
export type OverBudgetView = {
  events: "setup" | "timer" | "both";
  line: string;          // from copy.ts - the knob case or the arrived case
  backOff: string;       // the quiet line under TURN IT DOWN
  reason: string;        // the TRY ON DEVICE honesty-line reason
  live: string;          // the one live-region utterance for the transition
  apply(): void;         // the back-off: puts the knob back, or applies steps[0]
};

export type Tuner = {
  readonly knobs: readonly KnobDescriptor[];
  readonly indices: Readonly<Record<string, number>>;
  set(knobId: string, index: number): void;
  reset(knobId: string): void;
  resetAll(): void;
  surprise(): Promise<void>;
  /** Undefined at the defaults: a URL with no fragment IS the base configuration. */
  stamp(): string | undefined;
  destroy(): void;
};

export async function buildTuner(options: {
  entryId: string;
  indices?: Readonly<Record<string, number>>;
  /** Phase 7's install marker, and the only way a test or /dev/tune/ reaches over budget. */
  reserved?: { setup: number; timer: number };
  onview(view: TuneView): void;
  onpreview(engine: SimEngine): void;
  onladder(ladder: LadderView | undefined): void;
  onover(over: OverBudgetView | undefined): void;
}): Promise<Tuner>;

/** The single decision point for whether the ladder runs at all. Pure, and tested. */
export function needsLadder(cost: PadCost): boolean;
```

`buildTuner` resolves the entry through `byId` from `$lib/catalog`, picks `presetKnobs` or
`luaKnobs`, and emits a first `onview` in the **measuring** state immediately — before `padReady()`
resolves. The simulation never waits on the formatter: `onpreview` fires on the first tick with a
real engine while the meters still say `measuring…`.

**The two routes inside `set()`:**

| Route | Preview | Compile |
|---|---|---|
| `preview === "padsim"` | **immediate.** Build a new `PadSim` from the applied `PadState` and call `onpreview` synchronously | debounced 120 ms: `compileState` → `costOf` → `onview` settled |
| `preview === "lua"` | **debounced**, because a token substitution needs a fresh VM. `await createEngine(entry, indices)` **then** `onpreview` — the previous engine keeps painting for the whole await (D-06) | the same debounce measures the rendered Lua with `measureLua` per event |

Between a `set()` and the debounce landing, the view is **stale**: the *same last-known numbers*
dropped to `--color-ink-quiet`, never the `measuring…` word, which is reserved for the very first
measurement. That distinction is the UI spec's X-13 and it belongs in this module's state machine,
not in the component.

**`fit()` is called only when `cost().fits === false`**, through `fitState` from `$lib/pad`, with
`pinned` set to the `sheet` of the most recently moved knob. The compiler never proposes degrading
the control the visitor's hand is on — which is also the honest answer to "name the knob that pushed
it over": the compiler refuses to blame it, so the knob name comes from HANGAR's own record of which
knob moved last.

**`fit()` proposes and never applies.** TUNE-04 offers; it does not silently resolve. The preview
therefore always shows exactly the state the knobs describe, which is the property the compiler's own
header says it exists to protect.

**Lua entries state nothing about the ladder.** Their whole knob cross-product was proven in budget
at build time in Phase 8; there is no runtime ladder and no partial state to trim. `onladder` is
never called for a Lua entry, and `model.spec.ts` asserts it.

**Measured cost timings** (node, formatter initialised): starfield 1.13 ms, pinwheel 1.15,
faders 1.73, radar 1.87, joystick 2.23, dial 2.54, aurora 2.79, ninepads 2.81, tpad 3.99,
`fit()` on a fitting state 4.4 ms.
