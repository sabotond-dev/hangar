Lay the three foundations everything else in Phase 5 stands on, and pin the numbers the rest of the
phase measures itself against.

Wave 1. Three small, unrelated pieces of groundwork, deliberately grouped because each is a
prerequisite for a later wave and none of them is big enough to be a plan:

1. **The baseline.** Phase 8 D-17: no plan in this repository carries a literal suite total. The
   phase's first task re-measures `test:quick`, `test:sweep`, `test:e2e` and `check` and writes them
   into its own SUMMARY, and every plan after this one reads the previous plan's numbers.
2. **The WebKit project**, added *now* rather than in wave 12, because adding a Playwright project
   changes how every later count is computed and the change is worth isolating to a wave where the
   answer is provably "nothing moved".
3. **`SimHost.replaceEngine` and `fitState`.** Two functions, eight lines each, both of which a later
   wave would otherwise have to invent under pressure. `register()` cannot be used to swap an engine:
   it calls `unregister()`, which sets `canvas.width = 0`, and re-enters with `intersecting: false`,
   so the hero blanks for a frame and then stalls until the `IntersectionObserver` fires again
   (05-RESEARCH § Pitfall 3). And `fit()` is the one measuring function on the vendored compiler that
   `src/lib/pad/index.ts` does not re-export, so without this task the ladder would be reached around
   the FOUND-05 gate.

Purpose: the numbers, the browser and the two seams. Nothing visitor-facing changes.
Output: two edited config/source files, two extended specs, one recorded baseline.
</objective>

  <action>
Add one public method to `SimHost`, immediately after `register`:

```ts
/**
 * Swap the engine under an id, keeping the canvas, the observer and the slot
 * state.
 *
 * NOT register(). register() calls unregister(), which sets canvas.width = 0,
 * and re-enters with intersecting: false - so a knob turn would blank the hero
 * for a frame and then stall it until the IntersectionObserver fires again
 * (05-RESEARCH, Pitfall 3). This is the mechanism behind D-06's "the previous
 * engine keeps painting until the new one has run Setup": the caller awaits the
 * new engine first and swaps second, so the old one paints for the whole await.
 *
 * Unknown ids are a no-op rather than a throw: a knob turn racing an unmount is
 * a real sequence, not a programming error.
 */
replaceEngine(id: string, engine: HostEngine): void {
  if (this.destroyed) return;
  const entry = this.entries.get(id);
  if (typeof entry === "undefined") return;
  entry.engine = engine;
  if (this.reduced) this.stillFrame(entry);
  this.paint(entry, this.deps.now());
  this.wake();
}
```

Write the three tests **first** and observe them red, then add the method.

Order matters inside the method and the spec must pin it: `stillFrame` before `paint`, or a
reduced-motion visitor sees an unticked engine's blank frame. The `wake()` at the end is what restarts
a loop that had gone quiet because the previous engine had settled.

Then run the paired negative check: delete the `this.paint(...)` line, observe test 12 red **naming
the missing paint**, restore it, and re-run green. Record both observations in the SUMMARY.
