<objective>
The stores, before the three screens that read them.

**Why this wave is here and not at the research's wave 7.** The intro's returning-visitor card reads a
flag and the most recent draft (D-14 Q2). The gallery's rail counts `Favorites 08` and
`Recently used 06` (PDF page 2). My configs is nothing but these stores rendered. Building the screens
first would mean building each of them twice. 13-VALIDATION records the reordering as D-6.

**`localStorage`, with a documented ceiling, and the precedent is already load-bearing.**
`src/lib/device/snapshot.ts` imports **nothing** - zero specifiers, `import type` included - takes the
store as an argument, reads the property **inside its own `try`** (a browser configured to refuse
storage throws on the *access*, not only on the use - 07-RESEARCH's Pitfall 9), and degrades every
failure to "absent". `ScreenToggle.svelte:81` and `src/lib/browse/return.ts` are the same shape. This
module is the **fourth instance of a pattern that has already survived prerendering, quota and a
hostile browser**, and it is written by copying that shape rather than by rediscovering it.

**Size, honestly.** A Sandbox surface is a region list: the PDF's four-element surface serialises to
well under 1 KB. A Playground draft is `{ entryId, knobIndices[] }` - under 100 bytes. **Nothing stores
a thumbnail**: the gallery already renders sixteen live pads behind one clock, so a 96x96 PNG in
storage would be a worse picture at a thousand times the cost. With no thumbnails, `localStorage`'s
~5 MB holds thousands of records, and the escape hatch - IndexedDB - is **documented, not built**, with
the exact trigger written down: stored thumbnails, imported binaries, or a capture log.

**The version rule, and why it is doubled.** `SNAPSHOT_KEY = "hangar.snapshot.v1"` puts the version
**in the key name**, so a `.v2` sits beside the `.v1` and neither reader can misparse the other's
record - a stronger guarantee than a field inside the JSON, because an unknown-shaped record is never
opened at all. But **an exported file has no key name**, so the version also goes in the body. Both.
12-03 has already spent this pattern once (`hangar.snapshot.v2` beside `.v1`, the v1 record read as
`system = default` and never overwritten), and this module inherits that behaviour by name.

**Three objects, three words, three stores** (§9): a **draft** is editable working state recovered
locally; a **saved copy** is a named snapshot that can be reopened or shared; **device state** is what
is confirmed on a page, and it lives in the install store where it already is. *"Never use one generic
'Saved' indicator for all three"* is the spec's own sentence and it is why `drafts.ts` and `library.ts`
are two files rather than one with a flag.

Purpose: the local half of the product, built once, degrading honestly, before anything renders it.
Output: eight modules, one spec with seven tests. Term `+1 / +7`.
</objective>

**`hangar.collections.v1` is reserved and unread.** Naming it here stops 13-13 from picking a

Every record's body:

```ts
{ schema: 1, kind: "playground" | "sandbox", name, createdAt, editedAt, ... }
```

## The guard, copied from `snapshot.ts` rather than rewritten

```ts
export function readJson<T>(store: Storage | undefined, key: string): T | undefined {
  try {
    const raw = store?.getItem(key);        // the ACCESS is inside the try
    ...
  } catch { return undefined; }             // every failure degrades to absent
}
```

Four failure modes, each degrading to absent and **each a test**:
1. the key is not there;
2. the value is not JSON, or is JSON of the wrong shape;
3. `setItem` throws `QuotaExceededError` - the write is dropped and the **caller is told**, because a
   silent drop on a draft is a lost draft. `readJson` degrades silently; `writeJson` returns a boolean;
4. **the store itself throws on property access** - a browser configured to refuse storage. This is the
   one that is easy to miss and is Pitfall 9's own case.

## The five stores

| Module | Shape | Rules |
|---|---|---|
| `drafts.ts` | `{ [id]: Draft }` | one draft per source (`entryId` or a surface id); `editedAt` on every write; **never deletes another kind's draft** |
| `library.ts` | `{ [id]: SavedCopy }` | a named copy is created, never overwritten from its source (§11); rename, duplicate, delete |
| `favorites.ts` | `string[]` | entry ids, order-stable, **an id that is no longer in the catalog is dropped on read and the drop is counted** - Phase 12 removed three entries and Phase 11 removed nine, so this is a real case and not a hypothetical |
| `recent.ts` | `{ id, at }[]` | pushed on **open**, deduped by id, **capped at 12**; the PDF shows six, so six are shown and twelve are kept - state the two numbers and why they differ |
| `intro.ts` | `{ seen, at }` | written on the first successful mount of `/`; **a refusing browser therefore sees the intro every time, which is the safe direction** and is stated as a decision |

`motion.ts` adopts 13-04's re-homed control's key so the guard lives in one place; 13-04 wrote it with
a copied guard and this plan folds it in, **with the SUMMARY stating whether the behaviour changed**
(it must not).

## What this module refuses to do

- **No thumbnails.** Written into the header with the arithmetic: 96x96 PNG x 200 records is megabytes;
  the live simulator renders it for free and already does, sixteen at a time.
- **No IndexedDB.** Documented as the escape hatch with the exact trigger.
- **No Svelte.** These are plain modules; the reactive wrappers belong to the components that use them.
- **No collections.** Reserved key, nothing else.
