**What the PDF draws on pages 2 through 5, measured at a 1500px render** (`13-RESEARCH.md` §1, and the
figures are MEDIUM confidence because they came off a raster, which the header of the new module must
say):

| Region | Measured | As a fraction |
|---|---|---|
| Header band | 76 tall | fixed |
| Context bar | 59 tall | fixed |
| Left rail | 0 -> 224 | **~15%** |
| Centre | 224 -> 1044 | the remainder |
| Right inspector | 1044 -> 1500, **456 wide** | **~30%**, clamped 380-456 |
| Footer | ~50 tall | fixed |

**The spec says 200 / flexible / 300 at 1440 and its whole §13 responsive table is keyed to 300-340.**
The PDF's inspector is **50% wider than the spec allows**, and D-14 Q9 already settled it: the PDF wins
on look, §13's table is re-derived as fractions. The reason is concrete rather than aesthetic - the
inspector's **2 x 2 numeric grid** on PDF page 3 is two 190px fields plus a 22px gutter, **402px**,
which does not fit in 300 and would collapse to a single column.

**The three regions and the three zones.** The context bar (y 76 -> 135) carries **breadcrumb left,
status centre, destination and primary action right** - and on pages 2 and 4, where there is nothing to
apply, the destination zone is replaced by the sentence *"Preview without hardware"*. That is a real
structural rule: **the bar has three zones and the third is either a destination or a sentence, never
empty.**

**Three things in the current layout are load-bearing and none of them moves.** The two `onMount`
calls that start the session and the install store; the GPLv3 footer, which is licence compliance and
not decoration; and `SessionAnnouncer`, which is the page's one live region and whose **document order
the layout's own comment declares load-bearing**. This plan puts a shell around all three and states
that it checked each.

**The shell knows nothing about configurations.** It renders named slots. That is what stops
`/playground`, `/playground/[id]`, `/sandbox` and `/my-configs` from each growing their own header, and
it is the whole reason this wave exists before those four.

Purpose: one frame, one set of numbers, six regions, no route repeating any of it.
Output: seven new files, one layout rewritten, six tests. Term `+1 / +6`.

## `src/lib/ui/shell/layout.ts` - every number, once

```ts
export const HEADER_H = 76;          // PDF pages 2-5, measured at a 1500px render
export const CONTEXT_H = 59;
export const RAIL_FR = 224 / 1500;   // ~0.149
export const INSPECTOR_FR = 456 / 1500; // ~0.304
export const INSPECTOR_MIN = 380;
export const INSPECTOR_MAX = 456;
export const SURFACE_MAX = 600;      // spec section 7: "a practical maximum around 600px"
export const COARSE_TARGET = 44;     // section 12, at (pointer: coarse)
export const BREAKPOINTS = [1440, 1024, 768] as const;
```

The header carries: that the figures came off a **raster render at 1500px** and are therefore ±10%;
that the spec's 200/300 is superseded by D-14 Q9 with the 402px arithmetic that decided it; and that
**no component may write any of these numbers itself**.

§13's table, re-derived:

| Width | Rail | Centre | Inspector |
|---|---|---|---|
| >= 1440 | 224 fixed | flexible, surface <= 600 | **~30%, clamped 380-456** |
| 1024-1439 | 200 | flexible | 300-340 (the spec's own figure, which fits here) |
| 768-1023 | collapsible | preserve a usable square surface | below the surface, or a drawer |
| < 768 | drawer | focused surface + visible mode switch | bottom sheet or a separate Properties view |

**The two non-width rules that are easiest to lose and are therefore tests:** size touch targets by
`@media (pointer: coarse)` and never by viewport width; survive an orientation change without resetting
work.

## The six components, and what each is not

| File | Renders | Explicitly not |
|---|---|---|
| `Header.svelte` | the wordmark + `FOR ZONA`, the nav slot, the connection slot | **not** the connection control itself (13-11) |
| `Nav.svelte` | `PLAYGROUND` / `SANDBOX` / `MY CONFIGS` at ~15px uppercase, 0.05em tracking; the active item in the action colour with a **2px underline of the same colour** ~2px below the baseline box | not a router; it takes the current section as a prop |
| `ContextBar.svelte` | three zones: breadcrumb (11px uppercase tracked, secondary), status (centre), destination-or-sentence (right) | **not** the install state machine (13-11), **not** the page target (13-12) |
| `Footer.svelte` | `HANGAR / by intech studio` left; `Help & shortcuts · Device actions` right; **the GPLv3 source link, verbatim, unchanged** | not a place to lose licence compliance |
| `Rail.svelte` | a titled section list with an optional two-digit zero-padded count per row, a divider, a second section, and a bottom-pinned action | not the catalog, not the element list - it takes rows |
| `Inspector.svelte` | an eyebrow, a headline, sections with titles, and a bottom-pinned pair of actions, scrolling independently while the surface and the primary action stay visible (§7) | not the schema (13-09) |

**The selected-row rule is the Rail's and it is D-03's three signals**: a 3px action-colour left rule,
the raised fill, and an action-coloured label. `identity.spec.ts` test 6 already holds it; the Rail is
its first real subject and the SUMMARY says whether the test needed widening.

**The two-digit zero-padded count** (`36`, `08`, `06` on the PDF) is a formatter, not a string: it
takes a number and pads to two. **Above 99 it stops padding rather than truncating** - say so; the
catalog is 27 today but `All saved` counts the user's own library, which has no ceiling.
