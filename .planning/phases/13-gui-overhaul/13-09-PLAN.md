<objective>
The workspace, and the schema-driven inspector the spec asks production to build - which HANGAR already
has.

**§7 asks for a validated schema driving the controls, and `src/lib/tune/view.ts` is one.** Twelve knob
kinds (`colour`, `speed`, `direction`, `size`, `count`, `note`, `feel`, `amount`, `mode`, `bend`,
`spring`, `scale`), checked exhaustive against the vendored compiler's own union by a type-level
assertion, and a **total** widget rule at `view.ts:358`: `colour` resolves to the colour widget;
`direction|mode|bend|spring|scale|note` resolve to `words` when there are at most eight options and
every option has a word, else `rail`; everything else is `rail`, skinned as dots up to eight and as a
track from nine. The mapping onto §7's control inventory is close to one-to-one:

| §7 control | HANGAR today | What this plan does |
|---|---|---|
| Segmented buttons, 2-3 alternatives | `words` with n <= 3, already a `role="radiogroup"` of real radios in labels | **rename the skin.** No behaviour change |
| Select for larger enumerations | `words` at 4..8 renders as a row | **the boundary moves to five**: a row up to four, a `<select>` from five. The PDF uses a select for `On release`. This is a real change and it is stated |
| Slider plus editable value | `rail` with `skin: "track"`, and `KnobView.readout` already right-aligns the integer | The PDF shows `48%` **read-only**, so the value stays read-only - and **D-14 Q5 already settled that free-typed numerics live only in the Sandbox** |
| Numeric stepper for exact MIDI values | absent - every knob is an index into a closed list | **Not built here, on purpose.** Widening `@CC` would be a knob value-count change on shipped entries, and the standing rule requires the shape-character consequence. D-14 Q5 says no |
| Swatch opens a popover, exact value available | the picker is inline | **moved into a popover, unchanged inside** |
| Changed fields get a marker and a per-field reset | `RESET_ALL` exists; per-knob reset does not | **built** - it is `view.index !== view.default`, which is one comparison |
| Disabled fields include a concise reason | `DisabledReason` already forbids "present, disabled" without one | **already stronger than the spec.** Say so, change nothing |

**There is no Advanced section, and that is a decision written down rather than an empty disclosure.**
§7 proposes Curve, Smoothing, Phase, Clock sync, Voicing, Inversion, Velocity response and External
trigger. **HANGAR's entries declare none of them**, and §7's own boundary says *"use actual parameter
names, limits, units, defaults and dependencies from the configuration schema"*. Inventing a tier would
mean new tokens in the Lua on entries already sitting at 857-875 of 908 at the picker corner.

**The colour picker is the most expensive correctness in the tree and it is moved, not rewritten.**
942 lines: the RGB444 lattice, three 16-step rails, the cheap-step marks and the arithmetic that makes
the picker corner a real budget figure. §7 wants a swatch that opens a popover with the exact value
still available; the PDF draws the swatch, the hex `#DCFF71` and an `Edit color` link. **The popover
contains today's picker essentially unchanged**, and its **three `border-radius: 50%` stay round** -
they are circles, D-10 exempts circles, and 13-01's layer C proves each of the three is square-boxed.

**And so do `Knob.svelte`'s three.** D-10 named only the picker's; **D-15 extended the exemption to six,

PDF draws the `Movement rate` slider with a round lime thumb and the Sandbox Knob as a circle. The gate
counts **exactly six** across the tree and a seventh is red.
