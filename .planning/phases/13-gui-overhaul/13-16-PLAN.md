<objective>
The Sandbox's interface: PDF page 3, built so that a mouse is optional.

**What the PDF draws.** A left rail with `ADD AN ELEMENT` over four rows (`Fader`, `Button`, `Knob`,
`XY pad`, each with a `+`), a divider, then `ON THIS SURFACE` with one row per placed element carrying
its name left and its **type right in secondary**, the selected row raised and ruled; pinned bottom, an
outlined `+ New surface`. The centre: the eyebrow `SANDBOX / MY PERFORMANCE`, the name, a two-segment
`Edit` / `▷ Play` switch, a sub-line, `Undo` and `Redo` left with `Save copy` right, then the **571px
plate** holding a 9x9 lattice and the regions drawn as filled tinted rectangles with a 1px boundary and
an 11px uppercase name at the top-left; the selected one carries an **action-colour outline plus eight
small filled square handles** at its corners and edge midpoints. Below the plate: `ZONA · CONTINUOUS
TOUCH SURFACE` left, `4 elements` right. The inspector: `SELECTED ELEMENT / FADER`, the name at ~34px,
a `2 × 6 units` chip, an `Element name` field, `Position & size` as a **2 x 2 numeric grid**, the helper
*"Snap to light guides. Touch remains continuous."*, `MIDI output` with `CC number` and `Channel`,
`Appearance` with the swatch, and a pair of outlined buttons `Duplicate` / `Delete element`.

**The rule that shapes every interaction: no drag is ever required.** §2's research row is explicit -
WCAG 2.2 asks for *"single-pointer alternatives to dragging, not just keyboard shortcuts"* - and §8's
two creation paths converge on the same state: **area first** (drag a rectangle, **or click a start
point and an end point**) and **element first** (choose a type, then place its default region with a
click). Both are built. A drag is an accelerator, never a requirement, and the numeric fields are a
third complete path.

**The element list is not decoration.** §14: *"add a spatial keyboard model and an element list so the
surface is not the sole means of selection."* The PDF's `ON THIS SURFACE` rail **is** that list, and it
is not optional - `BUILD-08` exists because a canvas that is the only way to select something is a
canvas some people cannot use.

**Edit and Play** (§8): Edit changes selection and layout; Play routes gestures to the preview and
**locks structural editing**; the mode label is persistent and visible; *"switching modes must not lose
selection or draft history"*. Play is also **the third place `PREV-04` is reached** - mouse-as-finger
on a surface the user built - and 13-20 decides whether the three together close it.

**"Follow hardware selection" is explicitly not built.** §8 offers it as optional and defaults to
keeping the inspector stable; ZONA has one touch element, so there is no hardware selection to follow.
Say so in the code rather than leaving a reader to wonder.

Purpose: a surface anyone can build, with every structural edit reversible.
Output: two routes, four components, one history module, six tests, two e2e titles. Term `+1 / +6`,
e2e `+2 / +2`.
</objective>

<interfaces>

## The empty state (§8, S01)

*"Show the actual touch surface with quiet light guides."* Not an illustration and not a question mark -
**the real 9x9 plate with its lattice**, the direct instruction *"Add an element, or select an area on
the surface."* verbatim, one visible starter action and a small template alternative. §8 says *"remove
the question-mark placeholder"*; there is none in HANGAR and there will not be one.

**The template alternative** is one starter surface - a fader and a button, the two kinds that fit in
every branch of 13-02's answer - and it is named as a template rather than as a default, so an empty
surface stays possible.

## The two creation paths, both without drag

| Path | With a pointer | Without a drag | With the keyboard |
|---|---|---|---|
| **Area first** | drag a rectangle | **click a start cell, click an end cell** | move focus across the plate with arrows, mark with Enter, mark again |
| **Element first** | click `+` on a type, click a cell | the same - it is already click-only | tab to the type, Enter, arrow to a cell, Enter |

**Then the numeric path**: place anything, then type `Column`, `Row`, `Width`, `Height`. That is the
third complete route and it is the one §2's WCAG row exists for.

## Selection, handles and the lattice

- The selected region: an action-colour 1px outline **plus** eight filled square handles at corners and
  edge midpoints **plus** the raised row in the element list **plus** the action-coloured label - the
  three-signal rule again, with a fourth.
- **Snapping**: regions snap to cells; **values come from raw touch**. The PDF's own helper says it -
  *"Snap to light guides. Touch remains continuous."* - and 13-14's model already encodes it. The
  editor shows the proposed bounds **before committing** (§8).
- The lattice is a **static overlay**, not 81 stroked rectangles redrawn per frame; the research is
  explicit that path stroking is the expensive 2D primitive and that a static overlay is the fix.

## History (`history.ts`)

Undo and redo over **structural** edits: place, delete, move, resize, rename, retype, duplicate,
recolour, MIDI change. **The boundary rule matters and is stated**: a numeric field's keystrokes are
**one** entry, coalesced until focus leaves or the value commits - otherwise typing `12` into a width
costs two undos and the feature is annoying rather than useful. Deletion is undoable (§8's own
requirement).

**This is not `Undo randomize`.** 13-10 built that as one stored vector for the Playground's knobs;
this is a real history for a different object. Both headers say so, pointing at each other.

## The mode switch, and what Play locks

`Edit` / `▷ Play`. In Play: the palette is disabled with a reason, the handles disappear, the numeric
fields become read-only with a reason, and pointer input drives the preview. **Selection and history
survive the round trip** - assert it in both directions. The mode label is persistent and visible, and
the return action is the switch itself.

## The budget meter, and the cap

The meter from 13-10 renders `cost.ts`'s answer: *"N of 908 · room for about M more"*. **Sixteen is the
ceiling**, and the palette's `+` is disabled with a reason at sixteen - `DisabledReason`'s own rule,
which forbids a disabled control without a named reason. **If 13-14 found a cost above 908 before
sixteen**, the cap is that number and the message says so.
