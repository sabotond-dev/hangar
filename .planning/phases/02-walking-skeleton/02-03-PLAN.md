<standing_rules>
- **The restore rule (mandatory, phase-wide).** A successful `CONFIG/EXECUTE` sets
  `page_change_enabled = 0` in firmware (`grid_decode.c:1279`) and the ONLY thing that restores it is
  an inbound `HEARTBEAT` with `TYPE 255` (`grid_decode.c:717`; the timeout restore at
  `grid_esp32_port.c:480` is commented out). In this plan the rule becomes structure, three ways:
  `runNoOpCycle` sends it in a `finally`; the page carries a standing "Restore heartbeat" button that
  is enabled whenever the port is open, including after an error; and the page text says what it is
  for. Without it the user's ZONA cannot change page until it is power-cycled — that is not a no-op.
  **Never send `TYPE 254`.**
- Address the module by the `SX`, `SY` and `PAGENUMBER` its own heartbeat reports. A hardcoded page 0
  against a module on page 2 is NACKed by firmware (`grid_decode.c:1265`) and proves nothing.
- `PAGEACTIVE/EXECUTE`, `NVMERASE`, `PAGECLEAR` and `PAGEDISCARD` stay forbidden (D-06). Do not name
  them in any non-spec file, not even in a comment.
- **`requestPort()` is the first statement in the click handler and nothing is awaited before it.**
  Transient activation EXPIRES (about 4.9 s in Chromium) rather than being consumed. Modules load in
  `onMount`, exactly as `/dev/fidelity/+page.svelte:25-27` does.
- **Stale-wrangler preflight before ANY build or e2e run** (Phase 3 pattern): `netstat -ano | grep -w
  LISTENING | grep ":4173"`; if anything is listening, walk to the `npx-cli` root and
  `powershell -NoProfile -Command "taskkill /PID <root> /T /F"`. Killing `workerd` alone does not
  work. Playwright's `reuseExistingServer` will happily attach to a zombie serving a stale `build/`.
- **Playwright output goes to `.tmp-e2e/`, never `test-results/`** — Playwright unlinks its
  `outputDir` at the start of every run, so a redirect target inside it vanishes mid-run.
- **No Playwright test title may contain the word `failed`**, because the e2e gate greps the captured
  log for it.
- No Claude attribution anywhere, no emojis — including in page text. Prettier default style.
- Files created in a task are `git add`ed before any negative check is run against them.

The "required" definition for the heartbeat A/B, which must appear in the page text **before** the
run so the experiment has a falsifiable expectation (02-RESEARCH.md Open Question 1):

> With the host heartbeat off, within a 10 s window from connect: inbound HEARTBEAT frames arrive at
> 3 per second or more; both CONFIG/FETCH return a REPORT within 1000 ms; both CONFIG/EXECUTE return
> an ACKNOWLEDGE within 500 ms; and PAGESTORE returns an ACKNOWLEDGE within 3000 ms. If all four
> hold, the host heartbeat is not required.

The burst probe is read-only and is better evidence than the two writes: a `CONFIG/FETCH` is 49 bytes

`absorbFrame` keys the seen map on `${sx},${sy}`, coerces `HWCFG` with `Number` before
`module_type_from_hwcfg` and coerces `e.hwcfg` with `Number` before comparing in `module_hwcfgs()` —
both coercions are required and the desktop does both (`runtime.ts:2366`, `:2370`). It records the
active page from the class carrying `PAGENUMBER` that rides alongside a heartbeat, so the page number
is never a constant (D-10). **Three conditions, all required, before `activePage` moves:** the class
carries a `PAGENUMBER`; a `HEARTBEAT` class is present in the SAME decoded frame; and the class
carries neither `EVENTTYPE` nor `ACTIONLENGTH`. Without the second and third, a `CONFIG/REPORT` —
which also carries a `PAGENUMBER`, and arrives on every fetch — would silently retarget the run at
whatever page was last fetched. `identify` returns `undefined` until a `TYPE 1` heartbeat from a ZONA and
an active page have both been seen; the page refuses with a message if that has not happened inside
`IDENTIFY_WINDOW_MS`, because absence means the module is not the USB-attached one.

`storeAllowed` is `otherModules.length === 0` (D-12).

Every step this module emits uses a `StepId` from `STEP_IDS` in `$lib/transport` — `identify`,
`fetch-setup`, `fetch-timer`, `write-timer`, `write-setup`, `store`, `refetch-setup`,
`refetch-timer`, `restore-page-change`, `burst`. Never a string literal invented here: plan 05's
post-checkpoint gate asserts on those ids, and a gate cannot be written against ids that only exist
after the hardware run.

`writeBack` is sequential. **Two tokens must not appear anywhere in `sequence.ts`, including in
comments, because this task's acceptance greps count comment lines:** the parallel-promise combinator
(describe the rule as "sequential, one acknowledgement at a time" instead), and any literal assignment
or property setting the active page to zero (the page is unknown until a heartbeat reports it, so the
state starts `undefined` and is narrowed).
