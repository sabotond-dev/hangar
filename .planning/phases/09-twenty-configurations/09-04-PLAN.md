### The seven traps

`glag(0, x + y*9)` always, never a computed hardware index. Every division `//`, every `math.sqrt`
and `math.atan` closed with `// 1` (F2Ieq turns a fraction into 0, silently). Colour channels
truncate rather than clamp, so every knob value keeps all channels inside 0..255. Onset is
`e == 4 or e > 8`, an end is `e >= 5`, and code 9 is a tap with no separate lift. Never
`glp(n, l, -1)`. Never a 65535 keeper on a layer carrying a decaying trail. No token may be a prefix
of another in the same entry.

One layer caps at 49.6 % of the colour you ask for, so a card that must look bright paints layers 1
and 2 with the same value. Layer 0 is the alert layer and is never written.

Firmware advances armed phases in C every 10 ms with no Lua running: arm once with `glpfs` plus `glt`
and stagger the **starting phase** per cell. Rate is uint8 and wraps. `glt` maxes at 65535 ticks
(655 s) and on the last tick firmware zeroes the rate, so a long-lived animation must be re-armed
with `glf` or `glpfs` from the Timer.

**Route: `lua`.** `sends.scale` is read only when `sends.kind` is `"zones"` **and only on the 3x3 and

every chord shape is the same shape in every key. KEYS is the opposite argument: it removes notes.

**Mechanism.**

- `note = @BASE + x + y*@ROW` for the cell at (x, y). `@ROW` is the row interval in semitones, so the

- `deg = note % 12`. The scale is a 12-bit mask, one integer per scale, selected by `@SCALE`:

  inside the restricted subset. **Compute the four masks yourself and check each against its degree
  list before writing it into a knob value**; a wrong mask is a card that plays a scale nobody asked
  for and no gate will notice.

### GRIDLOCK

**The card.** Eighty-one clips under one hand. Fire one and a ring rolls out from it, which is how you
know it took.

**Route: `lua`.** `sends.grid` is `3x3 | 4x4 | 9x9`, and on the 9x9 the compiler emits a chromatic
zone map with one `gridColour` and one `heldColour` - there is no per-cell fired state and no ripple.
The card is a per-cell picture over a per-cell state table, which is outside the vocabulary.

**Not CHORUS.** CHORUS's bloom is the same firmware mechanism - a phase offset per cell so the LED
engine expands the ring in C for free - and that is deliberate: it is the cheapest spectacular thing
the module can do, and reusing it here costs nothing. What is different is the card. CHORUS is nine
chord pads; GRIDLOCK is eighty-one launch cells and a track grid you can count. Say both halves in the
header: the mechanism is shared on purpose, the configuration is not.

**Mechanism.**

- Setup paints nine 3x3 track blocks on layer 2 in two alternating shades of `@BLOCKC`, so the nine
  tracks are countable at rest without any legend. `restsBlack: false`.
- On onset: `cx = x*9//128`, `cy = y*9//128`. Fire it. The ripple is one pass over `a = 0..80`
  computing the Chebyshev distance `d = math.max(math.abs(px - cx), math.abs(py - cy))` from the fired
  cell - `math.max` and `math.abs` are both on the allow-list - and writing
  `glpfs(glag(0, a), 1, 255 - d*@SPREAD, 250, 0)` with `glt(..., 1, @TRAIL)`. The **starting phase**
  carries the ring outward; no Lua runs after the write. Clamp `255 - d*@SPREAD` at 0 with `glim` so a
  far cell does not wrap to a bright phase - that wrap is exactly the kind of silent uint8 fault this
  entry is most likely to ship.
- **The send.** Nine tracks by nine scenes does not fit a note number, and inventing an eighty-one
  note range would push past 127. Send `self:gms(@CH, 144, @BASE + cx, cy + 1, 0)`: the **column is
  the note**, the **row rides in the velocity**. Nine notes and nine velocities, both inside range,
  both mappable in a DAW in a minute. Write that mapping into the header **and** state it as the
  entry's own arithmetic, because a reader will otherwise assume a note per cell.
- Note-off: send it immediately after the note-on. A clip launcher is a trigger, not a held note.
  Nothing is stored per contact, so nothing can stick.
- `timer: ""`. The block picture is static and every ripple carries its own countdown. Say so.

**Traps for the header.** The `glim` clamp on the phase, and why: uint8 wrap would light the far
corners brightest. `math.abs`/`math.max` are on the allow-list; every division is `//`. Code 9 needs
no special case because the note-off is unconditional - say that explicitly, because it is the one
place in this phase where the code-9 trap is answered by design rather than by a branch. No keeper.

**The honest limit, for the card copy.** The pad shows what **you** fired, not what the host is
playing. There is no inbound MIDI in this phase (D-04), and a clip that stops on its own leaves the
cell looking fired. That sentence belongs in the header and the description must not imply otherwise.

| `base` | Lowest note | `note` | `@BASE` | `"36"`, `"48"`, `"60"`, `"24"` | index 1 |
| `channel` | Channel | `mode` | `@CH` | `"0"`, `"1"`, `"9"`, `"15"` | index 0 |

### TABLE

**The card.** Wavetable position across, filter down, and the grid draws the shape you are sitting on.

**Route: `lua`.** The pad draws a computed nine-column plot that changes with X. `look.kind` is
`none | breathe | shimmer | scan | wave | swirl | ripple | drift | showpiece` and none of them is a
data plot; `sends.kind: "xy"` sends the two axes but paints nothing. The card is the plot.

**Mechanism.**

- X selects one of four wave shapes, `w = x*4//128`, and Y is the filter.
- The plot: for each column `c` in 0..8, a height `h` in 0..8 from a per-shape expression. Keep the
  four expressions arithmetic rather than tabular if it is cheaper, and measure both ways - a
  nine-entry table per shape is 36 literals and will not fit beside four knobs, while
  `h = (c*2)%9` style arithmetic is a handful of characters. **Measure before choosing**, and record
  in the SUMMARY which form you shipped and what the other cost.
- Cells at or below the height are lit in `@WAVEC` on both layers; the rest are `@BGC` on layer 2
  only, dim, so the plot reads against a field rather than against black. `restsBlack: false`.
- Redraw **only when the shape index changes** - store it in `self.w` and compare. That is not an
  optimisation, it is the 256-byte-per-cycle rule: repainting 81 cells on every one of 100 samples a
  second is affordable in LED writes but the Lua time is not, and `touch_cb` must stay under about
  1000 microseconds or the module starts dropping touch samples. Write that reason in the header.
- Sends: `self:gms(@CH, 176, @CC, x*127//128, 0)` and `self:gms(@CH, 176, @CC + 1, y*127//128, 0)`,
  every sample, both 7-bit. Two CCs is under the eighteen-message cycle ceiling with room to spare.
- `timer: ""`. Nothing animates on its own; the plot moves only when you do. Say so, and note that
  this makes TABLE one of the phase's still cards - `listing.spec.ts` requires all three motions to
  occur and a wall of twenty animated cards would need its quiet ones anyway. **Confirm the motion
  against the fixture in task 3**; a card whose plot never changes without a finger will classify as
  `static`, and that is correct and should be declared, not corrected.

**Traps for the header.** Every division `//`. The height expression must never produce a fractional
or negative row - close it with `glim(h, 0, 8)`. Colour channels inside 0..255. Redraw gating on
`self.w`, marked do-not-remove with the touch-budget reason.

**The honest limit, for the card copy.** Nine columns of nine cells is a caricature of a wavetable,
not an oscilloscope; and the pad draws the shape it is **asking** for, not the one your synth is
producing.

**Knobs - five.**

| id | label | kind | token | values | default |
|---|---|---|---|---|---|
| `cc` | First controller | `amount` | `@CC` | `"1"`, `"11"`, `"74"`, `"16"` | index 2 |
| `channel` | Channel | `mode` | `@CH` | `"0"`, `"1"`, `"9"`, `"15"` | index 0 |
| `wave` | Wave colour | `colour` | `@WAVEC` | four bright triples | index 0 |
| `field` | Field colour | `colour` | `@BGC` | four dim triples | index 0 |
| `sense` | Redraw step | `feel` | `@SENSE` | `"1"`, `"2"`, `"4"`, `"8"` | index 0 |
