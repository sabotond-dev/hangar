### `gks`, exactly

`gks(default_delay_ms, is_modifier, state, keycode, ...)` - one leading delay, then any number of
three-tuples. The call is rejected unless `(nargs - 1) % 3 == 0`.

| field | values |
|---|---|
| `default_delay` | 0..255 ms between every step |
| `is_modifier` | 0 an ordinary key; 1 a modifier; **15 this tuple is a delay** (its third value is the delay in ms, 0..4095) |
| `state` | 0 up, 1 down, **2 down-then-up**, expanded by firmware |
| `keycode` | a USB HID usage id, 0..255 |

So a modified keystroke is one call: modifier down, key down-then-up, modifier up - three tuples after
the delay. **State 2 is what keeps it to one call**, and it matters: `gks` costs `10 + 4n` bytes of the
256-byte per-cycle protocol buffer, so about sixty-one key steps fit in a cycle and a chatty handler
starves everything else.

`gks` is **recorded and inert** in HANGAR (`lua-host.ts:407-410, 429`). It is callable bare.

### The seven traps

`glag(0, x + y*9)` always. Every division `//`; every `math.*` result closed with `// 1`. Colour
channels truncate rather than clamp. Onset is `e == 4 or e > 8`, an end is `e >= 5`, code 9 is a tap
with no separate lift. Never `glp(n,l,-1)`. Never a 65535 keeper on a decaying layer. No token may be
a prefix of another.

One layer caps at 49.6 % of the colour asked for; paint both for brightness. Layer 0 is never written.
Firmware advances armed phases in C for up to 655 s, then zeroes the rate - a long-lived animation
must be re-armed with `glf` or `glpfs` from the Timer.

### STAGE

**The card.** Nine scenes for a stream. The live one glows, the one you are lining up breathes beside
it, and it works on a machine with no software installed at all.

**Route: `lua`.** The only HID in the `sends` vocabulary is `sends.kind: "trackpad"`, which is a
mouse. There is no keyboard anywhere in `PadState`. Say so in the route note.

**Mechanism.**

- Nine 3x3 zones. Setup paints each zone's four corner cells in `@ZONEC` on layer 2 - countable at
  rest, `restsBlack: false` - and lights zone 0 as live.
- `self.l` is the live zone. On onset, fire zone `z`: send the keystroke and repaint two zones (the
  old live one back to idle, the new one to `@LIVEC` on both layers). Two zones, not eighty-one.
- The keystroke, one call:
  `gks(@DELAY, 1, 1, @MOD, 0, 2, @KEY0 + z, 1, 0, @MOD)` - modifier down, key down-then-up, modifier
  up. Ten arguments: one delay plus three tuples, so `(10 - 1) % 3 == 0` and firmware accepts it.
  **Check that arithmetic for the exact call you ship**; a rejected `gks` is silent.
- `@KEY0 + 8` must stay under 256 for every `@KEY0` value. The natural choices are the function-key
  block (F13 is usage id 104, so F13..F21 is 104..112) and the digit row (1 is usage id 30, so 1..9
  is 30..38). Write the arithmetic into the header.
- `@MOD` is a modifier usage id, or 0 for none. When it is 0 the two modifier tuples are wasted but
  harmless; measure whether a branch is cheaper than the two dead tuples and record the answer.
- The **preview** half - a zone breathing under a held finger - is `glpfs(a, 1, 0, @RATE, 3)` plus
  `glt(a, 1, 30000)` on the held zone, cleared on lift. That is the second half of the card's picture
  and it costs almost nothing.
- Timer: one line, re-arming `gtt(0, @PERIOD)` and re-issuing `glpfs` on the live zone, so the glow
  does not freeze after 655 s.

**Traps for the header.** The `gks` arity rule. `@KEY0 + 8 < 256`. Code 9: a fast tap must fire the
scene, so the onset filter is `e == 4 or e > 8`. `@DELAY` is 0..255 only. The keeper is 30000 on a

### SHUTTLE

**The card.** Scrub video with a finger. The arc grows and spins faster the harder you push it.

**Route: `lua`.** Repeated keystrokes at a rate derived from position. Nothing in `PadState` repeats
anything, and there is no keyboard in `sends` at all.

**Mechanism.**

- The pad is one horizontal shuttle. `s = x*9//128 - 4` gives a signed speed in -4..4. Store it in
  `self.s`.
- The Timer is the shuttle: it re-arms itself **first** with `gtt(0, @BASEP // (1 + math.abs(self.s)))`
  - so a faster speed means a shorter period - then, if `self.s` is non-zero, sends one keystroke:
  `gks(0, 0, 2, @KEYF)` for a positive speed and `gks(0, 0, 2, @KEYB)` for a negative one. Four
  arguments: one delay plus one tuple, `(4 - 1) % 3 == 0`.
  **The floor `//` matters twice** - the period and the speed - and `math.abs` is on the allow-list.
  Guard the period against zero with `math.max(..., 20)`; a `gtt` of 0 never fires and the shuttle
  would stop silently.
- The arc: the sixteen cells of the middle two rings, or a simple horizontal bar from the centre out
  to `|s|` cells - **ship the bar if the arc does not fit, and say which in the header**. Whatever it
  is, animate it by `glf(a, 2, @GAIN * |s|)` so the phase runs faster with the speed. That is the
  card: the animation rate **is** the data, which is ARC's argument applied to a different quantity,
  and the header should note the family resemblance and the difference.
- At rest the arc is a dim full ring in `@RESTC`, painted in Setup. `restsBlack: false`.
- Rate wraps at 256, so `@GAIN * 4` must stay under 256 - write the arithmetic into the header.

**Traps for the header.** The uint8 rate wrap. The `gtt` zero guard. Every division floored. `gks`
arity. Code 9 is harmless - a tap sets a speed and the Timer does the rest - and the header says so.
The 655 s ceiling is answered by the Timer re-arming the arc every period.

**The honest limit, for the card copy.** The same one STAGE has - HANGAR cannot show a keystroke -
plus a real one: a keystroke shuttle is coarse next to a jog wheel, because the host advances one
frame per key press and the pad can only press so fast inside a 256-byte cycle.

**Knobs - five.**

| id | label | kind | token | values | default |
|---|---|---|---|---|---|
| `period` | Slowest step | `speed` | `@BASEP` | `"400"`, `"300"`, `"200"`, `"120"` | index 1 |
| `gain` | Spin gain | `amount` | `@GAIN` | `"8"`, `"16"`, `"24"`, `"32"` | index 1 |
| `forward` | Forward key | `note` | `@KEYF` | four usage ids: `"15"` (L), `"79"` (right arrow), `"55"` (period), `"54"` (comma) | index 0 |
| `arc` | Arc colour | `colour` | `@ARCC` | four bright triples | index 0 |
| `rest` | Resting colour | `colour` | `@RESTC` | four dim triples | index 0 |

`@KEYB` is derived from `@KEYF` in the Lua rather than being a fifth knob - pick the paired key
arithmetically where the usage ids allow it, and **if they do not, make it a sixth knob rather than
shipping a wrong key**. Record which you did. Prefix check: `@BASEP`, `@GAIN`, `@KEYF`, `@ARCC`,
`@RESTC` - none is a prefix of another.
