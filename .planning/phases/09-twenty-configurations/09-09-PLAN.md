### The 655 second ceiling, which POMODORO exists inside

`glt` maxes at **65535 ticks, about 655 seconds**. When the countdown reaches 1, firmware sets the
rate to 0 and the animation **freezes at whatever phase it reached**, and **re-arming with `glt` alone
will not restart it** - the rate was zeroed. You must re-issue `glf` or `glpfs`. Re-arming *before*
expiry keeps the motion continuous.

`ZONA-CAPABILITIES.md` section 5.3 lists three ways to do it and says there is no fourth: a Timer
event re-arming, a `self.tim` rawset from Setup, or re-arming inside `touch_cb` - which only works
while somebody is touching the pad, and is therefore wrong for an ambient card. **A twenty-five minute
timer is the phase's clearest instance of this**, and it is a Timer-event card by necessity.

`gtt(index, 0)` never fires - the guard is `> 0` - and is identical to stopping the timer. A Timer
that computes a period must never let it reach zero.

Firmware's Timer fires on the next 100 Hz UI cycle after the countdown, so resolution is about 10 ms
and worse under load. A one-second tick is fine; a one-millisecond one is not.

### The seven traps

`glag(0, x + y*9)` always. Every division `//`; every `math.*` result closed with `// 1`. Colour
channels truncate rather than clamp. Onset is `e == 4 or e > 8`, an end is `e >= 5`, code 9 is a tap
with no separate lift. Never `glp(n,l,-1)`. Never a 65535 keeper on a decaying layer. No token may be
a prefix of another.

One layer caps at 49.6 % of the colour asked for; paint both for brightness. Layer 0 is never written,
and note that on ZONA the alert system touches only the **32 border LEDs** - the same ring POMODORO
draws on - so an alert will brighten it additively. That is a fact to know, not a fault to fix.

  <action>
**The card.** A twenty-five minute ring that drains around the edge, so the time left is a thing in
the room rather than a number on a screen.

**Route: `lua`.** A countdown state machine with a per-cell ring map. Nothing in `PadState` counts;
every `look.kind` is a phase generator with no notion of elapsed time.

**Mechanism.**

- The **32 border cells** are the ring: `x == 0 or x == 8 or y == 0 or y == 8`. Precompute the ring's
  cell order once in Setup into `self.r` - a clockwise walk - so the Timer indexes rather than
  recomputing.
- `self.t` is the seconds remaining, starting at `@MINS * 60`. The Timer re-arms itself first with
  `gtt(0, 1000)`, decrements, then paints: the first `self.t * 32 // (@MINS * 60)` cells of the ring
  in `@RINGC`, the rest black. **One divide, floored.** Repainting 32 cells once a second is nothing.
- The inner 7x7 breathes slowly in `@RINGC` during work and `@BREAKC` after the interval ends, so the
  card reads as "working" or "resting" from across a room without counting cells.
- **The 655 second ceiling, and this is the entry that meets it.** The breathe is armed with
  `glpfs(a, 2, p, 1, 3)` plus `glt(a, 2, 60000)` - 600 seconds - and a twenty-five minute interval is
  1500 seconds, so it would freeze twice during one pomodoro. The Timer therefore **re-issues
  `glpfs` on all 49 inner cells every `@REARM` seconds**, well before expiry, with `@REARM` a literal
  around 300. Write the whole argument into the header in capitals, with the firmware fact - *on the
  last tick firmware sets the rate to 0, so re-arming with `glt` alone will not restart it* - and mark
  the re-issue do-not-remove. **This is the single most important line in the entry**, and a card that
  dies after ten minutes on a visitor's real hardware is a broken card.
- Guard the Timer period: it is a literal 1000 here, never computed, so it can never reach zero.
- Start and pause: a tap anywhere in the inner 7x7 toggles `self.p`. A paused timer holds `self.t` and
  stops decrementing; the ring stays where it is. A tap while at zero resets to `@MINS * 60`.
- At zero: send `self:gms(@CH, 144, @NOTE, 110, 0)` and its note-off, flash the whole ring once, and
  switch the inner colour to `@BREAKC`. **One note, once** - not a note per second.
- `restsBlack: false`: Setup paints a full ring and starts the breathe, so the card is complete on
  arrival and the golden frames show a draining ring.

**Traps for the header.** The 655 second re-issue, in capitals, do-not-remove. `glt(a, 2, 60000)` is a
long keeper on a **background** layer with a single-digit rate - legitimate, three orders of magnitude
below the pitfall-1 rate floor, and marked do-not-fix, exactly as ARC's two keepers are. Every division
floored. Colour channels inside 0..255. Code 9 on the start-pause tap. And the note about layer 0: an
alert on ZONA lights the 32 border cells additively, so a page change or a USB event will briefly
brighten the ring - a fact, not a fault.

**The honest limit, for the card copy.** The pad has no clock of its own beyond its Timer, which fires
on the next 100 Hz cycle and drifts under load - this is a kitchen timer, not a stopwatch. Say the
drift plainly; over twenty-five minutes it is visible.

|---|---|---|---|---|---|
| `mins` | Minutes | `count` | `@MINS` | `"15"`, `"20"`, `"25"`, `"50"` | index 2 |
| `ring` | Working colour | `colour` | `@RINGC` | four warm triples | index 0 |
| `break` | Resting colour | `colour` | `@BREAKC` | four cool triples | index 0 |
| `note` | Alarm note | `note` | `@NOTE` | `"60"`, `"72"`, `"48"`, `"84"` | index 0 |
| `channel` | Channel | `mode` | `@CH` | `"0"`, `"1"`, `"9"`, `"15"` | index 0 |
