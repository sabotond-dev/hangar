### `self:gms` modes, which matter to two of these three

| mode | Emits |
|---|---|
| nil or 0 | `gms(ch, cmd, p1, p2)` - 7-bit |
| **1** | **CC 14-bit**: `gms(ch,0xB0,p1,p2//128)` then `gms(ch,0xB0,p1+32,p2%128)` |
| 2 | NRPN: CC99 = `p1//128`, CC98 = `p1%128`, CC6 = `p2` |
| 3 | NRPN 14-bit |

**Mode 1 uses `p1 + 32` for the least significant byte, so `p1` must be 0..31** for a standard
14-bit pair. That is a hard constraint on STRIP's controller knob and it is stated in its task.

Also: 14-bit CC is **two** messages per send. The protocol buffer is 256 bytes and clears once per
10 ms cycle, so about eighteen 7-bit messages or nine 14-bit ones fit in a cycle. Nothing here goes
near that, but a configuration that sent 14-bit X and Y for five contacts would not fit and firmware
does not queue.

### The 10-bit unlock

`self:txma(1023)` and `self:tyma(1023)` in Setup widen the coordinate range from 0..127 to 0..1023.
It buys the correct **range**, not extra resolution - there are 1024 distinct values either way. **Do
not set `txma(16383)`**: `16384 * 1023 / 1024 = 16368`, so the top fifteen codes are unreachable. Set
1023 and scale in Lua with `(v * 16383) // 1023`. Element state resets on a page change, so Setup is
the only place it can be asserted.

### The seven traps

`glag(0, x + y*9)` always. Every division `//`; every `math.*` result closed with `// 1` (a fraction
reaching a firmware call becomes 0, silently). Colour channels truncate rather than clamp. Onset is
`e == 4 or e > 8`, an end is `e >= 5`, code 9 is a tap with no separate lift. Never `glp(n,l,-1)`.
Never a 65535 keeper on a decaying layer. No token may be a prefix of another.

One layer caps at 49.6 % of the colour asked for; paint both for brightness. Layer 0 is never written.
Firmware advances armed phases in C for up to 655 s; past that the rate is zeroed and only `glf` or
`glpfs` restarts it.

**Mechanism.**

- Nine columns, `c = x*9//128`. There is no spare column: the rail is drawn by dimming the **top and
  bottom** cell of each column rather than by spending a column, and the header states that trade.
  Reconsider only if the measured card has room; if you spend a column on a master fader instead,
  that is a legitimate design and the header must then say the pad has eight strips and a master.
  **Whichever you ship, the description and the header must agree with the code.**
- Level: `lv = 8 - y*9//128`, so 0 at the bottom and 8 at the top. Store `self.v[c]`.
- Paint one column in one pass: cells at or below `lv` in `@LEVELC` on both layers, cells above in
  black, the top cell in `@RAILC` unless the column is muted, in which case the whole column paints
  `@MUTEC` dim and the top cell paints `@MUTEC` bright. One pass, never erase-then-paint - firmware
  has no double buffer and tearing is possible.
- Send: `self:gms(@CH, 176, @CC + c, self.v[c]*127//8, 0)` on every change, 7-bit. Nine controllers
  from `@CC`, so `@CC + 8` must stay under 128 for every `@CC` value: choose the values with that

  remembered level. **This is a latch**, so the header must carry the same warning HOLD's does: the
  simulator cannot reproduce the firmware stuck-contact bug, and a dropped release on a real module
  can leave a mute you did not ask for. Cross-reference HOLD's bench row.
- `timer: ""`. The picture is repainted on change and nothing animates on its own. Say so.
  **Confirm the motion against the fixture in task 3**: a card whose light never moves without a
  finger classifies as `static`, and that is correct - the catalog needs its still cards and
  `listing.spec.ts` requires all three motions to occur.

**Traps for the header.** Every division `//`. `@CC + 8` under 128. Code 9 handled - a tap on the mute
row must toggle exactly once, and a `e == 5`-only branch would miss it entirely. Colour channels
inside 0..255. The latch warning above. No keeper.

### STRIP

**The card.** The whole pad is one long fader, with a fine row along the bottom for the last few
numbers.

**Route: `lua`.** `sends.faders` is 3 or 4, and `hiRes` is a card-wide flag rather than a per-fader
one. One whole-pad fourteen-bit fader with a vernier row is not expressible.

**Mechanism.**

- Setup unlocks the range: `self:txma(1023) self:tyma(1023)`. Every division that was `/127` is now
  `//1023`. **Never `txma(16383)`** - the top fifteen codes would be unreachable. Write that in the
  header.
- Rows 0..7 are the coarse fader. `coarse = (1023 - y) * 2047 // 1023` gives 0..2047 from the vertical
  position - eleven bits from the sensor's ten, so state honestly in the header that the coarse half
  carries ten real bits and the arithmetic scales them, it does not invent resolution.
- The bottom row (row 8) is the vernier: `fine = x*8//1023`, 0..7, three bits.
- `value = coarse * 8 + fine`, clamped with `glim(value, 0, 16383)`.
- Send `self:gms(@CH, 176, @CC, value, 1)` - **mode 1**, which emits the pair
  `CC @CC = value//128` then `CC @CC+32 = value%128`. **Therefore every `@CC` value must be 0..31.**
  Choose from `"1"`, `"7"`, `"11"`, `"16"` and write the constraint into the header in capitals: a
  controller above 31 would send its least significant byte on a controller number that means
  something else, silently.
- The picture: a filled bar from the bottom up whose height is `coarse * 9 // 2048`, in `@BARC` on
  both layers; the bottom row's lit cell at `fine` in `@VERNC`; the unlit remainder in `@RAILC` dim so
  the pad reads as a fader rather than as a bar floating in black. `restsBlack: false`, and Setup
  paints the bar at a default value so the card is legible on arrival.
- `timer: ""`.

**Traps for the header.** The `p1` 0..31 constraint, in capitals. The `txma(16383)` trap, named and
refused. Every division `//`. `glim` on the value. Colour channels inside 0..255. Code 9 is harmless
here - a tap sets a value and there is nothing to release - and the header should say that explicitly
rather than leaving a reader to wonder where the note-off went.

can send a number finer than you can see, and the vernier row is the only part of the picture that

### LEARN

**The card.** A mapping helper. It lights only the row it is sending X on, then only the column for Y,
one at a time, so your host learns the right control the first time.

**Route: `lua`.** The compiler has this idea and refuses to ship it: `soloStream` is
**audition-only** derived state - `encodeStamp` never writes it, and `withChange`, `fit` and the
ledger strip it before measuring (`_pad.ts`, the `PadState` comment). A configuration whose whole
point is soloing one stream cannot be a `PadState`, because the field that would express it is
deliberately not persistable. Quote that in the route note; it is the sharpest route argument in the
phase.

**Mechanism.**

- Three modes in `self.k`: 0 sends X only, 1 sends Y only, 2 sends both. A tap on the centre cell
  (index 40) advances the mode. Everything else is a normal XY surface.
- The legend **is** the light. Mode 0 lights the bottom row in `@ONC` and everything else in `@OFFC`
  dim; mode 1 lights the left column; mode 2 lights both. Repaint on a mode change only, never on
  every sample - the touch budget rule again, and the header says so.
- Sends, on every sample outside the centre cell:
  `self:gms(@CH, 176, @CC, x*127//128, 0)` when the mode allows X, and
  `self:gms(@CH, 176, @CC + 1, y*127//128, 0)` when it allows Y. In mode 0 the Y message is not sent
  at all - not sent at a fixed value, **not sent** - because a host learning a control latches onto
  whatever moves and a constant stream would still be a stream. State that in the header; it is the
  entire feature.
- `@STEP` throttles the send: emit only when the value has moved by at least `@STEP`. A host's learn
  function is happier with a few clean messages than with a hundred, and it keeps the cycle budget
  clear. Store the last sent value per axis.
- `timer: ""`. `restsBlack: false` - the legend is painted in Setup.

**Traps for the header.** The centre-cell tap must use `e == 4 or e > 8`; a fast tap on the mode cell
is exactly the code-9 case and a missed one is a mode that does not change. Every division `//`.
Colour channels inside 0..255. Repaint gating, marked do-not-remove with its reason.

**The honest limit, for the card copy.** It fixes the problem on the device: it cannot tell you
whether the host heard it, because nothing in this phase receives.

**Knobs - five.**
