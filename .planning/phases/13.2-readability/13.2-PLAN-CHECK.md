## 1. Is the gate sufficient? The holes, ranked

### H-1 (BLOCKER) - the built-CSS hash is a function of the comment vocabulary, not of the styles

`src/app.css:1` is `@import "tailwindcss" source(".")`, so the Tailwind v4 scanner reads every file under `src/` - `.ts`, `.svelte`, `.spec.ts`, comments included (`.css` is not scanned) - and emits a utility rule for every token that spells a utility. Measured on the build on disk (`build/_app/immutable/assets/0.CJ_23Erf.css`): the `@layer utilities` block holds **45** classes, of which **5** are named by a `class` attribute in any `.svelte` or `app.html` (`block grid outline ring sr-only`) and **40** exist only because a word appears somewhere else in `src/`: `@container absolute backdrop-filter blur border border-collapse collapse container contents ease-out filter fixed flex flex-wrap font-display grow hidden inline inline-flex invert invisible lowercase ordinal relative resize ring-1 ring-4 row-0 sepia shadow shrink static table tabular-nums transform transition truncate underline uppercase visible`. The `@layer properties` block at the head of the file (49 `@property` registrations for `--tw-*`) is derived from the same set.

Three of those come from exactly one comment line each, in files the plans rewrite: `.row-0` from `src/lib/catalog/calibration.ts:31` (a plan 01 file, inside the 95-line header the plan cuts), `.ring-4` from `src/lib/sim/lua-smoke.spec.ts:6035` (a body comment), `.ordinal` from `src/lib/sandbox/copy.ts:183` plus `FacetRow.svelte:48` and one spec comment. Cut the `row-0` sentence in plan 01 and `cat build/_app/immutable/assets/*.css | sha256sum` moves at `--after 01`; the gate exits 1 on the CSS term; the plan 05 standing rule says "the source is put right, never the hash explained away" - which would mean restoring bench prose to keep a utility class nobody uses. The research claim "a comment inside `<style>` does not [move the CSS], because the Vite minifier strips it" is true of `<style>` blocks and of `app.css` and false of every `//`, `/* */` and `<!-- -->` comment in a `.ts`, `.svelte` or `.spec.ts` file.

The `@media` / `:where()` question in the brief: a CSS comment anywhere in a `<style>` block (inside an at-rule, a selector list or a declaration) is dropped by the minifier; the only comment surviving in the built CSS is the Tailwind `/*! ... */` banner and `src/` carries no `/*!` comment. That part of the design holds.

**What closes it (gate-side, no source change):** in `13.2-gate.sh`, hash the built CSS after removing the `@layer properties{...}` and `@layer utilities{...}` blocks (brace-balanced, per stylesheet) - that is the scoped hash and it must be equal; then record the class list of the utilities layer separately and assert two things about it: every class named by a `class` / `class:` / `@apply` token in `src/**/*.svelte` and `src/app.html` is still emitted (the five today), and any class that appears or disappears is printed by name in the `.txt`. A class no template names cannot change what a visitor sees. (The alternative - `source(none)` plus `@source "./**/*.svelte"` and `@source "./app.html"` in `app.css` - is a real improvement to the site but a one-time visible CSS delta, the kind of change the user excluded; if wanted, it is its own dated exception, not a silent part of 01.) The rename proof survives normalisation: Svelte 5.57 `cssHash` hashes the filename (`node_modules/svelte/src/compiler/validate-options.js:77`, verified), so a `.svelte` rename still moves the scoped hash; add `git diff --name-status` as the belt anyway (plan 06 note).

### H-6 (WARNING) - the census misses two literal shapes in templates

`hash-strings.mjs` reads `.svelte` templates by regex: quoted attribute values, whole text nodes, and quoted strings inside `{ }`. It does not see (a) backtick template literals in markup - six today, three of them user-facing in `RegionInspector.svelte` (`${CC_NUMBER} (X)` and kin); (b) text nodes that mix prose with `{expr}` - thirteen today, e.g. `Showing {showing} of {total} configurations.` in `BrowseToolbar.svelte`; (c) the four `data-testid={expr}` attributes (`FailureBlock`, `StartCard`, `PadSpinner`, `dev/type`).
