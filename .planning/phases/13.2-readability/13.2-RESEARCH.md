## Lead finding - the phase's real cost is not the edits, it is the specs that read the source as text

**Half of the source tree is comment.** Under `src/` outside `src/vendor/` and outside the 95 spec files: 193 files, **60,710 lines**, of which **29,651 are code, 27,480 are comment and 3,772 are blank** - comment is 48 % of the non-blank lines. **Header comments alone are 14,072 lines (23 % of the tree)**: 139 files open with a header over 25 lines, 90 over 50, 36 over 100, and the longest - `src/lib/catalog/entries/lumen.ts` - carries 530 lines of header above 56 lines of code. The eighteen hand-authored catalog entries together carry **5,600 comment lines over 1,383 code lines** (4,748 of them header); `src/lib/catalog/library.ts` carries 603 comment lines over 81; `src/lib/device/install.svelte.ts` 988 over 870. The functions are not the problem: measured with the TypeScript compiler API, **only nine functions in the whole non-spec tree exceed 80 lines**, and the store people would expect to be the worst (`install.svelte.ts`) has no method over 123 lines - its 1,938 lines are essays between short methods.

**The specs read that prose.** 68 spec and e2e files read files from disk; **106 source files are read by name by at least one spec**, and eight whole-tree walkers (`radius.spec.ts`, `forbidden-instructions.spec.ts`, `lazy.spec.ts`, `instrument.spec.ts`, `device-ui.spec.ts`, `identity.spec.ts`, `png.spec.ts`, `config-shape.spec.ts`) read every `.svelte`, `.css` or `.ts` under `src/`. Across those specs the compiler API found **1,687 literal needles in text assertions: 1,239 match the code of some source file, 121 are regular expressions, and 30 match source only inside a comment** - the last are the wording pins: ten spec titles (listed in A.7, every one by title) that assert a *comment paragraph* exists, with its date and plan id, in `install-copy.ts`, `tune/copy.ts`, `page-target.ts`, `install.svelte.ts`, `TuningRegion.svelte`, `MidiMonitor.svelte` and `sandbox/history.ts`. The "header in ten lines with one provenance pointer" rule the ROADMAP asks for reddens exactly those ten titles unless their bodies are re-aimed - and that re-aim is a spec edit, which the count gate permits (a title stays a title) and which the SUMMARY must list by title.

**Two things must be byte-identical and are easy to hash, so the gate is designed here and already run at HEAD.** `hash-wire.mjs` (scratchpad) imports the tree's own modules and prints one sha256 per Lua string HANGAR can put on a ZONA - the library's two halves and every part, the five firmware defaults, every hand-authored entry at its defaults, its picker corner and every single-knob position, every preset through the vendored compiler at its defaults, corner and single-knob positions, and the Sandbox's five strings for the PDF's page-3 surface - **1,735 strings, set sha256 `a24b256f7f07…dd769b`, 0.8 s**; with `--full` it also folds every entry's knob cross-product (232,728 Lua states, 126,920 preset states), **set `514cb2c7c3a4…19f9b`, 5.5 s**. `hash-strings.mjs` prints the census of every string literal in comment-stripped source (2,721 distinct, 6,342 occurrences: `e6af80e09d3d…8c966`), the copy modules' export lists (`10fad0020ce8…40ffef`) and the 320 `data-testid`s (`21fc9eb96531…74ce3`). A refactor that moves a literal keeps the census; one that edits a literal moves it and the diff names it.

**Primary recommendation:** run the phase as **six plans in blast-radius order, smallest first**, every plan bracketed by the same before/after script (`13.2-gate.sh`, section B), with **three files off the table by default** - `src/lib/ui/Knob.svelte` and `src/lib/ui/ColourPicker.svelte` (six circles pinned by line in `radius-allowlist.ts` and D-15; any edit above `:730` / `:840` moves the pins and needs a dated D-15 amendment in `13-CONTEXT.md`), and `src/lib/catalog/library.ts`'s string constants (the wire) - and **one rule the plan-check refuses to waive: no literal changes, no test title added or deleted, no `.svelte` file renamed** (Svelte 5.56 hashes the scoped class from the *filename*, so a rename moves the built CSS bytes; a comment inside `<style>` does not, because Vite's minifier strips it).

### A.1 Essay headers - the rule, and the shape of the cut

Proposed rule (for the planner to state once and for every plan to obey): **a header says what the module is, what it owns, and how to use it, in at most ten lines; provenance is one line with a pointer** - `// Decided at 13-12 (D-06); see 13-12-SUMMARY.md` - and the SUMMARYs keep the history. Measured figures that a spec asserts (a count, a date) stay in the spec; measured figures nobody asserts leave with the paragraph.

The three header registers found, with the recommended treatment:

1. **Design narrative of the Lua** (the 18 entries, 5,600 lines; `library.ts` sections 1-11). The mechanism, the message layout and the traps are genuinely load-bearing for whoever next edits a string. Keep those under three fixed headings - `MECHANISM`, `WHAT IT SENDS`, `TRAPS` - and move the costings, the bench verdicts and the "why not the other shape" paragraphs to one markdown file per entry under `docs/entries/` (or to nothing, with a pointer to the SUMMARY that costed it). Question D.5 asks which.
2. **Decision provenance** (`WHY ...` paragraphs, `RETIRED BY NAME, <date> (<plan>, <D-nn>)` paragraphs, "IT WAS SIXTEEN UNTIL PLAN 11-01"). One line each, pointer to the plan's SUMMARY. The `RETIRED BY NAME` lines are pinned by spec (A.7) - keep the one-line heading verbatim and cut the paragraph beneath, or re-aim the spec.
3. **Rules the file obeys** ("imports nothing", "dynamic, never `from`", "no `$derived`", the write-order rule). One line each, kept, because a spec enforces each and a reader needs to know before editing.

Files where the cut is largest, with the span: `lumen.ts:1-530`, `library.ts:1-479`, `morph.ts:1-376`, `wheels.ts:1-354`, `radar-points.ts:1-317`, `stage.ts:1-291`, `ghost.ts:1-282`, `sonar.ts:1-278`, `console.ts:1-276`, `strip.ts:1-265`, `arc.ts:1-264`, `steps.ts:1-252`, `install.svelte.ts:1-225`, `trackpad.ts:1-225`, `pomodoro.ts:1-215`, `install-copy.ts:1-210`, `sandbox/runtime.ts:1-202`, `snake.ts:1-167`, `chorus.ts:1-158`, `TuningRegion.svelte:1-152`, `cull.ts:1-144`, `sandbox/emit.ts:1-138`, `session.svelte.ts:1-134`, `tune/copy.ts:1-132`, `quadrant.ts:1-128`, `[id]/+page.svelte:1-120`, `sandbox/model.ts:1-119`, `DestinationZone.svelte:1-117`, `store/transfer.ts:1-114`, `sim/host.ts:1-112`.

## Common Pitfalls

1. **A rewritten comment spells a forbidden class.** `forbidden-instructions.spec.ts` scans comments in `src/lib/**/*.ts`. Name the page classes by number or not at all. Warning sign: the quick run's test 2 ("built in the descriptor module and named nowhere else") red on a docs-only plan.
2. **A `.svelte` rename or split.** The scoped class hash is the filename's; the built CSS and JS move; three specs read components by file name. Refuse.
3. **A fifth static `from` in either store.** `install.spec.ts:1286` and `session.spec.ts:1108` count four. A "helper extraction" that imports the helper statically is red. The stores keep their own copies of anything.
4. **`intro.spec.ts:345` pins the inline `localStorage` guard in `routes/+page.svelte`** (`try { return window.localStorage;`). The guard extraction skips that route.
5. **`synthetic.ts` regenerates a committed fixture.** A comment-only edit is fine; any code change must leave `synthetic-zona.json` byte-identical (`fixtures.spec.ts`, `synthetic.spec.ts:286`).
6. **Prettier reflows nothing in comments, but `npm run lint` runs it over `.planning/`?** No - `.prettierignore` covers it (`config-shape.spec.ts:195` asserts `src/vendor/` is in it); `docs/entries/*.md` would be formatted; write them prettier-clean.
7. **The build on disk is stale by one commit.** `artifacts.e2e.ts` (chunk c5) reads the archive stamp; rebuild before c5, as round 4c noted.
8. **Memory.** 0.34 GB free at research time; the browse hydration race in c2 goes red under 0.5 GB and is green alone at `--workers 1` (13.1-08). Note the figure beside every run, as the gates do.
9. **`--full` on the wire hash before the colour sampling patch ran for minutes** (the lattice is 4,096 per colour knob). The shipped harness samples the 27 sweep colours; do not "improve" it to enumerate.
10. **A header cut that deletes a fact a spec asserts.** The ten wording-pin titles are the known set; run the quick suite after each file, not each plan, in 13.2-03 and 13.2-05.
