<objective>
The three quiet surfaces: what a visitor reads before clicking, what they read about safety, and what
they hear.

Wave 9. None of these is a control and that is the point of all three.

**The note exists because of an ARIA ruling** (Y-23). In S1, S2 and S7 the device slot is a plain
button that connects — so its explanation cannot hang off it, because a control that both acts and
expands lies about one of its two jobs. The copy therefore sits inline beneath the header row, in a
region of its own, readable with no click at all. It costs **152px of header on every route in every
capable browser for the whole visit**, and it buys a safety promise and a picker explanation that are
read without a click on the one surface that exists on every page. That trade is 06-UI-SPEC's open
question 7 and it is made, not assumed.

**The reservation is measured, never asserted in pixels.** The region is a one-cell grid holding every
string it can ever show, with the non-current ones `visibility: hidden` and `aria-hidden` — Phase 5's
honesty-slot pattern exactly. Its height is therefore whatever the browser measures at the current
width, identical in every state, so no session transition can move the coverflow beneath it.

**The announcement logic lives in the store, not in the component.** The 500ms trailing coalescer, the
hold until the splash has finished, and the rule that a heartbeat never speaks are all decisions with
edge cases, and a decision with edge cases belongs where a node test can reach it. `SessionAnnouncer`
renders `session.speech` and does nothing else.

Purpose: CONN-03's pre-click explanation in both its mounts, SAFE-01 said out loud, and the one
session live region D-17 allows.
Output: three components, one layout wiring, two more tests on the session.
</objective>

<interfaces>
**The store's speech surface** (new, in `session.svelte.ts`):

```ts
/** What the one live region is currently saying. Empty string means silence. */
speech = $state("");

/**
 * Queue an utterance for the next 500ms trailing window. Called only on a
 * SESSION TRANSITION: detected, connected, disconnected, unplugged, forgotten,
 * and each failure by title. NEVER on a heartbeat, a page-number change, a
 * paint or a hover - a module reporting its page four times a second would
 * turn a screen reader into a metronome.
 */
#say(line: string): void;

/**
 * Hold every announcement until the returned function is called. FrontDoor
 * holds while the splash covers the row (plan 06-11), so a ZONA detected during
 * the opening is announced once, after it, rather than over it. Idempotent, and
 * a held utterance is replaced rather than queued: only the latest state is
 * worth speaking when the hold lifts.
 */
holdSpeech(): () => void;
```

**`PickerExplainer.svelte`** — one component, two mounts, never both at once (Y-11):

```svelte
let { testid = "picker-explainer" }: { testid?: string } = $props();
```
It renders exactly `PICKER_EXPLAINER` from `session-copy`, as one Body paragraph. It carries no
heading, no control and no tab stop. The **two-step sentence is not here** — it lives beneath
`Nothing listed?` in the `cancelled` block, where it is actionable (Y-09).

**`DeviceNote.svelte`** — the inline region beneath the header row:

```svelte
let { covered = false }: {
  /** True while the splash covers the row. Carries the wordmark's treatment verbatim. */
  covered?: boolean;
} = $props();
```

| Rule | Value |
|---|---|
| Geometry | `inline-size: min(372px, 100%)`, right edge flush with the device slot's, **text left-aligned inside it** |
| Content | two Body paragraphs, 8px apart; no border, no ground, no icon, no accent |
| Reservation | a one-cell grid holding every candidate string; non-current ones `visibility: hidden` **and** `aria-hidden="true"` |
| S1 / S7 | the pre-click line (hidden by its own twin when the chosen panel is rendering it) · the SAFE-01 sentence |
| S2 | the reconnect offer · the SAFE-01 sentence |
| S3 | the current status line · (empty, height held) |
| S4 / S5 / S6 | (empty, height held) — that copy is in the disclosure |
| S0a / S0b | **not rendered at all, with no reservation** — capability is terminal and there is nothing to explain |
| Motion | line changes are 160ms `ease-out`, **opacity only**; instant under reduced motion |
| ARIA | not a live region, and never announces — the session already speaks once |

**`SessionAnnouncer.svelte`** — the whole component:

```svelte
<div class="sr-only" data-testid="session-live" aria-live="polite" aria-atomic="true">
  {session.speech}
</div>
```
Visually hidden by the same technique the site already uses. It holds no timer, no logic and no
memory: everything it could get wrong lives in the store, where a node test can reach it.

**`+layout.svelte`** mounts it **before** `{@render children()}` — so the session's utterance precedes
the tuning and browse regions in the document, which is the whole of the "session speaks first"
mechanism and is stated honestly in the component header: there is no cross-region scheduler, and none
is built. The layout also calls `session.start()` in `onMount`, guarded by nothing else — `start()` is
idempotent (plan 06-06) and synchronous up to the capability decision.
