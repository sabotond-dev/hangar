<objective>
The control, and the quiet drawer behind it.

Wave 10. Two components and the gate over all seven.

**The slot is a button whenever a click does something, and a plain summary otherwise** — and the two
are never the same element in the same state. That single rule produces most of this contract: S1, S2,
S6 and S7 **act** and carry no `aria-expanded`; S0a, S0b, S4 and S5 **expand** and carry it; S3 is
disabled and busy. It is also why the note exists at all (plan 06-09) and why S6's disclosure is
opened by the arriving failure rather than by the button — the visitor's own click produced it, and
CONN-04's six-step recovery is worthless behind a second one.

**`ZONA DETECTED — CONNECT` does not ship** (Y-02, superseding 06-CONTEXT D-02's wording). It is a
statement and a command welded with an em dash, and its accessible name would tell a speech-input user
to say "ZONA detected connect" to press a connect button. It splits with no loss: the caption
`ZONA detected` over the label `CONNECT ZONA`.

**`DISCONNECT ZONA` is not a slot label either** (Y-22, superseding D-02's fourth string). CONN-08
requires the type and firmware to be visible *while connected*, and the slot is one 44px box: a slot
reading `DISCONNECT ZONA` shows neither, and it puts a session-ending action under a stray click on
the control a visitor uses to glance at the firmware.

Purpose: CONN-01's one control, CONN-05's two disclosures, CONN-06's reconnect affordance and
CONN-08's always-visible identity.
Output: two components, one structural gate at six tests.
</objective>

<interfaces>
**`DeviceSlot.svelte`** — `data-testid="device-slot"`, with `device-slot-label` and
`device-slot-caption` inside it.

Two stacked lines, each in a **14px fixed line box** (Y-10: `1.2` computes to 14.4px, which gives 28.8
in a 44px box and a half-pixel asymmetry that shifts by state), centred in the 44px row, with the 24px
`DeviceMark` 8px to their left.

| Slot state | Mark | Caption | Label | Element |
|---|---|---|---|---|
| S0a `unsupported` | dark | `Not in this browser` | `NO ZONA`, `--color-ink-dim` | summary, `aria-expanded` |
| S0b `insecure` | dark | `Needs HTTPS` | `NO ZONA`, `--color-ink-dim` | summary, `aria-expanded` |
| S1 `idle` | dark | none | `NO ZONA` at rest, `CONNECT ZONA` on hover/focus/touch-active | **plain button** |
| S2 `detected` | one cell, static | `ZONA detected` | `CONNECT ZONA` | **plain button** |
| S3 connecting | walking | none | `CONNECTING…` | disabled, `aria-busy="true"` |
| S4 `connected` | five-cell diagonal | none | `ZONA · fw 1.5.5 · page 3` (Micro **title**, `--color-ink`) **plus the multi-module tail**, below | summary, `aria-expanded` |
| S5 unplugged-while-connected | dark | `ZONA unplugged` | `NO ZONA` | summary, `aria-expanded` |
| S6 any open failure | dark | `Did not connect` | `CONNECT ZONA` | **plain button**; the disclosure is opened by the failure, not by this button |
| S7 `forgotten` | dark | none | `CONNECT ZONA` | **plain button** |

ARIA, exactly: the accessible name is **always the label line and only the label line**; the caption is
`aria-hidden="true"` and reaches the control through `aria-describedby` on a visually-hidden twin. In
S1 the name is `CONNECT ZONA` in both the resting and the hovered form, so a speech-input user says
what the button does, and the `aria-describedby` twin in S1 carries **`HIDDEN_NAME_IDLE`** —
`No ZONA is connected.` — which is the state the label alone cannot convey once it has swapped to the
hovered form. The identity summary wraps its `·` separators in `aria-hidden` spans, so the name is
`ZONA fw 1.5.5 page 3` rather than three "middle dot"s, and `aria-describedby` adds
`identityDescription(...)`. The multi-module tail is inside the label, so it is part of the accessible
name at widths where it renders and simply absent below 1024px — the disclosure's
`multiModuleLine(...)` carries it there.

**The multi-module tail (D-08, Y-19).** When `session.identity` carries other modules, the S4 label
ends with a trailing span:

```svelte
{#if tail}<span class="tail"> · {tail}</span>{/if}
```

where `tail = moduleTail(session.identity.otherModules)` from `session-copy` — `with EN16, BU16`, or
`undefined` for an empty list, in which case the separator is not rendered either. The full label is
therefore `ZONA · fw 1.5.5 · page 3 · with EN16, BU16`, exactly the Copywriting Contract's row.

**It is hidden below 1024px by a CSS media query on that span, and by nothing else:**

```css
@media (max-width: 1023.98px) { .tail { display: none; } }
```

**No width listener, no `matchMedia` in script, no `innerWidth` read.** Three reasons, and they go in
the header: a JS width read is wrong on the first paint of a prerendered page and would make the
label jump; a resize listener is state that has to be torn down and is one more thing to leak; and
CSS already does this at the compositor with no frame of its own. The tail's content is **also** in
the disclosure as `multiModuleLine(...)` at every width (Y-19: the tail collapses *into* the
disclosure), so nothing is lost below 1024px — the tail is the least time-critical part of the
identity and the disclosure is one click away.

`display: none` rather than `visibility: hidden` is deliberate here and is the one place this
component does not reserve: the tail is at the **end** of the line, so removing it shortens the label
and moves nothing above, below or to the left of it. The 44px box and the header row's height are
unchanged across the boundary, which 06-11 measures at 1280 and 900.

The label swap does **not** resize the box: both labels sit in one grid cell with the longer one as a
`visibility: hidden` sizing twin — Phase 5's honesty-slot technique. Motion is 160ms `ease-out`,
opacity and colour only, never height; instant under reduced motion.

The firmware and the page number are `var(--font-mono)`, weight 400, `font-variant-numeric:
tabular-nums`, as **numeric runs only**: the words `ZONA`, `fw`, `page` and the separators stay
Quicksand 600. Prose is never monospaced.

**`DeviceDetails.svelte`** — `data-testid="device-details"`. Non-modal, anchored to the slot: right
edges aligned, 8px below the header row, `max-inline-size: 360px`,
`inline-size: calc(100vw - 48px)` below 640px, `padding: 16px`, `border: 1px solid var(--color-line)`,
`border-radius: 10px`, `background: var(--color-ground)`. No shadow, no glow, no backdrop tint.

It exists in **five states only** — S0a, S0b, S4, S5, S6:

| State | Blocks, 16px apart |
|---|---|
| S0a / S0b | `FailureBlock` from `session.failureFor(CONNECT_LABEL)` |
| S4 | the identity line · the multi-module line when there is one · the SAFE-01 sentence · `DISCONNECT ZONA` · `FORGET THIS ZONA` with its one-line explanation |
| S5 | `The ZONA was unplugged. Nothing was written.` · the replug offer · `FORGET THIS ZONA` |
| S6 | `FailureBlock` · for `cancelled`, the `Nothing listed?` disclosure with its three steps, the `The chooser never appeared?` disclosure with its paragraph, the two-step sentence, and — only when `permissionDeclined` — the declined sentence |

Opening and closing: the slot toggles it in the four summary states; a failure arriving from a header
click **opens it automatically and moves focus into it** (`tabindex="-1"` container); `Escape` closes
and returns focus to the slot; focus leaving it closes it; a click outside closes it; a transition into
S1, S2 or S7 closes it because those states have no disclosure. It never opens while the chosen panel
is open — that surface renders the block instead (Y-11).

`FORGET THIS ZONA` renders **only when `session.canForget`** is true: a revoke control on a browser
that cannot revoke has no reason to state and no fix to offer, which is why DEGR-02's present-but-
disabled rule does not reach it. One click, no dialog, with the explanation above it; the session
disconnects first. Both `DISCONNECT ZONA` and `FORGET THIS ZONA` destroy themselves and hand focus
back to the slot, which by then reads `CONNECT ZONA`.
