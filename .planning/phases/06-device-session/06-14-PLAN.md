<objective>
The five things no machine can check, and the gate that says everything else is checked.

Wave 14, and the phase's last plan. Three pieces:

**The runbook.** `docs/SKELETON-RUNBOOK.md` said it plainly and it is still true: *Web Serial cannot
be automated — there is no CDP domain and no fake-device hook.* Everything a machine can check is
checked by this point; six things remain, and each has a reason it cannot be simulated rather than a
reason nobody got to it. One of them closes a hole Phase 2 left open: skeleton runbook row 0, the
port-conflict message, was **never exercised** — the operator had no Grid Editor running, and
`docs/SKELETON-RESULTS.md` names it as still open and says *"Phase 6 owns the failure vocabulary and
should close it."* This row is that closure.

**The gate.** The full suite, against the production static build served through the real Worker, with
the counts asserted as baseline plus the phase's stated delta. No deploy: the embargo is the user's
and this phase does not touch it.

**The honesty.** Three of Phase 6's five success criteria are tagged *(hardware)*. They close as
**verified-by-user-pending**, and the SUMMARY says so in those words. A phase that marked them done
because the fake serial agreed with a source reading would be doing the exact thing the fake serial's
own header warns about.

Purpose: CONN-01 to CONN-08 closed with qualifiers, and the hardware half handed to the person who
owns a ZONA.
Output: one runbook, one updated testing document, one green suite, one unanswered checkpoint.
</objective>

<interfaces>
**`docs/SESSION-RUNBOOK.md`**, modelled on `docs/SKELETON-RUNBOOK.md`: a **Before you start** block, a
**Getting the page open** block naming both `npm run preview` (on `http://127.0.0.1:4173`, a secure
context) and the deployed HTTPS origin with its Basic Auth prompt, the `file://` trap stated
explicitly, and then a table with a **Pass** column.

Two warnings the skeleton runbook did not need:

- **Running this checklist consumes and revokes a real browser permission.** Row E calls
  `forget()`, which mutates the browser's own profile state for this origin. That is the point of the
  row, and it is worth knowing before it happens.
- **While HANGAR holds the port, Grid Editor cannot open it.** The session holds it for a whole visit
  rather than for one panel, which is a deliberate behaviour change from Phase 4 and is why
  `DISCONNECT ZONA` is one click from the header.

The six rows:

| # | Row | Do this | Passes when | Why a machine cannot |
|---|---|---|---|---|
| **A** | The grant survives a browser restart (CONN-06) | Connect once. Quit the browser completely. Reopen and open the site. Click nothing. | The header reads `ZONA detected` over `CONNECT ZONA` on load, with no picker and no gesture. **Record the answer for the deployed HTTPS origin specifically** — grants are per origin and only `127.0.0.1:4173` has ever been tested. | Permission storage is the browser's own profile state |
| **B** | Unplug and replug (CONN-06, D-07) | Connect. Unplug the cable. Wait. Plug it back in. Do not reload. | Unplug flips the header immediately, before any click. Replug returns it to `ZONA detected`, and **one click reconnects with no picker**. A picker or an error here means the replug handling is wrong. | The new-token behaviour is Chromium's; the shim is modelled on a source reading, so this row is what turns the reading into evidence |
| **C** | Grid Editor holds the port (CONN-04) | With Grid Editor **running and connected**, click `CONNECT ZONA` and pick the ZONA. | The named block appears, names Grid Editor, and lists the six steps in order — never the browser's own sentence. Then quit Grid Editor from its tray, reload, reconnect. **Also report whether the copy read as helpful or as jargon.** | Phase 2's row 0 was never exercised; `SKELETON-RESULTS.md` names it open |
| **D** | A second Grid module, and a non-ZONA (CONN-07, D-08) | Attach a second Grid module beside the ZONA. Then, separately, connect with **only** a non-ZONA module attached. | With the rig: the identity names the other modules, in a stable order. With only a non-ZONA: the picker still **lists** it, and HANGAR refuses it by name. | Every frame in the Phase 2 run carried SX 0, SY 0; the other-module path has never met real traffic |
| **E** | `FORGET THIS ZONA` (D-10) | Connect, open the disclosure, click it. Then reload. | The port closes, the header returns to `NO ZONA`, and after the reload there is **no** offer — the picker is required again. The grant is gone from the browser's own site settings, and Grid Editor can open the module immediately. | Revocation is profile state; the exclusivity half is an operating-system fact |
| **F** | Firefox 151+ two-step prompt *(optional)* (CONN-03, D-04) | Connect from a clean Firefox 151+ desktop profile. | A site-permission prompt appears **before** the port chooser on the first request, and the pre-click copy prepared the visitor for it. **Record how long the two prompts took end to end**, and whether a second connect on the same profile skips the first. | The whole Phase 2 run was one browser; `SKELETON-RESULTS.md` names Firefox open |

Close with **What to hand back**: which rows passed; for any that did not, exactly what the page
showed instead; row A's answer for the deployed origin; row F's timing; and anything the runbook did
not predict.
