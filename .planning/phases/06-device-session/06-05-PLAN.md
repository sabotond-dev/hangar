The widening has to be careful in one direction that the earlier two did not: **all five of the
modules a header component is allowed to name live in exactly those directories.** So the rule is

allow-list is itself checked, by walking what those five modules import, with the walk **following** a
permitted specifier rather than flagging it. An allow-list nobody verifies is a hole with a comment on
it; a walk that flags its own allow-list is a gate nobody can keep green.

**Test 13's widened rule**, in `src/lib/config-shape.spec.ts`:

```ts
/** Anything that would drag @intechstudio/grid-protocol onto the first paint. */
const COMPILER_MARKERS = [
  "vendor", "intechstudio", "lib/pad",
  // Widened in Phase 6. The session's neighbours all reach the package at
  // module scope: constants.ts, decode.ts, descriptors.ts and sequence.ts each
  // import it, and device/try-on.ts imports both barrels. None of those three
  // strings matched before, so a header component could have imported the whole
  // 131,101-byte chunk with this gate green.
  "lib/transport", "lib/protocol", "lib/device",
];

/**
 * The five modules a first-paint component MAY name, by exact path and never by
 * prefix (05.1-08's lesson: the allowance is a list of paths, not a namespace).
 * Each one is verified light below rather than trusted.
 */
const PERMITTED_SPECIFIERS = [
  "$lib/device/session.svelte",
  "$lib/device/session-copy",
  "$lib/protocol/usb",
  "$lib/transport/ports",
  // Fifth, and the least obvious: src/lib/transport/transport.ts has ZERO
  // imports. Verified by reading it - its only exports are OpenFailure,
  // FailureCopy, classifyOpenError and failureCopy, and the DOMException and
  // SerialPort it names are globals, not specifiers. So the session can hold
  // the failure taxonomy and its copy STATICALLY, which is what makes
  // failureFor() synchronous for all nine states and lets a capability failure
  // render its sentence in the first hydrated frame.
  "$lib/transport/transport",
];
```

and `FRONT_DOOR_PAGES` gains `src/routes/+layout.svelte`, because it renders on every route including
`/` and it is where the session is started and the live region is mounted.

**The allow-list is verified, not asserted — and the walk must follow the allowance, not trip over
it.** Every one of the five permitted paths contains a marker substring itself (`lib/device`,
`lib/protocol`, `lib/transport`), so a walk that marker-checked every specifier it met would go red on
the allow-list on its first step. The rule is therefore, at **every** step of the walk including the
first:

1. Resolve the specifier: `$lib/x` becomes `src/lib/x`; a relative specifier resolves against the
   importing file; try `.ts` then `/index.ts`.
2. **If the specifier, after that resolution, is an EXACT match for a `PERMITTED_SPECIFIERS` entry,
   FOLLOW it** — visit that file and keep walking. Do not marker-check it.
3. **Otherwise marker-check it**, and record it as an offender if it matches.

Exact match, never prefix, is what keeps the rule honest, and it is the whole reason mutation 3 still
works: `$lib/protocol` is **not** `$lib/protocol/usb`, so a static `import { FrameScanner } from
"$lib/protocol"` inside `session-copy.ts` is marker-checked, matches `lib/protocol`, and goes red — on
the walk rather than on the direct scan. A prefix rule would have let it through and the allow-list
would be a comment again.

Guard against a silent walk: assert the number of files visited is **at least four**, and record the
number the walk reported.

**Test 12's generalisation.** Today it hardcodes `dev/skeleton`. It becomes: discover every directory
under `src/routes/dev/`, then assert that no file under `src/routes/` outside a probe's **own**
directory mentions any of their paths. Keep both non-vacuity guards — that routes were read, and that
at least two probe directories were discovered — so the assertion cannot pass on an empty walk.

**`forbidden-instructions.spec.ts`.** `SCANNED_DIRS` becomes `["src/lib"]`, with the note that this is
