<objective>
Three gate widenings, each deliberate, each named, each proven by a mutation.

Wave 5. The session and its two light modules exist; the components that will render them do not yet.
This is the wave where the guards learn about them, **before** a component can violate a rule that
nothing was watching.

The hole is precise and it is worth stating exactly. `config-shape.spec.ts` test 13 matches specifier
**text** against `COMPILER_MARKERS = ["vendor", "intechstudio", "lib/pad"]`. `$lib/transport` matches
none of them — so a `DeviceSlot.svelte` that statically imported the session which statically imported
the transport would sail straight through the source scan, and only the artefact scan would catch it,
and only after a build. That is the same hole `tune-ui.spec.ts` test 1 found for `$lib/tune/model`
and the same one 05.1-08 closed for `$lib/catalog`; this is its device-shaped instance.

The widening has to be careful in one direction that the earlier two did not: **three of the four
modules a header component is allowed to name live in exactly those directories.** So the rule is
markers **plus** an allow-list of four exact paths — not a prefix, per 05.1-08's own lesson — and the
allow-list is itself checked, by walking what those four modules import. An allow-list nobody verifies
is a hole with a comment on it.

Purpose: CONN-01's control has to live in a header that renders on the first paint of `/`, and SAFE-01
is only credible if the device path is inside the scan that forbids destructive instructions.
Output: two spec files amended, five mutations observed, no test count moved.
</objective>
