<objective>
A fake ZONA that lives in the page, and the probe that shows what the session did with it.

Wave 6. Web Serial cannot be automated — there is no CDP domain and no fake-device hook — but
`navigator.serial` is a **configurable accessor on `Navigator.prototype`**, which is exactly why the
shipped degrade tests can `delete` it. What deletes can also be defined, so a scripted serial
implementation installed by `addInitScript` before any page script runs can drive every state the
session has, on both Playwright projects, with no hardware.

One thing about that shim is easy to get wrong and would make every navigator-level test pass against
a page that fails in Chrome: **the bubble does not come for free.** Real `connect` and `disconnect`
events are fired *at the port* with `bubbles: true` and reach `navigator.serial` through the event
path. A plain `EventTarget` has no path, so the shim must dispatch at **both** the fake port and the
fake serial object, with `target` reporting the port in both.

And one thing about the probe is the point of it: it renders **no production chrome**. The header
slot, the disclosure and the note are waves 8 to 12; this page is a plain-text readout of `phase`, the
identity fields, the failure title, detail and steps, and the write counter — so an e2e can assert on
states the real chrome deliberately compresses, and so the session is proven in a browser before any
component exists to hide a bug in.

Purpose: CONN-01 and CONN-02's two messages, CONN-05's cancelled state, and DEGR-02's present-but-
disabled promise on the engine that can never install.
Output: one fixture module, one unlinked route, four browser tests.

<interfaces>
**`e2e/fake-serial.ts`** exports one function to be passed to `context.addInitScript`, plus the
`__hangarSerial` control surface the tests drive from `page.evaluate`. `06-RESEARCH.md` § Code
Examples 4 is the reference implementation; follow it, including its two load-bearing details:

- `Object.defineProperty(Navigator.prototype, "serial", { configurable: true, get: () => serial })`
  — the property is an accessor on the prototype, which `e2e/skeleton.e2e.ts` already proves by
  deleting it there.
- events dispatched at **both** the fake port and the fake serial object, with `target` reporting the
  port in both, because a plain `EventTarget` has no event path.

The control surface:

| Call | Effect |
|---|---|
| `grant(vid?, pid?)` | a port this origin has already been granted and that is attached; returns its index |
| `pick(i)` | the next `requestPort()` resolves with port `i` |
| `reject(name?, message?)` | the next `requestPort()` rejects; default `NotFoundError` / `No port selected by the user.` |
| `throwOnRequest(name, message)` | the next `requestPort()` **throws synchronously** (the activation failure) |
| `busy(i)` | `open()` on port `i` throws `NetworkError` |
| `openFails(i, name, message)` | `open()` on port `i` throws that named `DOMException` |
| `unplug(i)` | fires `disconnect` for port `i` and sets its `connected` false |
| `replug(vid?, pid?)` | mints a **new** port object and fires `connect` — exactly as Chromium does |
| `feed(i, bytes)` | pushes rx bytes into port `i`'s readable stream |
| `forgotten(i)` | whether `forget()` was called on port `i` |
| `writes()` | the number of chunks ever written to any fake port |

`feed`'s bytes are read **in Node from the committed capture** and pushed in by the test, never
inlined into the init script, so the one committed capture stays the source of truth and the shim
stays small.

**`src/routes/dev/session/+page.svelte`** — the fifth unlinked probe, following the four shipped ones:
prerendered, linked from nowhere, trailing slash. It renders, as plain text with stable testids:

| testid | Content |
|---|---|
| `session-phase` | `session.phase`, verbatim |
| `session-identity` | `ZONA <type> fw <M.m.p> page <n> others <a, b>` or `none` |
| `session-failure-title` / `-detail` / `-steps` | `session.failureFor("CONNECT ZONA")`, or `none` |
| `session-can-forget` | `true` / `false` |
| `session-writes` | the shim's counter when present, else `0` |

and three real buttons — `session-connect`, `session-disconnect`, `session-forget` — whose handlers
call the session's methods with **nothing awaited in front of `connect()`**.

**One small edit to `session.svelte.ts`: `start()` becomes idempotent.** The probe starts the session
in its own `onMount` in this wave, and plan 06-09 starts it in `+layout.svelte` for the whole site; a
second call must be a no-op rather than a second listener pair. A `#started` guard and one comment
naming both call sites.

**`#started` is an INSTANCE field, not a module-scope flag**, for the same reason `DeviceSession` is
exported and every node test constructs its own instance (06-03): a module-scope flag would be shared
across instances, so the second test in `session.spec.ts` would find `start()` already spent and would
silently assert against a session that never attached a listener. Say that in the comment beside it,
in one sentence, because it is the kind of thing a later reader "simplifies".
