<objective>
The four things that only happen after the cable is already in.

Wave 4, same file as wave 3. This is the half of the session that the hardware drives rather than the
visitor:

- **The listener pair, on `navigator.serial` and not on the port.** Phase 2's transport listens on the
  port, so it can notice a device leaving and never one arriving.
- **The replug identity trap, and it is the highest-value finding in the phase's research.** Chromium
  mints a fresh token for a re-added wired port (`serial_service.cc:317-325` returns `nullopt` from
  `GetPersistentIdentifier` for every non-Bluetooth port), so `connect` fires on a **different
  `SerialPort` object**. A handler that compares `ev.target === this.port` waits forever. The
  arriving port is identified by `getInfo()` and **adopted**.
- **The liveness watchdog, and it drives exactly one named state.** `MODULE_GONE_MS = 750` has been
  sitting unused in `constants.ts` since Phase 2, and this is what it is for: the **missed
  disconnect** — the module has gone silent for three missed heartbeats **and** the OS reports the
  port no longer attached, with no `disconnect` event having arrived. That lands in
  `unplugged-while-connected`, a state the taxonomy already has. It publishes **no new field**: a
  staleness flag with nothing rendering it would be a tenth state in everything but name, and
  06-UI-SPEC's contract is nine.
- **The continuous fold**, which is the other half of what the heartbeats buy: a page number that is
  true rather than a snapshot from connect time (CONN-08), and D-08's late-arriving rig modules.
- **`forget()`, in the only safe order.** The WICG steps do not close anything, so a naive
  implementation revokes the permission while still holding the port — telling the visitor HANGAR has
  forgotten their module while it is still talking to it.

And the gate under all of it: **zero writes**, proven twice, the way `try-on.spec.ts` test 3 proves
it — once dynamically against a transport that records every byte, once as a property of the file's
own source.

Purpose: CONN-06's unplug/replug half, CONN-08's live identity, D-10's revoke control and SAFE-01's
promise.

<interfaces>
**The listener pair.** Attached in `start()`, for the life of the page, and never removed:

```ts
#onSerialConnect = (ev: Event): void => {
  const port = ev.target as SerialPort | null;
  if (!port || !isZonaPort(port)) return;
  if (this.#transport) return;          // already connected to something
  this.#adopt(port);                    // REPLACES the stored reference
  this.phase = "detected";              // one click away. Never auto-open.
};

#onSerialDisconnect = (ev: Event): void => {
  if (ev.target !== this.#port) return; // this comparison IS safe: same object
  const wasLive = this.#transport !== undefined;
  void this.#teardown();
  this.identity = null;
  this.phase = wasLive ? "unplugged-while-connected" : "idle";
};
```

The asymmetry is the whole finding and it goes in a comment: **`disconnect` may compare object
identity, `connect` may not.** On disconnect the browser fires at the object you are holding; on
connect it fires at a new one. A `detected` port that leaves before it was ever opened returns to
`idle`, not to S5 — Phase 4's sentence says *"Nothing was written"* about a session that existed, and
there was none.

**The liveness watchdog**, armed when `connected` is reached, disarmed by every teardown:

```ts
// MODULE_GONE_MS is three missed heartbeats - the desktop's isAlive rule. This
// watchdog exists for ONE case: the MISSED DISCONNECT. A module can leave
// without an event - a cable pulled at the hub end, a browning-out hub, a
// device the OS suspended - and a connected session with no traffic of its own
// produces no read error either, so nothing else on this page would notice.
//
// It publishes no field of its own. Silence ALONE is not a state: a firmware
// crash on a port the OS still reports as attached leaves the session in
// connected, deliberately, because the taxonomy is nine and this phase renders
// no tenth.
#armWatchdog(): void {
  this.#timer = setTimeout(() => {
    const seen = this.identity?.zona.lastSeen;
    const gone = seen !== undefined && this.#now() - seen > MODULE_GONE_MS;
    if (gone && portIsAttached(this.#port!) === false) { ...unplug path... ; return; }
    this.#armWatchdog();                       // self-rescheduling, never setInterval
  }, MODULE_GONE_MS);
}
```
Both halves of that condition are load-bearing and the comment says so. `portIsAttached` returning
`undefined` — Chrome 89-129, which has no `connected` property — is **not** `false`, so an older
Chromium never takes this path and simply keeps the session until a real event or a read error
arrives. That is the right failure: the alternative would be tearing a live connection down on a
browser that cannot answer the question.

**The continuous fold.** `identifyOnly` registers the transport's single `onData` callback and
returns; `GridTransport` carries **one** callback, so whoever registers last owns the byte stream.
After identification resolves, the session registers **its own** pump over a fresh `FrameScanner` and
a fresh `IdentifyState`, and republishes `identity` from `identify(state)` as heartbeats arrive. The
module heartbeats at 4 Hz unprompted, so the rebuilt identity lands within about 250 ms and the rig
tail keeps filling for the life of the connection. Two rules on the republish:

- **Republish only when a rendered field changed** — the active page, the firmware triple, or the
  sorted list of other modules. Never on `lastSeen` alone: that would replace a `$state.raw` snapshot
  four times a second for a value nothing renders.
- **Sort `otherModules` by `sx`, then `sy`.** `[...state.seen.values()]` is arrival order, which is
  non-deterministic across runs, and a line that reorders itself between two loads reads as a bug.

**`absorbFrame` gains an optional clock.** It reads a module-scope `now = () => performance.now()`
today, which a node test cannot move:

```ts
export function absorbFrame(classes: DecodedClass[], state: IdentifyState, at: number = now()): void
```
Backwards compatible, two lines, every existing caller and `sequence.spec.ts` untouched. The session
passes its injected clock so the watchdog and the fold agree about time.

**`forget()`, in the only safe order** (the WICG steps have no close step):

```ts
async forget(): Promise<void> {
  const port = this.#port;
  if (!port || !("forget" in port)) return;   // @types declares it non-optional; the `in` test is
  await this.#teardown();                     // the only real guard (Chrome 103+, Firefox 151+)
  await port.forget();
  this.#port = undefined;
  this.identity = null;
  this.canForget = false;
  this.phase = "forgotten";                   // S7: getPorts() will not return it again
}
```
`canForget` is set from `"forget" in port` at adoption and is what decides whether the control
renders at all: a `FORGET THIS ZONA` button that does nothing is worse than none.

**`disconnect()`** tears down, clears the identity and returns to `idle` — never to `forgotten`,
because the permission is untouched.
