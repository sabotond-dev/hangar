<objective>
The slot takes its place in a header someone else built.

Wave 11, and the first plan in this phase that depends on **Phase 5.1 having shipped**. 05.1-09 turned
the wordmark into a flex row with one right-hand child — `BrowseLink`, `data-testid="browse-link"`,
the first tab stop. This phase adds a **second** child beside it, and the whole of the design work is
in not disturbing what is already there:

- **`BROWSE ALL` never collapses, never truncates, never becomes an icon and never moves.** It is site
  navigation and the first tab stop. The device slot is the thing that yields, because it is the thing
  with a disclosure behind it.
- **What yields, in order:** the multi-module tail first (below 1024px, into the disclosure), then the
  slot's own row (below 640px, onto a second header row). **No ellipsis anywhere**, because truncating
  the identity would hide the page number, which is the one part that changes live.
- **The second row below 640px is unconditional**, and that is the point. At a 320px viewport the
  usable inline space is 272px and one row needs about 358px even with the slot in its narrowest
  state — so it would wrap anyway, and *what* it wrapped would change with the session state, moving
  the headline and the coverflow at the exact moment a visitor plugged something in. A row that is
  always two rows never moves.
- **The opening is Phase 4's and is not renegotiated.** The slot and the note carry the wordmark's
  `.covered` treatment verbatim on `/`: absent from the very first painted frame, rising to full
  strength across the 700ms dissolve. And the session holds its first announcement until the splash
  has finished, so a ZONA detected during the opening is announced once, after it.

Purpose: CONN-01's one control and CONN-08's always-visible identity, on all three routes.
Output: two header wirings and a set of measurements that say the header cannot move.
</objective>

<interfaces>
**The row, after this plan.** `FrontDoor.svelte`'s header stays `space-between` with exactly **two**
children — the wordmark and a right-hand cluster — which is a smaller edit than a three-column grid
and leaves 05.1's slot alone:

```
HANGAR                                    BROWSE ALL      ▦ ZONA · fw 1.5.5 · page 3
└ h1, Micro, accent                       └ 5.1's slot     └ this phase's, corner-flush
```

```css
.cluster { display: flex; align-items: center; gap: 24px; }   /* lg */
```

DOM order inside the cluster is `BrowseLink` then `DeviceSlot`, which is also the visual order and
also the tab order — one line changes in 05.1's tab-order list and nothing else does.

**Below 640px the header is two rows.** Row 1 is the wordmark and `BROWSE ALL`; row 2 is the device
slot alone, right-aligned, 44px. **DOM order is unchanged**, so the tab order does not move with the
layout.

**The note sits beneath the header row**, inside the header block, on all three routes:
`<DeviceNote {covered} />`. Its right edge is flush with the device slot's; its text is left-aligned
inside it. On `/` it takes the same `covered` value as the wordmark; on `/c/{id}/` and `/browse/`
nothing is covered and nothing is suppressed — there is no splash to talk over, and a suppression
window that outlived the splash would silence a deep-linked visitor's reconnect offer for a second and
a half for no reason.

**The splash hold.** In `FrontDoor.svelte`, when `splash` is true, call `session.holdSpeech()` in
`onMount` and release it from `Splash`'s existing `onfinished` callback — the same callback that
already sets `opening = false`. Nothing else about the splash changes.

**`/browse/`** has no `BROWSE ALL` (the control would lead to the page you are on), so the device slot
is its only right-hand slot, and the note sits beneath the row above the `<search>` toolbar. Its
`browse-live` region is untouched.
