<objective>
Two leaves and a shared prop, before anything composes them.

Wave 8. The first three components of the device chrome, chosen because none of them knows what a
session is:

- **`PadSpinner` gains two props and no behaviour.** The shipped component is 32px with a hard-coded
  `role="img"`, `aria-label="Connecting"` and `data-testid="pad-spinner"` — none of which the header's
  24px decorative mark wants, and all three of which the panel's spinner still needs. `size = 32` and
  `decorative = false` reproduce today's output exactly, so Phase 4's spinner is untouched where it
  already ships. The walk's keyframes are percentage translates on an 11.111% cell, so they scale with
  no second animation and no new keyframes — which is the whole reason the mark reuses this component
  rather than copying it.
- **`DeviceMark`** is the session's non-text channel (Y-08). Four shapes — dark, one cell, walking,
  five-cell diagonal — so a viewer who sees no colour at all still reads four different states. No new
  SVG, no new icon, no canvas, no engine.
- **`FailureBlock`** is one component with two mounts (Y-11). Reading the six-step Grid Editor
  recovery twice, in two places, in two type sizes, is worse than reading it once — so the block is a
  single component and the surface that renders it passes its own control label.

Purpose: CONN-04's recovery on screen and CONN-08's connected shape, both as leaves that can be
wrong in isolation and cheap to fix.
Output: three components, no new test file yet — `device-ui.spec.ts` arrives in plan 06-10, when all
seven exist and the list it holds is complete.

<interfaces>
**`PadSpinner.svelte`, after this plan** — two props, no behaviour change:

```svelte
let { size = 32, decorative = false }: {
  /** Drives one custom property. The keyframes are percentage translates, so they scale. */
  size?: number;
  /** True drops role="img", aria-label and data-testid, so a decorative instance
      never collides with the panel's spinner in a selector - the two are on
      screen together throughout the connecting state. */
  decorative?: boolean;
} = $props();
```

`--spinner-size` replaces the two 32px declarations; every other declaration, every keyframe and the
reduced-motion block are untouched. `TryOnDevice.svelte` is **not** edited in this plan: its
`<PadSpinner />` keeps both defaults and therefore keeps rendering exactly what it renders today.

**`DeviceMark.svelte`** — 24px, `aria-hidden="true"` in every state, `data-testid="device-mark"`:

| `shape` | Rendering |
|---|---|
| `"dark"` | 81 dots at `--color-line-soft`, no lit cell |
| `"detected"` | one lit cell, top-left, static |
| `"connecting"` | `<PadSpinner size={24} decorative />` |
| `"connected"` | five lit cells forming the favicon's diagonal, static |

```svelte
let { shape }: { shape: "dark" | "detected" | "connecting" | "connected" } = $props();
```

The dot field is the pad recipe's first layer at 24px: the same radial-gradient background at an
11.111% pitch that `PadSpinner` already declares. Lit cells are `--color-accent`; unlit are
`--color-line-soft`. The mark carries no meaning the two text lines beside it do not — that is why it
is `aria-hidden`, and the header says so.

**`FailureBlock.svelte`** — the one block, either surface:

```svelte
let { block, testid = "failure-block" }: {
  /** Structurally declared: { title?, detail, steps }. Never imported from $lib/transport. */
  block: { title?: string; detail: string; steps: readonly string[] };
  testid?: string;
} = $props();
```

Title in Micro (title) at `--color-ink`; detail in Body at `--color-ink`; steps as a real `<ol>` at
`--color-ink-quiet`, one `<li>` per step, in order. **No heading element** — a disclosure is not a
document section (06-UI-SPEC, Accessibility Contract). An empty `steps` array renders no list at all
rather than an empty one, which is the `already-open` case. The block never renders a control and adds
no tab stop.
