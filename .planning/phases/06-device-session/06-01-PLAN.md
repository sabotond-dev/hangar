Wave 1. Nothing visible ships here. Three things land:

1. **The five baselines**, re-measured on a clean tree. Phase 5.1 was landing plans while this phase
   was planned, so no number written in `06-VALIDATION.md` may be trusted: `BASE_FILES`,
   `BASE_TESTS`, `BASE_SWEEP`, `BASE_E2E` and `PREV_E2E` are observed here and carried forward by
   every later SUMMARY. `BASE_E2E` and `PREV_E2E` start **equal**, and they are two names because
   they move differently: `PREV_E2E` rolls forward at 06-06, 06-07 and 06-13, while `BASE_E2E` is
   frozen at this measurement so 06-14's phase gate can assert `BASE_E2E + 16` against the clean
   tree rather than against a number that has already absorbed the phase's own additions.
2. **`already-open`.** `classifyOpenError` today drops both `InvalidStateError` forms — *"The port is
   already open."* and *"A call to open() is already in progress."* — into `unknown`, which renders
   the raw browser text on screen. A per-panel connection could not reach them. A session with a
   header control **and** a panel control bound to one action reaches them on a double click, so the
   in-flight guard (plan 06-03) makes them unreachable and this row is the net under it.
3. **The rig-aware `not-zona`.** `identifyOnly` returns `seen[0].moduleType` — the first module *by
   arrival order*, which on a chained rig may not be the module on the cable. `grid_decode.c:695-700`
   makes `heartbeatType === 1` the USB-attached module by definition, and `identify()` already uses
   exactly that rule to find the ZONA. The refusal sentence names a module; it should name the right
   one.

Purpose: CONN-04's "a named state instead of a raw exception" and CONN-07's "refused with a plain
message", both a layer below any component.
Output: two shipped modules amended, two specs grown, five numbers recorded.
</objective>

three existing call sites keep working with no edit:

```ts

  | "no-web-serial"
  | "insecure-context"
  | "cancelled"
  | "port-busy"
  | "unplugged"
  | "already-open"   // NEW
```

The new branch, inside the existing `err instanceof DOMException` block:

```ts
// Both InvalidStateError forms are HANGAR bugs wearing a DOMException:
// "The port is already open."            (serial_port.cc:121-122)
// "A call to open() is already in progress." (serial_port.cc:114-116)
// A site-wide session with two connect controls is what makes them reachable
// at all; plan 06-03's in-flight guard is the fix and this is the net.
if (err.name === "InvalidStateError") return "already-open";
```

**`failureCopy("already-open", …)`** renders the `unknown` row's title with a sentence in place of a
raw report and **no steps at all** (06-UI-SPEC, the failure table's `unknown` row):

```ts
case "already-open":
  return {
    title: "The port would not open",
    detail: "HANGAR is already connecting — one moment.",
    steps: [],
  };
```

The em dash is U+2014 and the sentence is one literal, never a concatenation. `raw` is deliberately
**not** interpolated: the browser's own words for this failure describe HANGAR's bug and mean nothing
to a visitor.

**`identifyOnly`'s `not-zona` outcome**, after this plan:

```ts
const seen = [...state.seen.values()];
if (seen.length === 0) return { kind: "silent" };
// The module on the USB cable reports heartbeat type 1 (grid_decode.c:695-700),
// which is the same rule identify() uses to find the ZONA. Arrival order is
// non-deterministic on a rig, so seen[0] names an arbitrary module.
const onCable = seen.find((m) => m.heartbeatType === 1) ?? seen[0];
return { kind: "not-zona", moduleType: onCable.moduleType };
```

**The synthetic rig, for the spec.** `heartbeatFrame` builds real encoder-derived frames for any
hwcfg. hwcfg values read from `grid.module_hwcfgs()` against the pinned package: ZONA RevH **161**,
EN16 RevH **195**, BU16 RevH **131**. Confirm all three against the package before using them; if a
number differs, use the package's and record the correction.
