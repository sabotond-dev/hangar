<objective>
The session, and the seam that lets it exist without a chunk.

Wave 3. D-05's store owns the port, the identity, the phase and the failure. Two design facts decide
the whole file and both are recorded in the interfaces block below:

1. **The reconnect offer must cost nothing.** `getPorts()`, the USB filter, the `connected` check and
   the capability rule are all light; only *opening* needs the protocol package. Today they are
   welded together in `web-serial.ts`, which imports `$lib/protocol`, which imports
   `@intechstudio/grid-protocol` at module scope — a 131,101-byte chunk. So this plan first splits
   the light half out (`src/lib/protocol/usb.ts`, `src/lib/transport/ports.ts`), one definition each,
   re-exported from their old homes so no existing caller changes. The session then statically
   imports only import-free-ish modules and **the whole load path — capability, listeners, the
   granted-port offer — runs with no dynamic import at all.**
2. **`requestPort()` is the first statement of the click handler and nothing may be awaited in front
   of it.** With `ZONA_USB` statically available that is now trivially true from two call sites, and
   the heavy modules are awaited *after* the chooser has been asked for.

This plan builds the machine up to and including identification. The `navigator.serial` listener
pair, the replug adoption, the liveness watchdog, `forget()` and the never-writes gate are plan
06-04, in the same file.

Purpose: CONN-06's silent reconnect, CONN-05's cancelled state, CONN-07's filter-and-verify and
CONN-01's one capability read.
Output: two light modules, one session store, eight tests.
</objective>

**The reactive surface.** Scalars and `$state.raw` snapshots only. The port, the transport, the
scanner and the identify accumulator are plain private fields, because `$state` deep-proxies plain
objects and arrays and a proxy in a callback that runs four times a second is pure cost.

**`start()` is synchronous and never opens anything.**

```ts
start(env = {}) {
  const capability = capabilityOf({ hasSerial: ..., secure: ... });   // session-copy, import-free
  if (capability !== "ok") {
    this.failureKind = capability === "unsupported" ? "no-web-serial" : "insecure-context";
    this.phase = capability;            // "unsupported" | "insecure", decided in this frame
    return;                             // no listeners, no getPorts, nothing fetched
  }
  ... attach the navigator-level listeners (plan 06-04) ...
  void this.#offerGranted();            // getPorts(), no gesture, never open()
}
```
`#offerGranted` filters `grantedZonaPorts()` by `portIsAttached(p) !== false` — **not** `=== true`,
because Chrome 89-129 has no `connected` and `undefined` must mean "keep it" — adopts the first and
sets `detected`, or sets `idle`. An empty list means "not plugged in", never "no grant" (Pitfall 9),
so nothing the `idle` state publishes may use the words access, permission or granted.

**`connect()` — one action, two call sites, one activation window.**

```ts
connect(): void {
  if (this.#busy) return;                 // kills both InvalidStateError rows
  this.#busy = true;
  if (this.#port && !this.#transport) { void this.#openAdopted(); return; }  // no chooser (D-06)
  let picking: Promise<SerialPort>;
  try {
    picking = this.#serial.requestPort({ filters: [ZONA_USB] });   // FIRST statement
  } catch (err) { void this.#refuse(err); this.#busy = false; return; }
  this.#clearFailure();
  this.phase = "choosing";
  void this.#afterPick(picking);
}
```
The `try` is not decoration: a lost transient activation is **thrown** by Chromium
(`serial.cc:291-293`), not rejected, so a `.catch()` on the stored promise would never see it.

**`#refuse(err, port?)`** awaits the memoised module promise (a failure is not activation-sensitive),
calls `classifyOpenError(err, port)` and maps the key onto a phase:

| `OpenFailure` | phase | note |
|---|---|---|
| `cancelled` | `cancelled` | |
| `port-busy` | `port-busy` | |
| `unplugged` | `unplugged-at-open` | the S6 open failure, rendered by `failureCopy("unplugged", …)` |
| `already-open` | `unknown` | the key is kept so the block reads the already-connecting sentence |
| `unknown` | `unknown` | `failureRaw` carries the message |

with one branch before the classifier: a `DOMException` named `NotAllowedError` is `cancelled` with
`permissionDeclined = true` (Y-06), because the classifier has no row for it and a declined
permission is a closed chooser by another route.

**`#openAdopted()`** sets `opening`, awaits the modules, opens with `BAUD_RATE` and
`READ_BUFFER_SIZE`, builds the transport through `openTransport`, sets `identifying`, and runs
`identifyOnly`. `identified` becomes `connected`; `not-zona` and `silent` set their phases **and
close the port**, because both recovery lists tell the visitor to try again and a port this page is
still holding would make that impossible. `#busy` is cleared in a `finally` on every path.

**`failureFor(label)`** is the one block, for either surface:

- a phase in `FAILURE_COPY_STATES` -> `failureCopy(this.failureKind ?? key, this.failureRaw, label)`
- `not-zona` -> `notZonaBlock(this.refusedModule, label)`
- `silent` -> `silentBlock(this.#windowSeconds, label)`
- `unplugged-while-connected` -> `unpluggedWhileConnectedBlock()`
- anything else -> `null`

It returns `null` until the modules have resolved **only** for the four transport-backed keys; the
two capability keys must render immediately, so `failureFor` handles `unsupported` and `insecure`
without the transport by... **awaiting nothing**: `failureCopy` is needed for their text, so the
session resolves the modules lazily *once a capability failure exists* as well — kicked off from
`start()`'s failure branch through the same memoised promise, off the critical path, and the block
renders as soon as it lands. State that trade in the file: the two terminal states fetch the chunk
they cannot use, once, after paint, because the alternative is duplicating `UNSUPPORTED_DETAIL`.
